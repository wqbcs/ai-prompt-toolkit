# 调研报告：软件工程学科建立历程——如何定义新工程学科

> **调研编号**：R11-K1-01
> **日期**：2026-05-29
> **目标**：研究软件工程从技艺到学科的建立历程，为"提示词工程"学科定义提供范式参考

---

## 1. 软件工程学科化历程

### 1.1 关键里程碑

| 年份 | 事件 | 意义 |
|------|------|------|
| 1968 | NATO软件工程会议(慕尼黑) | "软件工程"术语首次正式使用，回应"软件危机" |
| 1969 | Dijkstra《Go To语句有害论》 | 结构化编程理论基础 |
| 1970 | Winston Royce《管理大型软件系统开发》 | 瀑布模型提出 |
| 1975 | Brooks《人月神话》 | 软件工程经济学奠基 |
| 1984 | SEI成立(卡内基梅隆) | 软件工程研究所建立，CMM诞生 |
| 1987 | IEEE Std 730《软件质量保证标准》 | 首个软件工程国际标准 |
| 1991 | CMM v1.0发布 | 能力成熟度模型——学科化标志 |
| 1995 | SWEBOK启动 | 软件工程知识体系——学科化核心 |
| 2001 | SWEBOK Trial Version | 知识体系试行版 |
| 2004 | SWEBOK Guide v2004 | 知识体系正式发布——学科确立 |
| 2014 | SWEBOK v3 | 15个知识域，学科体系完善 |
| 2019 | ISO/IEC 19759:2019 | SWEBOK成为ISO国际标准 |

### 1.2 学科化关键要素

1. **知识体系(SWEBOK)**：15个知识域定义学科边界
   - 软件需求、软件设计、软件构造、软件测试、软件维护
   - 软件配置管理、软件工程管理、软件工程过程、软件工程工具与方法
   - 软件质量、软件工程经济学、计算基础、数学基础、工程基础、工程经济学

2. **能力模型(CMM/CMMI)**：5级成熟度定义能力等级
   - L1初始级→L2可管理级→L3已定义级→L4可量化级→L5优化级

3. **伦理准则(ACM/IEEE-CS)**：软件工程伦理规范
   - 公众利益优先、客户与雇主、产品、判断、管理、职业、同事、自我

4. **标准体系(IEEE/ISO)**：从术语到过程到质量
   - IEEE Std 610.12(术语)、ISO/IEC 12207(过程)、ISO/IEC 9126(质量)

5. **教育认证(ABET)**：本科/研究生课程认证
   - ABET认证标准、核心课程体系、毕业能力要求

6. **专业认证(PMP/CSDP)**：专业资质认证
   - IEEE CSDP(认证软件开发师)、CSTE(认证软件测试师)

7. **学术共同体**：期刊/会议/学会
   - IEEE TSE、ACM TOSEM、ICSE、FSE、ASE

## 2. 新工程学科建立的通用范式

### 2.1 六阶段模型

```
阶段1: 问题识别 → 识别"危机"或"鸿沟"，证明现有学科无法覆盖
阶段2: 概念形成 → 提出核心概念、术语、边界
阶段3: 知识体系化 → 构建知识体系(SWEBOK类比)
阶段4: 标准化 → 制定标准(IEEE/ISO类比)
阶段5: 教育认证化 → 建立教育体系和认证
阶段6: 生态成熟化 → 社区/工具/市场/就业
```

### 2.2 关键成功因素

| 因素 | 软件工程案例 | 对提示词工程的启示 |
|------|------------|------------------|
| 有明确的"危机"驱动 | 1960s软件危机 | AI幻觉/安全/可控性危机 |
| 有权威机构背书 | NATO/IEEE/SEI | 需要IEEE/ACM/ISO背书 |
| 有完整知识体系 | SWEBOK 15知识域 | 需要PEBOK(提示词工程知识体系) |
| 有能力成熟度模型 | CMMI 5级 | 需要5级提示词工程师能力模型 |
| 有伦理准则 | ACM/IEEE-CS伦理 | 需要提示词工程伦理准则 |
| 有标准体系 | ISO/IEC 12207 | 需要提示词工程过程标准 |
| 有教育体系 | ABET认证 | 需要5级课程+认证体系 |
| 有经济验证 | 软件产业规模 | AI产业规模(>$1000亿) |
| 有学术共同体 | ICSE/TSE | 需要PEConf/PET期刊 |
| 有工具链 | IDE/CI/CD | VS Code扩展/GitHub Actions |

### 2.3 反面教训

1. **过早声称学科成熟**：软件工程从1968到2004用了36年才确立SWEBOK
2. **忽视实践验证**：纯理论无法建立工程学科，必须有工业级实践
3. **闭门造车**：需要跨组织协作(IEEE+ACM+ISO+产业)
4. **忽视伦理**：无伦理的工程学科不可持续

## 4. 对提示词工程学科化的启示

### 4.1 可行性论证
- **危机驱动**：AI可控性危机(幻觉/注入/偏见/合规)比软件危机更紧迫
- **经济规模**：全球AI市场>$1000亿，提示词工程是关键使能技术
- **社会需求**：每个使用AI的组织都需要提示词工程能力
- **技术积累**：3年实践已有大量最佳实践和反模式积累

### 4.2 加速路径
软件工程用了36年，但提示词工程可加速：
1. **站在巨人之肩**：可直接复用软件工程范式(SWEBOK/CMMI/ABET)
2. **数字原生**：无需等待物理基础设施，工具链即时部署
3. **社区驱动**：开源+社交媒体可快速建立学术共同体
4. **产业迫切**：AI安全法规倒逼工程化需求
5. **预估时间线**：3-5年内可建立PEBOK v1.0

### 4.3 独特性
提示词工程区别于其他工程学科的独特性：
- **双层抽象**：既工程化提示词，又提示词工程化AI行为
- **人机共创**：非纯人设计，需要人机迭代优化
- **模型依赖**：核心对象(提示词)的效果高度依赖模型
- **语义工程**：以自然语言为"代码"，语义精度是核心
- **快速演化**：模型每季度迭代，提示词工程需同步演化

## 5. 结论

提示词工程学科化遵循"问题识别→概念形成→知识体系化→标准化→教育认证化→生态成熟化"六阶段范式。可借鉴软件工程36年经验，借助AI产业紧迫需求，3-5年内完成PEBOK v1.0建立。本体系v13.0.0将率先完成阶段1-4(问题识别→知识体系化→标准化→教育体系雏形)，为学科化奠定基础。
