# 提示词工程伦理准则 v1.0

> **版本**：v1.0 | **日期**：2026-05-29 | **参照ACM/IEEE-CS软件工程伦理规范**

---

## 1. 总则

提示词工程师应致力于提示词工程的道德和专业实践，确保AI系统行为对社会、个人和组织产生积极影响，同时最大限度地减少潜在危害。

---

## 2. 八大伦理原则

### 2.1 公众利益优先

提示词工程师应以公众利益为最高准则，特别是在安全、健康和公共福祉方面。

**具体义务**：
- 识别并披露提示词可能对社会产生的负面影响
- 拒绝设计意图欺骗、操纵或伤害用户的提示词
- 在公共利益与商业利益冲突时，优先考虑公共利益
- 对高风险应用(医疗/法律/金融)实施额外安全约束

### 2.2 客户与雇主

在保持公共利益优先的前提下，对客户和雇主提供最佳专业服务。

**具体义务**：
- 对提示词的能力和局限保持诚实
- 不夸大提示词效果，不隐瞒已知缺陷
- 保护客户专有信息和商业秘密
- 就潜在风险及时告知客户

### 2.3 产品质量

确保提示词产品达到最高专业标准。

**具体义务**：
- 遵循28条设计原则，规避28种反模式
- 执行22维度质量评估
- 通过17项门禁验证
- 建立持续改进机制

### 2.4 专业判断

保持客观、独立的专业判断。

**具体义务**：
- 不受商业压力影响而降低安全标准
- 技术判断基于实证而非直觉
- 对不确定结论明确标注不确定性
- 维护专业独立性

### 2.5 管理责任

管理者应促进伦理实践。

**具体义务**：
- 建立提示词评审机制(含伦理审查)
- 为团队提供伦理培训
- 不要求团队绕过门禁或安全约束
- 建立伦理问题上报渠道

### 2.6 职业发展

持续提升专业能力。

**具体义务**：
- 跟踪AI和提示词工程最新发展
- 参与继续教育(每年≥16学分)
- 为PEBOK和标准贡献知识
- 指导低级别从业者

### 2.7 同行协作

与同行公平协作，尊重知识产权。

**具体义务**：
- 尊重他人提示词作品的署名权
- 在评审中保持公正客观
- 共享非竞争性最佳实践
- 不恶意评价竞争对手作品

### 2.8 自我责任

对自身专业行为负责。

**具体义务**：
- 仅在能力范围内提供服务
- 对行为后果承担责任
- 持续反思潜在偏见和盲点
- 主动纠正已发现的错误

## 3. 高风险领域附加准则

### 3.1 医疗领域
- 提示词不得给出确定性诊断建议
- 输出必须包含"请咨询专业医师"声明
- 不得使用未经验证的医疗数据

### 3.2 法律领域
- 不得替代律师提供法律意见
- 输出必须标注"仅供参考，不构成法律意见"
- 不得引用过时法规

### 3.3 金融领域
- 不得提供具体投资建议
- 输出必须包含风险提示
- 遵守金融监管合规要求

### 3.4 儿童保护
- 面向儿童的提示词必须额外安全审查
- 不得收集儿童个人信息
- 内容必须适龄

---

## 4. 伦理审查流程

```
设计阶段 → 伦理自查清单(10项)
    ↓
评审阶段 → 伦理评审(2位评审员)
    ↓
测试阶段 → 偏见测试+公平性测试+安全测试
    ↓
部署阶段 → 影响评估+监控+告警
    ↓
运营阶段 → 定期伦理审计+用户反馈
```

---

## 5. 违规处理

| 级别 | 行为 | 处理 |
|------|------|------|
| 轻微 | 未遵循推荐实践 | 警告+培训 |
| 中 | 绕过门禁/夸大能力 | 暂停认证+整改 |
| 重 | 故意设计有害提示词/泄露隐私 | 撤销认证+通报 |
| 极重 | 造成实际伤害 | 撤销认证+法律追责 |
