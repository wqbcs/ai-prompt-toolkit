> **文档版本**：v1.0  
> **日期**：2026-05-28  
> **适用范围**：AI提示词体系01-12号核心文档55个场景模板

## 一、评估维度定义

| 维度 | 全称 | 定义 | 满分 | 评估对象 |
|------|------|------|------|----------|
| 结构 | 结构完整性 | 场景模板是否包含5要素(描述+输入+输出+检查清单+验收标准) | 20 | 每个场景模板 |
| 约束 | 约束条件完备性 | 约束是否覆盖技术/业务/安全/性能四维度 | 20 | 每个文档核心约束章节 |
| 角色 | 角色设定深度 | 角色定义是否含经验年限+专业领域+核心能力+工作方式 | 20 | 每个文档身份定义章节 |
| 输出 | 输出格式精确性 | 输出是否有明确格式(结构化/半结构化/自然语言)+示例 | 20 | 每个文档输出规范章节 |
| 清单 | 检查清单覆盖度 | 检查项是否覆盖该领域全部关键风险点 | 20 | 每个文档检查清单章节 |
| 推理 | 推理模式适配性 | 是否适配CoT/Few-shot/自纠错等推理模式 | 20 | 每个场景模板推理模式标注 |

## 二、评分标准（0-20分制）

### 2.1 结构完整性评分

| 分数段 | 标准 |
|--------|------|
| 0-5 | 场景仅有任务列表，无任何结构化要素 |
| 6-10 | 场景有部分要素（2-3个），但缺显式5要素标注 |
| 11-14 | 场景有4个要素，缺1个（通常缺验收标准或检查清单） |
| 15-17 | 场景有5要素，但部分要素内容过简（<3项） |
| 18-20 | 场景5要素完整，每个要素内容充实（≥3项）且格式规范 |

### 2.2 约束条件完备性评分

| 分数段 | 标准 |
|--------|------|
| 0-5 | 无约束或仅1条泛泛约束 |
| 6-10 | 有2-3条约束，但仅覆盖1-2个维度 |
| 11-14 | 有4-6条约束，覆盖2-3个维度 |
| 15-17 | 覆盖3个维度，但第4维度仅有隐含提及 |
| 18-20 | 覆盖技术/业务/安全/性能4维度，每个维度≥2条显式约束 |

### 2.3 角色设定深度评分

| 分数段 | 标准 |
|--------|------|
| 0-5 | 仅1句话角色声明（"你是一名专家"） |
| 6-10 | 含身份+领域，但缺经验和能力描述 |
| 11-14 | 含经验+领域+能力，但缺工作方式 |
| 15-17 | 含经验+领域+能力+工作方式，但工作方式<3条 |
| 18-20 | 4要素完整，工作方式≥3条且具体可操作 |

### 2.4 输出格式精确性评分

| 分数段 | 标准 |
|--------|------|
| 0-5 | 仅"输出XXX"文本，无格式约束 |
| 6-10 | 有格式提及（如"表格形式"），但无模板/示例 |
| 11-14 | 有格式模板，但缺示例 |
| 15-17 | 有格式模板+示例，但部分场景缺失 |
| 18-20 | 所有场景有格式模板+完整示例，含必含要素+禁止项 |

### 2.5 检查清单覆盖度评分

| 分数段 | 标准 |
|--------|------|
| 0-5 | 无检查清单或仅1-2项泛泛条目 |
| 6-10 | 有3-5项，但缺少关键风险点 |
| 11-14 | 有6-8项，覆盖主要风险但缺专项 |
| 15-17 | 有8-12项，覆盖全面但部分项缺检查方法 |
| 18-20 | 有≥12项，按维度分组，每项含检查点+方法+风险等级 |

### 2.6 推理模式适配性评分

| 分数段 | 标准 |
|--------|------|
| 0-5 | 无任何推理模式标注 |
| 6-10 | 有S1/S2适配标注，但无CoT/Few-shot |
| 11-14 | 有CoT指令或Few-shot示例，但仅1-2个场景 |
| 15-17 | 有CoT+Few-shot，覆盖≥50%复杂场景 |
| 18-20 | 多种推理模式(CoT+Few-shot+自纠错+ReAct)覆盖≥80%场景，含工具验证 |

## 三、评估流程

```
读取 → 分析 → 评分 → 记录 → 报告
```

### 3.1 读取阶段
- 读取01-12号核心文档
- 提取每个场景模板的5要素内容
- 提取核心约束、角色定义、输出规范、检查清单、推理模式标注

### 3.2 分析阶段
- 逐场景对比5要素完整性
- 逐文档对比约束4维度覆盖
- 逐文档对比角色4要素完整性
- 逐场景对比输出格式+示例
- 逐文档对比检查清单维度覆盖
- 逐场景对比推理模式标注

### 3.3 评分阶段
- 按上述评分标准逐维度打分（0-20）
- 记录每个维度的问题描述
- 计算文档总分（6维度之和）和均分

### 3.4 记录阶段
- 将评估结果写入evaluation_baseline.json或评估对比报告
- 更新iteration_state.json中的convergence_status
- 记录追溯信息到对应批次的trace JSON

### 3.5 报告阶段
- 生成维度得分对比表
- 生成文档总分对比表
- 生成维度排名变化表
- 分析收敛趋势（标准差、最低分变化）
- 列出仍未达标的维度及改进建议

## 四、收敛判定标准

### 4.1 维度收敛

| 条件 | 标准 | 说明 |
|------|------|------|
| 维度均分≥15 | 满分20的75% | 6个维度均分均≥15 |
| 维度标准差≤1.5 | 维度间差异小 | 6维度分数的标准差≤1.5 |
| 连续3次达标 | 趋势确认 | 连续3次评估均满足上述条件 |

### 4.2 迭代保障

| 条件 | 标准 | 说明 |
|------|------|------|
| 最小迭代次数≥56 | 覆盖充分 | B1-B9共51次+B10补充确保≥56 |
| 场景覆盖率100% | 55个场景 | 所有场景模板5要素完整 |

### 4.3 最终判定

```
IF 所有维度均分≥15 
AND 维度标准差≤1.5
AND 连续3次评估达标
AND 迭代次数≥56
AND 场景覆盖率=100%
THEN 收敛达标
ELSE 继续迭代
```
