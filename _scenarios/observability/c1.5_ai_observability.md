# AI应用可观测性场景模板

> 覆盖: LLM调用链追踪 / Token消耗监控 / 模型延迟分析 / 幻觉检测 / 成本归因

---

## 1. 陷阱（5项）

### 1.1 LLM调用链黑盒导致问题无法追踪
- LLM API调用（OpenAI/Claude/盘古大模型）被当作普通HTTP请求处理，缺乏Prompt/Completion维度的追踪
- 多轮对话、工具调用（Function Calling）、RAG检索等复杂LLM调用链缺乏端到端追踪
- LLM调用的输入（Prompt Template + 变量）和输出（Completion + Token统计）未记录到Span属性中
- LLM编排框架（LangChain/LlamaIndex/AutoGen）的内部调用链（检索→重排→生成→校验）不可见
- 华为云APM对LLM API调用的追踪停留在HTTP层面，无法区分不同模型、不同Prompt的业务语义

### 1.2 Token消耗无感知导致成本失控
- Token消耗缺乏实时监控和预算告警，月底账单超预期才发现成本问题
- 未区分输入Token和输出Token的成本差异（输出Token通常是输入Token的2-3倍价格）
- Token消耗未按业务维度（用户/租户/功能模块）归因，无法识别高消耗场景
- 缺乏Token消耗趋势预测，无法提前发现成本异常和优化机会
- 华为云ModelArts/盘古大模型的Token计费粒度较粗，缺乏细粒度的消耗分析工具

### 1.3 幻觉检测缺失导致输出质量失控
- LLM输出缺乏自动化的幻觉检测机制（事实性校验、一致性校验、置信度评估）
- 幻觉输出未纳入可观测性体系，无法量化幻觉率、定位幻觉高发场景
- RAG场景中检索结果与生成结果的一致性未校验，检索到错误文档后生成幻觉无法自动发现
- 缺乏人工反馈闭环（Thumbs Up/Down），用户发现的幻觉无法反馈到可观测性系统
- 华为云盘古大模型的内置安全过滤仅覆盖有害内容，不覆盖事实性幻觉

### 1.4 成本归因不清导致优化无方向
- LLM调用成本未按业务线/团队/用户归因，成本优化缺乏数据支撑
- 共享LLM服务（API Gateway/模型代理）的调用成本分摊规则不明确
- 不同模型（GPT-4o/GPT-4o-mini/Claude-3.5-sonnet/盘古-large）的成本差异未在可观测性中体现
- 缺乏成本效率指标（如：每$1产出多少有效Token、每次业务操作的LLM成本）
- 华为云ModelArths的成本分析功能按项目聚合，缺乏按功能/用户/场景的细粒度归因

### 1.5 模型延迟P99异常导致用户体验劣化
- LLM调用的首Token延迟（Time to First Token, TTFT）和总延迟（Total Latency）未分别监控
- Streaming场景下首Token延迟正常但生成速度慢（Token/s低），用户感知卡顿但P99总延迟正常
- 模型推理延迟受上下文长度影响（长Prompt导致延迟线性增长），缺乏Prompt长度与延迟的关联分析
- 高并发下模型API限流（429 Too Many Requests）导致重试延迟，未纳入延迟统计
- 华为云盘古大模型的延迟P99在不同Region差异大，缺乏跨Region延迟对比和优化

## 2. 性能（5项）

### 2.1 LLM调用链性能优化
- 使用OpenTelemetry Semantic Conventions for GenAI记录LLM调用的完整信息：gen_ai.system、gen_ai.request.model、gen_ai.request.max_tokens、gen_ai.response.finish_reason
- LLM编排框架（LangChain/LlamaIndex）配置回调（Callback）自动生成Span，记录检索→重排→生成的完整调用链
- 多轮对话的每次LLM调用创建独立子Span，通过session_id关联同一对话的所有Span
- 工具调用（Function Calling）的每次工具执行创建独立Span，记录工具名称、输入参数、执行结果
- 华为云APM配置自定义Span记录盘古大模型调用的业务属性（模型版本、Prompt模板、业务场景）

### 2.2 Token消耗预算控制
- 建立Token消耗的实时监控面板：总消耗量、输入/输出Token比、按模型分布、按业务场景分布
- 配置Token消耗预算告警：日消耗超阈值（80%/100%）触发P2/P1告警
- 实施Token限流策略：按用户/租户/业务场景设置Token配额，超出配额自动降级（切换到更便宜的模型）或拒绝
- Token消耗趋势预测：基于历史数据预测月度消耗，提前预警超预算风险
- 华为云ModelArts配置资源配额和用量告警，结合自定义指标实现细粒度Token监控

### 2.3 模型延迟P99优化
- 分别监控TTFT（首Token延迟）和Token/s（生成速率），两个指标独立优化
- 长Prompt优化：使用Prompt压缩、缓存相似Prompt的中间结果、减少System Prompt重复传输
- Streaming模式优化：配置合理的chunk_size和stream_timeout，平衡首Token延迟和生成流畅度
- 模型路由优化：简单问题路由到轻量模型（GPT-4o-mini/Claude-3.5-haiku），复杂问题路由到旗舰模型
- 华为云盘古大模型配置推理加速（Speculative Decoding/PD分离），降低TTFT和提升Token/s

### 2.4 幻觉检测效率优化
- 使用LLM-as-Judge模式：用另一个LLM评估生成结果的准确性和一致性，成本约为原调用的10-20%
- 规则化前置检测：对生成结果进行格式校验、数值范围校验、关键词校验，低成本的快速过滤
- RAG一致性校验：对比检索文档与生成结果的关键信息，检测事实性偏差
- 采样检测策略：不是每次调用都做幻觉检测，按比例采样（如10%）进行深度检测
- 华为云盘古大模型配置输出校验规则，结合内容安全审核实现自动化质量把关

### 2.5 成本归因与分摊
- LLM调用添加业务维度标签：app_name、feature_name、tenant_id、user_tier
- 建立成本效率指标：Cost Per Query（每次查询成本）、Cost Per Task（每项任务成本）、Token Efficiency（有效Token占比）
- 成本分摊模型：按调用量分摊 / 按Token量分摊 / 按业务收入分摊，选择最适合的分摊策略
- 成本优化看板：展示各业务线/模型/场景的成本排名和趋势，识别优化机会
- 华为云费用分析结合自定义标签实现LLM调用成本的细粒度归因

## 3. 安全（3项）

### 3.1 LLM提示注入追踪
- 提示注入攻击（Prompt Injection）的检测和追踪：记录所有Prompt中是否包含注入模式（如"忽略之前的指令"）
- 间接提示注入（通过外部数据源/文档注入）的追踪：记录RAG检索结果中是否包含可疑内容
- 注入攻击的影响范围追踪：哪些会话/用户受到了注入攻击的影响，攻击是否成功绕过了安全限制
- 华为云盘古大模型的内容安全审核日志作为注入攻击追踪的数据源
- 缓解措施：输入清洗和过滤、系统Prompt与用户输入隔离、输出审核和阻断

### 3.2 Token侧信道攻击
- 攻击者通过观察Token消耗模式推断系统Prompt的内容和结构（Token数量反映了Prompt长度）
- 多用户共享模型场景下，一个用户的Prompt长度可能泄露另一个用户的上下文信息
- API错误信息中的Token统计可能泄露模型配置和系统Prompt细节
- 华为云盘古大模型API的Token统计响应需过滤敏感细节，仅返回必要的Token数量
- 缓解措施：固定System Prompt的Token数量、Token统计信息脱敏、错误信息最小化

### 3.3 模型输出隐私泄露
- LLM输出可能包含训练数据中的个人信息（姓名、地址、电话），需检测和过滤
- 多租户场景下，模型输出可能泄露其他租户的数据（跨租户信息泄露）
- LLM输出的日志记录可能包含敏感信息（如生成的代码中的密钥、API Key）
- 华为云LTS记录的LLM调用日志需配置脱敏规则，过滤Prompt和Completion中的敏感内容
- 缓解措施：输出审核和过滤、日志脱敏、多租户数据隔离、差分隐私

## 4. 故障排查（5项）

### 4.1 LLM调用超时排查
- **现象**: LLM API调用超时，返回504或超时错误，用户等待时间过长
- **排查步骤**:
  1. 确认超时类型：连接超时（TCP连接失败）vs 读取超时（响应超时）vs 首Token超时
  2. 检查LLM API的服务状态（OpenAI Status/华为云健康看板）
  3. 分析超时请求的Prompt长度和Token数量，确认是否为长上下文导致的推理延迟
  4. 检查并发请求数是否触发API限流（429状态码），导致排队等待
  5. 检查网络链路：客户端→API Gateway→LLM API各环节的延迟
- **根因模式**: API限流排队 > 长上下文推理延迟 > API服务故障 > 网络延迟 > 客户端超时配置过短

### 4.2 Token消耗异常飙升排查
- **现象**: Token消耗突然增加数倍，成本超预期
- **排查步骤**:
  1. 按业务维度（用户/租户/功能）拆分Token消耗，识别最大增长来源
  2. 检查是否有异常调用模式：单用户大量调用、循环调用、无限重试
  3. 分析Prompt长度分布：是否有异常长的Prompt导致输入Token飙升
  4. 检查是否有模型切换：从便宜模型切换到昂贵模型（如GPT-4o-mini→GPT-4o）
  5. 华为云ModelArts查看Token消耗明细和异常调用记录
- **根因模式**: 异常用户/攻击 > 循环调用/无限重试 > Prompt膨胀 > 模型切换 > 业务量增长

### 4.3 幻觉输出检测排查
- **现象**: LLM生成的回答包含虚假信息、编造事实、与检索文档不一致
- **排查步骤**:
  1. 收集幻觉输出样本，分析幻觉类型：事实性错误 / 逻辑不一致 / 编造引用
  2. 检查RAG检索结果是否与幻觉相关：检索到错误文档/未检索到相关文档/文档本身有误
  3. 分析Prompt模板是否存在引导幻觉的因素（如"根据你的知识回答"vs"仅根据提供的文档回答"）
  4. 检查温度参数（temperature）是否过高，导致输出过于随机
  5. 华为云盘古大模型的输出审核日志分析幻觉模式
- **根因模式**: RAG检索错误 > Prompt设计不当 > 温度过高 > 模型能力不足 > 领域知识缺失

### 4.4 模型延迟抖动排查
- **现象**: LLM调用延迟在短时间内剧烈波动，P99延迟是P50的10倍以上
- **排查步骤**:
  1. 区分TTFT抖动和Token/s抖动：是首Token慢还是生成速度慢
  2. 检查延迟抖动的时间模式：固定周期（可能是批处理/负载均衡调度）/随机波动
  3. 分析抖动时段的请求特征：Prompt长度、并发量、模型版本是否变化
  4. 检查LLM API的负载均衡策略：是否被路由到不同的后端实例（延迟差异大）
  5. 华为云盘古大模型查看各Region的延迟分布，确认是否为特定Region的负载问题
- **根因模式**: 负载均衡不均 > 后端实例性能差异 > 限流排队波动 > Prompt长度分布不均 > 网络波动

### 4.5 成本异常归因排查
- **现象**: LLM调用成本与预期不符，但无法定位具体原因
- **排查步骤**:
  1. 对比成本变化的时段和幅度，确认是渐进增长还是突变
  2. 按模型拆分成本：不同模型的单价差异可能是成本变化的主要因素
  3. 按业务场景拆分成本：新功能上线、用户量增长、Prompt模板变更
  4. 分析Token效率：有效Token占比是否下降（如大量无效重试、冗余Prompt）
  5. 华为云费用中心结合资源标签分析成本归因
- **根因模式**: 模型切换/升级 > 业务量增长 > Prompt膨胀 > 重试策略不当 > 新功能上线

| **LLM框架支持** | OpenAI/Anthropic/LangChain | OpenAI/Anthropic/LangChain/LlamaIndex | 任意（需自行适配） |

| **成本追踪** | 按模型/按Prompt模板 | 按模型/按用户/按会话 | 自定义维度（需自行实现） |

| **适用场景** | Prompt管理+基础追踪 | LLM应用全生命周期可观测性 | 合规严格/深度定制需求 |

### 5.1 Pezzo — Prompt管理与调用追踪的轻量方案
- 优势：Prompt版本管理、A/B测试、成本监控、低代码接入、开源可自托管
- 劣势：功能深度不如Langfuse、社区规模较小、评估能力有限、对复杂编排链路支持不足
- 推荐场景：中小规模LLM应用、Prompt管理需求强、快速接入需求

### 5.2 Langfuse — LLM应用全生命周期可观测性方案
- 优势：完整的追踪+评估+标注+Prompt管理、LLM-as-Judge评估、人工标注、Score体系、活跃社区
- 劣势：高级功能需付费版、自托管需要基础设施、与华为云生态集成需手动配置
- 推荐场景：中大规模LLM应用、需要评估和质量闭环、团队有LLM应用开发经验

### 5.3 自建AI可观测性 — 完全自主的深度定制方案
- 优势：完全自主可控、与现有可观测性平台无缝集成、定制化程度最高、数据完全自主
- 劣势：开发维护成本高、需要AI+可观测性双领域专家、功能迭代慢、缺乏社区支持
- 推荐场景：合规严格（数据不出境）、大规模LLM应用、有专职AI可观测性团队、需要深度定制

## 6. 已知限制（≥3项）

### 6.1 LLM语义约定的标准化仍在早期
- OpenTelemetry的GenAI Semantic Conventions仍在Experimental阶段，属性命名和行为可能变更
- 不同LLM提供商（OpenAI/Anthropic/华为云盘古）的API响应格式差异大，统一追踪需要适配层
- LLM编排框架（LangChain/LlamaIndex/AutoGen）的回调接口不统一，追踪集成需要逐框架适配
- 华为云盘古大模型的API与OpenAI API部分兼容但存在差异，直接使用OpenAI SDK可能丢失特有属性

### 6.2 幻觉检测的准确性和成本矛盾
- LLM-as-Judge模式本身可能产生幻觉，评估结果的可靠性无法保证
- 高准确性幻觉检测需要复杂流水线（多模型交叉验证+事实库校验），成本可能超过原始调用
- 幻觉的边界定义模糊：什么是幻觉vs创造性表达vs合理推理，缺乏统一标准
- 采样检测策略会遗漏部分幻觉输出，全量检测成本过高

### 6.3 Token计量的透明度问题
- 不同LLM提供商的Token计数算法不透明（分词器差异），同一文本在不同提供商的Token数不同
- 流式输出的Token统计可能不准确（最后一个chunk的Token计数延迟）
- 缓存命中的Token（如OpenAI的Prompt Caching）如何计费和统计，各提供商策略不同
- 华为云盘古大模型的Token计费粒度和计数方式文档不够详细，难以精确预估成本

### 6.4 多模型路由的可观测性挑战
- 模型路由策略（简单问题→轻量模型，复杂问题→旗舰模型）的决策过程缺乏追踪
- 路由策略的效果评估缺乏量化指标：路由准确率、成本节省比例、质量损失程度
- 不同模型的输出质量和成本难以直接对比（输出风格和长度差异大）
- 华为云ModelArts的模型路由功能缺乏细粒度的追踪和评估工具

### 6.5 AI可观测性的隐私和合规特殊性
- LLM的Prompt和Completion可能包含大量用户输入的敏感信息（医疗、法律、金融场景）
- 可观测性系统记录的LLM调用日志属于高敏感数据，需要比普通日志更严格的访问控制和脱敏
- LLM评估数据集（人工标注的正确回答）可能包含专有知识，不能与第三方SaaS共享
- 华为云LTS记录LLM调用日志需特别注意脱敏规则配置，避免Prompt/Completion明文存储
