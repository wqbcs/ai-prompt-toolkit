# 分布式链路追踪场景模板

> 覆盖工具链: OpenTelemetry / Jaeger / Zipkin / SkyWalking / 华为云APM

---

## 1. 陷阱（5项）

### 1.1 采样率过高导致存储与性能双重灾难
- 全量采样（probability=1.0）在高QPS系统中会产生海量Span数据，存储成本线性增长
- Collector和后端存储（Elasticsearch/ClickHouse）写入压力骤增，反噬业务服务性能
- 采样率设置未按流量峰值+冗余系数计算，低估了突发流量的Span放大效应
- 缺乏基于流量自动调节的自适应采样机制，低谷期浪费、高峰期失控
- 华为云APM按Span计费模式下，过高采样率直接导致账单超预期

### 1.2 上下文传播断链导致链路碎片化
- 跨服务调用未正确注入/提取Trace Context（W3C TraceContext/B3），导致同一请求被拆分为多条独立链路
- 异步消息队列（Kafka/RabbitMQ）未在消息属性中传播上下文，消费者侧链路断裂
- 跨线程/协程场景（Go goroutine、Java CompletableFuture）未手动传递Context，子Span丢失父级关联
- gRPC/HTTP头大小限制导致Trace Context被截断，下游服务无法解析完整上下文
- 华为云APM Agent与手动埋点混用时，上下文格式不兼容导致链路拼接失败

### 1.3 Span属性缺失导致排查信息不足
- 关键业务属性（user_id、order_id、tenant_id）未记录到Span Attributes中，排障时无法按业务维度过滤
- 异常Span未记录error.kind、error.message、stack_trace等结构化错误信息，仅靠状态码无法定位根因
- HTTP/RPC调用未记录请求/响应头中的关键诊断字段（x-request-id、x-tenant-id）
- 数据库操作Span缺失db.statement、db.connection_pool等属性，无法分析慢查询根因
- 华为云APM自定义属性上报未遵循命名规范，导致属性索引失效、查询困难

### 1.4 跨语言追踪不一致导致链路无法拼接
- 多语言微服务（Go/Java/Python/Node.js）使用不同追踪SDK版本，Span传播协议实现存在差异
- 部分服务使用Jaeger原生SDK、部分使用OpenTelemetry SDK，上下文格式互不兼容
- 跨语言服务间序列化/反序列化行为不一致，导致Span属性值被截断或编码错误
- 华为云APM Agent对各语言的支持程度不同（Java最完善、Go/Python功能受限），埋点覆盖率差异大
- 不同语言的Sampler实现逻辑不一致，同一请求在不同服务层被不同策略采样，链路不完整

### 1.5 热点路径遗漏导致关键延迟无法追踪
- 未对P99延迟路径进行重点埋点，关键慢路径（数据库连接池等待、外部API调用、缓存穿透）成为追踪盲区
- 批量操作（批量写入、批量查询）未拆分为独立Span，无法定位批量操作中的慢请求
- 后台任务（定时任务、数据同步）未纳入追踪体系，延迟问题发现滞后
- 华为云APM默认采样对后台任务和低频路径覆盖不足，关键路径采样率偏低
- 缺乏基于SLO的热点路径自动发现机制，只能靠人工经验补充埋点

## 2. 性能（5项）

### 2.1 采样策略优化
- 采用尾部采样（Tail-Based Sampling）：在请求完成后根据错误状态、延迟阈值、业务属性决定是否保留，确保异常链路100%采样、正常链路按比例采样
- 实施自适应采样：根据实时QPS动态调整采样率，高峰期降低采样率、低谷期提高采样率，保持Span产出速率稳定
- 按服务重要性分级采样：核心服务（支付/订单）高采样率、辅助服务（通知/日志）低采样率
- 华为云APM中配置基于URL路径的差异化采样规则，关键接口采样率100%、健康检查接口采样率0.1%
- 采样策略配置集中管理，通过ConfigMap/配置中心动态下发，避免重启服务

### 2.2 上下文传播效率优化
- 使用W3C TraceContext标准格式（traceparent + tracestate），减少上下文传播头数量和大小
- 对高频调用链进行上下文传播路径优化，减少不必要的属性传递，降低序列化开销
- 异步场景使用Propagator自动注入/提取，避免手动传递Context导致的遗漏和性能损耗
- 华为云APM Agent配置上下文传播白名单，仅传播必要属性，减少跨服务通信开销
- 对gRPC/HTTP头进行压缩优化，确保Trace Context在头大小限制内完整传播

### 2.3 Span批量导出优化
- 配置OTLP Exporter批量发送参数：batch_size=512、max_queue_size=2048、export_timeout=30s
- 使用OpenTelemetry Collector作为中间层聚合，减少每个服务直连后端的连接数和写入压力
- Span数据先写入本地缓冲区（内存队列），异步批量发送，避免阻塞业务线程
- 华为云APM Agent配置批量上报间隔和批量大小，平衡实时性与吞吐量
- 监控Collector的队列积压指标（queue_size、dropped_spans），及时调整批量参数

### 2.4 热点路径分析优化
- 基于历史链路数据自动识别P99延迟热点路径，标记需要加强埋点的服务和接口
- 对热点路径实施重点采样：错误链路100%保留、P99以上延迟链路100%保留、正常链路1%采样
- 热点路径的Span添加详细属性：db.statement、http.url、rpc.method、messaging.destination
- 华为云APM中配置拓扑图热点路径高亮和自动告警，延迟超过阈值自动触发分析
- 定期审查热点路径覆盖率，确保每季度新增关键路径的埋点覆盖率达到100%

### 2.5 华为云APM集成优化
- 合理配置APM Agent采样策略：按应用分组设置不同采样率，避免全局统一配置
- 使用华为云APM的自定义Span和自定义指标功能，补充业务维度的可观测性
- 配置APM数据转发至LTS（日志服务）和CloudEye（监控服务），实现追踪-日志-指标三方关联
- 优化APM Agent资源占用：调整内存缓冲区大小、CPU采样间隔，避免Agent影响业务性能
- 华为云APM与OpenTelemetry Collector对接，实现混合架构下的统一数据采集和导出

## 3. 安全（3项）

### 3.1 敏感Span数据泄露
- Span Attributes中可能包含敏感信息（用户手机号、身份证号、密码、Token），需在导出前脱敏
- 华为云APM的数据存储区域需配置访问控制策略，限制Span数据的查询和导出权限
- 跨租户场景下，Span数据隔离不严可能导致租户A的链路数据被租户B查看
- 缺乏Span数据生命周期管理，过期敏感数据未及时清理，增加泄露风险
- 合规要求：GDPR/等保要求中，追踪数据属于个人数据处理范畴，需明确法律依据和保留期限

### 3.2 追踪信息注入攻击
- 攻击者可伪造Trace Context（traceparent头），注入非法TraceID/SpanID，导致追踪系统混乱
- 恶意构造超长的tracestate头，触发下游服务解析异常或内存溢出
- 通过篡改Span Attributes中的业务字段（如user_id、tenant_id），干扰链路分析结果
- 华为云APM Agent未校验上游传播的Context完整性，可能接受伪造的链路信息
- 缓解措施：对入口服务的Trace Context进行校验和清洗，限制tracestate大小、校验TraceID格式

### 3.3 跨服务鉴权绕过
- 追踪上下文中携带的认证信息（如x-auth-token在Span Attributes中）可能被误用于鉴权判断
- 服务间通过Span Attributes传递用户身份信息，缺乏独立鉴权机制，存在越权风险
- 华为云APM的跨服务调用拓扑中，敏感服务的调用关系暴露可能被用于攻击路径规划
- 追踪系统的管理接口（Jaeger Query API、APM控制台API）未配置严格鉴权，可能被未授权访问
- 建议：追踪数据与鉴权数据严格分离，追踪上下文仅用于诊断目的，不参与业务鉴权逻辑

## 4. 故障排查（5项）

### 4.1 链路断链排查
- **现象**: Jaeger/华为云APM中链路在某个服务节点断裂，无法看到完整调用链
- **排查步骤**:
  1. 确认断裂服务的上下游是否正确注入/提取了Trace Context（检查HTTP头/gRPC metadata）
  2. 检查断裂服务是否使用了不同的上下文传播格式（W3C vs B3 vs Jaeger原生格式）
  3. 检查异步调用（MQ/线程池）是否手动传递了Context
  4. 检查华为云APM Agent版本是否支持当前使用的传播协议
  5. 使用调试工具（w3c-trace-context-validator）验证上下文传播完整性
- **根因模式**: 上下文传播格式不匹配 > 异步场景未传递Context > Agent版本不兼容 > 网络中间件剥离头信息

### 4.2 采样率异常排查
- **现象**: 链路数据量突然暴增或骤降，存储成本异常或关键链路丢失
- **排查步骤**:
  1. 检查各服务的Sampler配置是否被意外修改（ConfigMap/环境变量变更）
  2. 确认是否存在流量突增导致固定采样率下Span量暴增
  3. 检查OpenTelemetry Collector的采样策略配置是否生效
  4. 华为云APM控制台查看各应用的采样率和Span上报量趋势
  5. 验证自适应采样算法是否因指标异常（如错误率飙升）触发了采样率调整
- **根因模式**: 配置变更 > 流量突增 > Collector策略失效 > 自适应采样异常触发

### 4.3 Span丢失排查
- **现象**: 链路中部分Span缺失，调用链不完整，无法看到某些服务或中间件的耗时
- **排查步骤**:
  1. 检查OTLP Exporter的dropped_spans指标，确认是否有Span因队列满被丢弃
  2. 检查Collector的receivers/processors/exporters是否有数据处理错误
  3. 检查后端存储（Elasticsearch/ClickHouse）的写入错误日志
  4. 华为云APM查看Agent的上报失败率和重试日志
  5. 检查网络连通性和带宽限制，确认Collector到后端的网络是否正常
- **根因模式**: 队列溢出丢弃 > Collector处理错误 > 存储写入失败 > 网络超时

### 4.4 延迟尖刺排查
- **现象**: 某服务P99延迟突然出现尖刺，但链路追踪中未明显体现根因
- **排查步骤**:
  1. 对比延迟尖刺时段的链路数据，检查是否有Span缺失导致耗时统计不准确
  2. 检查GC暂停（Java）/协程调度延迟（Go）是否记录了对应Span
  3. 分析数据库连接池等待时间和外部API调用延迟
  4. 华为云APM中对比延迟尖刺时段的拓扑图，识别新增或异常的调用路径
  5. 检查是否为采样偏差——正常请求被采样、慢请求被丢弃，导致P99统计偏低
- **根因模式**: GC/调度延迟 > 连接池耗尽 > 外部依赖变慢 > 采样偏差

### 4.5 华为云APM异常排查
- **现象**: 华为云APM控制台数据缺失、拓扑图异常、链路查询超时
- **排查步骤**:
  1. 检查APM Agent运行状态和日志（/opt/huawei/apm/agent/logs/）
  2. 确认Agent版本与APM服务端版本兼容性
  3. 检查应用与APM服务端的网络连通性（端口、防火墙、代理）
  4. 华为云控制台查看APM服务状态和配额使用情况
  5. 检查Agent配置中的ak/sk是否有效、区域配置是否正确
- **根因模式**: Agent异常退出 > 版本不兼容 > 网络不通 > 配额超限 > 鉴权失败

## 5. 替代方案（3项）

### 对比表格

| 维度 | OpenTelemetry | Jaeger | 华为云APM |
|------|--------------|--------|-----------|
| **架构模式** | SDK + Collector + 多后端 | Agent + Collector + Storage | SaaS Agent + 云端存储 |
| **部署复杂度** | 高（需自建Collector和后端） | 中（All-in-One/生产模式可选） | 低（Agent注入即用） |
| **多语言支持** | 优秀（11+语言官方SDK） | 良好（4种语言官方SDK） | 良好（Java最完善，Go/Python有限） |
| **上下文传播** | W3C TraceContext + B3 + 自定义 | Jaeger原生 + W3C | 华为云专有协议 + W3C |
| **采样策略** | 头部采样 + 尾部采样（Collector） | 头部采样 + 自适应采样 | 固定采样 + 按路径采样 |
| **存储后端** | Elasticsearch/ClickHouse/自定义 | Elasticsearch/Cassandra/内存 | 华为云托管存储 |
| **成本模型** | 自建成本（基础设施+运维） | 自建成本（基础设施+运维） | 按Span计费/包年包月 |
| **数据主权** | 完全自主 | 完全自主 | 数据存储在华为云 |
| **与云生态集成** | 需手动对接 | 需手动对接 | 原生集成CloudEye/LTS/CCE |
| **社区活跃度** | CNCF毕业项目，极度活跃 | CNCF毕业项目，活跃 | 华为云专属生态 |
| **适用场景** | 多云/混合云、需要灵活定制 | 单集群、中小规模微服务 | 华为云深度用户、快速上手 |

### 5.1 OpenTelemetry — 全链路标准化的首选
- 优势：厂商中立、CNCF生态、多信号（Trace+Metric+Log）统一采集、尾部采样、社区活跃
- 劣势：部署运维成本高、需自建后端存储、学习曲线陡峭、版本迭代快需持续跟进
- 推荐场景：多云/混合云环境、需要灵活切换后端、对数据主权有严格要求

### 5.2 Jaeger — 轻量级追踪的务实选择
- 优势：部署简单（All-in-One模式）、成熟稳定、CNCF毕业项目、Elasticsearch存储成熟
- 劣势：功能迭代慢、尾部采样需依赖Collector、多信号整合不如OpenTelemetry
- 推荐场景：中小规模微服务、已有Elasticsearch基础设施、快速上线需求

### 5.3 华为云APM — 华为云生态的零门槛方案
- 优势：Agent注入即用、与CCE/CloudEye/LTS原生集成、华为云技术支持、无需运维基础设施
- 劣势：厂商锁定、多语言支持不均（Go/Python功能受限）、定制能力有限、数据存储在云端
- 推荐场景：华为云深度用户、CCE集群部署、快速接入需求、无自建可观测性团队

## 6. 已知限制（≥3项）

### 6.1 OpenTelemetry SDK版本碎片化
- 不同语言的SDK成熟度差异大：Java/Python SDK功能完善，Go/Rust SDK部分功能仍在Alpha/Beta
- SDK大版本升级（v1.x → v2.x）存在Breaking Change，需要逐一适配各语言服务
- OpenTelemetry语义约定（Semantic Conventions）仍在快速迭代，属性命名可能在未来版本变更

### 6.2 尾部采样的实时性局限
- 尾部采样需要在请求完成后才能决策，引入额外延迟（通常100ms-1s）
- 高QPS场景下，尾部采样的内存开销显著（需缓存所有待决策Span）
- 华为云APM目前不支持尾部采样，仅支持头部采样策略

### 6.3 跨云/跨集群追踪的网络与成本挑战
- 跨VPC/跨Region的追踪数据传输受网络带宽和延迟限制
- 跨云场景（华为云+AWS+自建机房）的上下文传播依赖公网，存在安全和可靠性风险
- 华为云APM的跨集群追踪功能受限于同一账号下的集群，跨账号/跨云需要额外方案

### 6.4 追踪数据与日志/指标的关联深度不足
- OpenTelemetry的TraceID关联日志需要各服务手动将TraceID写入日志MDC/Context
- 华为云APM的链路-日志关联需要使用LTS并配置关联规则，配置复杂且存在延迟
- 指标与追踪的关联（Exemplar）在Grafana/Prometheus中支持有限，无法在所有指标上展示关联链路

### 6.5 长尾请求和批量操作的追踪覆盖不足
- 超长耗时请求（批处理、大数据量查询）的Span可能因TTL过期被后端存储清理，导致链路不完整
- 批量操作中每个子项的追踪需要手动创建子Span，开发成本高且易遗漏
- 华为云APM对超长链路（超过1000个Span）的展示和查询性能较差
