# c2.1 混沌工程基础

## 概述

本场景覆盖混沌工程的核心原则与实践，包括稳态假设定义、实验设计方法论、安全护栏机制以及华为云Chaos平台的使用。适用于团队建立混沌工程文化、制定实验规范以及选择工具链。

---

## 1. 陷阱（5项）

### 陷阱1：稳态假设过于乐观

- 稳态假设往往基于理想运行条件定义，忽略了长尾延迟、偶发超时、资源波动等真实生产环境中的常态现象
- 过于乐观的假设会导致实验设计偏离实际风险，使混沌实验沦为"走过场"，无法发现真正的系统脆弱点
- 典型表现：假设服务响应时间 < 200ms，但实际P99已达1.5s；假设可用性99.99%，但未计入计划维护窗口
- 应基于历史监控数据（P50/P95/P99/P999）定义稳态，并考虑季节性波动和业务高峰场景
- 建议使用基线对比法：取近30天监控数据的最差10%作为稳态下界，而非平均值

### 陷阱2：爆炸半径失控

- 实验的爆炸半径未在实验前明确定义，导致故障影响范围超出预期，波及非目标服务和用户
- 缺乏逐级扩大机制（blast radius ramp-up），直接在生产环境全量注入故障，无法及时止损
- 未设置爆炸半径的硬性边界（如命名空间隔离、可用区限制、用户比例上限），依赖人工判断终止实验
- 典型表现：本意测试A服务的容错能力，结果导致B服务级联故障，影响核心交易链路
- 必须在实验设计中显式声明：最大影响服务数、最大影响用户比例、最大影响时长、自动终止条件

### 陷阱3：安全护栏缺失

- 实验缺乏自动化的安全护栏（guardrails），仅依赖人工监控和手动终止，反应速度远不够
- 未定义"终止条件"（abort conditions），如错误率超过阈值、延迟超过阈值、特定告警触发等
- 缺乏"紧急停止"（emergency stop）机制，当实验失控时无法快速回滚所有注入的故障
- 未在非生产环境预演就直接在生产环境执行，缺少从Dev→Staging→Prod的渐进验证路径
- 安全护栏应包括：自动化指标监控+告警联动、实验时长硬上限、爆炸半径硬上限、一键回滚能力

### 陷阱4：实验结果不可复现

- 实验未记录完整的执行上下文（系统版本、配置、流量模式、依赖状态），导致结果无法复现
- 缺乏实验的版本化管理，实验定义、参数、结果散落在不同系统中，无法追溯
- 未使用基础设施即代码（IaC）定义实验，依赖手动操作导致每次执行存在差异
- 实验环境与生产环境差异过大（数据量、流量模式、配置），导致实验结论不可迁移
- 必须将实验定义代码化（Experiment as Code），纳入版本控制，并记录完整的实验日志和指标快照

### 陷阱5：华为云Chaos权限不足

- 华为云Chaos需要细粒度的IAM权限配置，常见问题包括：缺少chaos:experiment:create、chaos:action:inject等动作权限
- 跨账号/跨项目执行实验时，未配置代理授权（agency），导致实验无法注入到目标资源
- CCE集群中未安装Chaos DaemonSet，或DaemonSet权限不足（缺乏privileged模式或CAP_NET_ADMIN能力）
- 用户仅有只读权限就尝试创建和执行实验，导致操作被拒绝且报错信息不明确
- 建议按照最小权限原则配置专用混沌实验角色，包含实验管理、故障注入、监控读取三类权限

## 2. 性能（5项）

### 性能1：实验设计效率

- 采用"假设→实验→观察→学习"四步法，将实验设计时间控制在30分钟内（使用标准模板）
- 建立实验库（Experiment Catalog），将常见故障模式模板化，避免每次从零开始设计
- 使用A/B实验设计：同时运行对照组和实验组，减少环境差异对结果的影响
- 实验设计应遵循MINIMUM原则：最小化影响范围、最短持续时间、最少资源消耗、最易回滚
- 自动化实验编排：将多步骤实验（如"先注入延迟→观察1分钟→再注入错误"）编排为流水线

### 性能2：稳态行为定义

- 稳态行为必须量化为可观测指标，包含：延迟（P50/P95/P99）、错误率、吞吐量、资源利用率
- 使用滑动窗口（如5分钟）计算稳态指标，避免瞬时波动干扰判断
- 稳态基线应区分工作日/周末/节假日/促销期等不同场景，建立多维基线矩阵
- 引入统计显著性检验（如Mann-Whitney U检验），判断实验期间指标变化是否显著偏离稳态
- 自动化稳态验证：实验前自动采集稳态指标并生成报告，实验后自动对比偏差

### 性能3：爆炸半径控制

- 采用逐级扩大策略：1%→5%→10%→25%→50%→100%，每级停留足够观察时间后再扩大
- 使用标签选择器（label selector）精确定位目标资源，避免误注入到非目标资源
- 在Kubernetes中利用命名空间隔离实验，确保爆炸半径不跨越命名空间边界
- 设置爆炸半径的硬性上限：如同时注入故障的Pod数量不超过总量的30%，影响用户不超过5%
- 实时监控爆炸半径：实验期间持续统计实际影响范围，超出预期时自动终止

### 性能4：实验结果分析

- 建立标准化的实验报告模板：包含实验假设、参数、执行时间线、指标对比、结论、改进建议
- 使用差异分析图（diff chart）直观展示实验前后的指标变化，标注统计显著性
- 自动化指标采集：实验开始前5分钟→实验期间→实验结束后5分钟，三段式指标对比
- 引入混沌工程成熟度模型：从"发现脆弱点"到"量化韧性"到"持续验证"的三级评估
- 实验结论必须包含可执行的改进行动项（action items），并跟踪其完成状态

### 性能5：华为云Chaos调度优化

- 利用华为云Chaos的定时调度功能，在业务低峰期自动执行预设实验，减少对业务的影响
- 合理配置实验并行度：避免同一资源同时被多个实验注入不同类型故障
- 使用华为云Chaos的场景编排能力，将多个原子故障组合为复合场景（如"CPU压力+网络延迟"）
- 优化Chaos Agent的资源占用：限制DaemonSet的CPU/内存请求和限制，避免对业务容器造成资源竞争
- 配置Chaos实验的优雅终止（graceful shutdown），确保故障注入资源在实验结束时被完全清理

## 3. 安全（3项）

### 安全1：混沌实验误伤生产

- 生产环境实验必须经过变更评审（Change Advisory Board），并获得业务方和技术方的双重审批
- 实施金丝雀实验：先在1%流量上验证实验安全性，确认无异常后再逐步扩大
- 建立生产环境实验的"熔断机制"：当核心业务指标（如交易成功率）低于阈值时，自动终止所有进行中的实验
- 禁止在核心交易时段（如交易日9:30-15:00）执行非预定的混沌实验
- 实验执行人员必须具备应急响应能力，能够在实验失控时5分钟内完成故障回滚

### 安全2：实验数据泄露

- 混沌实验可能触发异常错误路径，导致日志中输出敏感信息（如数据库连接串、API密钥、用户PII）
- 实验期间的错误响应可能绕过正常的数据脱敏流程，直接返回原始数据
- 华为云Chaos的实验日志和报告可能包含资源拓扑、配置信息等敏感数据，需控制访问权限
- 实验数据（指标、日志、报告）的存储和传输必须加密，且仅限授权人员访问
- 建议在实验环境中使用脱敏数据，避免实验触发的异常路径泄露真实用户数据

### 安全3：实验权限越权

- 混沌实验平台的权限必须遵循最小权限原则，实验执行者仅能操作其负责的服务和资源
- 禁止跨团队执行混沌实验，除非获得目标团队的明确授权（审批流程）
- 华为云Chaos的IAM策略应限制：可注入的故障类型、可操作的资源范围、可执行实验的时间窗口
- 定期审计混沌实验的操作日志，检查是否存在越权操作或权限滥用
- 实验权限应与变更管理流程联动：未通过变更审批的实验，即使有技术权限也不应执行

## 4. 故障排查（5项）

### 故障排查1：实验未触发

- **现象**：实验状态显示"运行中"，但目标服务指标无任何变化
- **原因A**：华为云Chaos的DaemonSet未在目标节点上运行，检查`kubectl get pods -n chaos`确认DaemonSet状态
- **原因B**：故障注入的标签选择器未匹配到任何目标资源，检查选择器与实际资源标签是否一致
- **原因C**：实验的调度时间未到，或调度被暂停，检查实验的调度配置和状态
- **解决**：验证DaemonSet部署→验证标签选择器→验证调度配置→查看Chaos Controller日志

### 故障排查2：稳态假设验证失败

- **现象**：实验前稳态验证不通过，无法启动实验
- **原因A**：稳态指标基线未正确配置，或基线数据过期（超过30天未更新）
- **原因B**：当前系统本身已处于异常状态，尚未恢复到稳态
- **原因C**：稳态指标的采集源配置错误，采集到的数据无法代表真实状态
- **解决**：更新稳态基线→检查系统当前健康状态→验证指标采集源→手动校准稳态阈值

### 故障排查3：爆炸半径超预期

- **现象**：实验影响的服务数或用户数超出预设的爆炸半径上限
- **原因A**：依赖服务未识别，故障通过未监控的调用链传播到非目标服务
- **原因B**：共享资源（数据库连接池、缓存集群）受影响，导致同资源上的其他服务异常
- **原因C**：爆炸半径的实时监控延迟，从异常发生到检测到超限有1-2分钟延迟
- **解决**：立即终止实验→补充服务依赖图谱→增加共享资源隔离→缩短监控采集间隔

### 故障排查4：实验回滚失败

- **现象**：实验终止后，故障注入未完全清理，目标服务持续异常
- **原因A**：Chaos Agent异常退出，未执行清理逻辑，需手动检查并清理注入的故障
- **原因B**：网络故障注入修改了iptables规则，但清理时规则已被其他进程修改，导致清理不完全
- **原因C**：资源压力注入的stress进程未被正确终止，仍在后台消耗资源
- **解决**：检查Chaos Agent日志→手动清理残留的iptables规则→检查并终止残留的stress进程→验证系统完全恢复

### 故障排查5：华为云Chaos调度异常

- **现象**：定时实验未按预期执行，或执行时间严重偏移
- **原因A**：调度器时区配置错误，华为云Chaos默认使用UTC时间，需转换为本地时区
- **原因B**：调度器的并发限制，同一时段内可同时执行的实验数量有上限，超出的实验被排队
- **原因C**：调度器与Chaos Controller之间的通信异常，检查Controller的健康状态和网络连通性
- **解决**：校验时区配置→检查调度队列状态→验证Controller健康→查看调度器日志

## 5. 替代方案（3项）

### 替代方案对比

| 维度 | Chaos Mesh | Litmus | 华为云Chaos |
|------|-----------|--------|------------|
| **部署方式** | Helm部署到K8s集群，独立运行 | Helm部署，需Litmus Portal | 华为云托管服务，Agent部署到CCE |
| **故障类型** | 网络/资源/Pod/IO/时间/HTTP，覆盖全面 | 网络/资源/Pod/应用层，生态扩展 | 网络/资源/Pod/进程，华为云深度集成 |
| **调度能力** | Cron Workflow，基于Argo Workflows | 自定义调度器，支持ChaosResult | 华为云调度器，支持定时/周期/一次性 |
| **安全护栏** | 基于Admission Webhook的策略控制 | 基于RBAC + ChaosPolicy | IAM权限 + 安全护栏规则 + 变更审批集成 |
| **可观测性** | 集成Prometheus/Grafana Dashboard | ChaosResult CRD + Grafana | 集成华为云CES/AOM，统一监控 |
| **社区活跃度** | CNCF孵化项目，社区活跃（7k+ stars） | CNCF孵化项目，社区活跃（4k+ stars） | 华为云商业支持，社区相对封闭 |
| **多集群支持** | 支持多集群管理（控制面+数据面） | 支持多集群（ChaosCenter） | 仅支持华为云CCE集群 |
| **学习曲线** | 中等，YAML定义实验 | 中等，需理解ChaosEngine CRD | 低，Web控制台操作 |
| **适用场景** | 开源K8s环境，需灵活定制 | 云原生混沌工程平台，需Portal管理 | 华为云用户，需商业化支持和集成 |
| **成本** | 开源免费 | 开源免费（企业版收费） | 按使用量计费 |

### 替代方案1：Chaos Mesh

- 适合已使用开源K8s技术栈的团队，需要灵活定制故障类型和实验流程
- 优势：故障类型覆盖全面、社区生态丰富、支持自定义Chaos（Schedule、Workflow）
- 劣势：需要自行运维Chaos Mesh组件、多集群管理配置复杂

### 替代方案2：Litmus

- 适合需要Portal管理界面和多角色协作的团队
- 优势：ChaosCenter提供可视化实验管理、ChaosHub提供实验市场、支持GitOps
- 劣势：Portal部署资源占用较高、部分高级特性需企业版

### 替代方案3：华为云Chaos

- 适合华为云CCE用户，需要商业化支持和与华为云生态深度集成
- 优势：免运维、与CES/AOM/ILM深度集成、企业级安全护栏、商业支持SLA
- 劣势：仅支持华为云CCE、故障类型更新较慢、社区生态相对封闭

## 6. 已知限制（≥3项）

1. **环境依赖性强**：混沌实验结果高度依赖实验时的系统状态（流量、配置、依赖版本），同一实验在不同时间执行可能得到不同结论，难以得出确定性的韧性评估
2. **覆盖面有限**：当前混沌工程主要覆盖基础设施层（网络/资源/Pod）的故障，对应用逻辑层（业务规则异常/数据不一致/状态机错误）的故障模拟能力不足
3. **爆炸半径预测困难**：微服务架构下服务依赖关系复杂且动态变化，实验前难以精确预测故障传播路径和爆炸半径，存在"未知的未知"风险
4. **实验成本与收益难以量化**：混沌工程投入的人力、资源和风险成本难以精确衡量，而收益（避免的生产事故损失）是预防性的、难以直接量化
5. **华为云Chaos功能限制**：华为云Chaos目前不支持Windows容器、不支持Serverless场景（CCI）、不支持跨云混合部署环境的混沌实验
