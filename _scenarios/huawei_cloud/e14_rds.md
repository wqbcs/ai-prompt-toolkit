# 华为云RDS（关系型数据库）场景模板

## 概述

华为云关系型数据库服务（Relational Database Service, RDS）提供即开即用、高可用、可扩展的托管数据库服务，支持MySQL、PostgreSQL、SQL Server引擎。本模板覆盖实例管理、读写分离、备份恢复、参数调优及数据库代理等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：慢SQL拖垮实例

- 单条慢SQL占用大量CPU/IO资源，导致同一实例上所有数据库响应变慢，"一个慢查询害死整个实例"
- 未开启慢日志记录或阈值设置过高（如10s），慢SQL长期存在但未被发现，直到业务方投诉
- 慢SQL使用全表扫描（`ALL` 类型），在大表上每次查询扫描数百万行，IO和CPU资源被耗尽
- 优化器选择错误的执行计划（如统计信息过期导致索引选择错误），本应走索引的查询退化为全表扫描
- **规避**：开启慢日志并设置合理阈值（MySQL 1s/PG 100ms），定期分析慢日志Top SQL，使用 `EXPLAIN` 检查执行计划，定期执行 `ANALYZE TABLE` 更新统计信息

### 陷阱2：连接池耗尽

- 应用未使用连接池，每次请求新建连接，高并发时连接数迅速达到 `max_connections` 上限
- 连接池配置过大（如最大连接数1000），超过RDS实例的 `max_connections`，部分连接被拒绝
- 连接泄漏：应用获取连接后未正确释放（异常路径未关闭连接），连接池逐渐耗尽
- 长事务占用连接不释放，连接池中可用连接持续减少，新请求排队等待超时
- **规避**：使用连接池（HikariCP/Druid），最大连接数不超过RDS `max_connections` 的80%，设置连接超时和最大生命周期，监控 `active_connections` 指标

### 陷阱3：主从延迟过大

- 主实例写入压力大（大批量INSERT/UPDATE），binlog/ WAL同步速度跟不上，从库延迟持续增长
- 从库硬件规格低于主库，写入性能不足导致回放延迟
- 大事务产生的binlog/WAL量大，从库回放耗时长，延迟在事务提交后突增
- 网络抖动导致主从复制中断，重连后需回放积压的binlog/WAL，延迟恢复缓慢
- **规避**：主从规格保持一致或从库更高，避免大事务拆分为小事务，监控 `replication_lag` 指标，延迟超过阈值时读写分离路由到主库

### 陷阱4：备份窗口影响性能

- 自动备份在业务高峰期执行，备份过程产生的IO争抢导致数据库性能下降
- 全量备份（物理备份）读取所有数据文件，大实例备份耗时长，期间磁盘IO利用率持续100%
- 备份产生的临时文件占用磁盘空间，磁盘使用率高的实例可能因空间不足导致备份失败
- 逻辑备份（mysqldump/pg_dump）持锁时间过长，阻塞DDL操作甚至影响DML
- **规避**：将自动备份窗口设置在业务低峰期（如凌晨2:00-4:00），监控备份期间的IO和响应时间，磁盘预留20%空间

### 陷阱5：参数修改未生效

- 修改RDS参数后未重启实例，部分参数（如MySQL `innodb_buffer_pool_size`、PG `shared_buffers`）需要重启才能生效
- 修改参数后应用连接使用了旧的参数值（连接级参数），需断开重连才能使用新值
- 批量修改多个参数时，部分参数修改失败（超出范围或不兼容），但已修改的参数已生效，配置不一致
- 参数模板应用到实例后，部分参数被实例级覆盖，模板修改未实际生效
- **规避**：修改参数前确认是否需要重启，批量修改使用参数模板，修改后验证 `SHOW VARIABLES`/`SHOW PARAMETER` 确认生效，连接池设置最大生命周期自动刷新连接

## 二、性能优化（5项）

### 优化1：慢SQL分析与优化

- 使用RDS慢日志功能或性能洞察（Performance Insight）识别Top慢SQL
- 通过 `EXPLAIN` / `EXPLAIN ANALYZE` 分析执行计划，重点关注 `type`（MySQL）/ `scan type`（PG）和 `rows` 估算
- 常见优化手段：添加合适索引、避免 `SELECT *`、拆分复杂查询、使用覆盖索引避免回表
- MySQL优化器提示（Optimizer Hint）强制使用指定索引：`SELECT /*+ INDEX(t idx_name) */ ...`
- PG使用 `pg_stat_statements` 扩展统计SQL执行频率和耗时，定位高频慢查询

### 优化2：连接池配置

- 连接池最小连接数 = 常态并发数 × 1.2，最大连接数 = 峰值并发数 × 1.5，预留20%余量
- HikariCP推荐配置：`maximumPoolSize = CPU核数 × 2 + 有效磁盘数`，`minimumIdle = maximumPoolSize`
- 设置 `maxLifetime`（30分钟）和 `idleTimeout`（10分钟），定期刷新连接避免使用过期参数
- 开启连接验证（`connectionTestQuery = SELECT 1`），从池中获取连接时验证可用性
- 监控连接池的 `active_connections`、`idle_connections`、`pending_threads` 指标，及时调整池大小

### 优化3：读写分离路由

- 使用RDS数据库代理（Proxy）实现自动读写分离，应用无需修改代码
- 只读事务和查询语句自动路由到只读副本，写事务路由到主实例
- 配置读写分离权重：主库可承担部分读流量（如10%），避免只读副本空闲而主库过载
- 对一致性要求高的查询（如写入后立即读取），使用Hint `/*FORCE_MASTER*/` 强制路由到主库
- 监控各只读副本的 `replication_lag`，延迟超过阈值时将其从读权重中移除

### 优化4：参数调优（InnoDB/PG）

- **MySQL InnoDB核心参数**：
  - `innodb_buffer_pool_size`：设置为实例内存的60%~75%，这是最重要的性能参数
  - `innodb_io_capacity`：SSD设为10000~20000，HDD设为200~400，控制后台刷脏页速率
  - `innodb_flush_method`：Linux设为 `O_DIRECT`，避免双缓冲浪费内存
  - `sync_binlog`：非核心业务设为100~1000，核心业务设为1（最安全但最慢）
  - `innodb_flush_log_at_trx_commit`：设为2（每秒刷盘）性能与安全平衡
- **PostgreSQL核心参数**：
  - `shared_buffers`：设置为实例内存的25%，PG依赖操作系统缓存不建议设置过大
  - `effective_cache_size`：设置为实例内存的75%，指导优化器选择执行计划
  - `work_mem`：按并发数估算，`总内存×0.25/最大并发数`，避免排序溢出到磁盘
  - `maintenance_work_mem`：设置为实例内存的5%~10%，加速VACUUM和索引创建
  - `random_page_cost`：SSD设为1.1（接近顺序IO），HDD保持默认4.0

### 优化5：数据库代理优化

- 数据库代理（Proxy）支持连接多路复用，减少RDS实例的实际连接数
- 代理连接池模式：会话级连接池（适用于短连接）和事务级连接池（适用于长事务）
- 设置代理的 `slow_query_threshold`（1s），代理层记录慢查询便于快速定位
- 代理支持Hint路由控制，读写分离场景下精细化控制SQL路由目标
- 代理规格根据QPS选择：通用型代理支持数万QPS，高并发场景增加代理节点数量

## 三、安全加固（3项）

### 安全1：数据库审计

- RDS支持SQL审计功能，记录所有DML和DDL操作，满足等保合规要求
- 审计日志默认关闭，需在控制台手动开启，开启后对性能有轻微影响（约2%~5%）
- 审计日志存储在LTS（云日志服务），需配置日志组和日志流，设置合理的保留策略
- 高频小事务场景审计日志量巨大，建议仅审计关键操作（DDL、权限变更、数据导出）
- **加固**：生产环境强制开启SQL审计，关键操作实时告警，审计日志保留180天以上，定期审查审计记录

### 安全2：SSL传输加密

- RDS支持SSL/TLS传输加密，防止数据库通信被窃听或篡改
- MySQL和PostgreSQL均支持SSL连接，需下载CA证书并配置客户端
- 开启SSL后仅允许SSL连接（`require_secure_transport=ON`），非SSL连接被拒绝
- SSL加密增加约5%~10%的网络延迟，对延迟敏感的场景需评估影响
- **加固**：生产环境强制开启SSL，应用连接字符串添加SSL参数（`useSSL=true&requireSSL=true`），定期更新SSL证书

### 安全3：TDE透明加密

- RDS支持TDE（Transparent Data Encryption）透明数据加密，对存储的数据文件自动加密解密
- TDE对应用透明，无需修改代码，但开启后不可关闭，操作不可逆
- 开启TDE后备份文件也是加密的，恢复时需确保目标实例也支持TDE
- TDE对性能影响约5%~10%，主要影响IO密集型操作（全表扫描、大量写入）
- **加固**：包含敏感数据的实例强制开启TDE，密钥使用KMS（密钥管理服务）管理，定期轮换主密钥

## 四、故障排查（5项）

### 故障1：连接数耗尽

- **现象**：应用报错 `Too many connections`（MySQL）或 `FATAL: sorry, too many clients already`（PG）
- **排查步骤**：
  1. 查看RDS实例的 `max_connections` 当前值和活跃连接数
  2. 执行 `SHOW PROCESSLIST`（MySQL）或 `SELECT * FROM PG_STAT_ACTIVITY`（PG）查看各连接状态
  3. 识别占用连接的来源IP和用户，定位连接泄露的应用
  4. 检查是否有大量 `Sleep`/`idle` 状态的连接未释放
  5. 确认连接池配置是否合理，最大连接数是否超过RDS限制
- **处置**：Kill异常连接释放空间，调整应用连接池配置，增大 `max_connections` 参数（需评估内存影响）

### 故障2：主从切换失败

- **现象**：主实例故障后从实例未自动升主，或切换后应用连接异常
- **排查步骤**：
  1. 确认RDS实例是否为高可用架构（主备实例），单机实例无自动切换
  2. 查看主备切换日志，确认切换过程是否有报错
  3. 检查从库的复制状态（`SHOW SLAVE STATUS` / `PG_STAT_REPLICATION`），确认延迟是否过大
  4. 确认应用的数据库连接配置是否支持自动重连和DNS刷新
  5. 检查VIP/域名切换是否生效，DNS缓存是否已刷新
- **处置**：手动触发主备切换，调整DNS缓存时间（建议30s以内），应用使用连接池自动重连

### 故障3：慢SQL堆积

- **现象**：RDS实例CPU利用率持续100%，活跃连接数持续增长，新请求排队超时
- **排查步骤**：
  1. 查看 `SHOW PROCESSLIST` 或 `PG_STAT_ACTIVITY`，找到执行时间最长的查询
  2. 使用性能洞察（Performance Insight）查看Top SQL和等待事件
  3. 对慢SQL执行 `EXPLAIN` 分析执行计划，确认是否走了全表扫描
  4. 检查是否有锁等待（`INNODB_LOCK_WAITS` / `PG_LOCKS`），慢SQL阻塞其他查询
  5. 查看统计信息是否过期（`information_schema.TABLES` / `PG_STAT_USER_TABLES`）
- **处置**：Kill慢SQL释放资源，添加缺失索引，更新统计信息，设置 `statement_timeout` 限制最大执行时间

### 故障4：备份失败

- **现象**：自动备份或手动备份状态为"失败"，备份文件未生成
- **排查步骤**：
  1. 查看备份失败的具体错误码和错误信息
  2. 检查磁盘空间是否充足，备份临时文件需要额外空间
  3. 确认备份窗口内是否有大事务运行，长事务持锁导致备份超时
  4. 检查OBS存储配额是否已满（备份文件存储在OBS）
  5. 确认实例状态是否正常（非维护/升级状态）
- **处置**：清理磁盘空间，避开大事务运行时间执行备份，清理OBS过期备份释放配额

### 故障5：磁盘满

- **现象**：RDS实例报错 `The table is full` 或 `No space left on device`，写入操作失败
- **排查步骤**：
  1. 查看RDS实例的磁盘使用率和增长趋势
  2. 识别占用空间最大的表（`information_schema.TABLES` 按 `DATA_LENGTH` 排序）
  3. 检查是否有大量未清理的binlog/WAL（`SHOW BINARY LOGS` / `PG_WAL`）
  4. 确认临时表是否占用大量空间
  5. 查看是否有过期的备份文件未清理
- **处置**：清理无用数据和临时表，缩短binlog/WAL保留时间（注意影响主从复制），扩容磁盘，归档历史数据

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云RDS | 自建数据库 | 华为云PolarDB |
|------|-----------|-----------|---------------|
| **部署周期** | 分钟级 | 天级~周级 | 分钟级 |
| **高可用** | 主备自动切换（30s内） | 需自建主从+哨兵/ Patroni | 主备自动切换（30s内） |
| **存储架构** | 本地存储（主备各一份数据） | 本地存储 | 存储计算分离（共享存储） |
| **读写扩展** | 只读副本（最多5~10个） | 自建从库（无上限） | 只读节点（最多15个） |
| **存储扩容** | 扩容磁盘（需停机或在线） | 扩容磁盘（需停机） | 共享存储自动扩展 |
| **兼容性** | MySQL/PG/SQLServer | 任意版本 | MySQL/PG（高度兼容） |
| **性能上限** | 单实例数万QPS | 取决于硬件 | 单实例数十万QPS |
| **成本模型** | 按实例规格+存储计费 | 服务器+运维人力 | 按节点规格+存储计费 |
| **运维责任** | 华为负责基础设施运维 | 全部自行负责 | 华为负责基础设施运维 |
| **迁移成本** | 低（DRS数据迁移） | 高（手动迁移） | 低（DTS数据迁移） |

### 选择建议

- **选择RDS**：标准业务场景、需要多种数据库引擎、成本敏感、已有MySQL/PG运维经验
- **选择自建数据库**：需要特定版本或插件、对数据库有深度定制需求、数据不出私有云
- **选择PolarDB**：超高并发读写、存储计算分离需求、大存储容量、读写扩展要求高

## 六、已知限制（≥3项）

1. **只读副本延迟不可完全消除**：RDS只读副本通过异步复制同步数据，在高写入负载下主从延迟不可避免，对一致性要求极高的读取应路由到主库

2. **参数修改部分需重启**：RDS部分参数修改后需要重启实例才能生效（如 `innodb_buffer_pool_size`、`shared_buffers`），重启期间实例不可用约30秒~2分钟

3. **单实例只读副本数量限制**：MySQL引擎最多支持10个只读副本，PostgreSQL最多5个只读副本，SQL Server最多5个只读副本，超出需使用数据库代理或分库分表

4. **备份保留期限制**：自动备份默认保留7天，最长保留732天，超过保留期的备份自动删除不可恢复，长期归档需手动导出

5. **跨区域只读副本限制**：跨区域只读副本不支持级联（只读副本不能再挂只读副本），且跨区域复制延迟通常高于同区域

6. **SQL Server引擎限制**：SQL Server引擎不支持透明数据加密（TDE）的自行管理密钥，部分版本不支持跨可用区只读副本
