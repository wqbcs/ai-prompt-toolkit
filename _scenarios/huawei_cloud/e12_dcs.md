# 华为云DCS（分布式缓存）场景模板

## 概述

华为云分布式缓存服务（Distributed Cache Service, DCS）提供即开即用、安全可靠、弹性可伸缩的分布式缓存能力，兼容Redis和Memcached协议。本模板覆盖缓存实例管理、数据迁移、集群扩缩容、慢查询分析及灾备等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：大Key导致阻塞

- 单个Key的Value超过10KB（甚至MB级）时，读写操作耗时急剧上升，阻塞Redis单线程执行，影响所有客户端请求
- 使用 `KEYS *` 或 `HGETALL` 操作大Key时，O(N)复杂度导致长时间阻塞，触发客户端超时重连
- 删除大Key时使用 `DEL` 命令同步释放内存，主线程阻塞，严重时导致哨兵判定主观下线触发主从切换
- 大Key在集群模式下跨slot分布不均，某些节点成为热点，整体性能被最慢节点拖垮
- **规避**：使用 `redis-cli --bigkeys` 定期扫描大Key，大Value拆分为多个小Key（如Hash分片），删除大Key使用 `UNLINK` 异步删除

### 陷阱2：热Key分布不均

- 少量Key被高频访问（如热点商品、排行榜），单节点QPS达到上限而其他节点空闲，集群整体吞吐受限
- 热Key在集群模式下映射到固定slot，对应节点成为瓶颈，其他节点资源浪费
- 客户端未使用本地缓存，所有读请求穿透到DCS，热Key访问量被放大数十倍
- 热Key过期瞬间大量请求同时回源数据库，造成缓存击穿（与雪崩不同，击穿是单个Key）
- **规避**：热Key加本地缓存（如Guava Cache），集群模式下使用读写分离或 `read-only slave` 分担读压力，设置随机过期时间避免同时失效

### 陷阱3：缓存雪崩

- 大量Key设置相同的过期时间，到期瞬间缓存集体失效，请求全部穿透到数据库，数据库瞬时过载崩溃
- 缓存集群整体重启（如版本升级、故障恢复）后，冷启动阶段缓存为空，所有请求穿透到数据库
- 灾备切换后备用集群缓存为空，流量涌入导致数据库和缓存同时过载
- 批量预热缓存时未控制并发度，预热请求本身成为数据库的流量冲击
- **规避**：过期时间加随机偏移量（如TTL + random(0~300s)），实施缓存预热策略（启动时渐进式加载），数据库前增加限流和熔断保护

### 陷阱4：缓存穿透

- 查询不存在的Key（如非法ID、恶意攻击），缓存无数据可返回，请求全部穿透到数据库
- 大量恶意请求使用不同Key轮询，布隆过滤器无法完全拦截（存在误判率）
- 业务逻辑错误导致大量无效查询，如分页查询超出总页数每页都返回空结果
- 数据库查到空结果未写入缓存（`cache null`），同一无效查询反复穿透
- **规避**：空结果也缓存（设置较短TTL如60s），使用布隆过滤器拦截不存在的Key，接口层增加参数校验和限流

### 陷阱5：内存碎片率过高

- 频繁修改Value大小（如List/Hash增删元素）导致Redis内存分配器产生大量碎片，实际可用内存远小于分配内存
- 内存碎片率（`used_memory_rss / used_memory`）超过1.5时，部分内存被碎片占用无法使用，触发OOM风险增加
- 大量小Key在jemalloc中分配的内存块未充分利用，实际存储效率低
- 执行 `FLUSHDB` 或大量删除后，内存未归还操作系统（Redis默认不主动释放），RSS居高不下
- **规避**：监控 `mem_fragmentation_ratio` 指标，超过1.5时执行 `MEMORY PURGE` 或开启 `activedefrag` 自动碎片整理，选择合适的内存分配策略

## 二、性能优化（5项）

### 优化1：连接池优化

- 使用连接池管理DCS连接，避免频繁创建/销毁连接的开销（TCP三次握手+AUTH认证）
- 连接池大小根据并发量设置：最小连接数 = CPU核数 × 2，最大连接数 = 峰值QPS × 平均RT
- 启用连接池的健康检查（`testWhileIdle`），及时剔除已断开的连接，避免请求失败
- 设置合理的连接超时（`connectTimeout` 3s）和读写超时（`soTimeout` 2s），避免慢响应占满连接池
- 使用Lettuce等异步客户端替代Jedis同步客户端，单个连接即可支持高并发（基于Netty多路复用）

### 优化2：Pipeline批量操作

- 将多个独立命令打包为Pipeline一次发送，减少网络RTT（往返延迟），吞吐提升5~10倍
- 单个Pipeline包含的命令数控制在100~500条，过多会导致DCS处理时间过长阻塞其他客户端
- Pipeline中的命令应无依赖关系（后一条不依赖前一条结果），否则无法并行执行
- 集群模式下使用Pipeline需确保所有Key映射到同一slot，否则需使用Hash Tag（`{tag}`）强制同slot
- 批量操作优先使用 `MGET/MSET` 代替Pipeline中的多个GET/SET，减少命令解析开销

### 优化3：集群分片策略

- 集群模式下Key通过CRC16 % 16384映射到slot，Hash Tag可强制相关Key到同一slot
- 避免使用大量相同Hash Tag，否则所有请求集中到单个slot对应节点，失去分片效果
- 根据数据量和QPS选择集群规模：单节点建议内存不超过8GB，QPS不超过80000
- 扩容时slot迁移会导致短暂的性能抖动，建议在低峰期执行，并控制迁移速度
- 监控各节点的 `keyspace_hits/misses` 和 `instantaneous_ops_per_sec`，识别分片不均

### 优化4：慢查询优化

- 配置 `slowlog-log-slower-than` 为10000微秒（10ms），记录所有超过阈值的慢命令
- 定期检查 `SLOWLOG GET` 输出，分析慢命令类型和频率
- 常见慢命令优化：`KEYS *` → `SCAN`，`HGETALL` 大Hash → `HSCAN`，`SORT` → 业务层排序，`SINTER` 大集合 → 预计算
- 慢查询堆积时使用 `CLIENT LIST` 查看阻塞的客户端连接，定位问题来源
- 将分析类查询（聚合、排序）迁移到从节点执行，避免影响主节点写入性能

### 优化5：内存淘汰策略

- 根据业务特征选择淘汰策略：`allkeys-lru`（通用缓存）、`volatile-ttl`（有明确过期优先级）、`allkeys-lfu`（热点明显）
- 避免使用 `noeviction`（不淘汰），内存满时写入直接报错，业务中断风险高
- 设置 `maxmemory` 为实例总内存的70%~80%，预留空间给复制缓冲区和AOF重写缓冲区
- 使用 `MEMORY USAGE` 命令精确计算Key占用的内存（含内部数据结构开销），而非仅计算Value长度
- 监控 `evicted_keys` 指标，淘汰量持续增长时评估是否需要扩容或调整淘汰策略

## 三、安全加固（3项）

### 安全1：缓存数据加密

- DCS实例支持SSL/TLS传输加密，防止网络传输中数据被窃听，但默认未开启
- 传输加密会增加约10%~15%的性能开销，高吞吐场景需评估性能影响
- 数据持久化（RDB/AOF）文件未加密，存储在OBS时需开启OBS服务端加密
- 跨区域数据同步时（如DCS灾备），传输链路未加密可能导致数据泄露
- **加固**：生产环境强制开启SSL/TLS，AOF/RDB文件存储开启OBS加密，跨区域同步使用VPN或专线通道

### 安全2：访问白名单

- DCS实例支持IP白名单控制访问来源，默认允许所有VPC内IP访问，存在内部越权风险
- 白名单仅支持IP地址段，不支持安全组或IAM用户维度控制，细粒度权限需在应用层实现
- 白名单配置不当（如配置为0.0.0.0/0）等于未设置，任何VPC内ECS均可访问
- 跨VPC访问DCS时白名单需添加对端VPC的网段，但可能引入不必要的访问范围
- **加固**：严格配置IP白名单仅放通应用服务器IP，使用DCS的账号认证（Redis 6.0+ ACL），定期审计白名单配置

### 安全3：审计日志

- DCS实例的操作日志（创建/删除/扩容/参数修改）通过CTS（云审计服务）记录，但数据面操作（GET/SET等）默认无审计
- 敏感数据访问无审计记录，无法满足等保要求的"对重要数据的访问行为可追溯"
- DCS慢日志可作为部分审计参考，但不记录正常速度的读取操作
- Redis 6.0+ 的ACL功能可限制用户权限，但操作日志仍需外部采集
- **加固**：开启CTS全量审计记录管理面操作，数据面审计通过代理层（如Camellia Redis Proxy）记录访问日志，敏感Key使用命名规范便于追踪

## 四、故障排查（5项）

### 故障1：连接超时

- **现象**：客户端报错 `RedisConnectionException: Unable to connect` 或 `RedisCommandTimeoutException`
- **排查步骤**：
  1. 确认DCS实例状态是否为 `RUNNING`，是否有正在进行的维护操作
  2. 检查客户端与DCS是否在同一VPC，安全组和ACL是否放通6379端口
  3. 查看DCS实例的 `connected_clients` 是否达到 `maxclients` 上限
  4. 检查网络延迟（`redis-cli --latency`），确认是否有网络抖动
  5. 查看客户端连接池配置，连接超时和读写超时是否设置过短
- **处置**：调整安全组/ACL规则，升级DCS规格增加最大连接数，优化客户端连接池参数

### 故障2：慢查询飙升

- **现象**：DCS实例延迟突增，应用响应变慢，监控显示 `instantaneous_ops_per_sec` 下降
- **排查步骤**：
  1. 执行 `SLOWLOG GET 20` 查看最近的慢命令
  2. 检查是否有大Key操作（`MEMORY USAGE <key>` 确认Key大小）
  3. 查看是否有 `KEYS *`、`SORT`、`SINTER` 等O(N)复杂度命令
  4. 检查AOF持久化策略，`appendfsync always` 会导致每次写入都fsync，极大降低吞吐
  5. 分析 `INFO commandstats` 确认哪些命令调用次数和耗时异常
- **处置**：优化慢命令，拆分大Key，AOF策略改为 `everysec`，增加从节点分担读压力

### 故障3：内存溢出

- **现象**：DCS实例报错 `OOM command not allowed when used memory > 'maxmemory'`，写入操作失败
- **排查步骤**：
  1. 查看 `used_memory` 和 `maxmemory`，确认内存使用率
  2. 检查 `evicted_keys` 是否在增长，淘汰策略是否生效
  3. 分析 `MEMORY DOCTOR` 输出，确认是否有大Key或内存碎片问题
  4. 检查是否有大量Key未设置过期时间，导致内存持续增长
  5. 查看业务是否有突发写入流量，导致内存快速增长
- **处置**：清理无用Key，调整淘汰策略，扩容实例内存，对未设TTL的Key设置合理过期时间

### 故障4：主从切换失败

- **现象**：主节点故障后从节点未自动升主，或主从切换后客户端连接异常
- **排查步骤**：
  1. 确认DCS实例类型是否为集群或主备模式，单机实例无主从切换
  2. 检查哨兵/集群的 `master_link_status` 是否为 `ok`，从节点复制是否正常
  3. 查看主从切换日志，确认切换过程是否有报错
  4. 检查客户端是否支持自动重连和拓扑感知（如Lettuce的集群拓扑刷新）
  5. 确认DNS解析是否及时更新（DCS主备切换后VIP漂移，DNS可能有缓存）
- **处置**：使用支持拓扑刷新的客户端，调整DNS缓存时间，检查哨兵配置确保切换超时合理

### 故障5：集群脑裂

- **现象**：集群中出现两个主节点，数据写入不一致，部分Key在两个主节点上值不同
- **排查步骤**：
  1. 执行 `CLUSTER NODES` 查看集群拓扑，确认是否有多个节点标记为 `master`
  2. 检查网络分区历史，确认是否有短暂的网络中断导致哨兵误判
  3. 分析旧主节点的 `offset` 与新主节点差异，评估数据丢失量
  4. 检查 `min-slaves-to-write` 配置，确认是否设置了防脑裂参数
  5. 查看DCS实例的监控指标，确认脑裂发生时间点的网络和负载情况
- **处置**：停止旧主节点写入，将数据合并到新主节点，配置 `min-slaves-to-write` 防止脑裂再次发生

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云DCS | 自建Redis | AWS ElastiCache |
|------|-----------|----------|-----------------|
| **部署周期** | 分钟级（控制台创建） | 小时级~天级（安装配置） | 分钟级（控制台创建） |
| **运维责任** | 华为负责实例运维和监控 | 全部自行负责（部署/监控/升级） | AWS负责实例运维和监控 |
| **兼容性** | 兼容Redis 4.0/5.0/6.0 | 任意Redis版本 | 兼容Redis 5.0/6.0/7.0 |
| **高可用** | 主备/集群自动切换 | 需自建哨兵/集群 | 主备/集群自动切换 |
| **数据持久化** | 支持RDB/AOF | 完全自定义 | 支持RDB/AOF |
| **监控能力** | 云监控+DCS控制台 | 需自建Prometheus+Grafana | CloudWatch+ElastiCache控制台 |
| **备份恢复** | 自动备份+手动备份+恢复 | 需自建备份脚本 | 自动备份+手动备份+恢复 |
| **成本模型** | 按实例规格计费 | ECS成本+运维人力 | 按节点规格计费（通常更贵） |
| **扩展性** | 在线扩缩容（部分支持） | 手动扩缩容+迁移 | 在线扩缩容（部分支持） |
| **安全合规** | VPC隔离+SSL+白名单 | 自行实现 | VPC隔离+SSL+安全组 |

### 选择建议

- **选择DCS**：云原生业务、需要托管运维降低人力成本、华为云生态内应用
- **选择自建Redis**：需要最新Redis版本或自定义模块、对运维有深度控制需求、超大规模部署成本更优
- **选择ElastiCache**：AWS生态内应用、需要与AWS其他服务深度集成、全球多区域部署

## 六、已知限制（≥3项）

1. **集群模式不支持多Key事务**：DCS集群模式下，涉及多个Key的事务（`MULTI/EXEC`）要求所有Key在同一slot，跨slot事务会报错 `CROSSSLOT`，需使用Hash Tag强制同slot

2. **实例规格不可降配**：DCS实例支持在线扩容但不支持降配缩容，如需降配需创建新实例并迁移数据，操作窗口和风险较大

3. **大Key在线迁移风险**：在线迁移大Key时可能导致迁移任务超时或目标节点内存突增，建议迁移前先清理或拆分大Key

4. **单机实例无高可用**：DCS单机实例无主备切换能力，节点故障后需等待恢复或手动切换，生产环境务必使用主备或集群模式

5. **备份恢复粒度限制**：DCS备份为实例级别全量备份，不支持单个Key或单个数据库的细粒度恢复，误删Key需通过AOF日志回放

6. **Memcached引擎功能受限**：DCS的Memcached引擎不支持持久化、主备和集群模式，仅适用于纯缓存场景，无数据可靠性保障
