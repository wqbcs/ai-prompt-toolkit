# 华为云GaussDB（国产数据库）场景模板

## 概述

华为云 GaussDB 是自主研发的企业级分布式数据库，支持 MySQL、PostgreSQL 兼容模式及分布式部署形态。本模板覆盖实例管理、数据迁移、备份恢复、性能调优、高可用等核心场景，帮助团队规避国产数据库迁移和运维中的常见陷阱。

---

## 一、常见陷阱（5项）

### 陷阱1：数据迁移兼容性问题

- 从 MySQL 迁移到 GaussDB(for MySQL) 时，部分 MySQL 特有语法（如 `INSERT ... ON DUPLICATE KEY UPDATE` 的特定用法）行为不一致
- 从 Oracle 迁移到 GaussDB 时，PL/SQL 语法差异导致存储过程/触发器大量重写，迁移工作量远超预期
- 字符集和排序规则差异：GaussDB 默认字符集可能与源库不同，导致中文排序/比较结果不一致
- 自增列（AUTO_INCREMENT/SEQUENCE）的值在迁移后可能不连续或起始值不正确，影响业务逻辑
- **规避**：迁移前使用 DRS（数据复制服务）的预检查功能扫描兼容性问题；逐项验证存储过程和触发器；字符集显式指定；自增列迁移后手动校正起始值

### 陷阱2：备份恢复RTO超标

- 全量备份 + 增量备份的恢复流程在大数据量（> 5TB）场景下 RTO 可能超过 8 小时，远超业务容忍范围
- 跨区域备份恢复时数据传输耗时占 RTO 的 60% 以上，跨区域 RTO 可能超过 24 小时
- 备份加密后恢复速度降低 30%~50%，未计入 RTO 预估导致恢复承诺无法兑现
- 恢复过程中遇到备份文件损坏（OBS 存储层静默错误），无备选备份可恢复
- **规避**：定期执行备份恢复演练测量真实 RTO；关键业务使用同城双活架构替代备份恢复；备份文件做完整性校验；配置跨区域备份冗余

### 陷阱3：SQL语法差异

- GaussDB(for MySQL) 不支持部分 MySQL 8.0 新特性（如 CTE 递归的特定语法、窗口函数的部分选项）
- GaussDB(for PostgreSQL) 与原生 PostgreSQL 的扩展生态不兼容，部分常用扩展（如 PostGIS、pg_trgm）不可用
- DDL 语法差异：`ALTER TABLE` 的在线变更行为不同，GaussDB 可能锁表时间更长
- 隐式类型转换规则差异：看似相同的 SQL 在 GaussDB 和源库上返回不同结果
- **规避**：使用 DRS 预检查识别不兼容 SQL；关键查询在 GaussDB 上逐条验证结果；避免使用数据库特定扩展，优先使用标准 SQL

### 陷阱4：连接池耗尽

- 应用侧连接池（如 HikariCP）最大连接数设置超过 GaussDB 实例的 `max_connections` 限制，新连接被拒绝
- 长事务持有连接不释放，连接池逐渐耗尽，新请求超时但应用日志仅显示连接超时而非根因
- GaussDB 分布式模式下协调节点和数据节点的连接数分别计算，总连接数为协调节点数 × 单节点连接数，极易超限
- 微服务架构下多个服务共享同一 GaussDB 实例，连接数配额分配不均导致某服务连接不足
- **规避**：总连接数 = GaussDB max_connections × 80%（预留运维连接）；长事务设置超时自动回滚；分布式模式关注各节点连接数；按服务分配连接配额

### 陷阱5：主从切换数据丢失

- 异步复制模式下主库故障切换，尚未同步到从库的事务丢失，数据一致性受损
- 半同步复制超时后降级为异步复制，此时主库故障仍然可能丢失数据
- 分布式模式下分片主从切换顺序不当，全局事务一致性被破坏
- 主从切换后应用未刷新连接，旧主库的读写操作导致数据不一致
- **规避**：对数据一致性要求高的业务使用强同步复制；切换后应用自动重连并校验主从一致性；分布式模式使用分布式事务保证全局一致性

## 二、性能优化（5项）

### 优化1：查询优化器调优

- 使用 `EXPLAIN ANALYZE` 分析慢查询执行计划，关注全表扫描（Seq Scan）和嵌套循环连接（Nested Loop）
- 更新统计信息：`ANALYZE` 命令确保优化器基于最新数据分布选择执行计划
- 配置 `enable_nestloop=off` 等优化器参数，对特定查询强制使用更优的连接方式
- 对复杂查询使用 Query Hint（如 `/*+ NestLoop(t1 t2) */`）引导优化器选择更优计划
- 定期收集慢查询日志，使用 GaussDB 的 SQL 审计功能识别 TOP N 慢查询并逐项优化

### 优化2：索引策略优化

- 遵循最左前缀原则设计复合索引：将等值条件列放在前面，范围条件列放在后面
- 避免过度索引：每个索引增加写入开销 5%~10%，高频写入表的索引数控制在 5 个以内
- 使用部分索引（Partial Index）仅索引满足条件的数据，减少索引体积和维护开销
- 定期检查无效索引：未使用的索引（通过 `pg_stat_user_indexes` 监控 idx_scan=0）应删除
- 分布式模式下选择合适的分布键：分布键选择不当导致数据倾斜，部分节点负载过高

### 优化3：连接池配置

- GaussDB 内置连接池（`thread_pool`）：启用后减少线程创建/销毁开销，高并发场景 QPS 提升 30%
- 应用侧 HikariCP 配置建议：`maximumPoolSize = CPU核心数 × 2 + 磁盘数`，`minimumIdle = maximumPoolSize / 2`
- 连接池设置 `connectionTimeout=3000` 和 `maxLifetime=1800000`，避免长时间占用连接
- 分布式模式：协调节点连接池大小 = 数据节点数 × 单节点期望并发数
- 监控连接池指标：活跃连接数/空闲连接数/等待线程数，设置告警阈值

### 优化4：读写分离效率

- 配置只读副本分担读流量：写操作走主库，读操作走只读副本，读 QPS 可线性扩展
- 应用侧使用读写分离中间件（如 GaussDB 代理）：自动路由读写请求，对应用透明
- 读写分离延迟监控：主从延迟 > 100ms 时将强一致性读切回主库，避免读到过期数据
- 只读副本数量根据读 QPS 计算：只读副本数 = 读 QPS / 单副本可承载 QPS
- 对延迟敏感的写后读场景使用 hint 强制走主库：`/*+ readmaster */`

### 优化5：分布式查询性能

- 选择合适的分布键：优先选择高频查询的等值条件列，确保关联查询的数据在同一节点
- Colocation Join：关联查询的表使用相同分布键，避免跨节点数据重分布（Redistribute）
- 广播小表：对维度表使用广播分布（Replicate），避免 Join 时的数据重分布开销
- 合理设置分片数：分片数 = 数据节点数 × 每节点期望分片数（通常 2~4），过多分片增加协调开销
- 使用分布式计划缓存：相同的分布式查询计划缓存后复用，减少优化器重复计算

## 三、安全加固（3项）

### 安全1：数据加密

- 启用 GaussDB 透明数据加密（TDE）：数据文件和备份文件均加密存储，密钥由 KMS 管理
- 传输层加密：强制 SSL/TLS 连接，禁止明文连接（`ssl=on`，`require_ssl=on`）
- 敏感字段加密：身份证号、手机号等使用应用层加密（AES-256）后存储，数据库仅存储密文
- 密钥轮换：TDE 密钥和 KMS 主密钥定期轮换（建议 90 天），旧密钥加密的数据自动重新加密
- 备份加密：自动备份和手动备份均启用加密，密钥与数据库 TDE 密钥分离管理

### 安全2：访问控制

- 最小权限原则：应用账号仅授予 `SELECT/INSERT/UPDATE/DELETE` 权限，禁止 `ALL PRIVILEGES`
- 管理账号与业务账号分离：DBA 账号使用 IAM 强认证，业务账号使用密码认证
- 限制登录来源：通过 `pg_hba.conf` 或安全组限制可连接的 IP 范围
- 定期审计账号权限：检查是否存在未使用账号、过度授权账号、默认账号未修改密码
- 敏感操作（DROP TABLE/TRUNCATE/DROP DATABASE）需要二次确认或独立授权

### 安全3：审计日志

- 启用 GaussDB 审计日志：记录所有 DDL/DCL 操作和关键 DML 操作
- 审计日志接入 LTS（云日志服务）：集中存储和检索，保留期限 ≥ 180 天
- 配置审计告警：对异常操作（如批量 DELETE、DROP TABLE、权限变更）实时告警
- 定期审计审查：每月检查审计日志，识别异常访问模式和潜在安全风险
- 审计日志不可篡改：配置 LTS 日志的防篡改策略，确保审计记录的完整性

## 四、故障排查（5项）

### 故障1：连接超时

- **现象**：应用连接 GaussDB 超时，报错 `Connection timed out` 或 `Communications link failure`
- **排查步骤**：
  1. 检查 GaussDB 实例状态：是否正常运行，是否在进行维护/升级
  2. 检查网络连通性：从应用服务器 `telnet <db-host> <db-port>` 确认网络可达
  3. 检查安全组/网络ACL：是否阻断了数据库端口（默认 3306/5432）
  4. 检查连接数：`SHOW PROCESSLIST` 或 `pg_stat_activity` 确认是否连接数已满
  5. 检查 GaussDB 的 `wait_timeout`/`idle_in_transaction_session_timeout` 是否过短
- **处置**：修复网络配置/释放空闲连接/提升连接数配额/调整超时参数

### 故障2：慢查询

- **现象**：部分 SQL 执行时间远超预期，影响业务响应时间
- **排查步骤**：
  1. 查看慢查询日志：`long_query_time` 设为 1s，收集慢 SQL
  2. `EXPLAIN ANALYZE` 分析执行计划：关注全表扫描、低效连接、排序操作
  3. 检查统计信息是否过期：`ANALYZE` 更新后重新查看执行计划
  4. 检查索引使用情况：查询是否命中索引，是否有冗余索引
  5. 分布式模式：检查是否存在跨节点数据重分布（Redistribute）
- **处置**：添加/优化索引/更新统计信息/重写 SQL/调整分布键

### 故障3：主从延迟

- **现象**：只读副本数据落后于主库，读写分离后读到过期数据
- **排查步骤**：
  1. 检查复制延迟指标：`seconds_behind_master` 或 `replay_lag`
  2. 检查主库写入压力：是否有大事务/大批量写入导致 binlog 积压
  3. 检查从库资源：CPU/IO 是否瓶颈导致回放速度跟不上
  4. 检查网络延迟：主从之间的网络带宽和延迟
  5. 检查从库是否有长查询阻塞回放：DDL 操作可能阻塞从库回放
- **处置**：优化大事务为小批次写入/升级从库规格/优化从库查询/启用并行回放

### 故障4：备份失败

- **现象**：自动备份或手动备份任务失败
- **排查步骤**：
  1. 检查备份任务错误日志：OBS 访问失败/磁盘空间不足/实例状态异常
  2. 检查 OBS 桶状态：桶是否存在、配额是否充足、权限是否正确
  3. 检查实例磁盘空间：备份过程需要临时空间，磁盘不足会导致备份失败
  4. 检查实例状态：备份期间实例是否发生了主从切换或故障
  5. 检查备份保留策略：是否超过最大备份数限制
- **处置**：修复 OBS 配置/释放磁盘空间/检查实例状态/调整备份保留策略

### 故障5：迁移中断

- **现象**：DRS 迁移任务中断，进度停止
- **排查步骤**：
  1. 查看 DRS 任务日志：网络断连/源库权限变更/目标库写入失败
  2. 检查源库状态：是否在维护/重启/大事务执行中
  3. 检查网络连通性：DRS 实例与源库/目标库之间的网络
  4. 检查迁移账号权限：源库读取权限/目标库写入权限是否完整
  5. 检查数据冲突：目标库已有数据与迁移数据冲突导致写入失败
- **处置**：修复网络/恢复源库/补全权限/清理目标库冲突数据/重启迁移任务

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云GaussDB | MySQL（RDS/自建） | PostgreSQL（RDS/自建） |
|------|-------------|-------------------|----------------------|
| **数据库类型** | 自研分布式/MySQL兼容/PG兼容 | 开源关系型 | 开源关系型 |
| **分布式能力** | 原生分布式，透明分库分表 | 需中间件（ShardingSphere/Vitess） | 需中间件（Citus/Pgpool） |
| **国产化** | 信创目录，等保三级，国密支持 | 开源，无国产化认证 | 开源，无国产化认证 |
| **MySQL兼容** | GaussDB(for MySQL)高度兼容 | 原生MySQL | 不兼容 |
| **PG兼容** | GaussDB(for PostgreSQL)高度兼容 | 不兼容 | 原生PostgreSQL |
| **扩展生态** | 有限，核心扩展内置 | 丰富的MySQL插件 | 极丰富的PG扩展 |
| **性能上限** | 分布式线性扩展，PB级存储 | 单机/主从模式，TB级存储 | 单机/Citus分布式 |
| **高可用** | 同城双活/跨城容灾/金融级 | 主从复制/组复制 | 流复制/逻辑复制 |
| **成本模型** | 按规格+存储计费，分布式节点多成本较高 | 开源免费/按规格计费 | 开源免费/按规格计费 |
| **适用场景** | 国产化替代/分布式需求/金融级HA | MySQL生态/中小规模/成本敏感 | PG生态/复杂查询/扩展需求 |

### 选择建议

- **选择GaussDB**：国产化合规要求、分布式需求（单表 > 10亿行）、金融级高可用、华为云深度用户
- **选择MySQL**：成本敏感、MySQL生态成熟、中小规模业务、团队MySQL经验丰富
- **选择PostgreSQL**：复杂查询需求、丰富的扩展生态（PostGIS等）、JSON/JSONB 支持、团队 PG 经验丰富

## 六、已知限制（≥3项）

1. **扩展兼容性有限**：GaussDB(for PostgreSQL) 不支持 PostGIS、pg_trgm、hstore 等常用 PostgreSQL 扩展，依赖这些扩展的业务（如 GIS 应用）需要寻找替代方案或使用原生 PostgreSQL

2. **分布式模式限制**：分布式模式下不支持跨分片的 FOREIGN KEY 约束、部分复杂子查询、存储过程的分布式执行，从单机迁移到分布式需要评估 SQL 兼容性

3. **备份粒度限制**：GaussDB 备份仅支持实例级和库级，不支持表级备份，对大实例中仅需要恢复个别表的场景恢复效率较低

4. **DDL 操作锁表**：部分 DDL 操作（如 `ALTER TABLE ADD COLUMN`）在 GaussDB 上可能锁表时间比 MySQL/PostgreSQL 更长，大表变更需在低峰期执行

5. **连接数与内存强绑定**：GaussDB 的 `max_connections` 与实例内存规格强绑定，提升连接数需要升级实例规格，无法仅调整参数而不升级资源
