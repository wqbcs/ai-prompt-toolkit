# 华为云DWS（数据仓库）场景模板

## 概述

华为云数据仓库服务（GaussDB DWS, Data Warehouse Service）是基于MPP架构的云原生分析型数据库，兼容PostgreSQL协议，提供海量数据分析能力。本模板覆盖集群管理、数据导入、查询优化、快照恢复及弹性伸缩等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：数据倾斜严重

- 创建表时选择不合适的分布键（Distribution Key），导致数据在各个DN（数据节点）上分布严重不均
- 使用日期列作为分布键时，查询特定日期的数据仅命中单个DN，其他DN空闲，无法利用MPP并行能力
- 分布键的基数（Cardinality）过低（如性别、状态字段），大量数据集中到少数DN，出现"数据热点"
- 使用 `RANDOM` 分布时虽数据均匀，但关联查询时需广播或重分布数据，网络开销极大
- **规避**：选择高基数、频繁用于JOIN的列作为分布键，使用 `SELECT * FROM PG_GET_TABLE_SKEWNESS('schema.table')` 检查数据倾斜率，倾斜率超过10%需调整分布键

### 陷阱2：查询未利用分区

- 创建了分区表但查询条件未包含分区键，导致全分区扫描（Partition Scan退化为Full Scan），查询性能未提升
- 分区裁剪（Partition Pruning）仅在查询条件为等值或范围匹配时生效，使用函数或表达式包裹分区键会导致裁剪失效
- 多级分区中仅使用低级分区键查询，高级分区仍需扫描，裁剪效果不完整
- 分区数量过多（超过1000个）时，查询规划阶段的分区裁剪耗时增加，反而降低查询性能
- **规避**：查询条件必须包含分区键，避免在分区键上使用函数，分区数量控制在100~500之间，使用 `EXPLAIN` 确认查询计划中包含 `Partitioned Scan` 和裁剪信息

### 陷阱3：导入性能瓶颈

- 使用单条INSERT语句逐行导入数据，每条INSERT都是一次事务提交，WAL写入和索引更新开销极大
- 通过OBS外表导入时，OBS文件未做合理分片，单文件过大导致单个DN处理时间过长
- 导入目标表有大量索引，每条数据导入都触发索引更新，索引维护开销远超数据写入
- 导入过程中触发大量统计数据自动收集（ANALYZE），消耗集群资源影响导入吞吐
- **规避**：使用 `COPY` 命令或批量INSERT批量导入，OBS文件按DN数量分片并行导入，导入前删除索引导入后重建，导入后手动执行 `ANALYZE`

### 陷阱4：快照恢复超时

- 大集群（数十个DN）的快照恢复耗时随数据量线性增长，TB级数据恢复可能超过数小时
- 快照恢复期间集群不可用，业务完全中断，恢复超时影响RTO指标
- 跨区域恢复快照时，数据需从远端OBS下载，网络带宽成为瓶颈
- 增量快照依赖全量快照，恢复时需先恢复全量再叠加增量，链式依赖导致恢复时间叠加
- **规避**：合理规划快照策略（全量+增量），大集群拆分为多个小集群降低单次恢复时间，跨区域恢复使用同区域OBS副本减少网络传输

### 陷阱5：弹性伸缩不均衡

- 弹性伸缩增加DN节点后，已有表的数据不会自动重分布到新节点，新节点空闲而老节点满载
- 扩容后需手动执行 `REDISTRIBUTE TABLE` 重分布数据，大表重分布耗时长且影响在线查询
- 缩容时系统选择移除的DN上数据需迁移到保留DN，迁移过程消耗大量网络和IO资源
- 弹性伸缩与查询并发执行时，重分布操作与查询争抢资源，导致查询性能下降
- **规避**：在低峰期执行弹性伸缩和重分布，设置资源队列限制重分布操作的资源消耗，扩容后及时执行数据重分布

## 二、性能优化（5项）

### 优化1：查询并行度优化

- 使用 `query_dop` 参数控制查询并行度，默认值可能不是最优，根据集群规模和查询复杂度调整
- 简单查询设置较低的 `query_dop`（如2~4），避免并行初始化开销超过查询本身
- 复杂聚合查询设置较高的 `query_dop`（如8~16），充分利用多核和多DN并行能力
- 并行度过高导致DN间通信量增加，出现"并行反而变慢"的现象，需通过 `EXPLAIN PERFORMANCE` 分析
- 使用资源队列（Resource Queue）为不同业务设置不同的并行度上限，防止大查询占满集群资源

### 优化2：分区裁剪优化

- 选择合适的分区策略：范围分区（按日期）、列表分区（按地区）、哈希分区（按ID），匹配业务查询模式
- 分区键与排序键（Sort Key）配合使用，查询可同时利用分区裁剪和排序优化
- 使用多级分区（如年-月两级）时，确保查询条件覆盖高级和低级分区键
- 避免分区粒度过细（如按小时分区），分区数量过多增加元数据管理开销
- 定期清理过期分区（`DROP PARTITION`）比删除数据（`DELETE`）更高效，直接释放存储空间

### 优化3：数据导入COPY优化

- 使用 `COPY FROM` 批量导入替代INSERT，性能提升10~100倍，减少事务提交和WAL开销
- OBS外表导入时，文件格式选择CSV或ORC，ORC格式列存压缩率更高、导入速度更快
- 多个OBS文件并行导入，文件数量与DN数量对齐，每个DN处理一个文件分片
- 导入前设置 `maintenance_work_mem` 为较大值（如1GB），加速索引创建和统计数据收集
- 关闭自动统计收集（`enable_auto_analyze=off`），导入完成后手动执行 `ANALYZE`

### 优化4：索引策略

- DWS列存表默认使用MinMax索引（稀疏索引），适合大范围扫描，不适合精确查询
- 对高频等值查询的列创建B-tree索引，但索引数量不宜过多，每个索引增加导入和更新开销
- 避免在低基数列（如性别、状态）上创建B-tree索引，索引选择度太低查询优化器不会使用
- 使用部分索引（Partial Index）仅索引满足条件的数据行，减少索引体积和维护开销
- 表达式索引（如 `LOWER(column)` ）仅在查询使用相同表达式时生效，查询条件需与索引表达式完全一致

### 优化5：资源队列管理

- 使用资源队列（Resource Queue）限制不同业务组的并发数、内存和CPU资源，防止大查询占满集群
- 为ETL任务和交互式查询设置不同的资源队列，ETL队列限制并发但允许长时间运行
- 设置资源队列的 `active_statements` 限制并发查询数，超出排队等待而非报错
- 监控资源队列的 `queue_length` 和 `execution_count`，识别资源瓶颈和排队情况
- 使用工作负载管理（WLM）自动分类查询到不同资源队列，根据查询特征自动路由

## 三、安全加固（3项）

### 安全1：数据脱敏

- DWS支持动态数据脱敏策略（Dynamic Data Masking），对敏感字段（手机号、身份证号）查询时自动脱敏
- 脱敏策略与角色绑定，不同角色看到不同粒度的数据，如运营人员看到脱敏数据而DBA看到原始数据
- 脱敏规则包括：遮盖、替换、截断、哈希等，根据数据敏感级别选择合适的脱敏方式
- 脱敏策略仅影响查询结果，存储数据仍为原始值，导入导出时需额外控制
- **加固**：对包含PII（个人身份信息）的列配置脱敏策略，定期审计脱敏规则覆盖完整性，导出数据需单独审批

### 安全2：行级权限控制

- DWS支持行级安全策略（Row Level Security, RLS），限制不同角色只能访问满足条件的行
- RLS策略与表绑定，指定角色和条件表达式，如 `CREATE POLICY dept_policy ON employees FOR SELECT TO role_a USING (dept = 'A')`
- 策略分为PERMISSIVE（或逻辑）和RESTRICTIVE（与逻辑），多个策略叠加时需注意逻辑关系
- 表的所有者（Owner）默认不受RLS策略限制，需使用 `ALTER TABLE ... FORCE ROW LEVEL SECURITY` 强制所有者也受约束
- **加固**：多租户场景使用RLS实现租户数据隔离，避免通过视图封装带来的性能和维护开销

### 安全3：审计日志

- DWS支持操作审计日志，记录DDL、DML、权限变更等操作，满足等保合规要求
- 审计日志默认关闭，需通过 `audit_enabled=on` 和 `audit_object=on` 开启
- 审计日志存储在集群本地，需定期导出到OBS长期保存，否则磁盘空间可能被日志占满
- 高频DML操作产生大量审计日志，影响集群IO性能，建议仅审计关键表和关键操作
- **加固**：开启全量审计，关键操作（DDL、权限变更、数据导出）单独配置审计规则，审计日志定期归档到OBS并设置生命周期策略

## 四、故障排查（5项）

### 故障1：查询超时

- **现象**：查询执行时间超过 `statement_timeout` 被自动取消，或查询长时间运行无响应
- **排查步骤**：
  1. 使用 `PG_STAT_ACTIVITY` 查看当前运行的查询及其状态（`active`/`waiting`）
  2. 检查查询是否被资源队列阻塞（`waiting` 状态且 `resource_queue` 非空）
  3. 使用 `EXPLAIN PERFORMANCE` 分析查询计划，定位耗时最长的算子
  4. 检查是否有锁等待（`PG_LOCKS` 视图），查询被其他事务阻塞
  5. 查看DN节点的CPU/内存/IO指标，确认是否有资源瓶颈
- **处置**：优化查询SQL和执行计划，调整资源队列配置，增加 `statement_timeout` 阈值，解除锁等待

### 故障2：数据导入失败

- **现象**：`COPY` 或OBS外表导入报错，提示数据格式错误、权限不足或连接失败
- **排查步骤**：
  1. 检查导入文件的格式是否与表定义匹配（列数、数据类型、分隔符）
  2. 确认OBS桶的访问权限，DWS集群是否已授权读取OBS
  3. 查看导入日志中的具体错误行号和错误信息
  4. 检查目标表的磁盘空间是否充足（各DN独立计算空间）
  5. 确认导入过程中是否有唯一约束冲突或数据类型溢出
- **处置**：修复数据格式问题，配置OBS访问权限，清理磁盘空间，使用 `fill_missing_fields` 或 `ignore_extra_data` 容错参数

### 故障3：磁盘空间不足

- **现象**：DN节点报错 `No space left on device`，查询和导入操作失败
- **排查步骤**：
  1. 查询 `PG_TABLESPACE_SIZE` 和 `PG_DATABASE_SIZE` 定位空间占用最大的数据库和表
  2. 检查是否有大量临时表未清理（`PG_CLASS WHERE relnamespace = pg_my_temp_schema()`）
  3. 查看是否有过期的快照未清理，快照占用OBS空间但不占用本地磁盘
  4. 检查各DN的空间使用是否均衡，数据倾斜可能导致单DN磁盘满
  5. 确认WAL日志和审计日志是否占用过多空间
- **处置**：清理临时表和过期数据，扩容集群磁盘，重分布数据解决倾斜，调整日志保留策略

### 故障4：快照恢复中断

- **现象**：快照恢复过程中报错中断，集群状态异常
- **排查步骤**：
  1. 查看恢复日志中的错误码和错误信息
  2. 确认目标集群规格是否与快照源集群兼容（节点数、版本号）
  3. 检查OBS存储中的快照文件是否完整，是否有损坏
  4. 确认目标集群的磁盘空间是否大于快照数据量
  5. 检查恢复过程中是否有网络中断或OBS访问异常
- **处置**：重新执行恢复，确保目标集群规格和版本兼容，检查OBS快照完整性，必要时联系技术支持

### 故障5：节点故障

- **现象**：DWS集群中某个DN节点状态变为 `Down`，查询报错或性能下降
- **排查步骤**：
  1. 在管理控制台查看节点状态和故障描述
  2. 检查节点所在主机的CPU/内存/磁盘指标，确认是否资源耗尽
  3. 查看DN节点的日志（`pg_log` 目录），定位具体错误
  4. 确认是否触发了主机维护窗口
  5. 检查是否有大量写入导致WAL积压，DN无法及时刷盘
- **处置**：尝试重启DN节点，若无法恢复则执行节点替换，替换后数据从副本重建，期间集群性能可能下降

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云DWS | AWS Redshift | 自建Greenplum |
|------|-----------|--------------|---------------|
| **架构** | MPP + 列存 + 向量化 | MPP + 列存 | MPP + 列存/行存 |
| **兼容性** | 兼容PostgreSQL | 兼容PostgreSQL（部分） | 兼容PostgreSQL |
| **部署周期** | 分钟级 | 分钟级 | 天级~周级 |
| **弹性伸缩** | 在线扩容（需重分布） | 在线扩容（Elastic Resize） | 需停机扩容 |
| **存储计算分离** | 部分支持（存算分离版） | 支持（RA3节点） | 不支持 |
| **数据导入** | OBS外表/COPY/DRS | S3/COPY | 本地文件/外部表 |
| **并发能力** | 数百并发 | 数百并发 | 数百并发 |
| **冷热数据** | 支持OBS冷热分层 | 支持S3冷热分层 | 需手动实现 |
| **运维责任** | 华为负责基础设施运维 | AWS负责基础设施运维 | 全部自行负责 |
| **成本模型** | 按节点规格计费 | 按节点规格计费 | 服务器+运维人力 |

### 选择建议

- **选择DWS**：华为云生态内应用、需与GaussDB生态集成、国内合规要求、成本敏感
- **选择Redshift**：AWS生态内应用、需要存算分离架构（RA3）、全球多区域部署、与AWS分析服务集成
- **选择自建Greenplum**：需要深度定制、已有Greenplum运维经验、数据不出私有云、超大规模集群成本更优

## 六、已知限制（≥3项）

1. **列存表不支持唯一约束**：DWS列存表不支持PRIMARY KEY和UNIQUE约束，仅行存表支持，需通过业务逻辑保证数据唯一性

2. **扩容需重分布数据**：集群扩容后已有表的数据不会自动重分布到新节点，需手动执行 `REDISTRIBUTE TABLE`，大表重分布耗时长且影响在线查询性能

3. **单查询内存限制**：单个查询使用的内存受 `query_mem` 和资源队列限制，超大聚合查询可能因内存不足报错，需调整参数或拆分查询

4. **跨集群查询不支持**：DWS不支持跨集群的数据库链接（DBLink），跨集群数据查询需通过数据导入导出或联邦查询实现

5. **并发写入冲突**：DWS使用MVCC但同一表的高并发UPDATE/DELETE可能产生大量死元组，VACUUM清理不及时导致查询性能下降

6. **OBS外表性能受限**：通过OBS外表查询数据的性能远低于本地表，适合数据导入导出而非高频查询，频繁查询OBS外表会产生大量流量费用
