# 华为云AS（弹性伸缩）场景模板

## 概述

华为云弹性伸缩（Auto Scaling, AS）可根据业务需求自动调整计算资源，支持告警策略、定时策略、健康检查等机制。本模板覆盖伸缩组配置、伸缩策略、告警伸缩、定时伸缩及健康检查等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：伸缩策略冲突

- 同一伸缩组配置多条告警策略时，若指标和阈值存在重叠（如CPU>70%扩容，CPU>80%扩容），可能同时触发导致超出预期的扩容数量
- 定时策略与告警策略冲突：定时任务即将执行缩容时，告警策略触发扩容，导致资源反复震荡
- 多条策略的冷却时间不一致，短冷却时间的策略频繁触发，长冷却时间的策略被抑制
- 伸缩组设置了期望实例数后，多条策略的扩缩容数量累加可能超过最大实例数限制
- **规避**：每个伸缩组仅配置1~2条核心策略，避免策略重叠；使用策略优先级机制；扩缩容步长设置合理（建议每次1~2台）

### 陷阱2：冷却时间不当

- 冷却时间过短（如60秒）：扩容后新实例尚未完成应用初始化，监控指标未改善，触发连续扩容导致资源浪费
- 冷却时间过长（如600秒）：突发流量期间无法快速扩容，业务受损
- 扩容冷却和缩容冷却使用相同值：扩容应短冷却快速响应，缩容应长冷却避免误缩
- 告警策略触发的冷却时间与定时策略的冷却时间相互独立，未统一管理
- **规避**：扩容冷却时间设为实例启动+应用预热时间+1分钟缓冲（通常3~5分钟），缩容冷却时间设为5~10分钟确保流量稳定

### 陷阱3：健康检查误判

- 健康检查类型选择不当：使用ELB健康检查时，应用启动慢但健康检查间隔短，导致新实例反复被标记为不健康并替换
- 健康检查超时时间设置过短：应用GC暂停期间健康检查超时，实例被误判为不健康
- ECS健康检查与ELB健康检查同时启用但判断结果冲突，AS以ELB结果为准但用户未感知
- 健康检查阈值设置过于敏感（如1次失败即判定不健康），网络抖动导致频繁替换实例
- **规避**：健康检查间隔 ≥ 10秒，超时时间 ≥ 5秒，不健康阈值 ≥ 3次，应用启动慢的场景使用ELB健康检查的延迟注册功能

### 陷阱4：实例启动失败

- 伸缩配置中的镜像/Flavor已下线或配额不足，扩容时实例创建失败但伸缩活动记录不够明确
- 用户数据脚本（user-data）执行失败导致实例启动异常，但AS仍将实例加入伸缩组
- 新实例加入后端服务器组失败（安全组/网络配置问题），流量无法路由到新实例
- 伸缩配置中的密钥对/密码设置不正确，导致实例创建成功但无法登录排查问题
- **规避**：定期验证伸缩配置的有效性（手动触发一次性扩容测试），user-data脚本加入日志输出和健康检查点，确保安全组/网络配置正确

### 陷阱5：伸缩组配置不一致

- 伸缩组关联的VPC/子网/安全组被修改后，伸缩组配置未同步更新，新实例使用旧配置创建失败
- 伸缩配置中的镜像更新后，已运行实例未替换，导致伸缩组内实例版本不一致
- 跨可用区伸缩组的可用区列表被缩减，缩容时实例从已移除的可用区删除导致数据丢失
- 伸缩组关联的ELB监听器配置变更后，健康检查逻辑改变但未调整AS健康检查参数
- **规避**：使用基础设施即代码（Terraform/ROS）管理伸缩组和关联资源，变更时全量更新；镜像更新后使用实例刷新（Instance Refresh）功能逐步替换

## 二、性能优化（5项）

### 优化1：扩缩容响应速度优化

- 使用预热镜像（已包含应用和依赖的自定义镜像），避免启动后再拉取应用包，将实例就绪时间从5分钟缩短到1分钟
- 伸缩配置使用云硬盘快照创建数据盘，省去应用初始化的等待时间
- 预先创建所需数量的弹性IP并绑定到NAT网关，避免扩容时分配EIP导致的延迟
- 开启实例自动注册到ELB后端服务器组，缩容时自动移除，减少手动操作延迟
- 对于可预测的流量高峰，使用定时策略提前5~10分钟扩容，而非等待告警触发

### 优化2：实例预热优化

- 配置ELB健康检查的"延迟注册"时间（通常60~180秒），实例启动完成后再接收流量
- 应用启动脚本使用 readiness probe 模式：启动完成后主动通知AS/ELB可以接收流量
- 预热期间避免执行重计算任务（如缓存预热、数据加载），优先完成服务注册和健康检查
- 使用渐进式流量接入：新实例先接收10%流量，确认无异常后逐步增加到100%
- 伸缩配置的user-data中添加启动完成标记文件，配合自定义健康检查确认应用就绪

### 优化3：告警阈值调优

- 告警指标选择：Web服务使用CPU利用率+请求延迟，批处理使用队列深度，数据库使用连接数+IO利用率
- 阈值设置采用"渐进式"策略：CPU 60%预警观察，70%触发1台扩容，80%触发2台扩容
- 告警持续时间需 ≥ 2个采集周期（通常4分钟），避免瞬时毛刺触发误扩容
- 缩容阈值与扩容阈值保持合理间距（如扩容70%/缩容30%），避免扩缩容震荡
- 结合业务周期特征动态调整阈值：工作日/周末/节假日使用不同阈值，通过定时策略切换

### 优化4：批量伸缩效率

- 单次扩缩容步长不宜过大（建议1~5台），大批量扩容改为分批次执行，减少创建失败率
- 批量扩容时设置合理的批次间隔（如每批间隔1分钟），避免同时创建过多实例导致底层资源争抢
- 使用伸缩组的"期望实例数"一次性调整到目标数量，由AS分批执行，而非手动逐台操作
- 大规模缩容（>10台）时采用优雅缩容：先从ELB移除→等待连接排空→再终止实例
- 批量操作失败时设置自动回滚，将期望实例数恢复到变更前的值

### 优化5：跨可用区均衡

- 伸缩组配置多可用区时，启用"均衡分配"策略，确保实例均匀分布到各可用区
- 单可用区故障时，AS自动在其他可用区创建实例补充容量，但需要配置足够的多可用区子网
- 跨可用区扩容时考虑ELB的跨区流量转发能力，避免所有流量集中到某个可用区
- 监控各可用区实例数量比例，当偏差超过20%时手动调整或触发再均衡
- 可用区扩容优先级设置：将可用性高的区域设为首选，备选可用区仅在首选区资源不足时使用

## 三、安全加固（3项）

### 安全1：伸缩实例安全组缺失

- 伸缩配置中未指定安全组或指定了过于宽松的安全组，新扩容的实例暴露不必要的端口
- 伸缩组与ELB安全组配置不一致，新实例加入后端服务器组后被ELB健康检查拒绝
- 安全组规则变更后，已运行的伸缩实例未同步更新，导致安全策略不统一
- 伸缩配置中的安全组被误删除，扩容时实例创建失败但错误信息不直观
- **加固**：伸缩配置使用独立安全组（仅放行业务端口和ELB健康检查），使用安全组引用而非直接指定ID，变更时通过实例刷新统一更新

### 安全2：敏感数据泄露

- 伸缩配置的user-data脚本中硬编码数据库密码、API密钥等敏感信息，任何能查看伸缩配置的人都能获取
- 实例启动日志中输出了user-data的敏感参数，其他用户通过系统日志可读取
- 缩容时实例上的本地数据未清除即释放，可能被后续分配到同一物理机的其他租户读取
- 伸缩配置的镜像中预置了SSH密钥或凭证，泄露后影响所有扩容的实例
- **加固**：敏感信息通过DEW（数据加密服务）或IMS（镜像服务）注入，user-data仅引用加密引用名；缩容前执行数据擦除脚本；使用加密镜像

### 安全3：未授权伸缩操作

- 伸缩组未配置操作权限控制，任何有AS访问权限的用户都能触发扩缩容，可能误操作导致业务受损
- API调用未做来源IP限制，凭证泄露后攻击者可恶意扩容消耗资源或缩容导致服务降级
- 伸缩策略的触发条件被恶意构造（如注入异常监控数据触发大量扩容）
- 伸缩活动未接入CTS审计，异常操作无法追溯
- **加固**：通过IAM策略限制AS操作权限（仅允许特定角色执行伸缩操作），API网关配置IP白名单，伸缩策略设置最大扩容数量上限，CTS全量审计

## 四、故障排查（5项）

### 故障1：伸缩活动失败

- **现象**：伸缩活动记录显示 `FAILED`，但未创建或删除实例
- **排查步骤**：
  1. 查看伸缩活动详情页的失败原因（`failure_reason` 字段）
  2. 常见原因：资源配额不足、Flavor/镜像不可用、可用区资源不足
  3. 检查伸缩配置是否完整：镜像ID、Flavor、安全组、密钥对是否有效
  4. 检查VPC/子网剩余IP数量是否充足
  5. 查看是否触发了冷却时间限制导致活动被拒绝
- **处置**：修复伸缩配置、申请配额提升、更换可用区或Flavor、调整冷却时间

### 故障2：实例不健康

- **现象**：伸缩组内实例被标记为不健康，AS自动替换实例但反复失败
- **排查步骤**：
  1. 查看健康检查类型和判断逻辑：ECS健康检查（系统状态）还是ELB健康检查（应用状态）
  2. 通过VNC登录不健康实例，检查应用进程是否运行（`systemctl status app`）
  3. 检查ELB健康检查配置：协议、端口、路径、间隔、阈值是否合理
  4. 检查实例系统日志 `/var/log/messages` 和应用日志，定位崩溃原因
  5. 确认健康检查端口未被防火墙/安全组阻断
- **处置**：修复应用启动问题、调整健康检查参数、修复安全组规则

### 故障3：扩容超时

- **现象**：告警触发扩容后，伸缩活动长时间处于 `IN_PROGRESS`，实例未创建成功
- **排查步骤**：
  1. 检查伸缩活动列表，确认扩容是否已触发以及当前进度
  2. 检查底层ECS创建是否卡在某个阶段（通过ECS控制台查看实例状态）
  3. 检查可用区资源库存是否充足，资源不足时创建排队等待
  4. 检查user-data脚本是否执行超时（如依赖外部服务下载大文件）
  5. 检查是否因并发创建过多实例导致API限流
- **处置**：更换可用区/Flavor、优化user-data脚本、分批次扩容、联系华为云支持排查资源库存

### 故障4：缩容数据丢失

- **现象**：AS自动缩容时删除了包含重要数据的实例，数据不可恢复
- **排查步骤**：
  1. 确认实例是否使用了本地盘存储数据（本地盘数据随实例释放而丢失）
  2. 检查伸缩组的缩容策略：默认删除最旧实例，可能导致有数据的实例被优先删除
  3. 确认是否有实例保护机制（standby）防止关键实例被缩容
  4. 检查数据是否已持久化到云硬盘/OBS/RDS等持久化存储
- **处置**：对存储关键数据的实例设置实例保护，数据迁移到持久化存储，调整缩容策略为"删除最新实例"

### 故障5：策略未触发

- **现象**：监控指标已超过阈值，但伸缩策略未触发扩缩容活动
- **排查步骤**：
  1. 确认策略是否已启用（策略状态为 `INSERVICE`）
  2. 检查告警策略关联的CES告警规则是否正常触发（在CES控制台查看告警历史）
  3. 确认是否处于冷却时间内，冷却期内策略不触发
  4. 检查伸缩组当前实例数是否已达到最大/最小实例数限制
  5. 检查策略的触发条件是否配置正确：指标名称、比较符、阈值、持续时间
- **处置**：启用策略、调整冷却时间、放宽最大/最小实例数范围、修正触发条件

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云AS（弹性伸缩） | 手动扩缩容 | K8s HPA（Pod水平伸缩） |
|------|---------------------|-----------|----------------------|
| **响应速度** | 分钟级自动（1~5分钟） | 小时级人工 | 秒级自动（10~60秒） |
| **伸缩粒度** | ECS实例级（1vCPU起步） | ECS实例级 | Pod级（更细粒度，0.1vCPU起步） |
| **健康检查** | ECS/ELB健康检查，自动替换 | 人工判断 | Liveness/Readiness探针 |
| **策略灵活性** | 告警+定时+周期策略 | 完全自定义但需人工 | 指标+自定义指标+定时Cron |
| **应用感知** | 无应用感知，仅看指标 | 人工应用感知 | 强应用感知（探针+指标） |
| **成本优化** | 抢占式实例+按需 | 包月为主 | 抢占式Pod+按需 |
| **运维复杂度** | 低（配置即用） | 低但不可靠 | 高（需维护K8s集群） |
| **适用架构** | 传统VM架构 | 所有架构 | 容器化微服务架构 |
| **跨AZ支持** | 支持，自动均衡 | 手动选择 | 取决于K8s集群部署 |
| **预热/冷启动** | 需配置预热时间 | 无 | 容器秒级启动 |

### 选择建议

- **选择AS**：传统VM架构业务，需要自动弹性伸缩但不希望引入K8s复杂度；Web服务、批处理、中间件等场景
- **选择手动扩缩容**：业务流量完全可预测且变化缓慢，伸缩频率极低（月度级别），或业务对自动伸缩不可控有顾虑
- **选择K8s HPA**：已容器化的微服务架构，需要秒级弹性响应和更细粒度的伸缩控制，有K8s运维能力

## 六、已知限制（≥3项）

1. **伸缩组实例数上限**：单个伸缩组最大实例数上限为200（可申请提升到1000），超大规模业务需要拆分多个伸缩组或使用多集群架构

2. **冷却时间不可禁用**：伸缩活动的冷却时间最少为0秒但告警策略默认冷却300秒，完全禁用冷却时间可能导致扩缩容风暴，建议保留最小60秒冷却

3. **不支持跨Region伸缩**：伸缩组仅能在单个Region内创建和操作，跨Region的高可用需结合DNS/GSLB实现，AS本身不提供跨Region编排能力

4. **缩容策略有限**：缩容策略仅支持"最旧实例优先"和"最新实例优先"两种，不支持基于实例负载的自适应缩容（如优先缩容低负载实例），可能导致高负载实例被误删

5. **实例替换不可回退**：健康检查触发的实例替换操作不可撤销，旧实例释放后数据无法恢复（本地盘场景），必须在应用层保证数据无状态或已持久化

6. **告警策略依赖CES**：AS告警策略依赖云监控服务（CES）的指标采集，CES采集间隔默认5分钟（细粒度1分钟需额外开通），指标延迟可能导致扩容响应滞后

7. **定时策略时区固定**：定时策略的执行时间默认使用UTC时区，与北京时间（UTC+8）有8小时时差，配置时需注意换算，避免在非预期时间触发伸缩
