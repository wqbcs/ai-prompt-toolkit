# 华为云VPC（虚拟私有云）场景模板

## 概述

华为云虚拟私有云（Virtual Private Cloud, VPC）为租户提供逻辑隔离的云上网络环境，支持自定义网段、子网、安全组、路由表等网络组件。本模板覆盖VPC创建、子网划分、安全组配置、路由表管理、NAT网关及对等连接等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：子网CIDR冲突

- 创建VPC和子网时，未规划全局CIDR地址池，导致不同VPC或子网间网段重叠，后续建立对等连接或VPN时路由冲突
- 新增子网的CIDR与已有子网存在包含关系（如10.0.0.0/16与10.0.1.0/24），虽然API允许创建但路由规则会产生歧义
- 企业混合云场景中，云上VPC网段与线下数据中心网段重叠，导致IPsec VPN连通后路由不可达
- 扩容时新建子网未预留足够地址空间，后期业务增长需要更大的CIDR但已被相邻子网占用
- **规避**：创建VPC前绘制全局CIDR规划表，使用RFC 1918私有地址段并按业务域分片分配，预留至少30%的地址空间用于扩展

### 陷阱2：安全组规则冲突

- 多个安全组绑定同一ECS时，规则取并集，导致预期外的入方向放通，出现"明明没开放但能访问"的现象
- 安全组规则的优先级按方向和协议类型独立评估，用户误以为规则按行号从上到下匹配（实际无顺序概念，全部生效）
- 出方向默认全放通，入方向配置了严格限制，但ECS主动外联后回包被拒绝——实际不会，因为安全组有状态追踪，但用户常误配置出方向规则导致异常
- 不同安全组对同一端口的放通/拒绝规则共存时，放通优先，用户期望"拒绝优先"但实际为"白名单优先"
- **规避**：每个ECS绑定的安全组不超过3个，规则变更前使用流量仿真工具验证效果，定期审计安全组规则冗余和冲突

### 陷阱3：路由表环路

- 自定义路由表中配置了指向对等连接的路由，但对端VPC又配置了指回源VPC的路由，形成路由环路，数据包在两个VPC间循环直至TTL耗尽
- 传播路由与自定义路由目标冲突时，传播路由优先级低于自定义路由，但用户误以为传播路由会覆盖自定义路由
- 配置多个路由规则匹配同一目标网段时，最长前缀匹配规则生效，但用户未注意掩码长度导致流量走向与预期不符
- 双NAT网关场景下，路由表同时指向两个NAT网关，SNAT会话在不同网关间跳转导致连接中断
- **规避**：路由表变更前绘制路由拓扑图，使用路由追踪工具验证端到端可达性，避免在同一路由表中配置重叠目标网段

### 陷阱4：NAT网关SNAT耗尽

- NAT网关的SNAT端口池有限（每个EIP约65535个端口），高并发短连接场景下端口耗尽，新建连接失败
- 多个ECS共用同一NAT网关EIP时，SNAT端口竞争加剧，部分ECS随机出现连接超时
- 长连接业务未设置TCP Keepalive，NAT网关因连接空闲超时（默认900s）清理映射表，导致连接静默断开
- NAT网关规格（小型/中型/大型）与实际带宽/连接数不匹配，小规格网关在高流量下丢包
- **规避**：根据并发连接数选择NAT网关规格，启用TCP Keepalive保活长连接，高并发场景使用多个EIP做SNAT池扩展端口空间

### 陷阱5：对等连接不可路由

- 建立VPC对等连接后未在两端路由表中添加指向对等连接的路由规则，导致对等连接状态为"已接受"但流量不通
- 跨账号对等连接中，仅请求方配置了路由，接收方未配置路由，导致单向可达
- 对等连接两端的VPC网段重叠时，路由规则冲突导致流量无法正确转发，对等连接虽已建立但实际不可用
- 对等连接不支持传递路由：A-B、B-C建立对等连接，A无法通过B访问C，但用户期望中转路由可达
- **规避**：对等连接建立后立即在两端路由表添加路由规则，验证双向可达性，网段重叠时使用NAT或中转VPC解决，不依赖传递路由

## 二、性能优化（5项）

### 优化1：VPC网络吞吐优化

- 选择合适的VPC网络类型：默认网络 vs 增强型网络（基于SR-IOV），增强型网络提供更高带宽和更低延迟
- 对高吞吐业务（如大数据传输、视频流），使用增强型网卡（智能网卡）卸载网络处理，提升ECS网络PPS
- 合理规划子网大小，过大的子网（如/16）增加ARP表项和广播域，影响网络转发效率
- 跨可用区部署时使用增强型负载均衡（ELB），避免单可用区网络瓶颈
- 监控VPC流日志（Flow Log），识别流量热点并调整网络拓扑

### 优化2：安全组规则评估效率

- 减少安全组规则数量，每个安全组规则不超过50条，避免规则膨胀导致评估延迟增加
- 使用安全组引用（安全组互引）替代IP地址段规则，减少规则条目数并提升可维护性
- 合并相同方向的连续端口规则为端口范围（如22,80,443合并为多端口规则），减少规则评估次数
- 避免在安全组中使用0.0.0.0/0大范围放通后再逐条拒绝，应采用最小化白名单策略
- 定期清理无效规则（指向已释放EIP的规则、过期的临时规则），保持规则集精简

### 优化3：路由表查找优化

- 减少路由表中冗余路由条目，每个路由表规则数控制在100条以内
- 使用最长前缀匹配时，避免配置过多重叠网段的路由规则，增加查找深度
- 传播路由与自定义路由混合使用时，明确优先级关系，避免无效的传播路由增加查找开销
- 对等连接和VPN网关的路由优先级低于自定义路由，合理规划路由优先级层级
- 使用路由表关联多个子网时，评估子网数量对路由查找性能的影响

### 优化4：NAT网关并发优化

- 根据业务并发量选择NAT网关规格：小型（10000连接）、中型（50000连接）、大型（200000连接）
- 高并发场景使用多个EIP绑定同一NAT网关，扩展SNAT端口池（每个EIP约65535端口）
- 短连接密集型业务调整TCP TIME_WAIT超时参数，加速端口回收
- 启用DNAT规则时，合理规划端口映射范围，避免与SNAT端口池冲突
- 监控NAT网关的 `snat_connections` 和 `bandwidth_usage` 指标，及时扩容

### 优化5：对等连接带宽优化

- 对等连接带宽受限于两端VPC的带宽配额，跨区域对等连接需要额外购买云连接带宽
- 同区域内对等连接无带宽限制，但受两端ECS网络带宽约束，合理选择ECS网络规格
- 跨区域对等连接使用云连接（Cloud Connection）时，选择与业务流量匹配的带宽包规格
- 对等连接的流量计入两端VPC的流量配额，避免单侧带宽耗尽导致对等连接吞吐下降
- 对大流量对等连接场景，考虑使用专线（Direct Connect）替代，获得稳定低延迟的高带宽通道

## 三、安全加固（3项）

### 安全1：安全组过于宽松

- 安全组入方向规则包含0.0.0.0/0的22/3389端口放通，将SSH/RDP暴露在公网，成为暴力破解和勒索软件的入口
- 出方向默认全放通，ECS可任意访问外部地址，存在数据外泄和C2回连风险
- 安全组规则中使用了大范围CIDR（如10.0.0.0/8），实际仅需访问少数IP，违反最小权限原则
- 临时调试时添加的宽泛规则未及时清理，成为持久化的安全漏洞
- **加固**：入方向仅放通必要端口和来源IP，出方向限制为目标IP和端口，使用安全组模板统一管理，定期审计安全组规则

### 安全2：VPC流量镜像

- VPC流量镜像可将指定子网的流量复制到镜像目的，用于安全分析但也可被滥用进行流量窃听
- 镜像规则配置不当可能镜像全量流量，导致镜像目的端存储和计算资源过载
- 镜像流量未加密传输，中间人可截获镜像数据获取敏感信息
- 流量镜像的权限控制不足，非安全团队也可创建镜像规则
- **加固**：严格限制流量镜像的创建权限，仅安全运营团队可操作，镜像流量使用TLS加密，定期审查镜像规则

### 安全3：网络ACL配置

- 网络ACL是无状态的，入方向和出方向规则独立评估，用户常忘记配置回包规则导致连接异常
- ACL规则按优先级从低到高匹配，首条匹配生效，与安全组的"全部规则叠加"逻辑不同，容易混淆
- ACL与安全组同时使用时，流量需同时通过两层检查，配置不当导致合法流量被拒绝
- ACL规则优先级设置混乱，低优先级的拒绝规则被高优先级的放通规则覆盖，安全策略形同虚设
- **加固**：ACL用于子网级别的粗粒度隔离，安全组用于实例级别的细粒度控制，两者配合使用但避免规则冲突，变更前在测试环境验证

## 四、故障排查（5项）

### 故障1：子网IP耗尽

- **现象**：ECS创建失败，报错 `Insufficient free IPs in subnet`，但子网看似还有可用地址
- **排查步骤**：
  1. 查看子网详情中的 `total_ips` 和 `used_ips`，确认剩余可用IP数
  2. 检查是否有已停止的ECS占用IP（按需ECS停止后仍占用IP，包周期ECS可释放IP）
  3. 查看子网中是否有预留IP（系统保留4个IP：网络地址、网关、广播地址、DHCP）
  4. 检查负载均衡器、NAT网关、VPN网关等资源是否占用子网IP
  5. 确认子网CIDR是否足够大，是否存在碎片化IP分配
- **处置**：清理不再需要的ECS释放IP，或创建新子网扩展地址空间，长期方案是规划更大的CIDR

### 故障2：安全组未生效

- **现象**：安全组规则配置正确但流量仍被放通或拒绝，与预期不符
- **排查步骤**：
  1. 确认ECS绑定的安全组是否为预期的安全组，可能绑定了多个安全组导致规则叠加
  2. 检查ACL规则是否与安全组规则冲突（ACL拒绝优先于安全组放通）
  3. 查看安全组规则的方向（入/出）和协议类型是否匹配实际流量
  4. 确认安全组规则的远端是否配置正确（IP地址段或安全组引用）
  5. 检查ECS内部防火墙（iptables/firewalld）是否与安全组规则冲突
- **处置**：调整安全组规则或ACL规则消除冲突，确保ECS内部防火墙与安全组策略一致

### 故障3：路由不可达

- **现象**：两个子网间或VPC与外部网络间无法通信，ping不通或TCP连接超时
- **排查步骤**：
  1. 检查源和目标是否在同一VPC内，同VPC不同子网默认互通
  2. 查看路由表中是否有指向目标网段的路由规则
  3. 确认路由下一跳（对等连接/NAT网关/VPN网关/ECS）是否正常工作
  4. 检查安全组和ACL是否放通了相关流量
  5. 使用VPC流日志分析丢包位置和原因
- **处置**：添加缺失的路由规则，修复下一跳资源，调整安全组/ACL规则放通流量

### 故障4：NAT网关故障

- **现象**：VPC内ECS无法访问公网，或公网无法通过DNAT访问VPC内服务
- **排查步骤**：
  1. 检查NAT网关状态是否为 `ACTIVE`，是否绑定EIP
  2. 查看路由表中是否有指向NAT网关的0.0.0.0/0路由
  3. 确认SNAT规则是否配置了正确的子网和EIP
  4. DNAT场景检查端口映射规则是否正确（协议、端口、后端ECS）
  5. 查看NAT网关的连接数和带宽是否达到规格上限
- **处置**：修复路由和SNAT/DNAT规则，升级NAT网关规格，或增加EIP扩展端口池

### 故障5：对等连接不通

- **现象**：VPC对等连接状态为"已接受"，但两端ECS无法互相访问
- **排查步骤**：
  1. 确认两端VPC的路由表中是否添加了指向对等连接的路由规则
  2. 检查对等连接两端的VPC网段是否重叠（重叠则路由冲突）
  3. 验证安全组和ACL是否放通了对等连接的流量
  4. 跨账号对等连接确认接收方已接受请求并配置了路由
  5. 跨区域对等连接确认云连接带宽包是否已配置且带宽充足
- **处置**：在两端路由表添加路由规则，解决网段重叠问题（重新规划CIDR或使用NAT），调整安全组/ACL放通流量

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云VPC | 自建SDN（如OpenStack Neutron） | 物理网络隔离 |
|------|-----------|-------------------------------|-------------|
| **隔离级别** | 逻辑隔离（VXLAN/租户VNI） | 逻辑隔离（VXLAN/GRE） | 物理隔离（独立交换机/线缆） |
| **部署周期** | 秒级（API创建） | 小时级~天级（需部署SDN控制器） | 天级~周级（物理布线） |
| **弹性能力** | 随时创建/删除子网和路由 | 依赖SDN控制器和底层网络 | 无弹性，需物理扩容 |
| **运维复杂度** | 托管运维，用户仅需配置 | 需运维SDN控制器和虚拟交换机 | 需运维物理网络设备 |
| **成本模型** | 按流量和组件计费 | 软件免费，硬件和运维成本高 | 一次性CAPEX极高 |
| **网络性能** | 虚拟化开销，万兆共享 | 取决于SDN实现，可优化 | 线速转发，性能最优 |
| **多租户支持** | 原生支持，租户间完全隔离 | 需配置，隔离性取决于SDN | 物理隔离，天然多租户 |
| **适用场景** | 云原生业务、混合云 | 私有云、需要灵活网络策略 | 极高安全要求、低延迟交易 |
| **SLA** | 99.95% | 自定义 | 自定义 |
| **跨地域互通** | 云连接/对等连接原生支持 | 需自建Overlay隧道 | 需专线互联 |

### 选择建议

- **选择VPC**：云原生业务、需要快速部署和弹性伸缩、混合云组网场景，利用云上托管网络降低运维成本
- **选择自建SDN**：私有云部署、需要深度定制网络策略、已有OpenStack等云平台基础架构
- **选择物理网络隔离**：金融交易等极低延迟场景、军工/政府等强制物理隔离要求、超大规模数据中心

## 六、已知限制（≥3项）

1. **子网不可跨可用区**：子网创建时绑定单个可用区，创建后不可变更可用区，如需多可用区部署需创建多个子网

2. **对等连接不传递路由**：VPC对等连接不支持传递路由，A与B、B与C分别建立对等连接，A不能通过B访问C，需使用云连接或企业路由器实现传递路由

3. **安全组规则数量限制**：每个安全组默认最多100条规则，每个ECS最多绑定5个安全组，规则总数上限500条，复杂网络策略需拆分为多个安全组

4. **VPC创建后网段不可变更**：VPC的CIDR在创建后不可修改，如需变更需重建VPC并迁移所有资源，操作风险和成本极高

5. **NAT网关不支持IPsec VPN**：NAT网关仅提供SNAT/DNAT功能，不支持VPN网关的IPsec功能，两者需分别部署

6. **网络ACL无状态**：网络ACL是无状态的，入方向放通的流量其回包需在出方向单独配置规则，与安全组的有状态行为不同，容易遗漏回包规则
