# 华为云BMS（裸金属服务器）场景模板

## 概述

华为云裸金属服务器（Bare Metal Server, BMS）提供专属物理服务器，兼具云上弹性与物理机性能，适用于高性能计算、大数据、核心数据库等场景。本模板覆盖裸金属创建、镜像管理、网络配置、高性能计算及安全加固等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：镜像格式不兼容

- BMS仅支持特定镜像格式（QCOW2/ZVMD），直接上传RAW或其他格式镜像会导入失败，且错误提示不明确
- 外部导入镜像时，未安装bms-network-config和cloud-init工具导致网络配置和初始化失败
- 镜像大小超过系统盘容量时创建失败，但错误信息仅提示"创建失败"无具体原因
- 使用公共镜像创建BMS时，部分公共镜像仅支持ECS不支持BMS，界面过滤不完善容易误选
- **规避**：使用华为云官方BMS公共镜像作为基础，自定义镜像时确保安装 `bms-network-config`、`cloud-init` 和 `onecloud-resetPwd` 插件

### 陷阱2：网络配置超时

- BMS网络配置依赖DHCP获取地址，裸金属服务器启动较慢（5~15分钟），DHCP超时导致网络不通
- 多网卡场景下，未正确配置策略路由导致第二块网卡流量无法返回，表现为"能ping通但业务不通"
- SR-IOV直通网卡需在镜像中预装对应驱动（Mellanox/Intel），否则VF设备无法识别
- VPC安全组规则在BMS上通过iptables/ebtables实现，规则数量过多（>200条）导致网络性能严重下降
- **规避**：BMS创建后等待状态变为 `ACTIVE` 再配置网络，多网卡使用 `nmcli` 配置策略路由，提前安装SR-IOV驱动

### 陷阱3：RAID配置错误

- BMS创建时选择RAID级别后不可在线修改，选错RAID级别只能重建服务器
- RAID0虽性能最高但无冗余，单盘故障导致全部数据丢失，生产环境误用RAID0风险极大
- 部分BMS规格的RAID控制器不支持RAID5/6，创建时选择了不支持的级别导致失败
- 系统盘做了RAID1后可用空间减半，但用户按单盘容量规划导致空间不足
- **规避**：创建前确认BMS规格支持的RAID级别，生产环境使用RAID1/10，大数据场景用RAID5/6，仅临时数据用RAID0

### 陷阱4：固件版本冲突

- BMS固件（BIOS/BMC）版本与镜像内核不兼容，导致启动异常或硬件特性不可用
- 升级BMC固件后IPMI连接方式变更，原有的带外管理脚本失效
- 不同批次的BMS硬件微差异（如网卡型号迭代）导致同一镜像在不同批次服务器上行为不一致
- 固件自动升级可能在维护窗口触发服务器重启，未做业务切换导致服务中断
- **规避**：创建BMS后记录固件版本，升级前在测试环境验证兼容性，生产环境关闭自动固件升级

### 陷阱5：弹性不足

- BMS不支持热迁移，系统盘扩容需关机，业务中断不可避免
- BMS创建周期长（5~15分钟），无法像ECS一样秒级扩容应对突发流量
- BMS不支持规格变更（变配），性能不足时只能新建更高规格服务器并迁移数据
- BMS不支持抢占式实例，成本优化手段有限
- **规避**：将无状态计算层放在ECS/容器上弹性伸缩，BMS仅用于数据库/HPC等必须物理机性能的场景，通过分层架构弥补弹性不足

## 二、性能优化（5项）

### 优化1：磁盘IO优化

- 根据业务IO模式选择存储方案：顺序IO大块用本地HDD RAID0/10，随机IO小块用NVMe SSD
- 使用NVMe本地盘时，开启 `io_uring` 减少系统调用开销，相比传统libaio提升15%~30%吞吐
- RAID控制器开启WriteBack缓存模式（需BBU/电容保护），写入性能提升3~5倍
- 文件系统选择：XFS适合大文件顺序读写，Ext4适合小文件随机读写，数据库场景考虑裸设备
- 调整IO调度器：NVMe SSD使用 `none`/`noop`，HDD使用 `mq-deadline`，避免默认的 `cfq` 导致延迟波动

### 优化2：网络SR-IOV

- 启用SR-IOV将物理网卡VF直通给BMS，绕过虚拟交换机，网络延迟降低30%~50%
- 高性能网络场景选择支持SR-IOV的BMS规格（如带Mellanox ConnectX-5/6网卡）
- SR-IOV VF数量有限（通常64~128个），规划时需预留VF给管理网络
- 启用SR-IOV后安全组规则不在VF上生效，需在物理交换机或BMS内部通过iptables实现
- 使用DPDK框架配合SR-IOV实现用户态网络处理，单核转发性能可达10Mpps以上

### 优化3：GPU直通

- GPU型BMS（如pi2/pir2规格）支持GPU直通，CUDA/MPI应用直接访问GPU硬件
- 安装NVIDIA驱动和CUDA Toolkit版本需与GPU型号匹配，版本不兼容导致GPU不可用
- 多GPU场景使用NVLink/NVSwitch互联时，确保BMS规格支持对应拓扑，避免走PCIe Switch导致带宽瓶颈
- 监控GPU利用率（`nvidia-smi`），当 `gpu_util` 持续低于30%时考虑调整任务调度策略
- GPU显存不足时使用统一内存（Unified Memory）或梯度检查点技术，而非简单增加GPU数量

### 优化4：HPC调度优化

- 使用Slurm/PBS等HPC调度器管理BMS集群，避免资源空闲或过度争抢
- MPI任务使用HC/IB网络（如100Gb RoCEv2），相比普通TCP网络延迟降低10倍
- MPI进程绑定到物理核（`mpirun -bind-to core`），避免进程在核间迁移导致缓存失效
- HPC任务数据使用Burst Buffer（NVMe SSD缓存层）加速，减少对并行文件系统的压力
- 配置MPI集合通信算法（如NCCL的Ring/Tree算法），根据集群规模和拓扑选择最优算法

### 优化5：内存带宽优化

- NUMA感知的内存分配：使用 `numactl --preferred=node` 将进程绑定到本地NUMA节点
- 大页内存（HugePages）减少TLB miss：2MB大页适合一般HPC，1GB大页适合数据库
- 内存带宽敏感型应用（如矩阵运算）避免跨NUMA访问，跨NUMA带宽下降40%~60%
- 使用 `perf stat -e cache-misses,cache-references` 监控缓存命中率，低于90%需优化数据布局
- 对内存密集型任务，适当降低每核分配的进程数，避免L3缓存争抢

## 三、安全加固（3项）

### 安全1：物理访问控制

- BMS的IPMI/BMC带外管理口必须放置在独立管理网络，禁止暴露到公网
- BMC默认密码必须在首次登录后修改，使用12位以上包含大小写字母+数字+特殊字符的强密码
- 启用BMC的SSH密钥认证，禁用密码登录，限制管理IP段访问
- 定期审计BMC访问日志，检测异常登录尝试（如非工作时间、非授权IP）
- 如无需远程带外管理，在安全组中关闭BMC端口（623/UDP IPMI、443/TCP BMC WebUI）

### 安全2：固件安全加固

- 定期检查并升级BIOS/BMC固件，修复已知CVE漏洞（如IPMI漏洞CVE-2019-6260）
- 禁用BIOS中不必要的启动选项（如USB启动、PXE网络启动），防止物理攻击
- 启用Secure Boot功能，确保仅加载经数字签名的内核和驱动
- 禁用BIOS中的SMM（系统管理模式）调试接口，防止SMM级别的恶意代码注入
- 建立固件版本基线，每次升级前后对比固件哈希值，防止供应链攻击

### 安全3：BMC漏洞防护

- IPMI协议本身存在安全缺陷（如RAKP认证漏洞），BMC必须部署在隔离网络
- 禁用IPMI v1.5，仅使用IPMI v2.0+，并启用加密通信
- BMC固件升级包必须从华为云官方渠道获取，验证数字签名后再升级
- 对BMC WebUI启用HTTPS，禁用HTTP明文访问，配置证书为受信CA签发
- 监控BMC异常行为：非预期的重启、固件变更、用户创建等，接入SIEM实时告警

## 四、故障排查（5项）

### 故障1：启动失败

- **现象**：BMS创建后状态长时间停留在 `BUILD` 或变为 `ERROR`
- **排查步骤**：
  1. 查看BMS详情页的 `fault` 字段获取错误原因
  2. 检查镜像是否为BMS支持的格式且已安装必要驱动
  3. 通过BMC IPMI查看服务器启动日志（`sol activate`），定位卡在哪个阶段
  4. 检查是否因资源不足导致调度失败（目标机柜无空闲位置）
  5. 查看系统日志 `/var/log/messages` 确认内核启动阶段是否有panic
- **处置**：更换镜像、检查驱动兼容性、提交工单处理硬件调度问题

### 故障2：网络不通

- **现象**：BMS创建成功但无法SSH连接，ping不通
- **排查步骤**：
  1. 检查安全组是否放行了SSH（22端口）和ICMP协议
  2. 通过VNC控制台登录BMS，检查网卡是否获取到IP地址（`ip addr`）
  3. 检查路由表（`ip route`），确认默认路由指向正确网关
  4. 多网卡场景检查策略路由是否配置（`ip rule list`）
  5. 检查iptables规则是否阻止了入站流量
- **处置**：修复安全组规则、配置DHCP/静态IP、添加缺失的路由或策略路由

### 故障3：磁盘IO异常

- **现象**：磁盘IO延迟突然升高，`iostat` 显示 `%util` 接近100%或 `await` 超过50ms
- **排查步骤**：
  1. 使用 `iostat -xz 1` 查看各磁盘的IO统计，定位具体是哪块盘
  2. 检查RAID控制器状态（`storcli64 show`），是否有盘降级或重建
  3. 查看是否有大量随机IO（`iostat` 的 `rrqm/s` 和 `wrqm/s` 比值）
  4. 检查是否触发了磁盘故障预警（SMART属性异常）
  5. 使用 `iotop` 查看哪个进程占用IO最多
- **处置**：RAID重建期间IO性能会下降（属正常现象），坏盘需提交工单更换，优化应用IO模式

### 故障4：GPU驱动问题

- **现象**：`nvidia-smi` 报错或GPU设备不可见
- **排查步骤**：
  1. 检查GPU设备是否被内核识别（`lspci | grep -i nvidia`）
  2. 查看内核日志是否有GPU驱动相关错误（`dmesg | grep -i nvidia`）
  3. 确认NVIDIA驱动版本与GPU型号兼容（`cat /proc/driver/nvidia/version`）
  4. 检查CUDA版本与驱动版本的兼容性矩阵
  5. 确认GPU功耗限制是否正常（`nvidia-smi -q -d POWER`），异常低功耗可能是硬件故障
- **处置**：重新安装匹配版本的GPU驱动，清理旧驱动残留（`nvidia-uninstall`），必要时提交工单更换GPU

### 故障5：电源故障

- **现象**：BMS意外关机或重启，BMC日志记录电源异常
- **排查步骤**：
  1. 通过IPMI查看SEL日志（`ipmitool sel list`），确认是否有电源相关事件
  2. 检查BMS是否配置了UPS，市电波动可能导致意外关机
  3. 查看功耗统计（`ipmitool dcmi power reading`），是否超过电源额定功率
  4. 高负载场景下CPU/GPU功耗突增触发过流保护
  5. 检查机柜PDU是否正常，多台BMS同时高负载可能超过PDU容量
- **处置**：降低业务负载避免过流、确保UPS供电、联系华为云更换故障电源模块

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云BMS（裸金属服务器） | 华为云ECS（弹性云服务器） | 华为云DEH（专属主机） |
|------|--------------------------|--------------------------|----------------------|
| **性能** | 原生物理机性能，无虚拟化损耗 | 共享物理机，有虚拟化开销（3%~8%） | 物理隔离但仍有虚拟化层 |
| **弹性** | 创建5~15分钟，不支持热迁移 | 秒级创建，支持热迁移和规格变更 | 分钟级，支持ECS热迁移 |
| **存储** | 本地盘+云硬盘，支持RAID | 仅云硬盘（部分规格带本地盘） | 云硬盘为主 |
| **网络** | SR-IOV/DPDK支持，最高100GbE | 普通虚拟网络，最高25GbE | 同ECS |
| **GPU** | GPU直通，原生CUDA性能 | vGPU共享，性能有损耗 | 不支持GPU型 |
| **计费** | 按需/包月，价格较高 | 按需/包月/抢占式，灵活 | 按主机包月 |
| **运维** | 需自行管理OS/RAID/固件 | OS管理为主，硬件由华为负责 | OS管理为主 |
| **合规** | 物理隔离，满足高合规要求 | 多租户共享，合规受限 | 主机级物理隔离 |
| **适用场景** | HPC/GPU/核心数据库/大数据 | Web/微服务/中间件/通用计算 | 合规隔离+弹性兼顾 |
| **SLA** | 99.95% | 99.95% | 99.95% |

### 选择建议

- **选择BMS**：需要原生物理机性能（HPC/GPU计算、核心数据库、大数据分析），或合规要求不允许虚拟化层
- **选择ECS**：通用业务计算、Web服务、微服务架构，需要弹性伸缩和成本优化
- **选择DEH**：需要物理隔离满足合规要求，但业务仍以虚拟化方式运行，兼顾隔离与弹性

## 六、已知限制（≥3项）

1. **创建周期长**：BMS创建需要5~15分钟（含硬件初始化、RAID配置、OS安装），远慢于ECS的秒级创建，不适合需要快速弹性扩容的场景

2. **不支持规格变更**：BMS创建后CPU/内存/磁盘规格不可变更（不支持变配），性能不足时只能新建更高规格BMS并迁移数据，迁移过程涉及业务中断

3. **不支持热迁移**：BMS不支持在线热迁移，维护窗口或硬件故障时必须停机处理，需要通过应用层高可用架构（如数据库主从切换）来保障业务连续性

4. **本地盘数据风险**：带本地盘的BMS，本地盘数据不参与云硬盘的快照/备份，服务器释放或硬件故障后本地盘数据不可恢复，关键数据必须存放在云硬盘或定期备份

5. **镜像限制严格**：BMS自定义镜像必须安装 `bms-network-config`、`cloud-init` 等必需组件，且仅支持QCOW2/ZVMD格式，外部导入流程复杂且易出错

6. **安全组性能损耗**：BMS安全组通过iptables/ebtables在OS内部实现，规则数量过多（>200条）会导致网络性能显著下降，与ECS的安全组硬件卸载实现不同

7. **GPU型BMS区域限制**：GPU型BMS（pi2/pir2等规格）仅在部分区域可用，且GPU型号和数量配置不可变更，跨区域不可迁移
