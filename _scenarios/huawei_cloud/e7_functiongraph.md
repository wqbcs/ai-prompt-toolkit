# 华为云FunctionGraph（函数工作流）场景模板

## 概述

华为云 FunctionGraph 是事件驱动的 Serverless 计算服务，支持函数创建、触发器配置、工作流编排、冷启动优化与监控告警。本模板覆盖 Serverless 架构从开发到生产的关键场景，帮助团队规避 FaaS 常见陷阱并构建高效可靠的函数应用。

---

## 一、常见陷阱（5项）

### 陷阱1：冷启动延迟过高

- 函数长时间未调用后首次执行需加载运行时和代码，Java/Spring 函数冷启动可达 5~15s，严重影响用户体验
- 函数依赖包过大（如引入整个 AWS SDK），冷启动时解压和加载耗时长，Python 函数也可能达到 3~5s
- VPC 配置的函数冷启动更慢：需额外分配 ENI 和配置网络，延迟增加 1~3s
- 冷启动时间随代码体积线性增长但用户缺乏感知，直到线上投诉才暴露问题
- **规避**：使用轻量运行时（Node.js/Python 优先于 Java）；精简依赖包；预留实例消除冷启动；VPC 函数使用 VPC 访问通道

### 陷阱2：函数超时

- 函数默认超时时间 3 秒，长时间处理任务（如文件转码、大数据聚合）频繁超时
- 函数内同步调用外部 API 但未设置连接超时和读取超时，外部服务卡住导致函数超时
- 递归或循环处理大量数据时未做分片，单次调用处理时间超出函数最大超时限制（900秒）
- 函数超时后被强制终止但部分副作用已执行（如数据库写入了一半），导致数据不一致
- **规避**：合理设置超时时间；外部调用设置独立的连接/读取超时；大任务拆分为多次调用；关键操作使用幂等设计

### 陷阱3：触发器配置错误

- OBS 触发器配置的文件前缀/后缀过滤条件错误，导致不匹配的事件也触发函数执行
- APIG 触发器未配置鉴权，函数 API 裸露在公网，任何人可调用产生费用
- DIS/Kafka 触发器的批处理大小设置过大，单次拉取过多消息导致函数超时或 OOM
- 多个触发器绑定同一函数但未区分事件来源，函数内无法正确处理不同触发源的事件格式
- **规避**：严格配置触发器过滤条件；APIG 触发器必须启用鉴权；批处理大小 ≤ 函数内存/超时的安全阈值；函数内解析事件源字段

### 陷阱4：工作流编排死循环

- 函数工作流（Workflow）中步骤的跳转条件配置错误，A步骤完成后又跳回A，形成无限循环
- 工作流的循环计数器未设置上限，异常数据导致循环不终止，工作流执行时间和费用持续增长
- 工作流步骤间的数据传递格式不一致，某步骤解析失败后进入错误处理分支又跳回原步骤
- 并行步骤的某个分支持续失败，重试策略配置为无限重试，导致工作流永远无法完成
- **规避**：所有循环必须设置最大迭代次数；重试策略配置最大重试次数和退避间隔；并行步骤设置超时和失败策略；工作流总执行时间设上限

### 陷阱5：监控盲区

- 函数执行失败但未配置 DLQ（死信队列），失败事件丢失无法追溯和重试
- 函数内部异常被 catch 后静默处理，外部监控显示调用成功但业务逻辑实际未执行
- 工作流编排的子步骤失败但工作流整体状态显示成功（错误处理跳转到成功节点）
- 函数并发执行数达到配额上限被限流，但监控仅显示调用次数不显示限流次数
- **规避**：配置 DLQ 收集失败事件；函数内异常必须上报日志或抛出；工作流失败步骤标记明确状态；监控限流指标（ThrottledInvocations）

## 二、性能优化（5项）

### 优化1：冷启动预热优化

- 配置预留实例：对延迟敏感的核心函数设置最小实例数 ≥ 1，消除冷启动延迟（费用按预留时长计费）
- 使用 Provisioned Concurrency 预初始化函数实例，请求到达时直接执行，延迟降至 < 100ms
- 预热策略：通过定时触发器（如每 5 分钟）发送预热请求保持实例活跃，成本低于预留实例
- 代码优化：延迟初始化（Lazy Load）非必要模块，减少冷启动时的加载量；全局变量缓存复用
- 运行时选择：冷启动速度 Node.js > Python > Java；对冷启动敏感场景避免使用 Java/Spring

### 优化2：函数执行效率

- 利用函数执行上下文复用：全局变量/连接池在热调用间复用，避免每次调用重新初始化
- 数据库连接使用连接池（如 Python 的 SQLAlchemy QueuePool），热调用复用连接减少建连开销
- 函数代码中使用流式处理替代全量加载：大文件使用流式读写（OBS 分段上传/下载），避免 OOM
- CPU 密集型函数选择更大内存规格：FunctionGraph 的 CPU 与内存正相关，更大内存 = 更多 CPU
- 避免在函数内做繁重的序列化/反序列化，使用 Protobuf/MessagePack 替代 JSON

### 优化3：触发器吞吐优化

- OBS 触发器使用事件通知而非轮询，事件驱动模式下延迟 < 1s，轮询模式延迟取决于轮询间隔
- Kafka/DIS 触发器增大批处理大小（如 100~500 条/批），减少函数调用次数，提升吞吐
- APIG 触发器启用缓存策略，对幂等 GET 请求设置缓存 TTL，减少函数调用次数
- SMN 触发器使用消息过滤，仅订阅感兴趣的事件类型，避免无关事件触发无效函数调用
- 定时触发器避免全量扫描，结合增量标记（如 OBS 最后修改时间）仅处理新增数据

### 优化4：工作流并行度调优

- 工作流并行步骤数设为 5~20：过少无法充分利用并发，过多增加调度开销和出错概率
- Map 状态的并发度根据下游服务承受能力设置：如写入数据库的并发数 ≤ 连接池大小
- 并行步骤使用分片策略：将大数据集拆分为 N 个分片，每个分片一个并行任务，避免单个任务过重
- 工作流步骤间传递精简数据：仅传递必要参数和引用（如 OBS 路径），避免传递大 payload
- 对 IO 密集型步骤使用异步等待模式，释放工作流执行资源，避免长时间占用步骤

### 优化5：预留实例策略

- 对核心业务函数配置预留实例，预留数量 = 峰值 QPS × P99 延迟（秒）÷ 单实例并发数
- 使用按指标伸缩的预留实例策略：日常保持低预留，CPU/并发率超阈值自动扩容预留
- 非核心函数不配置预留实例，利用按需实例 + 预热策略控制冷启动
- 预留实例的内存规格选择最优性价比：先压测确定函数实际内存使用量，预留实例选择 1.2~1.5 倍
- 定期审查预留实例利用率：利用率 < 30% 的预留实例考虑降配或取消

## 三、安全加固（3项）

### 安全1：函数执行权限越权

- 函数的 IAM 代理权限遵循最小权限原则：仅授予函数实际需要的 OBS/DDS/Redis 等服务权限
- 不同函数使用不同的 IAM 代理，避免多个函数共享一个过大的权限集
- 函数内禁止使用硬编码的 AK/SK 访问华为云服务，统一使用 IAM 代理认证
- 定期审计函数权限配置：检查是否存在 `*.*` 通配符权限，收敛到具体资源和操作
- 对特权操作（如删除资源、修改配置）的函数配置双重授权：IAM 代理 + 运行时参数校验

### 安全2：触发器注入攻击

- APIG 触发器必须配置鉴权（IAM Token / 自定义认证），禁止匿名访问
- 函数入口严格校验输入参数：类型检查、长度限制、特殊字符过滤，防止注入攻击
- OBS 触发器事件中提取的文件名/路径不得直接用于文件操作，必须校验路径合法性防止路径穿越
- 对用户上传的内容（如通过 APIG 触发器传入的 JSON）做 schema 校验，拒绝不符合预期的输入
- 函数日志中禁止输出完整的请求 payload（可能含敏感信息），脱敏后记录

### 安全3：工作流数据泄露

- 工作流步骤间传递的数据通过加密通道传输，敏感数据使用 KMS 加密后传递
- 工作流执行历史记录中的步骤输入/输出默认保留 7 天，敏感数据应在步骤内清除
- 工作流的 OBS 触发文件存储在私有桶中，配置桶策略限制访问范围
- 工作流执行角色的权限限制在必要资源范围内，禁止跨项目/跨服务访问
- 工作流调试日志关闭后再上线生产，避免在日志中暴露步骤间传递的敏感中间数据

## 四、故障排查（5项）

### 故障1：函数执行超时

- **现象**：函数执行达到超时时间后被强制终止，返回超时错误
- **排查步骤**：
  1. 查看函数执行日志，确认卡在哪个步骤（外部调用/数据处理/文件IO）
  2. 检查外部服务响应时间：函数内调用的 API/数据库是否延迟过高
  3. 检查数据量是否超出预期：单次处理的数据量是否过大
  4. 检查函数内存是否足够：内存不足导致频繁 GC，执行变慢
  5. 检查是否存在死循环或阻塞操作：如无限重试、锁等待
- **处置**：增加超时时间/优化外部调用/拆分数据处理/增大函数内存/修复逻辑错误

### 故障2：触发器未触发

- **现象**：事件发生后函数未被调用，触发器似乎不工作
- **排查步骤**：
  1. 检查触发器状态：是否启用，最近触发时间
  2. OBS 触发器：检查文件路径是否匹配前缀/后缀过滤条件，检查事件类型是否匹配
  3. APIG 触发器：检查 API 发布状态，是否部署到正式环境
  4. 定时触发器：检查 cron 表达式是否正确，时区是否匹配
  5. 检查函数并发配额：是否因并发已满导致新触发被限流
- **处置**：修正触发器过滤条件/发布 API/修正 cron 表达式/提升并发配额

### 故障3：工作流卡住

- **现象**：工作流执行长时间处于 Running 状态，不前进也不失败
- **排查步骤**：
  1. 查看工作流执行详情：当前卡在哪个步骤
  2. 检查卡住步骤的子函数执行状态：是否在等待/超时/死循环
  3. 检查并行步骤是否有分支失败但未配置失败策略
  4. 检查步骤跳转条件：是否存在循环跳转但无退出条件
  5. 检查工作流执行的步骤输入数据：是否因数据格式错误导致解析卡住
- **处置**：终止卡住的工作流执行/修复跳转条件/配置步骤超时/修正数据格式

### 故障4：冷启动抖动

- **现象**：函数偶尔出现高延迟（P99 远高于 P50），延迟分布呈双峰特征
- **排查步骤**：
  1. 统计函数调用延迟分布：区分冷启动调用和热启动调用
  2. 检查冷启动频率：函数的调用间隔是否超过实例保活时间（约 10~30 分钟）
  3. 检查 VPC 配置：VPC 函数冷启动额外延迟 1~3s
  4. 检查代码包大小：大依赖包解压耗时更长
  5. 检查初始化逻辑：全局初始化是否耗时过长（如加载大模型文件）
- **处置**：配置预留实例/启用预热策略/精简依赖/优化初始化逻辑/VPC 函数使用访问通道

### 故障5：日志采集缺失

- **现象**：函数执行日志部分丢失或完全不可见
- **排查步骤**：
  1. 检查函数日志配置：是否关联了 LTS 日志组/日志流
  2. 检查日志打印方式：是否使用了运行时标准输出（自动采集）而非自定义日志文件
  3. 检查日志量是否过大：单次调用日志超过 10KB 可能被截断
  4. 检查函数是否被限流：限流的调用可能不产生完整日志
  5. 检查 LTS 日志流配额：是否超过日志写入速率限制
- **处置**：关联 LTS 日志组/使用标准输出打印日志/精简日志内容/提升 LTS 配额

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云FunctionGraph | AWS Lambda | 自建FaaS |
|------|-------------------|-----------|---------|
| **运行时支持** | Node.js/Python/Java/Go/PHP | Node.js/Python/Java/Go/C#/Ruby | 自定义任意语言 |
| **最大执行时间** | 900秒（15分钟） | 900秒（15分钟） | 无限制（取决于部署方式） |
| **冷启动** | VPC函数较慢，非VPC 100ms~3s | VPC函数较慢，Provisioned Concurrency可消除 | 完全可控（常驻进程模式无冷启动） |
| **工作流编排** | 内置工作流（Function Graph） | Step Functions | 自建（Argo/Cadence/Temporal） |
| **触发器生态** | OBS/SMN/DIS/Kafka/APIG/Timer | S3/SNS/Kinesis/DynamoDB/API GW/EventBridge | 自建事件总线 |
| **VPC集成** | 支持，冷启动额外延迟 | 支持，冷启动额外延迟 | 原生内网访问 |
| **计费模型** | 按调用次数+执行时长+内存 | 按请求次数+执行时长+内存 | 服务器成本（按需/包月） |
| **免费额度** | 每月100万次调用+40万GBs | 每月100万次调用+40万GBs | 无 |
| **SLA** | 99.95% | 99.95% | 自定义 |
| **适用场景** | 华为云生态/国内合规 | AWS生态/海外部署 | 完全定制化/长时任务 |

### 选择建议

- **选择FunctionGraph**：华为云深度用户、国内合规要求、需要与OBS/SMN/DIS深度集成
- **选择Lambda**：AWS生态深度用户、海外业务部署、需要Step Functions成熟的工作流编排
- **选择自建FaaS**：需要自定义运行时、长时任务（> 15分钟）、完全控制冷启动策略、成本敏感型高频调用场景

## 六、已知限制（≥3项）

1. **执行时长上限**：函数单次执行最大超时 900 秒（15 分钟），超过此限制的任务无法使用 FunctionGraph，需拆分为工作流或改用 CCE/CCI

2. **代码包大小限制**：函数代码包（含依赖）最大 500MB（解压后），超大依赖（如 PyTorch）需通过 OBS 挂载或自定义镜像方式加载

3. **并发配额限制**：单函数默认最大并发 1000，单账号默认最大并发 3000，高并发场景需提前申请提额，审批周期 1~3 个工作日

4. **VPC 函数冷启动**：配置了 VPC 访问的函数冷启动额外延迟 1~3 秒（需分配 ENI），对延迟敏感场景建议使用 VPC 访问通道或预留实例

5. **工作流步骤数限制**：单工作流最大支持 100 个步骤，复杂业务流程需拆分为多个子工作流，步骤间的数据传递仅支持 JSON 格式且大小限制 32KB
