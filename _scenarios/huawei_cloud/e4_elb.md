# 华为云ELB（弹性负载均衡）场景模板

## 概述

华为云弹性负载均衡（Elastic Load Balance, ELB）将访问流量自动分发到多台后端服务器，支持四层（TCP/UDP）和七层（HTTP/HTTPS）负载均衡，提供健康检查、会话保持、SSL卸载等能力。本模板覆盖负载均衡器创建、监听器配置、后端服务器组、健康检查及会话保持等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：监听器配置错误

- 七层监听器（HTTP/HTTPS）配置了四层才支持的功能（如UDP监听），或反之，导致配置不生效
- HTTPS监听器未选择SSL证书或选择了已过期证书，创建监听器成功但业务流量不通
- 监听器前端端口与后端端口混淆：前端端口是客户端访问端口，后端端口是后端服务器监听端口，两者可以不同但极易配反
- 监听器的空闲连接超时时间（idle_timeout）设置过短，长连接业务（WebSocket、数据库连接池）频繁断开
- **规避**：创建监听器前明确协议栈（四层/七层）和前后端端口映射，HTTPS监听器提前准备有效证书，长连接业务设置idle_timeout ≥ 300秒

### 陷阱2：后端服务器权重不均

- 后端服务器权重默认均为1，但服务器规格不同（如4核vs8核），导致低规格服务器过载
- 权重设置为0时服务器不接收新连接但现有连接保持，误以为权重0等于移除
- 动态调整权重时未考虑会话保持的影响，部分会话持续路由到高权重服务器导致负载不均
- 后端服务器组中混合了不同可用区的服务器，未启用跨可用区负载均衡导致流量倾斜
- **规避**：根据服务器规格比例设置权重（4核:8核 = 1:2），权重调整后观察5~10分钟流量分布，启用"加权最少连接"算法替代轮询

### 陷阱3：健康检查过于敏感

- 健康检查间隔过短（如5秒）+ 不健康阈值过低（如2次），网络抖动导致后端服务器频繁被标记为不可用
- 健康检查路径返回200但响应体不符合业务预期（如返回维护页面），ELB认为健康但实际不可服务
- 健康检查超时时间设置过短（如2秒），后端应用GC暂停期间健康检查失败触发批量摘除
- 健康检查端口与业务端口不同，检查通过但业务端口实际异常
- **规避**：健康检查间隔 ≥ 10秒，超时 ≥ 5秒，不健康阈值 ≥ 3次，健康检查路径使用独立于业务的健康检查端点（如 `/health`）

### 陷阱4：会话保持失效

- 四层（TCP）监听器启用会话保持基于源IP，但客户端经过NAT/代理后源IP相同，导致流量集中到单台后端
- 七层（HTTP）监听器启用会话保持使用Cookie，但后端应用也设置了同名Cookie导致冲突
- 会话保持超时时间短于业务会话周期，用户操作中途被路由到不同后端导致状态丢失
- 后端服务器被健康检查摘除后，其上的会话保持记录丢失，重建连接被路由到其他服务器
- **规避**：四层会话保持使用"加权最少连接+源IP哈希"组合；七层使用ELB注入Cookie而非应用Cookie；超时时间设为业务会话周期的1.5~2倍

### 陷阱5：SSL证书过期

- SSL证书过期后HTTPS监听器停止服务，但ELB不自动告警（需依赖CES证书到期告警规则）
- 证书更新操作需要先在SCM（证书管理服务）上传新证书，再到ELB监听器替换，操作步骤多且中途可能断流
- 多个监听器共享同一证书时，更新证书需逐个监听器替换，遗漏某个监听器导致部分业务中断
- 中间证书未安装导致移动端浏览器报证书链不完整，但桌面端浏览器正常，问题隐蔽
- **规避**：在CES配置证书到期30/14/7天多级告警，证书更新使用蓝绿切换方式（新建监听器→切换DNS→删除旧监听器），确保完整证书链

## 二、性能优化（5项）

### 优化1：连接数优化

- 选择合适的ELB规格：共享型ELB有连接数限制（如5万并发），独享型ELB可配置更高规格（最高100万+并发）
- 四层监听器使用"加权最少连接"算法替代默认轮询，自动将新连接分配到当前连接数最少的服务器
- 调整监听器的连接限速（rate_limit）：防止单个客户端IP占用过多连接，建议单IP限速1000~5000连接/秒
- 启用连接复用：七层监听器开启后端HTTP/1.1 Keep-Alive连接复用，减少TCP握手开销
- 监控ELB的 `ActiveConnection` 和 `NewConnection` 指标，当连接数接近规格上限时提前升级或分流

### 优化2：后端响应时间优化

- 后端服务器响应时间直接影响ELB的并发处理能力：响应越快，连接释放越快，吞吐越高
- 七层监听器启用响应缓存（如静态资源缓存），重复请求直接由ELB返回，减少后端压力
- 配置后端服务器的连接超时：connect_timeout（1~5秒）、read_timeout（30~60秒）、write_timeout（30~60秒）
- 对慢请求后端设置独立的慢速服务器组，避免慢请求拖垮整体响应时间
- 监控后端响应时间P99，超过500ms时排查慢查询/慢IO，优化后再观察ELB吞吐变化

### 优化3：健康检查频率调优

- 健康检查频率影响故障发现速度和后端服务器负载：频率高→发现快→负载高
- 推荐参数组合：间隔10秒 + 超时5秒 + 不健康阈值3次 = 最快30秒发现故障
- 后端服务器数量多（>50台）时，健康检查请求量 = 服务器数 × (60/间隔秒数)，间隔过短可能对后端造成压力
- 对关键业务使用更激进的检查（间隔5秒 + 阈值2次 = 最快10秒发现），对非关键业务使用宽松检查（间隔30秒）
- 健康检查路径应轻量（不查询数据库/不调用外部服务），返回简单200 OK即可

### 优化4：七层路由效率

- 转发规则数量影响路由匹配性能：单个监听器转发规则建议不超过50条，超过后匹配延迟增加
- 域名+URL路径匹配时，将高频域名/路径的规则放在前面，利用短路匹配减少比较次数
- 使用正则表达式匹配时，复杂正则（如嵌套量词）可能导致ReDoS，建议使用精确匹配或前缀匹配
- 七层ELB的请求头处理：移除不必要的请求头转发，减少后端解析开销
- 启用HTTP/2提升前端连接效率：单连接多路复用，减少TLS握手和TCP连接数

### 优化5：跨可用区流量均衡

- 创建ELB时选择多可用区部署，确保单个可用区故障时流量自动切换到其他可用区
- 后端服务器组中各可用区服务器数量保持均衡，避免某可用区服务器过少成为瓶颈
- 开启ELB的跨可用区负载均衡功能，确保流量按服务器权重均匀分配（而非按可用区分配）
- 监控各可用区的流量分布，偏差超过20%时检查后端服务器权重和健康状态
- 跨可用区部署时注意网络延迟差异（同区 < 1ms，跨区 1~3ms），对延迟敏感业务尽量保持同可用区

## 三、安全加固（3项）

### 安全1：DDoS防护

- ELB前端暴露公网IP，是DDoS攻击的直接目标，必须配置DDoS防护策略
- 开启华为云DDoS高防（Advanced Anti-DDoS），设置流量清洗阈值和黑白名单
- 七层监听器配置请求限速（rate_limit）：单IP每秒请求上限，防止单客户端耗尽连接
- 启用WAF（Web应用防火墙）防护七层攻击：SQL注入、XSS、CC攻击等
- 配置访问控制策略（IP黑白名单），仅允许可信IP段访问ELB，拒绝已知攻击源
- 监控 `InBandwidth` 和 `NewConnection` 指标突增，配置告警及时发现攻击

### 安全2：SSL卸载安全

- HTTPS监听器启用TLS 1.2+，禁用TLS 1.0/1.1和弱密码套件（如RC4、DES、MD5）
- 配置HSTS响应头（`Strict-Transport-Security: max-age=31536000`），强制浏览器使用HTTPS
- 使用SCM（证书管理服务）集中管理证书，避免私钥分散存储在多台服务器上
- 启用OCSP Stapling减少客户端证书验证延迟，同时避免客户端直接访问CA的OCSP服务器
- 定期扫描SSL配置安全性（如使用SSL Labs测试），确保评分达到A以上
- 证书私钥使用SM2/RSA 2048+，禁用弱密钥长度

### 安全3：后端服务器暴露风险

- 后端服务器不应绑定公网IP（EIP），仅通过ELB对外暴露，减少攻击面
- 后端服务器安全组仅允许ELB的内网IP段访问业务端口，拒绝其他来源的直连
- 后端服务器管理端口（SSH 22、RDP 3389）通过VPN或Bastion访问，禁止公网暴露
- 后端服务器仅开放必要的业务端口，数据库端口（3306/5432/27017）禁止外部访问
- 定期扫描后端服务器的安全组和网络ACL，发现违规暴露的端口及时修复

## 四、故障排查（5项）

### 故障1：后端不可达

- **现象**：ELB健康检查失败，后端服务器被标记为不健康，业务请求返回502/503
- **排查步骤**：
  1. 从ELB所在子网尝试telnet后端服务器端口：`telnet <backend_ip> <port>`
  2. 检查后端服务器安全组是否允许ELB所在子网的入站流量
  3. 检查后端服务器应用是否正常监听端口：`netstat -tlnp | grep <port>`
  4. 检查后端服务器是否已加入正确的后端服务器组
  5. 检查后端服务器子网路由是否配置正确，是否能回包到ELB
- **处置**：修复安全组规则、重启应用、修正服务器组配置、修复路由

### 故障2：响应延迟高

- **现象**：客户端请求响应时间明显增加，但后端服务器CPU/内存正常
- **排查步骤**：
  1. 查看ELB监控指标：`BackendResponseTime` 是否升高，区分是ELB延迟还是后端延迟
  2. 检查ELB连接数是否接近规格上限，排队等待导致延迟
  3. 检查后端服务器负载：CPU steal time、磁盘IO await、网络带宽利用率
  4. 检查健康检查频率是否过高占用后端资源
  5. 七层ELB检查转发规则数量和复杂度，过多规则增加匹配时间
- **处置**：升级ELB规格、优化后端性能、减少转发规则、调整健康检查频率

### 故障3：会话丢失

- **现象**：用户操作过程中会话状态丢失，需要重新登录
- **排查步骤**：
  1. 检查是否启用了会话保持，以及会话保持类型（源IP/Cookie）
  2. 检查会话保持超时时间是否短于业务会话周期
  3. 检查后端服务器是否被健康检查摘除后重新加入，导致会话映射丢失
  4. 七层ELB检查Cookie名称是否与后端应用Cookie冲突
  5. 四层ELB检查是否存在NAT/代理导致大量请求源IP相同
- **处置**：调整会话保持超时时间、使用应用级会话存储（Redis）、更换会话保持类型

### 故障4：SSL握手失败

- **现象**：HTTPS请求失败，浏览器提示SSL握手错误或证书无效
- **排查步骤**：
  1. 使用 `openssl s_client -connect <elb_ip>:443` 测试SSL握手过程和错误信息
  2. 检查证书是否过期：`openssl x509 -in cert.pem -noout -dates`
  3. 检查证书链是否完整：中间证书是否已安装
  4. 检查TLS版本和密码套件是否与客户端兼容
  5. 检查SNI配置：多个域名使用同一监听器时，是否正确配置了SNI证书
- **处置**：更新证书、安装中间证书、调整TLS版本和密码套件、配置SNI

### 故障5：流量不均衡

- **现象**：后端服务器负载差异明显，部分服务器过载而部分空闲
- **排查步骤**：
  1. 检查后端服务器权重配置是否合理
  2. 检查负载均衡算法：轮询（Round Robin）在权重不同时可能不均匀，建议使用加权最少连接
  3. 检查会话保持是否导致流量集中：大量会话保持到某台服务器
  4. 检查健康检查是否将部分服务器标记为不健康，流量集中到健康服务器
  5. 检查跨可用区流量分布是否均衡
- **处置**：调整权重和算法、缩小会话保持超时时间、修复不健康服务器、启用跨可用区均衡

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云ELB（弹性负载均衡） | Nginx自建负载均衡 | 硬件LB（如F5/A10） |
|------|--------------------------|-------------------|-------------------|
| **部署方式** | 全托管SaaS服务 | ECS上自建 | 物理设备采购部署 |
| **四层/七层** | 同时支持TCP/UDP/HTTP/HTTPS | 支持四层(stream)和七层(http) | 全面支持L4~L7 |
| **弹性** | 自动弹性，按需付费 | 需手动扩容ECS规格 | 固定性能，需提前规划 |
| **SSL卸载** | 支持，证书管理集成SCM | 支持，需手动管理证书 | 支持，硬件加速性能极高 |
| **健康检查** | 内置，多种协议支持 | 需自行配置upstream check | 内置，功能丰富 |
| **DDoS防护** | 集成基础DDoS防护+高防 | 需额外部署防护组件 | 内置ADC和DDoS防护 |
| **成本** | 按规格/流量计费，起步低 | ECS成本+运维人力 | 高额硬件采购+维保 |
| **运维复杂度** | 低（全托管） | 中（需维护Nginx+OS） | 高（需专业网络工程师） |
| **性能上限** | 独享型最高百万级并发 | 取决于ECS规格（十万级） | 百万~千万级并发 |
| **适用场景** | 通用Web/微服务/API网关 | 定制化需求、成本敏感 | 超大规模、金融核心 |

### 选择建议

- **选择ELB**：绝大多数云上业务场景，需要快速上线、弹性伸缩、低运维成本，配合华为云生态（AS/CES/WAF）形成完整解决方案
- **选择Nginx自建**：有高度定制化需求（如自定义路由逻辑、特殊协议代理）、成本敏感且具备Nginx运维能力
- **选择硬件LB**：超大规模业务（百万级以上并发）、金融核心系统、需要L4~L7全功能（如全局负载均衡、链路优化）、有专业网络运维团队

## 六、已知限制（≥3项）

1. **共享型ELB性能限制**：共享型ELB的连接数和带宽由所有租户共享，存在资源争抢风险，关键生产业务建议使用独享型ELB以确保性能保障

2. **后端服务器组数量限制**：单个ELB可创建的后端服务器组数量有限（默认50个），七层监听器的转发规则总数也有上限（默认500个），复杂路由场景需规划规则数量

3. **会话保持限制**：四层TCP监听器的会话保持仅支持源IP哈希，当客户端经过CDN/NAT时效果不佳；七层HTTP监听器的会话保持Cookie由ELB注入时，不支持跨域名共享

4. **证书更新短暂中断**：HTTPS监听器替换证书时，已有连接不受影响但新连接可能短暂失败（约1~2秒），对零中断要求的业务需使用蓝绿监听器切换方式

5. **七层ELB不支持WebSocket长连接超时自定义**：WebSocket连接的空闲超时时间固定为60秒（部分规格可调整到300秒），超出后连接被ELB主动断开，需要客户端实现心跳保活机制

6. **健康检查源IP不可自定义**：ELB健康检查请求的源IP为ELB内部IP段（100.64.0.0/10），后端服务器安全组必须放行该网段，但部分用户安全策略不允许放行大段IP

7. **跨Region负载均衡不支持**：ELB仅在单个Region内工作，跨Region的全局负载均衡需结合DNS（华为云DNS）或GSLB实现，ELB本身不提供跨Region流量分发能力
