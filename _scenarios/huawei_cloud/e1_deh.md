# 华为云DEH（专属主机）场景模板

## 概述

华为云专属主机（Dedicated Host, DEH）是将物理服务器独占分配给租户的云服务，满足合规隔离、性能保障等需求。本模板覆盖专属主机分配、云服务器放置、资源池管理、合规隔离及性能调优等核心场景。

---

## 一、常见陷阱（5项）

### 陷阱1：主机自动分配失败

- 使用自动分配策略时，系统可能因库存不足或可用区资源紧张导致分配失败，但错误信息不够明确
- 在控制台选择自动放置时，若未指定可用区偏好，系统可能将云服务器放置到非预期的专属主机上
- 当专属主机剩余vCPU/内存不足时，自动分配静默失败，用户误以为配置有误反复重试
- 跨可用区自动分配无回退机制，首次分配失败后需手动介入选择目标主机
- **规避**：创建前通过 `GET /v1.0/{project_id}/dedicated-hosts` 查询可用资源，明确指定 `dedicated_host_id` 或 `availability_zone`

### 陷阱2：可用区不匹配

- 专属主机与云服务器必须位于同一可用区，跨可用区放置会直接报错
- 当用户在某个可用区创建了专属主机后，创建ECS时若未手动选择同一可用区，界面虽提示但极易忽略
- 伸缩组配置中引用专属主机时，若可用区与伸缩组配置不一致，扩容时实例创建失败
- 迁移场景下，目标专属主机所在可用区与源ECS不同，导致热迁移不可用
- **规避**：创建专属主机后记录其可用区，所有关联ECS/伸缩组强制指定同一可用区，使用标签（Tag）标注可用区归属

### 陷阱3：资源超分

- 专属主机上可超分vCPU（如72核主机放置超过72 vCPU的ECS），但内存不可超分，容易导致调度失败
- 超分比例不当导致主机上ECS性能争抢，出现CPU steal time飙升
- 用户误以为专属主机资源独享等于无限制，在单台主机上过度堆叠ECS实例
- 内存超分尝试会被API直接拒绝，但错误码与一般配额不足混淆
- **规避**：监控主机级 `cpu_util` 和 `mem_util` 指标，vCPU超分比例建议不超过2:1，内存严格不超分

### 陷阱4：合规隔离漏洞

- 虽然专属主机提供物理隔离，但共享VPC/子网时，同VPC内其他租户的ECS仍可进行二层通信
- 合规要求如等保三级要求"物理隔离"，但DEH仅做到主机级隔离，网络层隔离需额外配置
- 专属主机上的ECS与其他ECS共享安全组时，安全组规则可能不满足合规最小化原则
- 跨专属主机的ECS迁移可能遗留数据残片，合规审计时未覆盖迁移轨迹
- **规避**：为专属主机上ECS配置独立VPC/子网，安全组遵循最小权限原则，定期执行合规扫描

### 陷阱5：性能调优盲点

- 专属主机上ECS的NUMA拓扑与物理机绑定，但用户未感知NUMA亲和性，vCPU跨NUMA分配导致内存访问延迟翻倍
- 网络带宽在主机级别共享，单ECS大量收发包可能挤占同主机其他ECS网络配额
- 本地磁盘IO受限于物理机硬件，多ECS并发IO时出现IO争抢但未触发告警
- 专属主机上放置多种规格ECS时，大小规格混部导致资源碎片化，无法再放置大规格ECS
- **规避**：同主机ECS规格尽量统一，开启NUMA亲和性感知调度，监控主机级网络和IO指标

## 二、性能优化（5项）

### 优化1：主机放置策略优化

- 根据业务负载特征选择放置策略：CPU密集型选择高主频主机，内存密集型选择大内存主机
- 利用 `host_type` 参数选择合适规格（如 general / compute / memory），避免规格错配导致的性能浪费
- 对延迟敏感型业务，优先选择与数据库/存储同可用区的专属主机，减少跨区网络延迟
- 使用反亲和性策略将关键业务分散到不同专属主机，避免单主机故障导致业务全面中断
- 定期评估主机利用率，对利用率低于30%的主机进行ECS合并迁移，释放冗余主机

### 优化2：云服务器密度调优

- 根据业务峰值/均值比率计算最优ECS密度：峰值/均值 > 3的业务适合超分，< 1.5的业务不超分
- vCPU超分比例参考：Web服务类 2:1~3:1，数据库类 1:1，大数据类 1:1~1.5:1
- 内存配置预留10%给Hypervisor开销和系统缓存，避免内存耗尽触发OOM
- 使用云监控监控各ECS的CPU steal time，超过5%时应减少同主机ECS数量
- 热迁移低利用率ECS到其他主机，保持每台主机ECS密度在合理范围

### 优化3：资源池利用率提升

- 建立专属主机资源池视图，实时统计各主机vCPU/内存/存储利用率
- 新建ECS时通过调度算法优先分配到利用率适中的主机（40%~70%），避免热点主机
- 对闲置主机（利用率持续 < 15%超过7天）执行ECS迁移后释放，降低成本
- 设置资源池容量水位线：50%预警、70%告警、90%禁止新建，防止资源耗尽
- 使用标签体系管理主机归属（部门/项目/环境），实现资源池的精细化运营

### 优化4：NUMA亲和性优化

- 创建ECS时通过flavor选择与NUMA边界对齐的规格（如vCPU数为单NUMA节点核数的整数倍）
- 对于数据库等内存敏感型应用，确保ECS的vCPU和内存分配在同一NUMA节点
- 使用 `hw:numa_nodes` 和 `hw:numa_cpu.0` 等元数据指定NUMA拓扑，避免跨NUMA访问
- 监控 `numastat` 指标，当远端内存访问占比超过20%时重新调整ECS规格
- 对性能要求极高的场景，使用整机NUMA绑定（CPU pinning），消除vCPU调度抖动

### 优化5：网络吞吐优化

- 专属主机网络带宽受物理网卡限制，建议高吞吐业务选择25GbE及以上规格主机
- 启用SR-IOV直通模式，将物理网卡VF直接分配给ECS，绕过虚拟交换机开销
- 对网络密集型业务，避免在同一主机上放置多个高吞吐ECS，防止带宽争抢
- 使用增强型网卡（智能网卡）卸载网络处理，释放主机CPU用于业务计算
- 监控主机级 `network_throughput` 指标，当利用率超过80%时考虑分散ECS或升级主机规格

## 三、安全加固（3项）

### 安全1：专属主机物理隔离验证

- 验证专属主机确实独占物理服务器：通过管理控制台查看主机详情确认无其他租户ECS
- 检查Hypervisor层配置，确认不存在共享CPU/内存资源的隐式通道
- 使用安全合规扫描工具验证物理隔离有效性，确保满足等保/PCI-DSS等合规要求
- 定期审计专属主机的ECS列表，确认无未授权实例被放置到专属主机上
- 建立隔离验证清单：物理独占 ✅、Hypervisor隔离 ✅、网络隔离 ✅、存储隔离 ✅

### 安全2：租户数据残留检测

- 专属主机释放前必须执行数据擦除：使用 `shred` 或厂商提供的擦除工具覆写磁盘
- ECS删除后检查本地存储是否彻底清除，特别是本地盘型专属主机（如高IO型）
- 迁移ECS后验证源主机上无残留数据，包括临时文件、swap分区和日志
- 对合规要求严格的场景，在专属主机生命周期结束后执行NIST 800-88标准擦除
- 建立数据残留检测流程：删除→擦除→验证→记录，确保可追溯

### 安全3：合规审计缺失

- 专属主机操作（分配/释放/迁移）未接入CTS（云审计服务），导致操作不可追溯
- 安全组规则变更未记录，无法满足等保要求的审计日志留存6个月以上
- 专属主机上ECS的操作系统补丁未统一管理，存在已知CVE漏洞未修复的风险
- 缺少定期合规检查机制，主机隔离状态、数据擦除记录、访问控制策略无自动化验证
- **加固**：开启CTS全量审计，配置LTS日志收集，建立自动合规巡检流水线，关键操作设置MFA二次验证

## 四、故障排查（5项）

### 故障1：主机状态异常

- **现象**：专属主机状态变为 `fault` 或 `maintenance`，无法在该主机上创建/操作ECS
- **排查步骤**：
  1. 查看主机详情页的错误码和故障描述
  2. 检查是否触发了华为云平台维护窗口（提前7天邮件通知）
  3. 查询主机上的ECS是否均处于正常状态，个别异常ECS可能导致主机状态异常
  4. 通过API `GET /v1.0/{project_id}/dedicated-hosts/{host_id}` 获取详细状态
- **处置**：若为维护窗口，等待维护完成；若为硬件故障，提交工单申请主机替换并迁移ECS

### 故障2：云服务器创建失败

- **现象**：在专属主机上创建ECS返回 `OutOfResource` 或 `PlaceFailed` 错误
- **排查步骤**：
  1. 检查目标专属主机剩余vCPU/内存是否满足ECS规格要求
  2. 确认ECS flavor在专属主机类型上是否支持（部分flavor仅支持特定host_type）
  3. 检查可用区是否一致，跨可用区放置会直接失败
  4. 查看项目配额是否充足（`ecs_quota` 和 `dedicated_host_quota`）
  5. 检查镜像是否支持专属主机部署（部分市场镜像不支持）
- **处置**：调整ECS规格、更换目标主机、或申请配额提升

### 故障3：资源分配不均

- **现象**：多台专属主机间利用率差异极大，部分主机过载而部分闲置
- **排查步骤**：
  1. 导出所有专属主机的vCPU/内存利用率数据
  2. 检查ECS创建时是否指定了 `dedicated_host_id`，未指定则可能集中分配到同一主机
  3. 分析是否存在大规格ECS独占主机导致资源碎片化
  4. 检查自动放置策略是否配置了负载均衡分配
- **处置**：手动迁移ECS实现均衡分布，调整自动放置策略，对碎片化主机进行ECS重组

### 故障4：性能瓶颈定位

- **现象**：专属主机上ECS出现CPU steal time高、网络吞吐低、磁盘IO延迟大
- **排查步骤**：
  1. CPU瓶颈：查看 `cpu_steal` 指标，超过5%说明同主机ECS争抢CPU资源
  2. 网络瓶颈：检查主机级网络带宽利用率，确认是否有ECS占用过多带宽
  3. 磁盘瓶颈：查看本地盘IO队列深度和await时间，多ECS并发IO时可能争抢
  4. 内存瓶颈：检查 `mem_used_percent` 和 `swap_usage`，确认是否接近内存上限
  5. NUMA瓶颈：分析 `numastat` 数据，确认是否存在跨NUMA远端内存访问过多
- **处置**：减少同主机ECS密度、迁移高负载ECS、调整NUMA拓扑、升级主机规格

### 故障5：维护窗口影响

- **现象**：收到华为云维护通知，专属主机将在指定时间进入维护状态
- **排查步骤**：
  1. 确认维护窗口时间范围和对业务的影响（ECS是否需要重启）
  2. 检查是否有ECS正在运行关键业务，评估是否需要提前迁移
  3. 确认是否已开启ECS自动恢复功能
  4. 查看维护类型：硬件维护需要停机，固件升级可能仅需要重启Hypervisor
- **处置**：维护前将关键ECS热迁移到其他专属主机，维护后验证业务恢复正常，记录维护日志

## 五、替代方案（3项）

### 方案对比

| 维度 | 华为云DEH（专属主机） | 华为云专属云（DeC） | 本地机房自建 |
|------|----------------------|---------------------|-------------|
| **隔离级别** | 主机级物理隔离 | 区域级物理隔离（独立机房/机柜） | 完全物理隔离 |
| **部署周期** | 分钟级（自动分配） | 天级（需申请资源池） | 周级~月级（采购部署） |
| **弹性能力** | 可弹性增减专属主机 | 资源池内弹性，整体偏固定 | 无弹性，需提前采购 |
| **运维责任** | 华为负责硬件运维 | 华为负责基础设施运维 | 全部自行负责 |
| **合规认证** | 继承华为云等保/PCI-DSS | 独立合规域，满足更高要求 | 需自行通过认证 |
| **成本模型** | 按主机包年/包月 | 按资源池包年/包月 | 一次性CAPEX + 持续OPEX |
| **网络能力** | 共享VPC，同普通ECS | 独立VPC/网段，更强隔离 | 完全自主网络架构 |
| **适用场景** | 中等合规要求、需要物理隔离 | 高合规要求、独立监管域 | 极高合规/特殊硬件需求 |
| **SLA** | 99.95% | 99.95% | 自定义（取决于架构） |
| **迁移成本** | 低（ECS热迁移） | 中（资源池内迁移） | 高（物理搬迁） |

### 选择建议

- **选择DEH**：需要物理隔离满足合规要求，但业务仍需弹性伸缩和云上运维便利性
- **选择专属云**：监管要求独立物理区域（如金融核心系统），需与公共云完全隔离
- **选择本地机房**：有特殊硬件需求（如定制GPU/FPGA）、数据出境限制、或超大规模长期部署成本更优

## 六、已知限制（≥3项）

1. **规格限制**：专属主机上仅支持特定flavor的ECS，不支持裸金属服务器和GPU型ECS（部分区域除外），具体支持的flavor列表以控制台展示为准

2. **可用区绑定**：专属主机创建后可用区不可变更，其上ECS也必须位于同一可用区，跨可用区迁移需新建主机并手动迁移ECS

3. **本地存储限制**：部分专属主机类型配备本地盘，本地盘数据不参与云备份，ECS迁移或主机释放后本地盘数据将丢失，需提前备份

4. **热迁移约束**：专属主机间的ECS热迁移要求源和目标主机类型兼容，跨主机类型（如从general迁移到compute）可能不支持热迁移，需关机迁移

5. **维护窗口不可避让**：华为云平台维护期间专属主机可能需要重启，虽然有7天提前通知，但无法永久避让，关键业务需做好高可用架构设计

6. **配额限制**：专属主机数量受项目配额限制，默认配额较低（通常5台），大规模使用需提前申请提额，审批周期1~3个工作日

7. **不支持抢占式实例**：专属主机上不可创建抢占式ECS实例，仅支持按需和包年/包月计费模式
