# 提示词体系效果评估框架

> **版本**：v1.0.0  
> **定位**：定义AI提示词体系的效果评估指标、阈值与闭环流程  
> **适用**：所有项目提示词文档的质量评估与持续优化

---

## 一、核心指标定义

| 指标 | 标识 | 定义 | 计算方式 |
|------|------|------|----------|
| 输出完整度 | `output_completeness` | 场景模板5要素（身份定义、输入规范、处理步骤、输出规范、验收标准）覆盖率 | 已覆盖要素数 / 5 × 100% |
| 输出准确率 | `output_accuracy` | AI实际输出与期望输出的一致性 | 一致项数 / 评估项总数 × 100% |
| 结构合规率 | `structure_compliance` | 输出符合Schema/格式规范的比例 | 合规项数 / 评估项总数 × 100% |
| 执行耗时 | `execution_time_ms` | 从输入提交到完整输出的时间 | 端到端计时（毫秒） |

### 1.1 输出完整度详细说明

场景模板5要素覆盖率检查：

| 要素 | 权重 | 检查点 |
|------|------|--------|
| 身份定义 | 20% | 是否包含角色、能力边界、行为规范 |
| 输入规范 | 20% | 是否定义必填/选填字段及类型 |
| 处理步骤 | 20% | 是否包含明确的执行流程 |
| 输出规范 | 20% | 是否定义输出格式与结构 |
| 验收标准 | 20% | 是否包含可量化的完成条件 |

### 1.2 输出准确率评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 内容准确性 | 40% | 输出内容是否与任务要求一致 |
| 逻辑连贯性 | 30% | 输出推理过程是否逻辑自洽 |
| 实用性 | 30% | 输出是否可直接用于实际工作 |

### 1.3 结构合规率评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| Schema合规 | 50% | 输出是否符合_interface定义的Schema |
| 格式合规 | 30% | 输出是否符合规定的Markdown/JSON/YAML格式 |
| 术语合规 | 20% | 输出是否使用_glossary中定义的标准术语 |

## 二、阈值定义

| 指标 | 优良阈值 | 合格阈值 | 危险阈值 |
|------|----------|----------|----------|
| 输出完整度 | ≥95% | ≥85% | <85% |
| 输出准确率 | ≥90% | ≥85% | <85% |
| 结构合规率 | ≥95% | ≥90% | <90% |
| 执行耗时 | ≤10000ms | ≤20000ms | >30000ms |

### 2.1 优化触发条件

以下任一条件满足时，**触发优化流程**：

- **输出准确率 < 85%** → 触发内容优化
- **结构合规率 < 90%** → 触发结构优化
- **输出完整度 < 85%** → 触发模板补全
- **执行耗时 > 30000ms** → 触发性能优化

## 三、闭环流程

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  评估    │ ──→ │  分析    │ ──→ │  优化    │ ──→ │ 再评估   │
│ Evaluate │     │ Analyze │     │ Optimize│     │Re-eval  │
└─────────┘     └─────────┘     └─────────┘     └─────────┘
     ↑                                               │
     └───────────────────────────────────────────────┘
                    （直到满足优良阈值）
```

### 3.1 评估阶段（Evaluate）

1. 按场景模板逐项执行AI输出采集
2. 对照5要素检查完整度
3. 对照期望输出检查准确率
4. 对照Schema/格式检查结构合规率
5. 记录执行耗时
6. 生成评估报告至 `_evaluations/reports/`

### 3.2 分析阶段（Analyze）

1. 对比当前指标与基线指标（`_evaluations/baseline/`）
2. 识别指标下降或未达阈值的根因
3. 按影响范围分类：体系级 / 文档级 / 场景级
4. 生成优化建议清单

### 3.3 优化阶段（Optimize）

1. 按优先级排序优化建议（P0 > P1 > P2 > P3）
2. 执行优化修改（提示词调整 / 模板补全 / Schema修正）
3. 记录变更至 CHANGELOG.md
4. 更新版本号（根据联动规则）

### 3.4 再评估阶段（Re-evaluate）

1. 对优化后的体系重新执行评估
2. 对比优化前后指标变化
3. 若仍存在危险阈值项 → 返回分析阶段
4. 若全部达到合格阈值 → 更新基线，闭环完成

|------|--------|--------|------|------|

- [ ] 未达标，需优化后重评
