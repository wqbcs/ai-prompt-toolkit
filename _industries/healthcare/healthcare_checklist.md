# 医疗行业专项检查清单

> **版本**：v1.0.0
> **适用**：医院信息系统、医疗SaaS、健康监测、医药研发、医疗AI系统

---

## 一、HIPAA合规清单

### 1.1 隐私规则(Privacy Rule)
- [ ] 受保护健康信息(PHI)使用和披露最小必要原则
- [ ] 患者权利：访问/修改/会计记录/限制使用/保密通信
- [ ] 隐私通知发布(NPP)并定期更新
- [ ] 业务关联协议(BAA)与所有PHI处理方签署
- [ ] 最低必要标准：仅访问完成工作所需的最少PHI

### 1.2 安全规则(Security Rule)
- [ ] 管理防护：安全管理人员指定/风险评估/员工培训/应急计划/审计日志
- [ ] 物理防护：设施访问控制/工作站安全/设备/媒体控制
- [ ] 技术防护：访问控制/审计控制/完整性控制/传输加密/存储加密

### 1.3 违规通知规则(Breach Notification Rule)
- [ ] 违规发现后60天内通知受影响个人
- [ ] 超过500人违规通知HHS和媒体
- [ ] 违规风险评估和文档化(4因素风险评估法)

## 二、数据脱敏检查

### 2.1 18种PHI标识符脱敏
- [ ] 姓名 → 保留首字母或完全脱敏
- [ ] 地址 → 保留州/市，脱敏街道和门牌号
- [ ] 日期 → 保留年，脱敏月日(89岁以上统一为90+)
- [ ] 电话号码 → 保留区号，脱敏后7位
- [ ] 传真号码 → 同电话
- [ ] 电子邮件 → 完全脱敏或哈希
- [ ] 社会保障号 → 完全脱敏
- [ ] 医疗记录号 → 哈希或令牌化
- [ ] 健康计划受益人号 → 哈希或令牌化
- [ ] 账户号码 → 保留后4位，其余脱敏
- [ ] 证书/执照号 → 哈希
- [ ] 车辆标识/序列号 → 脱敏
- [ ] 设备标识/序列号 → 哈希
- [ ] Web URL → 脱敏
- [ ] IP地址 → 保留前3段，脱敏第4段
- [ ] 生物标识 → 哈希
- [ ] 全脸照片 → 模糊化或移除
- [ ] 其他唯一标识号/码/特征 → 哈希

### 2.2 脱敏策略
| 场景 | 策略 | 说明 |
|------|------|------|
| 开发/测试环境 | 合成数据生成 | 基于真实数据分布生成，无真实PHI |
| 数据分析 | 安全港脱敏 | 18种标识符全部移除或泛化 |
| 跨机构研究 | 有限数据集 | 移除直接标识符，保留日期和地理信息 |
| 生产环境 | 令牌化/加密 | 可逆脱敏，按需还原 |

### 2.3 重新标识风险评估
- [ ] 脱敏数据重新标识风险评佔(k-匿名/l-多样性/t-接近性)
- [ ] 小数据集(样本<100)需额外泛化
- [ ] 稀有疾病/罕见特征组合需特殊处理
- [ ] 跨数据集关联分析风险评估

## 三、医疗AI安全检查

### 3.1 AI模型安全
- [ ] 训练数据合规：授权来源+脱敏处理+偏差评估
- [ ] 模型验证：独立测试集验证+临床验证+监管审批
- [ ] 模型可解释性：决策可追溯+特征重要性+反事实解释
- [ ] 模型鲁棒性：对抗样本防御+分布偏移检测+异常输入处理
- [ ] 模型公平性：不同人口统计组间无歧视性差异

### 3.2 AI辅助诊断安全
- [ ] 输出标注"AI辅助参考，不替代医生诊断"
- [ ] 置信度阈值：低置信度结果标记需人工审核
- [ ] 边界case处理：罕见病/多病共存/矛盾症状的人工兜底
- [ ] 反馈闭环：医生纠正→模型迭代→版本管理→回滚机制
- [ ] 监管合规：FDA De Novo/510(k)/CE标记等审批路径

### 3.3 医疗数据安全
- [ ] 数据采集：知情同意+最小必要+用途限定
- [ ] 数据存储：加密存储(AES-256)+访问控制(ABAC)+审计日志
- [ ] 数据传输：端到端加密(TLS1.2+)+安全API+数据完整性校验
- [ ] 数据共享：去标识化+共享协议+审计追踪+撤销机制
- [ ] 数据销毁：安全删除(DoD 5220.22-M)+销毁证明+审计记录

### 3.4 医疗设备(IoMT)安全
- [ ] 设备认证和授权(MFA/证书)
- [ ] 固件签名验证和更新安全
- [ ] 网络分段(医疗设备专用VLAN)
- [ ] 异常行为检测(数据外泄/未授权访问)
- [ ] 设备生命周期管理(注册/监控/退役/数据擦除)

## 四、中国医疗数据合规

### 4.1 核心法规
| 法规 | 核心要求 | 提示词适配 |
|------|---------|-----------|
| 《个人信息保护法》 | 敏感个人信息(医疗健康)单独同意+最小必要 | 所有场景添加医疗信息保护审查 |
| 《数据安全法》 | 医疗数据分类分级+安全评估 | 数据架构设计添加医疗数据分级 |
| 《健康医疗数据安全指南》 | 医疗数据分类分级5级+安全保护要求 | 数据处理场景添加分级标注 |
| 《人类遗传资源管理条例》 | 遗传资源采集/保藏/利用/出境审批 | 涉及遗传数据场景添加审批检查 |

### 4.2 医疗信息化标准
| 标准 | 核心要求 |
|------|---------|
| HL7 FHIR | 医疗数据交换标准(Patient/Observation/DiagnosticReport等资源) |
| DICOM | 医学影像存储和传输标准 |
| ICD-10/11 | 疾病分类编码标准 |
| SNOMED CT | 临床术语系统 |
| LOINC | 临床观测指标编码 |
