# 提示词体系效果评估框架 v5（八维度）

> **版本**：v2.0.0
> **定位**：定义AI提示词体系v4.0.0的效果评估指标、阈值与闭环流程
> **升级**：从六维度扩展至八维度，新增前沿技术适配度+行业垂直化覆盖度
> **适用**：所有项目提示词文档的质量评估与持续优化

---

## 一、核心指标定义（八维度）

| 指标 | 标识 | 定义 | 计算方式 |
|------|------|------|----------|
| 输出完整度 | `output_completeness` | 场景模板5要素覆盖率 | 已覆盖要素数 / 5 × 100% |
| 输出准确率 | `output_accuracy` | AI实际输出与期望输出的一致性 | 一致项数 / 评估项总数 × 100% |
| 结构合规率 | `structure_compliance` | 输出符合Schema/格式规范的比例 | 合规项数 / 评估项总数 × 100% |
| 执行耗时 | `execution_time_ms` | 从输入提交到完整输出的时间 | 端到端计时（毫秒） |
| 指令遵循率 | `instruction_following` | AI对prompt中约束指令的遵循比例 | 遵循指令数 / 总指令数 × 100% |
| 鲁棒性 | `robustness` | 边界输入/对抗输入下输出质量保持率 | 合格输出数 / 总测试输入数 × 100% |
| 前沿技术适配度 | `frontier_tech_adaptation` | PoT/Active-Prompt/APE/Agent-First等前沿技术集成度 | 评分1-5分（见评分标准） |
| 行业垂直化覆盖度 | `industry_coverage` | 行业场景/术语/合规的深度适配程度 | 评分1-5分（见评分标准） |

### 1.1 前沿技术适配度评分标准

| 分数 | 标准 |
|------|------|
| 5 | 完整集成PoT/Active-Prompt/APE/Agent-First中的3种以上，且运用深入 |
| 4 | 集成2种前沿技术，且运用合理有效 |
| 3 | 集成1种前沿技术，或2种但运用浅层 |
| 2 | 仅有传统CoT/Few-shot，未使用前沿技术 |
| 1 | 无任何高级提示工程技术 |

### 1.2 行业垂直化覆盖度评分标准

| 分数 | 标准 |
|------|------|
| 5 | 覆盖5+行业，含行业术语/合规/场景深度适配 |
| 4 | 覆盖3-4行业，行业适配较深 |
| 3 | 覆盖1-2行业，或3+行业但适配较浅 |
| 2 | 仅有通用场景，1个行业浅层适配 |
| 1 | 纯通用，无行业适配 |

## 二、八维度权重配置

| 维度 | 权重 | 评估方式 | 说明 |
|------|------|---------|------|
| 输出完整度 | 15% | 规则检查+LLM-as-Judge | 5要素覆盖率 |
| 输出准确率 | 20% | LLM-as-Judge为主 | 核心质量维度 |
| 结构合规率 | 15% | 规则检查(Schema验证) | 格式/Schema合规 |
| 执行耗时 | 5% | 规则(计时) | 性能指标 |
| 指令遵循率 | 15% | 规则检查+LLM-as-Judge | 约束遵循度 |
| 鲁棒性 | 10% | 对抗测试+LLM-as-Judge | 边界case通过率 |
| 前沿技术适配度 | 10% | LLM-as-Judge | 技术先进性 |
| 行业垂直化覆盖度 | 10% | LLM-as-Judge | 行业深度 |

## 三、阈值定义

| 指标 | 优良阈值 | 合格阈值 | 危险阈值 |
|------|----------|----------|----------|
| 输出完整度 | ≥95% | ≥85% | <85% |
| 输出准确率 | ≥90% | ≥85% | <85% |
| 结构合规率 | ≥95% | ≥90% | <90% |
| 执行耗时 | ≤10000ms | ≤20000ms | >30000ms |
| 指令遵循率 | ≥90% | ≥85% | <85% |
| 鲁棒性 | ≥90% | ≥80% | <80% |
| 前沿技术适配度 | ≥4分 | ≥3分 | <3分 |
| 行业垂直化覆盖度 | ≥4分 | ≥3分 | <3分 |

### 3.1 优化触发条件

以下任一条件满足时，**触发优化流程**：

- **输出准确率 < 85%** → 触发内容优化
- **结构合规率 < 90%** → 触发结构优化
- **输出完整度 < 85%** → 触发模板补全
- **执行耗时 > 30000ms** → 触发性能优化
- **指令遵循率 < 85%** → 触发约束强化
- **鲁棒性 < 80%** → 触发边界case增强
- **前沿技术适配度 < 3分** → 触发前沿技术集成
- **行业垂直化覆盖度 < 3分** → 触发行业适配扩展

## 四、闭环流程

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  评估    │ ──→ │  分析    │ ──→ │  优化    │ ──→ │ 再评估   │
│ Evaluate │     │ Analyze │     │ Optimize│     │Re-eval  │
└─────────┘     └─────────┘     └─────────┘     └─────────┘
     ↑                                               │
     └───────────────────────────────────────────────┘
                    （直到满足优良阈值）
```

### 4.1 评估阶段
1. 按场景模板逐项执行AI输出采集
2. 对照5要素检查完整度
3. 对照期望输出检查准确率（LLM-as-Judge）
4. 对照Schema/格式检查结构合规率
5. 对照核心约束检查指令遵循率
6. 执行边界/对抗case检查鲁棒性
7. 评估前沿技术集成度
8. 评估行业垂直化覆盖度
9. 记录执行耗时
10. 生成评估报告至 `_evaluations_v5/reports/`

### 4.2 分析阶段
1. 对比当前指标与基线指标（`_evaluations_v5/baseline/`）
2. 识别指标下降或未达阈值的根因
3. 按影响范围分类：体系级 / 文档级 / 场景级
4. 生成优化建议清单（含优先级）

### 4.3 优化阶段
1. 按优先级排序优化建议（P0 > P1 > P2 > P3）
2. 执行优化修改
3. 记录变更至 CHANGELOG.md
4. 更新版本号

### 4.4 再评估阶段
1. 对优化后重新执行评估
2. 对比前后指标变化
3. 若仍存在危险阈值项 → 返回分析
4. 若全部达到合格阈值 → 更新基线，闭环完成
