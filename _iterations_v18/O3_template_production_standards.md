## 生产可用级模板标准

### 1. 模板结构规范

每个场景模板必须包含以下10个要素：

| 序号 | 要素 | 说明 | 状态 |
|------|------|------|------|
| 1 | 场景ID | 唯一标识符，格式 `{category}-{seq}` | 必须 |
| 2 | 场景名称 | 简洁描述场景用途 | 必须 |
| 3 | 角色定义 | 经验+领域+能力+工作方式4要素 | 必须 |
| 4 | 输入模板 | 含变量占位符+输入示例 | 必须 |
| 5 | 输出模板 | JSON/YAML/Markdown格式+输出示例 | 必须 |
| 6 | 约束条件 | 技术+业务+安全+性能4维度 | 必须 |
| 7 | 检查清单 | 可勾选的验收项（非描述性） | 必须 |
| 8 | 边界处理 | 空输入/异常输入/超大输入处理 | 必须 |
| 9 | 错误恢复 | 失败时的重试/降级策略 | 必须 |
| 10 | 示例对话 | 至少1组完整输入→输出示例 | 必须 |

### 2. 输入模板规范

```markdown
## 输入模板

### 必填参数
| 参数 | 类型 | 说明 | 示例 |
|------|------|------|------|
| code_snippet | string | 待审查的代码 | `void main() { ... }` |

### 可选参数
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| language | string | auto | 编程语言 |
| review_focus | string[] | all | 审查重点 |
```

### 3. 输出模板规范

```markdown
## 输出模板

### JSON输出格式
```json
{
  "summary": "一句话概述",
  "issues": [
    {
      "id": "ISS-001",
      "severity": "high|medium|low",
      "category": "security|performance|style|logic",
      "description": "问题描述",
      "location": { "line": 42, "column": 10 },
      "suggestion": "修复建议",
      "auto_fixable": true
    }
  ],
  "score": 85,
  "recommendation": "总体建议"
}
```
```

### 4. 检查清单规范（可勾选验收项）

```markdown
## 验收检查清单

- [ ] 输出包含summary字段且非空
- [ ] issues数组中每项包含id/severity/category/description
- [ ] severity仅取high/medium/low三值
- [ ] score为0-100整数
- [ ] 所有代码建议可执行（非伪代码）
- [ ] 无重复issue
- [ ] 高严重度issue占比不超过30%（如超过需二次确认）
```

### 5. 边界处理规范

```markdown
## 边界处理

| 场景 | 处理策略 |
|------|---------|
| 空代码输入 | 返回 `{error: "code_snippet不能为空", code: 422}` |
| 超长代码(>10K行) | 分段审查，合并报告 |
| 不支持的语言 | 返回支持语言列表+建议 |
| 语法错误代码 | 标记语法错误，跳过语义分析 |
| 二进制文件 | 拒绝处理，返回错误 |
```
