## 一、LLM-as-Judge核心概念

LLM-as-Judge是使用大语言模型自动评估其他LLM输出质量的方法论，可替代或辅助人工评估，实现规模化、一致性、可重复的质量评估。

### 1.1 核心优势
- **规模化**：可批量评估大量输出，不受人工评估带宽限制
- **一致性**：同一评估prompt下评分标准统一，避免人工主观偏差
- **可追溯**：评估prompt版本化管理，评估结果可复现
- **低成本**：相比人工评估显著降低成本（约1/10~1/100）

### 1.2 核心挑战
- **位置偏差(Position Bias)**：LLM倾向于给先出现的选项更高分数
- **冗长偏差(Verbosity Bias)**：LLM倾向于给更长的输出更高分数
- **自我偏好(Self-Preference)**：LLM倾向于给自己的输出更高分数
- **一致性不足**：同一评估器对相似输入可能给出不同评分

## 二、LangSmith评估框架要点

### 2.1 评估类型
| 类型 | 说明 | 适用场景 |
|------|------|---------|
| 自动评估 | 基于规则/匹配的评估 | 格式合规性、关键词存在性 |
| LLM-as-Judge | 使用LLM评估LLM输出 | 输出质量、相关性、有用性 |
| 人工评估 | 人工标注评估 | 最终质量把关、争议裁决 |

### 2.2 LangSmith评估工作流
1. 创建数据集（输入-期望输出对）
2. 定义评估器（LLM-as-Judge prompt模板）
3. 运行实验（批量执行+评估）
4. 对比结果（不同版本/模型间对比）
5. 迭代优化（基于评估结果调整prompt）

### 2.3 LangSmith关键特性
- **数据集版本化**：评估数据集支持版本管理
- **实验追踪**：每次评估运行自动记录完整追踪
- **对比视图**：支持A/B测试和版本间对比
- **反馈标注**：支持人工反馈叠加到自动评估

## 三、评估Prompt设计最佳实践

### 3.1 评估Prompt结构模板

```markdown
你是一个严格的{评估领域}质量评估专家。

## 评估任务
评估以下AI输出在{场景名称}场景中的质量。

## 评分标准
- 5分(优秀)：完全满足要求，输出完整、准确、结构规范
- 4分(良好)：基本满足要求，有轻微不足
- 3分(合格)：满足最低要求，有明显可优化空间
- 2分(不足)：部分满足要求，关键要素缺失
- 1分(失败)：未满足要求，输出质量不合格

## 评估维度（每维度独立评分，加权平均）
1. 完整度(权重30%)：5要素覆盖情况
2. 准确性(权重30%)：内容与任务要求的一致性
3. 结构性(权重20%)：格式/Schema合规性
4. 实用性(权重20%)：输出可直接用于实际工作的程度

## 输入
{input_content}

## AI输出
{ai_output}

## 评估要求
1. 逐维度给出评分(1-5)和评分理由
2. 计算加权总分
3. 识别最需改进的维度
4. 给出具体改进建议
```

### 3.2 一致性保障策略
| 策略 | 实现方式 |
|------|---------|
| 固定评分范围 | 使用1-5或1-10固定整数评分 |
| 多次采样 | 同一输入评估3次取众数/中位数 |
| 交叉评估 | 使用不同模型作为Judge取平均 |
| 参考对比 | 提供参考答案让Judge做对比评估 |
| Chain-of-Thought | 要求Judge先推理再评分 |
| 反转测试 | 交换A/B顺序验证位置偏差 |

### 3.3 评分校准方法
1. **基线校准**：对已知质量的样本集建立评分基线
2. **锚点对齐**：定义5分和1分的明确锚点样本
3. **偏差纠正**：统计位置/冗长偏差并应用纠正因子
4. **人工抽检**：抽取10-20%样本人工复核，计算Judge-人工相关系数

## 四、Promptfoo LLM-as-Judge实践

> 注：promptfoo文档URL返回404，以下基于promptfoo公开信息补充

### 4.1 Promptfoo评估配置
```yaml
# promptfooconfig.yaml
providers:
  - openai:gpt-4-turbo
  - openai:claude-3-opus

prompts:
  - prompt1.txt
  - prompt2.txt

tests:
  - description: "代码审查场景评估"
    vars:
      code: "{{code_input}}"
    assert:
      - type: llm-rubric
        value: "评估代码审查报告的完整性和准确性..."
        threshold: 4.0
      - type: contains-json
        threshold: 0.9
```

### 4.2 Promptfoo核心特性
- **声明式配置**：YAML定义评估流程
- **多模型对比**：同一测试集跨模型运行
- **断言类型丰富**：llm-rubric/contains-json/regex/相似度等
- **CLI+CI集成**：支持命令行和CI/CD流水线集成

## 五、对本提示词体系的适用建议

### 5.1 八维度评估中的LLM-as-Judge应用
| 维度 | 评估方式 | Judge Prompt重点 |
|------|---------|-----------------|
| 输出完整度 | 规则+Judge | Judge评估要素覆盖深度和质量 |
| 输出准确率 | Judge为主 | 对比期望输出评估一致性 |
| 结构合规率 | 规则为主 | Schema验证+格式检查 |
| 执行耗时 | 规则(计时) | 不适用 |
| 前沿技术适配度 | Judge为主 | 评估CoT/ReAct等技术运用质量 |
| 行业垂直化覆盖度 | Judge为主 | 评估行业术语和场景覆盖深度 |

### 5.2 实施路线
1. **Phase 1**：为55个场景模板建立评估数据集（输入+期望输出）
2. **Phase 2**：设计8维度对应的8个Judge Prompt模板
3. **Phase 3**：执行基线评估，建立v4.0.0评分基线
4. **Phase 4**：A/B测试框架搭建，支持版本间对比
5. **Phase 5**：CI/CD集成，每次变更触发回归评估
