## 一、战略反问四问（对抗性自审，不自我美化）

### Q1 定位是啥？
名义定位"Prompt 的 ESLint + 全生命周期工具链"。但联网检索发现：
`promptlint-ai`（35 规则）/ `llm-promptlint` / `promptlint.dev` **都在抢"ESLint for
prompts"心智**，且全是 20~35 规则、零依赖、单一用途的轻量工具。本项目真实形态是
**261 规则 + 130 维度 + 73 MCP + 116 探针 + 21 Provider + A/B + 模板市场的"大杂烩"**，
规模是竞品 10 倍，却**无 git remote（未发布）、无真实用户**。

**判定**：定位与"ESLint for prompts"市场现实脱节 —— 市场要的是**轻而单点锋利**的刀，
我们端来的是全套厨房。

### Q2 核心价值是啥？
剥掉 scope bloat，真正可防守的 moat 是 README 自己论证的那段：**确定性、可复现、
零 LLM 成本、<100ms、SARIF 输出的 CI 门禁**。竞品 hybrid（regex+LLM）在 CI 有采样
方差、重跑可能翻裁决，**结构性不能当门禁**。这才是别人抢不走、用户真要的价值。
其余（A/B/模板市场/130 维度/21 Provider）要么要 LLM 调用（与零 LLM 核心矛盾）、
要么稀释叙事。

### Q3 方向有啥问题？
三个硬伤：
1. **R216→R219 全是内部打磨**（location 契约 / 96 处 sentinel / 22 站点行:列），
   **零用户、零分发**下打磨 linter 内部 = 教科书级低价值打磨陷阱；
2. **261 规则只 22 站点有行:列**，剩下 239 条要安全落地必须重构检测逻辑（高风险低
   收益）—— 继续磨是陷阱；
3. **scope bloat**：没人会 adopt 竞品 10 倍的功能面。真正的 wedge 是"确定性 CI 门禁"
   这一把刀，不是全家桶。

### Q4 低价值打磨陷阱，具体指什么？
location 契约 / 行:列 / 版本 67.34.x / 5968 测试 / 双基线 / 棘轮 —— 全是**用户不可见
的内部工程优雅 + vanity 指标**。没有用户在用，这些不产生任何采用价值。

**结论：停掉内部打磨，转向"发布 + 楔子"。核心价值只有一个 —— 确定性 CI 门禁的可信度。**

## 二、联网调研（2026-10-01，博客/自媒体/GitHub/开源平台）

### 竞品格局（四段）

| 段位 | 代表 | 规模 | 定位 | 与本项目关系 |
|---|---|---|---|---|
| 轻 linter | promptlint 族（20~35 规则，零依赖） | 小 | "ESLint for prompts" 单点 | 抢心智，功能窄 |
| 运行时护栏 | LLM Guard / llm-guardrails | 中 | 输入/输出拦截 + PII 脱敏 | 运行时层，非 CI 门禁 |
| 动态红队 | NVIDIA/garak | 大 | 需活体 target 的动态探针 | 我们 probe 是其静态子集 |
| eval+红队 CI | promptfoo（24k stars，已被 OpenAI 收） | 大 | eval + 红队 + CI/CD + SARIF | 最接近"CI 门禁"竞品，但 **eval 要 LLM 调用**（非确定性） |

**关键空档**：`promptfoo` 的 CI 门禁要 LLM 调用（成本 + 采样方差）；`promptlint` 轻但
**无中文、无 SARIF 深度、无确定性门禁叙事**。**"确定性 + SARIF + 中文 + CI 门禁"
四合一，目前无人做** —— 这是本项目的真空档。

### 真实痛点（来自博客/issue/实战）
1. **注入检测器被用户禁用，头号原因是误报**：prompt-injection-defender 用户
   "**第 5 次误报、零确认 TP → 禁用插件**"，根因是 regex 签名过宽（`highest priority`
   / `reset state` / `role:` 全命中，无 AI 语境限定）。→ **FP 是 adoption killer**，
   本项目双基线 FP 0.91% 是护城河，但**没让用户看见**。
2. **指标要按 FP 预算评估，不是 AUC**：nhimg 文章（2026-08）"检测器只在
   recall@可接受FP 下才有用，model-card 分数误导"。→ 双基线（FP 预算 + 漏检）正
   对位，是叙事武器。
3. **攻击签名演化快**：`prompt-sentinel` 明确"jailbreak techniques evolve fast,
   refresh periodically"。→ 签名需**可更新**，不能焊死在工具版本里。

### 可复用组件（避免重复造轮子）

| 组件 | 复用点 | 对本项目价值 |
|---|---|---|
| **prompt-database**（3900+ 攻击，1300 高信号，OWASP2025+MITRE 映射，pip 可装） | golden 攻击集**扩样源** | 解决 L3-6 前置=扩样，双基线从 73 自制→千级真实攻击 |
| **prompt-sentinel**（156,802 条 3 类标注） | FP/漏检**测试语料**（英文为主） | 扩样 + hard negative（benign 陷阱） |
| **anti-trojan-source**（285 confusable + Cf/Cc 类目）/ **indium**（Python，TR39 1861 字符） | P260/P261 零宽/BiDi 规则的对齐参考 | 信源已用 ATR-2026-00276，此处作交叉验证，不重构 |
| **prompt-shield-signatures**（ed25519 签名威胁情报 feed，每日刷新） | **签名 feed + 签名校验** 思路 | 签名更新免工具升级，契合"确定性 + 供应链安全"核心 |

### 信源可信度诚实声明
以上竞品/组件均来自公开 web 检索（2026-10-01），未逐一克隆验证其 star/license。
**实现前**对每个拟复用的库单独验证 license + 实际 API，不凭检索快照下结论。

## 四、本轮实施决策（R220）

**主线 = A1（golden 扩样）+ B1/B2（explain 接线 + 硬编码修复）**

理由：
1. **A1 直接放大核心价值可信度**（双基线 73→200+ 真实攻击），解决 R217 反思指出的
   L3-6 前置=扩样，复用 prompt-database（不造轮子），正交于检测逻辑（低回归风险）。
2. **B1/B2 直击 adoption killer（FP）**，纯本地零网络依赖，explain 基础设施已存在
   （只接线 + 修硬编码，不造轮子），用户可见。
3. 两者都是 wedge 级，非打磨。C1/C2 列项待后续（C1 需设计、C2 需发布凭据）。

**实现纪律**（用户指令）：
- 每个拟复用库**实现前**单独验证 license + 实际 API（不凭检索快照）；
- 扩样 expected 标注走**语义映射**（OWASP/technique → P 规则族），不确定者**不纳入**
  （不循环标注：不靠"linter 命中"反推 expected）；
- 每端维持公认最优栈（Python CLI / TS 扩展 / LSP），不绑单一技术栈，不硬编码。
