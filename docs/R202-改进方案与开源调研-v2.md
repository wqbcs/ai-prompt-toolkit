### 1.2 社区痛点（博客/HN/GitHub issues 挖掘）

1. **静默回归是头号焦虑**（appropri8 2025）：代码测试全绿但模型回答质量退化，用户先于团队发现。Prompt drift（改一个逗号，助手从 helpful 变 sarcastic）无自动化防线。
2. **garak 三大槽点**：① 只做模型层，无法注入业务/应用上下文定制 probe；② 响应评估基础、误报多；③ 报告碎片化（只有聚合统计+人工翻 hit log）。
3. **garak #1608（未闭环）**：probe 强制覆写 `max_tokens`/`temperature`，推理模型（reasoning）输出被截断；社区共识是 **generation params 必须用户可配置**，probe 默认值只是建议。
4. **promptfoo 槽点**（DeepEval 对比文）：YAML 工作流僵化、指标集窄、缺编程式 API 导致回归测试/高级实验难扩展；数据隐私担忧（无 API key 时请求可能经 promptfoo 服务器）。
5. **不可复现性**（Medium 2026-01）：同一 prompt 多次运行输出不同，失败难以复现 → 红队结果必须记录完整输入/输出/种子/模型版本。
6. **成熟团队的闭环模式**（Failure Mining）：生产失败 → 提取精确输入+上下文 → 编码为测试用例 → 永久锁定行为。eval suite 是"活的失败数据库"。
7. **Drift Sentinel**：夜间/定时跑评估，drift 是信号不是故障 —— 行为基线对比比单次分数更重要。
8. **DSPy GEPA 教训**：单次 compile 花费可达数百美元；GEPA 必须喂 feedback 型 metric（`Prediction(score, feedback)`）而非纯标量 —— 优化器价值取决于 metric 质量。

## 2. 定位反问（先回答，再列清单）

**Q1: 这个项目定位是啥？**
> 现状回答：Prompt 的"左移质量与安全门禁"——在 Prompt 上线前，用零模型调用的静态分析（255 规则 Lint + 安全评分卡 + 红队 probe）拦截问题，再用动态评估（130 维度）量化质量。对标：ESLint/CodeQL 之于代码 = 本项目之于 Prompt。

**Q2: 产品核心价值是啥？**
> 竞品全部是"必须调模型才能测"（promptfoo/garak/deepeval 都要发 LLM 请求），**只有本项目能在 CI 里零成本、零密钥、离线跑**。这是护城河：
> - 静态 255 规则 = 秒级反馈，PR 门禁可用
> - 离线 = 数据不出本地（竞品 promptfoo 的数据隐私槽点正好是我们的卖点）
> - 中文规则 15 条中文注入检测 = 竞品空白

**Q3: 目前推进方向有啥问题？**
> 对抗性审查发现 3 个偏差：
> 1. **mypy 清零后继续堆类型标注是低价值打磨**（R201 已收官，后续 mypy 投入归零，只保棘轮）
> 2. **规则数量通胀风险**：255 条规则中大量是"正则能匹配就报"的启发式，误报率未度量。数量从卖点变负债（llm-security-scanner 只有 21 条规则但条条可 CI 化）
> 3. **动态侧弱于静态侧**：eval-multi 不是真矩阵（缺 prompt×model×场景展开）、优化器 gepa 是死代码 —— 用户跑完 Lint 后"然后呢"没有闭环
>
> **调整**：下轮重心从"静态规则增量"转向"闭环体验"（CI 门禁 → 基线回归 → 失败用例沉淀）+ 清理死代码。

**Q4: 低价值打磨陷阱（当前在犯/需警惕）**
| 陷阱 | 现状 | 处置 |
|---|---|---|
| mypy 类型洁癖 | 443→0 已完成，继续投入边际收益≈0 | **停止**，棘轮保 0 即可 |
| 规则数量军备竞赛 | P241+ 继续加正则规则 | **冻结规则新增**，先度量误报率；新增必须带真实样例+误报基线 |
| 组件数字营销 | README 宣称 255/130/73/94/6 | 已动态计算对齐（R192/R194），保持 |
| 优化器死代码 | gepa PanguProvider 构造+调用均不成立 | **清理或激活**（见 P1-3） |
| 假功能 | 市场/审核/部署端点大量 next()/mock | 明确标注 experimental，或移除 CLI 入口 |

## 3. 改进清单（按优先级）

### P0 — 闭环体验（直接决定"然后呢"，R203-R206）

| # | 项 | 说明 | 借鉴 |

| P0-1 | **CI 门禁 `--fail-on`** | `prompt-cli lint --fail-on high` 退出码语义 + SARIF 已就绪 → 补 GitHub Code Scanning 上传示例 + 最小 `.github/workflows` 模板 | llm-security-scanner |

| P0-3 | **失败用例沉淀** | `prompt-cli capture-failure <file>`：把一次评估失败的输入+输出+维度分数编码为可回归测试用例（yaml），进 `tests/fixtures/`，永久锁定 | Failure Mining 闭环 |

| # | 项 | 说明 |
|---|---|---|

### P3 — 明确不做（奥卡姆剃刀）

- ✗ 自研前端 Web UI（playground 已够用，不扩）
- ✗ 自研红队大模型攻击生成器（promptfoo 的 AI 动态攻击是其商业核心，MIT 开源版做对抗生成是资源黑洞）
- ✗ 规则数量破 300（数量不是价值，误报率才是）
- ✗ 多语言绑定（保持 Python 内核 + MCP 协议边界，其他语言端靠 MCP 接入，符合"不被单一技术栈绑定"约束）
