# R126 改进清单 v3.0 — ai-prompt-toolkit 持续改进循环

> 生成时间: 2026-07-28 | 当前版本: v55.0.0 | 规则数: 220 | OWASP覆盖率: 80.0%

## 一、功能增添 (7项)

### F1. lint --rules-search 规则搜索引擎
- **痛点**: 220条规则难以快速找到需要的规则, 用户需要按关键词/OWASP/类别搜索
- **改进**: 添加 `lint --rules-search "injection"` 搜索规则, 支持fuzzy match
- **开源参考**: ESLint的`--print-config` + promptfoo的规则分类
- **量化指标**: 搜索响应<50ms, 覆盖全部220条规则

### F2. lint --fix --dry-run 干运行修复预览
- **痛点**: `--fix`直接修改文件, 用户无法预览修复效果
- **改进**: `--dry-run`只输出将要修复的内容, 不实际修改
- **开源参考**: ESLint `--fix-dry-run`, rubocop `--dry-run`
- **量化指标**: dry-run输出与实际修复100%一致

### F3. eval --compare 评估对比(多版本/多模板)
- **痛点**: 无法同时对比多个prompt模板的评估结果
- **改进**: `eval --compare tpl1.md tpl2.md tpl3.md` 并排对比
- **开源参考**: DeepEval的comparison模式, LangFuse的评分对比
- **量化指标**: 支持2-10个模板对比, 差异高亮

### F4. lint --baseline 基线管理
- **痛点**: CI中lint新发现无法区分已知/新增问题
- **改进**: 基线文件存储已知finding, CI仅报新增问题
- **开源参考**: semgrep `--baseline`, codeql baseline管理
- **量化指标**: CI误报率降低50%+

### F5. MCP prompt_rules_search 工具
- **痛点**: MCP客户端无法搜索可用规则
- **改进**: 新增MCP工具搜索规则(按关键词/OWASP/类别)
- **开源参考**: promptfoo MCP + garak MCP模式
- **量化指标**: 搜索结果含规则描述/修复建议/OWASP映射

### F6. lint --statistics 规则命中率统计
- **痛点**: 不知道哪些规则被触发最多, 无法优化规则集
- **改进**: 统计每条规则触发次数, 输出排序报告
- **开源参考**: ESLint timing插件, SonarQube规则热度
- **量化指标**: 命中率+耗时+findings三维排序

### F7. P221-P225 供应链安全规则(第3方依赖/模型来源/数据溯源)
- **痛点**: OWASP LLM03仅7条规则覆盖, 供应链安全规则不足
- **改进**: 添加模型来源验证/依赖审计/数据溯源/版本锁定/签名验证5条规则
- **开源参考**: OWASP LLM03指南 + aom-sci的model-card规范
- **量化指标**: OWASP LLM03覆盖从7→12条

## 二、内容改进 (4项)

### C1. 未映射44条规则补全OWASP映射
- **现状**: 44条规则未映射到OWASP LLM Top 10
- **改进**: 为每条未映射规则分配至少1个OWASP ref
- **目标**: 覆盖率从80%→95%+

### C2. 所有规则双语描述完整性审计
- **现状**: 部分规则缺description_en/remediation_en
- **改进**: 补量并补全所有220条规则的英文描述
- **目标**: 100%双语覆盖

### C3. CHANGELOG自动生成
- **现状**: CHANGELOG手动维护, 易遗漏
- **改进**: git commit约定式格式 + 自动生成CHANGELOG
- **开源参考**: conventional-changelog, git-cliff
- **目标**: 每次发版自动生成

### C4. 规则文档自动生成
- **现状**: 无规则详细文档, 用户需读源码
- **改进**: 自动从LintRule定义生成docs/rules.md
- **开源参考**: ESLint规则文档, semgrep规则集文档
- **目标**: docs/rules.md含全部220条规则

## 三、细节优化 (5项)

### D1. lint --progress 进度条优化
- **痛点**: Rich进度条在大目录下闪烁
- **改进**: 稳定进度条 + 文件名显示 + 预估时间
- **参考**: rich.Progress最佳实践

### D2. Finding行号/列号定位
- **痛点**: Finding只报规则ID, 不报具体位置
- **改进**: 添加line/col到Finding, 支持编辑器跳转
- **开源参考**: ESLint的line/column, SARIF格式
- **目标**: lint输出含位置, SARIF含位置

### D3. eval --format csv 输出格式
- **痛点**: 缺CSV格式, 不便Excel分析
- **改进**: 添加csv格式选项
- **目标**: `eval --format csv` 输出标准CSV

### D4. lint --ignore-file 忽略文件
- **痛点**: 无类似.eslintignore的忽略机制
- **改进**: 支持.promptignore文件 + --ignore-file选项
- **开源参考**: .eslintignore, .gitignore模式
- **目标**: 支持!important否定模式

### D5. 错误提示友好化
- **痛点**: 部分错误输出为原始异常堆栈
- **改进**: 友好化错误提示 + 建议/文档链接
- **目标**: 用户错误不再看到traceback

## 四、用户体验改善 (5项)

### U1. lint --interactive 富交互选择
- **痛点**: 当前interactive逐条确认, 效率低
- **改进**: Rich checkbox多选 + 全选/反选 + 批量确认
- **参考**: questionary.checkbox, Inquirer.js

### U2. 首次使用引导(wizard)
- **痛点**: 新用户不知道从哪里开始
- **改进**: `prompt-toolkit init` 交互式引导配置
- **参考**: create-react-app, cargo init

### U3. lint结果分享(链接/剪贴板)
- **痛点**: 无法快速分享lint结果给团队
- **改进**: `lint --share` 生成临时链接或复制到剪贴板
- **参考**: sharify, hastebin模式

### U4. 暗色主题适配
- **痛点**: 输出在暗色终端不清晰
- **改进**: 自动检测终端主题 + 颜色适配
- **参考**: Rich auto-detect + NO_COLOR标准

### U5. 空状态引导提示
- **痛点**: 无finding时不清楚下一步
- **改进**: "全部通过! 🎉" + 建议运行eval/probe
- **参考**: GitHub Actions空状态提示
