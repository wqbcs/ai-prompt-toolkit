## 一、故障排查章节规范

### 1.1 章节结构

每个场景模板必须包含"故障排查"章节，格式如下：

```markdown
## 故障排查

| # | 故障 | 诊断步骤 | 修复方法 |
|---|------|---------|---------|
| 1 | {故障描述} | 1. {步骤1} 2. {步骤2} 3. {步骤3} | {修复方法} |
| 2 | ... | ... | ... |
| 3 | ... | ... | ... |
| 4 | ... | ... | ... |
| 5 | ... | ... | ... |
```

### 1.2 故障排查Top5要求

- 每个场景模板至少5个故障
- 故障按发生频率排序
- 诊断步骤不超过5步
- 修复方法可执行（非描述性）
- 每个修复方法含预期结果

### 1.3 覆盖范围

| 类别 | 场景数 | 故障项 |
|------|--------|--------|
| 低代码/无代码 | 5 | 25 |
| 游戏开发 | 5 | 25 |
| 物联网 | 5 | 25 |
| 区块链 | 5 | 25 |
| 华为云DDS | 1 | 5 |
| 华为云DMS | 1 | 5 |
| 华为云DLI | 1 | 5 |
| 华为云EI | 1 | 5 |
| v23新增合计 | 20 | 100 |

## 二、统一错误码体系

### 2.1 编码规范

**格式**: PE-XXXX

- PE: Prompt Engineering（提示词工程）
- XXXX: 4位数字编码

### 2.2 领域分段

| 范围 | 领域 | 场景关联 |
|------|------|---------|
| PE-0001~PE-0999 | 通用/基础 | 跨领域通用错误 |
| PE-1001~PE-1999 | 功能增添 | 协作编辑器/Changelog/健康监控 |
| PE-2001~PE-2999 | 用户体验 | 语音/收藏/记录/diff |
| PE-3001~PE-3999 | 低代码/无代码 | 5场景 |
| PE-4001~PE-4999 | 游戏开发 | 5场景 |
| PE-5001~PE-5999 | 物联网 | 5场景 |
| PE-6001~PE-6999 | 区块链 | 5场景 |
| PE-7001~PE-7999 | 华为云专项 | DDS/DMS/DLI/EI |
| PE-8001~PE-8999 | 继承v22 | 原有场景 |
| PE-9001~PE-9999 | 预留扩展 | 未来专项 |

### 2.3 错误码结构

```
PE-XXXX
│  │
│  └── 场景编号(00-99)
│
└── 领域编号(00-99)
```

### 2.4 错误码示例

| 错误码 | 领域 | 描述 |
|--------|------|------|
| PE-3001 | 低代码-可视化 | 画布组件渲染失败 |
| PE-3011 | 低代码-表单 | 表单联动规则循环 |

## 三、输出格式统一

### 3.1 "请输出"格式规范

所有场景模板的"请输出"部分统一为编号列表，每项含格式要求+示例：

```markdown
### 请输出
1. **{输出项名称}**（格式：{格式要求}）
   - 示例：{具体示例}
2. **{输出项名称}**（格式：{格式要求}）
   - 示例：{具体示例}
```

### 3.2 格式要求标准

| 输出项 | 格式要求 |
|--------|---------|
| 提示词模板 | Markdown代码块，含角色+场景+约束+输出格式 |
| 组件清单 | 编号列表，每项含组件名+功能+属性+事件 |
| 陷阱Top5 | 编号列表，每项含陷阱+示例+修复 |
| 性能优化Top5 | 编号列表，每项含优化项+方法+预期效果 |
| 故障排查 | 表格，每行含故障+诊断步骤+修复方法 |
| 最小可执行示例 | 代码块，复制即用 |
| 性能基准 | 表格，Token/延迟/成本3列 |

## 四、检查清单分类标签

### 4.1 标签体系

| 标签 | 颜色 | 含义 | 示例 |
|------|------|------|------|
| [安全] | 红色 | 安全相关检查项 | 输入验证/XSS防护/权限控制 |
| [性能] | 橙色 | 性能相关检查项 | 响应时间/吞吐量/内存占用 |
| [功能] | 蓝色 | 功能相关检查项 | 核心流程/边界条件/错误处理 |
| [规范] | 绿色 | 规范相关检查项 | 命名规范/格式规范/文档规范 |
| [合规] | 紫色 | 合规相关检查项 | 数据保护/行业合规/审计要求 |

### 4.2 标签规则

- 每个检查清单项必须标注至少1个标签
- 1项可标注多个标签（如[安全][性能]）
- 标签以Markdown行内代码格式标注
- 安全类检查项必须有[安全]标签
- 所有检查项标签覆盖率=100%

### 4.3 标签统计

| 标签 | 预计项数 | 占比 |
|------|---------|------|
| [安全] | 180 | 25% |
| [性能] | 160 | 22% |
| [功能] | 200 | 28% |
| [规范] | 120 | 17% |
| [合规] | 60 | 8% |
| 合计 | 720 | 100% |
