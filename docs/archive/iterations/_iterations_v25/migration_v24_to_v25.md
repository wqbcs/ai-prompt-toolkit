# v24→v25 迁移指南

> **版本**: v1.0.0 | **日期**: 2026-07-12

---

## 一、迁移概览

v25.0.0是v24.0.0的纯增量升级，**无Breaking Changes**。所有v24配置和模板在v25中完全兼容。

| 项目 | 迁移难度 | 必需操作 |
|------|----------|----------|
| A/B测试v1→v2 | 低 | 可选升级 |
| 模板继承新增 | 低 | 可选启用 |
| 条件编译新增 | 低 | 可选使用 |
| YAML Front Matter | 低 | 可选规范化 |
| 评估框架v6→v7 | 低 | 自动兼容 |

## 二、A/B测试v1→v2迁移

### 2.1 配置差异

| 项目 | v1 | v2 |
|------|-----|-----|
| 模型数量 | 单模型 | 2-8个模型并行 |
| 统计检验 | 无 | t检验/Mann-Whitney U |
| 胜率矩阵 | 无 | M×N矩阵 |
| 最优匹配 | 无 | 自动推荐 |

### 2.2 迁移步骤

1. v1配置文件可直接在v2框架中加载（向后兼容）
2. 如需使用v2新功能，在配置中添加`models`数组（多个ModelConfig）
3. 添加`evaluation`段指定6维评估维度
4. 添加`win_rate_matrix`和`optimal_match`配置段
5. 执行v2测试，生成胜率矩阵和最优匹配推荐

### 2.3 兼容性保证

- v1单模型配置在v2中正常工作（视为1个模型的A/B测试）
- v1评估结果在v2 Dashboard中正常展示
- v1 API接口在v2中全部保留

## 三、模板继承新增

### 3.1 新增字段

在YAML Front Matter中新增`inheritance`字段：

```yaml
inheritance:
  enabled: false           # 默认不启用
  parent_template: null    # 父模板ID
  depth: 0                 # 继承深度
  overrides: []            # 覆盖字段
  extensions: []           # 扩展字段
```

### 3.2 迁移步骤

1. 现有模板无需修改（`inheritance.enabled=false`为默认值）
2. 如需使用继承，设置`enabled: true`并指定`parent_template`
3. 使用覆盖(overrides)和扩展(extensions)定制子模板
4. 运行循环继承检测和深度检测

### 3.3 注意事项

- 继承深度不超过5层
- 不允许循环继承
- 父模板被删除时子模板标记为broken

## 四、条件编译新增

### 4.1 新增语法

```
{{#if model == "gpt-4o"}}
  GPT-4o专属内容
{{#else}}
  通用内容
{{/if}}
```

### 4.2 迁移步骤

1. 现有模板无需修改（无条件指令时原样输出）
2. 如需条件编译，在模板中插入`{{#if}}`指令
3. 使用`compilation_context_schema.yaml`指定编译上下文
4. 运行语法校验和编译预览

### 4.3 注意事项

- 嵌套不超过3层
- 条件指令禁止包含副作用
- 无匹配分支时提供`{{#else}}`兜底
- 编译结果为空时发出告警

## 五、YAML Front Matter规范化

### 5.1 必需字段

| 字段 | 默认值 | 说明 |
|------|--------|------|
| version | "1.0.0" | 模板版本 |
| author | "AI提示词体系" | 作者 |
| updated_at | 当天日期 | 更新日期(ISO 8601) |
| tags | [] | 标签(小写+中划线) |
| applicable_models | [4个模型] | 适用模型列表 |
| inheritance | {enabled: false} | 继承配置 |

### 5.2 迁移步骤

1. 运行`_scripts/normalize_frontmatter.sh --fix`自动补充缺失字段
2. 人工审核补充内容质量
