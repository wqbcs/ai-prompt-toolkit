# 第一部分：边缘计算5场景

## 场景1：模型量化

### 场景模板

```
角色：边缘AI模型量化工程师
任务：为{model_name}设计{method}量化方案

输入：
- 原始模型：{model_path}(FP32/FP16)
- 量化方法：{method}(GPTQ/AWQ/SmoothQuant/ONNX-INT8/BitNet)
- 目标硬件：{hardware}(ARM/NPU/Intel/昇腾)
- 精度要求：{accuracy_threshold}

请设计：
1. 量化配置（bits/group_size/damp_percent/校准数据集）
2. 敏感层分析（哪些层保持高精度）
3. 量化精度评估（PPL/下游任务/KL散度）
4. ONNX转换+优化（算子融合+常量折叠）
5. 华为昇腾适配（如适用）

请输出量化方案JSON。
```

### 陷阱5

| # | 陷阱 | 严重等级 | 修复方法 |
|---|------|---------|---------|
| 1 | 校准数据分布偏移 | P0 | 用推理分布一致的200~500条数据 |
| 2 | 敏感层量化导致精度崩溃 | P1 | 敏感度分析+首尾层跳过量化 |
| 3 | ONNX算子不兼容 | P1 | 自定义算子注册+opset版本检查 |
| 4 | 量化后模型输出异常值 | P1 | 激活值裁剪+输出层FP16 |
| 5 | 昇腾NPU推理精度差异 | P2 | 昇腾CANN适配+精度对齐测试 |

### 性能基准
- Token消耗：3K-8K | 延迟：2-5s | 成本：$0.02-0.05/次

### 最小可执行示例

```
输入：YOLOv8n INT8量化部署到华为Atlas 200 DK
提示词：请设计YOLOv8n ONNX INT8量化方案：
1. 校准数据配置（COCO val2017子集200张）
2. 敏感层分析+跳过策略
3. 量化后mAP评估（目标：mAP下降<1%）
4. ONNX→OM模型转换（昇腾ATC工具）
5. Atlas 200推理性能预估

预期输出：{quantConfig:{bits:8,calibSize:200},sensitiveLayers:["Conv_0","Conv_156"],expectedMapDrop:"0.8%",atcCommand:"atc --model=yolov8n.onnx --output=yolov8n --soc=Ascend310"}
```

### 常见错误Top5

| # | 错误 | 修复方法 |
|---|------|---------|
| 1 | 所有层统一量化 | 敏感度分析+混合精度 |
| 2 | 校准数据太少 | 最少200条代表性数据 |
| 3 | 未测试极端输入 | 添加边界值测试+异常值检测 |
| 4 | 忽略量化后推理速度 | 端到端benchmark+warmup |
| 5 | ONNX opset版本不对 | 与目标runtime匹配+向下兼容 |
