## 场景1：图像理解

### 场景模板

```
角色：多模态AI图像理解工程师
任务：设计{task_type}图像理解提示词方案

输入：
- 任务类型：{task_type}(OCR/目标检测/图像描述/视觉问答/医学影像)
- 视觉模型：{vlm}(Qwen-VL/InternVL/LLaVA)
- 图像类型：{image_type}
- 输出要求：{output_format}

请设计：
1. 图像预处理提示词（分辨率/裁剪/增强策略）
2. 提示词模板（角色+任务+约束+输出格式）
3. 后处理规则（结构化提取+校验+纠错）
4. 多图对比提示词（如适用）
5. 错误处理策略

请输出完整提示词方案JSON。
```

### 陷阱5

| # | 陷阱 | 严重等级 | 修复方法 |
|---|------|---------|---------|
| 1 | 图像分辨率过高token爆炸 | P1 | 自适应缩放+关键区域裁剪+分块处理 |
| 2 | OCR结果格式混乱 | P1 | 指定JSON输出格式+坐标绑定+校验规则 |
| 3 | 忽略图像方向/旋转 | P2 | 自动旋转校正+EXIF方向处理 |
| 4 | 多图对比顺序敏感 | P2 | 编号标注+位置无关提示 |
| 5 | 细节幻觉(VLM编造不存在内容) | P1 | 约束"仅描述可见内容"+置信度评分 |

### 性能基准
- Token消耗：5K-12K | 延迟：3-8s | 成本：$0.03-0.10/次

### 最小可执行示例

```
输入：发票OCR识别，Qwen-VL模型，输出结构化JSON
提示词：请识别发票图片中的所有字段，按以下JSON格式输出：
{"invoiceNumber":"", "date":"", "seller":"","buyer":"","items":[{"name":"","quantity":"","price":""}],"totalAmount":""}
仅输出图片中明确可见的信息，不可见字段填null。

预期输出：完整的发票结构化数据
```

### 常见错误Top5

| # | 错误 | 修复方法 |
|---|------|---------|
| 1 | 一次塞入太多图片 | 单图处理+汇总，最多4图/次 |
| 2 | 未指定输出语言 | 明确"请用中文输出" |
| 3 | 图像质量差导致失败 | 图像增强+重试+降级到纯文本 |
| 4 | 结果未校验直接使用 | JSON Schema校验+字段完整性检查 |
| 5 | 忽略隐私信息 | PII检测+脱敏+人工审核 |

## 场景2：视频分析

### 场景模板

```
角色：多模态AI视频分析工程师
任务：设计{task_type}视频分析提示词方案

输入：
- 任务类型：{task_type}(关键帧提取/视频QA/异常检测/内容摘要/时序定位)
- 视频时长：{duration}
- 分析模型：{model}
- 输出要求：{output_format}

请设计：
1. 关键帧采样策略（均匀/场景切换/运动检测）
2. 时序建模提示词（帧序号+时间戳+事件描述）
3. 长视频分段处理方案（>5分钟）
4. 实时流处理提示词（如适用）
5. 视频生成评估提示词（如适用）

请输出完整方案JSON。
```

### 陷阱5

| # | 陷阱 | 严重等级 | 修复方法 |
|---|------|---------|---------|
| 1 | 关键帧采样丢失关键事件 | P1 | 场景切换检测+运动量采样+关键帧冗余 |
| 2 | 长视频token超限 | P0 | 分段处理+摘要合并+滑动窗口 |
| 3 | 时序关系丢失 | P1 | 强制时间戳标注+因果链提示 |
| 4 | 实时流延迟过高 | P1 | 关键帧预采样+流式输出+异步处理 |
| 5 | 视频内容安全未过滤 | P0 | 内容安全检测+敏感帧过滤+审核 |

### 性能基准
- Token消耗：8K-20K | 延迟：5-15s | 成本：$0.05-0.20/次

### 最小可执行示例

```
输入：10分钟会议视频，提取关键讨论点和决策
提示词：请分析以下会议视频关键帧，提取：
1. 讨论主题（按时间顺序）
2. 关键决策和结论
3. 待办事项和负责人
按时间戳标注每个事件。

预期输出：[{timestamp:"00:02:15", topic:"Q3预算审批", decision:"通过", actionItems:[...]}]
```

### 常见错误Top5

| # | 错误 | 修复方法 |
|---|------|---------|
| 1 | 每帧都分析 | 关键帧采样，1fps足够 |
| 2 | 忽略音频信息 | 音频转文字+与视觉信息融合 |
| 3 | 分段后丢失上下文 | 段间重叠+全局摘要 |
| 4 | 输出格式不统一 | 强制JSON Schema+时间戳格式 |
| 5 | 视频编码格式不支持 | 预处理统一编码(H.264) |

## 场景3：语音处理

### 场景模板

```
角色：多模态AI语音处理工程师
任务：设计{task_type}语音处理提示词方案

输入：
- 任务类型：{task_type}(ASR/TTS/语音克隆/情感分析/声纹识别)
- 语言：{language}
- 模型：{model}(Whisper/CosyVoice/FunASR)
- 场景：{scenario}

请设计：
1. 语音预处理提示词（降噪/VAD/分段）
2. ASR转写提示词（专有名词/口音/标点）
3. 语音对话提示词（如适用）
4. TTS合成提示词（如适用）
5. 语音安全检测提示词

请输出完整方案JSON。
```

### 陷阱5

| # | 陷阱 | 严重等级 | 修复方法 |
|---|------|---------|---------|
| 1 | ASR专有名词识别差 | P1 | 热词表+上下文纠错+领域词典 |
| 2 | 长音频VAD分段不准 | P1 | Silero VAD+能量检测双保险 |
| 3 | 中文标点丢失 | P2 | 后处理标点恢复模型 |
| 4 | 语音克隆被滥用 | P0 | 声纹授权+水印+使用限制 |
| 5 | 方言/口音识别率低 | P1 | 多方言微调+置信度+人工回退 |

### 性能基准
- Token消耗：2K-6K | 延迟：2-8s | 成本：$0.01-0.05/次

### 最小可执行示例

```
输入：会议录音ASR转写，中文，含技术术语
提示词：请将以下会议音频转写为文字，注意：
1. 技术术语准确（Kubernetes、gRPC、Redis等）
2. 识别说话人（说话人1/说话人2...）
3. 添加标点符号
4. 标注不确定部分[?]

预期输出：{speaker:"说话人1", text:"我们决定将Kubernetes集群从1.28升级到1.30...", confidence:0.95}
```

### 常见错误Top5

| # | 错误 | 修复方法 |
|---|------|---------|
| 1 | 未做降噪预处理 | 降噪+VAD+静音切除 |
| 2 | 音频格式不支持 | 统一转WAV 16kHz单声道 |
| 3 | 忽略说话人分离 | 使用说话人分离模型+标注 |
| 4 | 超长音频一次处理 | 按VAD分段+每段<30s |
| 5 | 未处理重叠语音 | 重叠检测+分别转写+合并 |

## 场景4：跨模态推理

### 场景模板

```
角色：多模态AI推理工程师
任务：设计{task_type}跨模态推理提示词方案

输入：
- 任务类型：{task_type}(图文推理/图表QA/文档理解/多模态CoT/视觉数学)
- 输入模态：{modalities}(text+image/text+audio/text+image+table)
- 推理深度：{depth}(单步/多步CoT/自反思维)
- 模型：{model}

请设计：
1. 多模态输入对齐提示词（模态间引用+绑定）
2. 跨模态推理链提示词（CoT步骤+模态引用）
3. 推理验证提示词（自反+交叉验证）
4. 错误修正提示词
5. 推理效率优化提示词

请输出完整方案JSON。
```

### 陷阱5

| # | 陷阱 | 严重等级 | 修复方法 |
|---|------|---------|---------|
| 1 | 模态间引用混乱 | P1 | 编号绑定：图1→描述1→推理1 |
| 2 | 推理链断裂 | P1 | 强制逐步推理+每步引用证据 |
| 3 | 视觉幻觉传导到推理 | P0 | 每步验证"是否在图像中可见" |
| 4 | 推理token消耗过大 | P2 | 关键步CoT+简单步直推+缓存 |
| 5 | 忽略图表数据精度 | P1 | 数值精确提取+四舍五入标注 |

### 性能基准
- Token消耗：6K-15K | 延迟：5-12s | 成本：$0.04-0.12/次

### 最小可执行示例

```
输入：分析柱状图中的销售趋势并预测Q4
提示词：请逐步分析图1中的销售数据：
1. 提取每月具体数值
2. 计算环比增长率
3. 识别趋势（上升/下降/波动）
4. 基于趋势预测Q4（附置信区间）
每步请引用图1中的具体数据作为证据。

预期输出：{step1:{data:{...}}, step2:{growthRates:{...}}, step3:{trend:"上升"}, step4:{prediction:{...}, confidence:0.75}}
```

### 常见错误Top5

| # | 错误 | 修复方法 |
|---|------|---------|
| 1 | 跳过中间步骤直接结论 | 强制逐步推理+每步输出 |
| 2 | 数值提取不精确 | 要求精确到小数点+与原图交叉验证 |
| 3 | 推理无验证环节 | 添加自反步骤+结论验证 |
| 4 | 多模态信息未融合 | 显式绑定：文字描述+视觉证据+推理 |
| 5 | 忽略不确定性 | 输出置信度+假设条件 |

## 场景5：多模态RAG

### 场景模板

```
角色：多模态RAG工程师
任务：设计{task_type}多模态RAG提示词方案

输入：
- 知识类型：{types}(文本/图片/表格/混合)
- 检索策略：{strategy}(文本嵌入/图像嵌入/混合/跨模态)
- 生成模型：{model}
- 应用场景：{scenario}

请设计：
1. 多模态文档Chunk方案（图文对齐+表格结构化）
2. 多模态检索提示词（查询扩展+跨模态检索）
3. 多模态重排提示词（Cross-Encoder+相关性评分）
4. 多模态生成提示词（检索结果+多模态答案）
5. 质量评估提示词（相关性+完整性+准确性）

请输出完整方案JSON。
```

### 陷阱5

| # | 陷阱 | 严重等级 | 修复方法 |
|---|------|---------|---------|
| 1 | 图文Chunk不对齐 | P0 | 图文对齐分块+交叉引用ID |
| 2 | 只检索文本忽略图表 | P1 | 混合检索：文本+图像+表格3路 |
| 3 | 表格信息在Chunk中丢失 | P1 | 表格特殊处理：Markdown/HTML保留结构 |
| 4 | 检索结果未去重 | P2 | 语义去重+MMR多样性 |
| 5 | 生成时引用不精确 | P1 | 强制来源标注[Doc1-P3][Fig2] |

### 性能基准
- Token消耗：6K-15K | 延迟：5-12s | 成本：$0.04-0.12/次

### 最小可执行示例

```
输入：产品手册多模态RAG（含文字+图片+表格），查询"如何更换滤芯"
提示词：请从产品手册中检索"更换滤芯"相关信息：
1. 检索文字说明+示意图+规格参数表
2. 合并多模态检索结果
3. 生成步骤式回答（附图引用和参数引用）

预期输出：{steps:[{step:1, text:"打开前盖", imageRef:"Fig3-2"}, {step:2, text:"逆时针旋转滤芯90°", imageRef:"Fig3-3"}, ...], specs:{ref:"Table2-1", filterModel:"CF-200"}}
```

### 常见错误Top5

| # | 错误 | 修复方法 |
|---|------|---------|
| 1 | 图文分离索引 | 图文对齐索引+联合检索 |
| 2 | 忽略表格语义 | 表格→Markdown+语义理解 |
| 3 | 生成无来源标注 | 强制来源引用[Doc-Fig] |
| 4 | 检索召回率低 | 多路召回+查询扩展+重排 |
| 5 | 长文档处理差 | 分层索引+概要+细节二级检索 |
