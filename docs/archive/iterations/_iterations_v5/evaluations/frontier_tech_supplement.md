## 二、Agent-First适配指令

### 05-A 测试策略 Agent-First

```markdown
<!-- Agent-First: 测试策略多Agent协作 -->

【Agent1: 测试策略Agent】
职责：分析项目特点，制定分层测试策略
输入：项目技术栈+代码结构+业务复杂度
输出：测试策略文档(分层策略+优先级+资源分配)

【Agent2: 用例设计Agent】
职责：基于策略设计具体测试用例
输入：测试策略+需求规格+代码覆盖率数据
输出：测试用例集(单元/集成/E2E)

【Agent3: 覆盖率验证Agent】
职责：验证测试覆盖率，识别遗漏
输入：测试用例+源代码
输出：覆盖率报告+遗漏风险点+补充建议

【Agent协作流程】
策略Agent → 用例Agent → 覆盖率Agent → (如遗漏>5%) → 用例Agent(补充)
```

### 06-A Pipeline设计 Agent-First

```markdown
<!-- Agent-First: Pipeline设计多Agent协作 -->

【Agent1: Pipeline设计Agent】
职责：根据项目需求设计CI/CD Pipeline
输入：项目技术栈+部署目标+质量要求
输出：Pipeline YAML+阶段定义+质量门禁

【Agent2: 安全审查Agent】
职责：审查Pipeline安全性
输入：Pipeline配置+安全基线
输出：安全审查报告+加固建议

【Agent协作流程】
设计Agent → 安全Agent → (如有P0安全问题) → 设计Agent(修正)
```

### 07-A 监控体系 Agent-First

```markdown
<!-- Agent-First: 监控体系多Agent协作 -->

【Agent1: 指标设计Agent】
职责：设计监控指标体系(四大黄金信号+业务指标)
输入：系统架构+SLA+关键业务流程
输出：指标定义(名称/类型/采集方式/告警阈值)

【Agent2: 告警规则Agent】
职责：生成告警规则和分级策略
输入：指标定义+历史告警数据
输出：告警规则YAML+分级策略+通知配置

【Agent3: Dashboard Agent】
职责：生成Grafana Dashboard配置
输入：指标定义+告警规则
输出：Dashboard JSON+面板布局+变量配置

【Agent协作流程】
指标Agent → 告警Agent → Dashboard Agent
```

### 10-D 知识库 Agent-First

```markdown
<!-- Agent-First: 知识库多Agent协作 -->

【Agent1: 知识提取Agent】
职责：从文档/代码/工单中提取知识条目
输入：企业文档+代码注释+历史工单
输出：知识条目(标题/内容/标签/关联)

【Agent2: 知识组织Agent】
职责：组织知识结构，建立关联和检索索引
输入：知识条目
输出：知识图谱+分类体系+检索索引

【Agent协作流程】
提取Agent → 组织Agent
```

## 三、PoT适配指令

### 05-B 用例设计 PoT

```markdown
<!-- PoT: Program-of-Thoughts用例设计 -->

请按Program-of-Thoughts方法设计测试用例：

1. 【编写验证函数】
   根据需求规格，编写可执行的测试代码：
   - 每个测试函数对应1个需求点或1个边界条件
   - 包含setup/execute/verify三阶段
   - 标注测试类型(单元/集成/E2E)

2. 【执行验证】
   运行测试代码，获取覆盖率报告：
   - 行覆盖率、分支覆盖率、路径覆盖率
   - 识别未覆盖的代码路径

3. 【根据结果调整】
   根据覆盖率报告补充测试：
   - 对未覆盖的P0路径补充测试
   - 对边界条件补充异常测试
   - 重新执行验证覆盖率达标(≥80%)
```

### 07-C 容量规划 PoT

```markdown
<!-- PoT: Program-of-Thoughts容量规划 -->

请按Program-of-Thoughts方法进行容量规划：

1. 【编写预测脚本】
   基于USL模型编写容量预测脚本：
   ```python
   def predict_capacity(N, lambda_val, sigma, kappa):
       X_N = (lambda_val * N) / (1 + sigma * (N - 1) + kappa * N * (N - 1))
       return X_N
   ```

2. 【执行预测】
   输入当前负载数据，执行容量预测：
   - 计算当前系统最大吞吐量
   - 预测不同N值下的吞吐量
   - 识别争用系数σ和一致性系数κ

3. 【根据结果调整】
   基于预测结果制定扩缩容策略：
   - 确定N_max(最大有效节点数)
   - 制定水平扩展策略
   - 制定垂直扩展策略
   - 定义扩缩容触发条件
```

   基于数据生成复盘报告：

## 四、Active-Prompt适配指令

### 06-C 质量门禁 Active-Prompt

```markdown
<!-- Active-Prompt: 不确定性驱动的选择性测试 -->

请按Active-Prompt方法管理质量门禁：

1. 【评估不确定性】
   对每个代码变更评估测试必要性(1-6分)：
   - 1-2分(低)：文档/配置变更→跳过深度测试
   - 3-4分(中)：逻辑微调→标准测试
   - 5-6分(高)：核心逻辑/安全相关→深度测试+安全扫描

2. 【选择性执行】
   基于不确定性分数选择性执行：
   - 低不确定性：仅格式检查+编译检查
   - 中不确定性：单元测试+集成测试
   - 高不确定性：全量测试+安全扫描+性能回归

3. 【效果验证】
   统计质量门禁通过率和缺陷逃逸率：
   - 目标：缺陷逃逸率<2%
   - 目标：质量门禁通过率>95%
```

### 10-A API文档 Active-Prompt

```markdown
<!-- Active-Prompt: 不确定性驱动的选择性文档更新 -->

请按Active-Prompt方法管理API文档更新：

1. 【评估更新必要性】
   对API变更评估文档更新必要性(1-6分)：
   - 1-2分：内部实现变更→跳过文档更新
   - 3-4分：参数/返回值微调→增量更新
   - 5-6分：接口签名变更/新增接口→完整更新

2. 【选择性更新】
   基于评估结果选择性更新文档：
   - 低必要性：仅更新变更日志
   - 中必要性：更新参数说明+示例
   - 高必要性：完整重写接口文档+示例+SDK
```

### 11-A 项目规划 Active-Prompt

```markdown
<!-- Active-Prompt: 不确定性驱动的选择性规划调整 -->

请按Active-Prompt方法管理项目规划调整：

1. 【评估调整必要性】
   对项目状态评估规划调整必要性(1-6分)：
   - 1-2分：进度偏差<10%→保持原规划
   - 3-4分：进度偏差10-20%或风险增加→局部调整
   - 5-6分：进度偏差>20%或重大风险→全面重规划

2. 【选择性调整】
   基于评估结果选择性调整规划：
   - 低必要性：仅更新进度状态
   - 中必要性：调整优先级+资源分配
   - 高必要性：重新评估范围+时间线+风险
```
