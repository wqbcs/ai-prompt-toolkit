## 二、AI Red Teaming Framework — 红队测试框架

### 2.1 garak (NVIDIA)

| 项目 | 详情 |
|------|------|
| GitHub | https://github.com/NVIDIA/garak |
| Stars | 8.5k |
| 语言 | Python (50.5%) |
| License | Apache 2.0 |

**核心特性:**
1. LLM漏洞扫描器——类似nmap/Metasploit但面向LLM
2. 插件化架构：probes(攻击探针) → detectors(检测器) → evaluators(评估器) → generators(模型接口) → harnesses(编排)
3. 20+攻击探针类别：DAN/encoding/promptinject/gcg/badchars/malwaregen/xss/leakreplay/packagehallucination等
4. 支持多后端：HuggingFace/OpenAI/Replicate/AWS Bedrock/NIM/REST
5. 结构化JSONL报告 + HTML可视化报告

**可借鉴功能点:**
- **Probe分类体系**——直接映射到我们RedTeam的10大攻击类，garak的20+类可归并：
  - `dan` → 越狱攻击
  - `encoding` → 编码绕过
  - `promptinject` → 提示注入
  - `leakreplay` → 数据泄露
  - `malwaregen` → 恶意内容生成
  - `xss` → 注入攻击
  - `packagehallucination` → 幻觉利用
  - `gcg` → 对抗性后缀攻击
  - `badchars` → Unicode绕过
  - `snowball` → 级联幻觉
- Harness编排模式——probewise harness的probe→detector自动匹配机制
- Generator抽象层——统一的模型调用接口设计

**集成可行性:** ★★★★★  
Python原生，架构完全可移植！garak的probe→detector→evaluator三层架构与我们的Security/RedTeam模块高度对齐。**建议直接参考其插件体系，实现Python版本的RedTeam探针框架。**

## 三、Prompt Optimization — 自动Prompt优化框架

### 3.1 DSPy (Stanford)

| 项目 | 详情 |
|------|------|
| GitHub | https://github.com/stanfordnlp/dspy |
| Stars | 36.3k |
| 语言 | Python (99.4%) |
| License | MIT |

**核心特性:**
1. **编程而非提示**——用Python代码替代脆弱的Prompt
2. 自动Prompt优化算法：Bootstrap Few-Shot / MIPRO / GEPA(2025新)
3. 模块化AI系统——Signature → Module → Optimizer三层抽象
4. 支持RAG Pipeline / Agent Loop / 分类器等复杂系统
5. 最新的GEPA算法（2025.07）——反射式Prompt进化，可超越强化学习

**可借鉴功能点:**
- **Compiler模块**——DSPy的Signature→Module→编译流程直接对应我们的Prompt Compiler：
  - Signature（声明式输入输出定义）→ 我们的Lint规则可验证Signature合规性
  - Module（可组合的AI模块）→ 我们的Compiler可将高级描述编译为优化Prompt
  - Optimizer（自动调优）→ 我们的AB-Test可集成优化算法
- GEPA反射式进化算法——可集成到我们的AB-Test模块作为自动优化策略
- 断言系统（DSPy Assertions）——可作为我们Lint规则的扩展

**集成可行性:** ★★★★★  
Python原生，MIT协议，学术界顶配。**强烈建议将DSPy的优化算法集成到我们的Compiler+AB-Test模块中**，实现"编写→编译→优化→评估"的闭环。

**可借鉴功能点:**

  - `@mcp.tool()`装饰器——每个工具一行装饰器+类型提示
  - `@mcp.resource()`资源模板——Prompt作为资源暴露
  - 类型提示自动生成Schema——大幅减少样板代码
- **Client模式**——我们的AB-Test可连接外部MCP Server获取评估数据
- **Streamable HTTP传输**——生产级部署方案

**集成可行性:** ★★★★★  
**这是最核心的集成点！** 我们44个MCP tools应直接基于v2 SDK重写，享受：
- 代码量减少70%+（类型提示即Schema）
- 生产级传输协议
- 官方生态兼容性

**v2迁移注意：** v2当前为beta阶段(2.0.0b1)，稳定版预计2026-07-27发布。建议锁定 `mcp>=1.27,<2` 后升级。
