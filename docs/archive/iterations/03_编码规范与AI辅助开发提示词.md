## 二、核心约束

1. **可读性优先**：代码是写给人看的，顺便让机器执行
2. **一致性高于一切**：整个项目使用统一的风格，比使用最优风格更重要
3. **最小意外原则**：API、函数命名和行为遵循直觉
4. **防御性编程**：边界检查和异常处理覆盖所有公开接口
5. **测试先行（或至少不后置）** ：生产代码与测试代码同时产出

## 三、编码规范通用要求

### 3.1 命名规范

| 元素 | 约束 | 示例 |
|------|------|------|
| 类名 | PascalCase，名词性 | `UserService`, `PaymentRequest` |
| 方法名 | camelCase，动词性 | `getUserById()`, `processPayment()` |
| 变量名 | camelCase，描述性 | `userList`, `paymentAmount` |
| 常量名 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 包/模块 | lowercase-with-hyphens | `user-service`, `payment-handler` |
| 数据库表 | snake_case，复数 | `users`, `payment_records` |
| 数据库字段 | snake_case | `created_at`, `user_id` |

### 3.2 代码结构规范

```
src/
├── controller/    # 路由/控制器层 — 仅做参数解析和路由转发
├── service/       # 业务逻辑层 — 核心业务逻辑
├── repository/    # 数据访问层 — 数据库/外部存储操作
├── model/         # 数据模型定义 — 实体/DTO/VO
├── middleware/    # 中间件 — 认证/日志/限流
├── utils/         # 工具类 — 无业务含义的通用函数
└── config/        # 配置定义 — 环境配置/常量
```

### 3.3 函数规范

- **单一职责**：一个函数只做一件事
- **长度控制**：不超过 50 行（超过需说明理由）
- **参数控制**：不超过 3 个参数（超过用对象封装）
- **无副作用**：避免修改传入参数
- **纯函数优先**：相同输入必须有相同输出

### 3.4 注释规范

```
// 好的注释：解释 WHY，不是 WHAT
// 根据业务规则，超过 30 天的订单不允许退款
if (order.createAt < now - 30.days) { ... }

// 坏的注释：重复代码信息
// 获取用户信息
val user = getUser(userId)  // ✗ 废话

// 文档注释：公开 API 必须包含
/**
 * 根据用户 ID 获取用户信息
 * @param userId 用户唯一标识
 * @return 用户实体，不存在返回 null
 * @throws IllegalArgumentException userId 为空时抛出
 */
```

### 3.5 错误处理规范

```
// ✅ 好：明确区分预期内和预期外异常
// 预期内：业务逻辑分支（if-else）
// 预期外：系统异常（try-catch）

// ✅ 好：异常信息携带上下文
throw new PaymentException("订单[${orderId}]支付失败", cause)

// ❌ 坏：吞掉异常
try { ... } catch (e: Exception) { }  // 不要空 catch

// ❌ 坏：向上抛出原始异常无上下文
throw e  // 丢失调用链上下文
```

**【回滚策略】**
1. **双写并行期**：新旧代码同时运行，新代码写新表/新队列，旧代码写旧表/旧队列，对比结果一致性
2. **灰度切换**：按用户/流量比例逐步切到新代码，每阶段对比监控指标

- **A/B对比**：相同请求分别走新旧代码路径，对比响应内容和耗时

| **性能评估** | N+1查询检查 | 循环内无数据库调用，批量操作替代逐条操作 |
| **性能评估** | 不必要对象创建检查 | 热路径无大对象频繁创建，无GC压力点 |
| **性能评估** | 连接池/缓存配置检查 | 数据库/HTTP/Redis连接池配置合理 |
| **可维护性** | 代码风格一致性检查 | 命名/缩进/注释风格与项目规范一致 |
| **可维护性** | 错误处理完备性检查 | 无空catch块，异常信息含上下文，错误码一致 |
| **可维护性** | 可测试性检查 | 依赖可Mock，函数职责单一，有对应单元测试 |

    def __init__(self, code: str, message: str):

        self.message = message
