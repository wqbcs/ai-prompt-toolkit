## 1. 压缩策略详细设计

### 1.1 渐进压缩级别

| 级别 | 策略组合 | 目标压缩率 | 效果衰减容限 | 适用场景 |
|------|----------|-----------|-------------|----------|
| L0 | 无压缩(原始) | 0% | 0% | 基准对照 |
| L1 | 冗余消除+缩写约定 | 15-25% | <2% | 所有场景(含安全关键) |
| L2 | L1+引用替代+语义合并 | 25-40% | <5% | 非安全关键场景 |
| L3 | L2+模板化+条件折叠 | 40-60% | <8% | 高频简单场景 |

### 1.2 压缩技术细节

#### 冗余消除规则
```
规则RE-1：重复约束合并 → 保留最强表述
  原始："必须使用TypeScript。代码必须用TypeScript编写。TypeScript是强制要求。"
  压缩："必须使用TypeScript(strict mode)"

规则RE-2：默认值省略 → 省略与模型默认一致指令
  原始："请用中文回答。请使用Markdown格式。"
  压缩：(省略，因模型默认中文+Markdown)

规则RE-3：上下文去重 → 引用共享块
  原始：多个场景重复的"角色定义"块
  压缩：{{ref:role_definition}}
```

#### 缩写约定映射
```
CR = Code Review          CI = 持续集成
SLO = 服务等级目标        SLA = 服务等级协议
K8s = Kubernetes          PG = PostgreSQL
TS = TypeScript           FP = 函数式编程
OOP = 面向对象编程        DDD = 领域驱动设计

指令速记：

R = 审查    O = 优化    F = 修复

级别速记：
C = 严重    H = 高      M = 中      L = 低
```

#### 引用替代模板

  role_definition: "角色定义完整内容..."

## 4. 压缩策略推荐

| 场景类别 | 推荐级别 | 压缩率 | 衰减 | 理由 |
|----------|----------|--------|------|------|
| 安全关键(04/07/08) | L1 | ~14% | <0.5% | 安全优先，最小压缩 |
| 复杂业务(01/02/03/05/06) | L2 | ~35% | <2% | 效果保持，适度压缩 |
| 数据工程(12/13/15) | L2 | ~38% | <2% | 信息密度适中 |
| 轻量轻(09/11/14) | L3 | ~45% | <3% | 高频使用，极致压缩 |
| 文档类(10) | L2 | ~35% | <2% | 可读性需保持 |
