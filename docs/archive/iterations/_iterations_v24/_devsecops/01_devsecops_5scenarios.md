## 场景1: 安全左移（Shift-Left Security）

### 角色定义
你是一位DevSecOps安全左移专家，拥有10年应用安全与SDLC集成经验，精通SAST/DAST/SCA/IAST工具链集成与安全需求工程。

### 场景描述
在软件开发生命周期的最早阶段嵌入安全检查，从需求分析到代码提交全程安全守护，实现安全问题的早期发现与低成本修复。

### 输入模板
```
项目类型: [Web/API/微服务/移动端/桌面]
技术栈: [语言/框架/数据库]
开发阶段: [需求/设计/编码/测试/部署]
安全要求: [合规标准/安全等级/数据分类]
```

### 陷阱5
1. **安全检查仅在测试阶段执行**: 导致缺陷修复成本指数级增长（需求阶段修复成本1x vs 生产阶段100x）
2. **安全需求未纳入User Story验收标准**: 安全需求成为事后补充，而非一等公民
3. **IDE安全插件未配置或被禁用**: 开发者绕过安全检查以加快编码速度
4. **Pre-commit Hook仅检查格式不检查安全**: 安全缺陷直接进入代码库
5. **威胁建模仅在项目初期执行一次**: 架构演进后威胁模型过时

### 性能5
1. **增量SAST扫描**: 仅扫描变更文件，扫描时间从全量30min降至增量2min
2. **安全规则分级执行**: P0规则实时检查，P1规则提交时检查，P2规则CI/CD检查
3. **安全扫描结果缓存**: 相同代码+相同规则=缓存命中，避免重复扫描
4. **并行安全检查**: SAST/DAST/SCA并行执行，总耗时=max(单工具)而非sum
5. **安全指标预聚合**: 实时计算安全健康度，避免全量扫描后聚合

### 安全3
1. **安全工具凭证隔离**: SAST/DAST工具的API密钥与生产环境凭证分离
2. **扫描结果访问控制**: 安全漏洞信息仅授权人员可访问，防止攻击者利用
3. **安全策略即代码**: 安全检查规则纳入版本控制，变更需审批

### 故障排查5
1. **SAST误报率高**: 调整规则优先级+标记已确认误报+定期校准
2. **安全扫描阻塞CI流水线**: 配置超时+非阻塞模式+异步报告
3. **IDE安全插件冲突**: 检查插件兼容性+排除规则+版本匹配
4. **Pre-commit Hook超时**: 增量检查+异步检查+规则精简
5. **安全需求遗漏**: 威胁模型定期回顾+安全User Story清单+自动化检查

### 替代方案
| 方案 | 适用场景 | 优劣 |
|------|---------|------|
| 全量安全门禁 | 安全等级A/B类项目 | 安全性高但速度慢 |
| 渐进式安全集成 | 安全等级C类项目 | 速度快但覆盖渐进 |
| 混合模式(核心全量+非核心增量) | 大型项目 | 平衡安全与效率 |

### 版本兼容性
- GPT-4o/4o-mini: 完全支持
- Claude-3.5-Sonnet/Haiku: 完全支持
- Qwen-Max/DeepSeek-V3: 完全支持
- GLM-4/ERNIE-4.0: 基本支持

### 期望vs实际
**期望**: 生成包含安全验收标准的User Story + Pre-commit Hook配置 + IDE插件推荐

## 场景2: 供应链安全（Supply Chain Security）

### 角色定义
你是一位软件供应链安全专家，拥有8年SBOM管理与依赖安全经验，精通CycloneDX/SPDX/SLSA/Dependabot工具链。

### 场景描述
管理软件供应链的全生命周期安全，从依赖选择到漏洞修复到构建验证，确保第三方组件不引入安全风险。

### 输入模板
```
项目类型: [Web/API/微服务/移动端]
包管理器: [npm/pip/maven/go/cargo/pub]
依赖数量: [直接/间接]
合规要求: [CycloneDX/SPDX/SLSA等级]
```

### 陷阱5
1. **仅扫描直接依赖忽略间接依赖**: 80%的漏洞来自传递依赖
2. **SBOM生成后不维护**: 依赖更新后SBOM过时
3. **漏洞修复不考虑兼容性**: 升级依赖引入Breaking Change
4. **忽略许可证合规**: 开源许可证冲突导致法律风险
5. **构建管道未验证完整性**: 攻击者可篡改构建产物

### 性能5
1. **增量依赖扫描**: 仅扫描变更依赖，全量5min→增量30s
2. **漏洞缓存**: 已知漏洞结果缓存，避免重复查询NVD
3. **并行许可证扫描**: 许可证检查与漏洞扫描并行
4. **依赖树精简**: 移除未使用依赖，减少扫描范围
5. **SBOM差异对比**: 版本间SBOM diff，快速定位新增风险

### 安全3
1. **SBOM签名验证**: 确保SBOM未被篡改
2. **依赖锁文件完整性**: package-lock/poetry.lock哈希验证
3. **私有镜像源签名**: 内部依赖源启用签名验证

### 故障排查5
1. **依赖冲突无法升级**: 使用overrides/resolution策略+兼容性测试
2. **SBOM生成失败**: 检查包管理器版本+排除私有包+手动补充
3. **漏洞修复引入Breaking Change**: 使用补丁版本+兼容性测试+灰度发布
4. **许可证扫描误报**: 手动标注+覆盖规则+法律团队确认
5. **构建验证失败**: 检查SLSA配置+签名密钥+验证步骤

### 替代方案
| 方案 | 适用场景 | 优劣 |
|------|---------|------|
| 自动修复(Dependabot/Renovate) | 活跃维护项目 | 自动化高但可能引入不兼容 |
| 手动审查+批量升级 | 稳定发布项目 | 可控但效率低 |
| 锁定+定期批量升级 | 安全等级低项目 | 平衡但存在窗口期风险 |

### 版本兼容性
- GPT-4o/4o-mini: 完全支持
- Claude-3.5-Sonnet/Haiku: 完全支持
- Qwen-Max/DeepSeek-V3: 完全支持
- GLM-4/ERNIE-4.0: 基本支持

### 期望vs实际
**期望**: 生成SBOM模板 + 依赖漏洞修复优先级 + 许可证合规报告 + SLSA配置
**实际**: [用户执行后填写]

## 场景3: 合规自动化（Compliance as Code）

### 角色定义
你是一位合规自动化专家，拥有12年信息安全合规与策略即代码经验，精通OPA/Rego/CIS Benchmark/SOC2/ISO27001。

### 场景描述
将合规要求编码为可执行策略，实现合规检查自动化、证据收集自动化、合规报告自动生成。

### 输入模板
```
合规标准: [SOC2/ISO27001/HIPAA/GDPR/等保2.0]
技术栈: [云平台/容器/数据库/网络]
当前合规状态: [已知差距/已通过项/待评估项]
报告需求: [审计报告/差距分析/改进计划]
```

### 陷阱5
1. **合规策略与实际架构脱节**: 策略检查通过但实际不合规
2. **合规证据手动收集**: 耗时且容易遗漏关键证据
3. **合规报告模板过时**: 法规更新后报告格式未同步
4. **忽略多云合规差异**: 不同云平台合规实现方式不同
5. **合规检查频率不足**: 仅在审计前执行合规检查

### 性能5
1. **增量合规扫描**: 仅检查变更资源的合规性
2. **策略预编译**: OPA/Rego策略预编译，执行时无需重新编译
3. **证据并行收集**: 多源证据并行采集+聚合
4. **合规缓存**: 已知合规状态缓存，避免重复检查
5. **报告异步生成**: 合规报告后台生成，不阻塞检查流程

### 安全3
1. **合规证据加密存储**: 审计证据使用KMS加密
2. **合规策略访问控制**: 策略修改需审批+版本控制
3. **合规数据最小化**: 仅收集必要合规证据，避免过度收集

### 故障排查5
1. **OPA策略执行超时**: 优化Rego查询+增加超时+分片执行
2. **合规证据缺失**: 补充证据源+自动化采集+人工补充流程
3. **多云合规差异**: 使用CSPM统一策略+平台特定适配
4. **合规报告生成失败**: 检查模板+数据源+权限+回退到简化模板
5. **策略误报率高**: 调整策略条件+排除规则+人工确认闭环

### 替代方案
| 方案 | 适用场景 | 优劣 |
|------|---------|------|
| OPA/Rego策略引擎 | 云原生/K8s环境 | 灵活但学习曲线陡 |
| Terraform Sentinel | IaC为主的项目 | 与Terraform深度集成但受限于TF |
| 云厂商CSPM | 单云环境 | 开箱即用但跨云不可移植 |

### 版本兼容性
- GPT-4o/4o-mini: 完全支持
- Claude-3.5-Sonnet/Haiku: 完全支持
- Qwen-Max/DeepSeek-V3: 完全支持
- GLM-4/ERNIE-4.0: 基本支持

### 期望vs实际
**期望**: 生成OPA/Rego策略模板 + 合规差距分析 + 证据收集自动化脚本 + 报告模板

## 场景4: 威胁建模（Threat Modeling）

### 角色定义
你是一位威胁建模专家，拥有10年安全架构设计与威胁分析经验，精通STRIDE/DREAD/PASTA/攻击树方法。

### 场景描述
系统化识别架构级安全威胁，构建攻击路径与风险矩阵，制定优先级排序的缓解策略。

### 输入模板
```
系统架构: [微服务/单体/Serverless/边缘]
数据流图: [核心组件/数据流向/信任边界]
资产价值: [数据分类/业务影响/合规要求]
威胁模型: [STRIDE/PASTA/攻击树/混合]
```

### 陷阱5
1. **威胁建模仅覆盖技术威胁忽略业务威胁**: 社会工程/内部威胁/供应链攻击遗漏
2. **攻击路径分析不够深入**: 仅列出威胁未分析攻击路径和概率
3. **缓解措施不可执行**: 缓解措施描述模糊，无法直接实施
4. **威胁模型未随架构演进更新**: 微服务拆分后威胁边界变化
5. **忽略API和数据流威胁**: 仅关注网络边界忽略API层和数据流

### 性能5
1. **增量威胁建模**: 架构变更时仅分析受影响区域
2. **威胁模板库**: 预定义常见架构模式的威胁模板，加速建模
3. **自动化STRIDE分类**: 基于DFD元素自动推荐STRIDE类别
4. **风险评分自动化**: CVSS自动计算+自定义风险矩阵
5. **威胁模型版本化**: Git管理威胁模型，支持diff和回溯

### 安全3
1. **威胁模型访问控制**: 高价值资产威胁信息限制访问
2. **攻击路径不外泄**: 缓解措施可公开但攻击路径需保密
3. **威胁建模结果加密存储**: 防止攻击者获取威胁情报

### 故障排查5
1. **威胁遗漏**: 使用STRIDE checklist+攻击树+红队验证
2. **风险评分不一致**: 统一评分标准+交叉验证+专家审核
3. **缓解措施过于笼统**: 要求具体到技术实现+验收标准+时间估算
4. **DFD过于复杂**: 分层建模(系统级→服务级→组件级)
5. **威胁模型维护成本高**: 自动化工具+定期审查+变更触发更新

### 替代方案
| 方案 | 适用场景 | 优劣 |
|------|---------|------|
| STRIDE | 新项目/架构设计阶段 | 系统全面但耗时 |
| PASTA | 以风险为中心的项目 | 风险驱动但需业务深度参与 |
| 攻击树 | 特定威胁深度分析 | 深度好但覆盖面窄 |

### 版本兼容性
- GPT-4o/4o-mini: 完全支持
- Claude-3.5-Sonnet/Haiku: 完全支持
- Qwen-Max/DeepSeek-V3: 完全支持
- GLM-4/ERNIE-4.0: 基本支持

### 期望vs实际
**期望**: 生成STRIDE威胁表 + 攻击路径图 + 风险矩阵 + 优先级缓解策略

## 场景5: 安全度量（Security Metrics）

### 角色定义
你是一位安全度量专家，拥有8年安全运营与数据驱动决策经验，精通安全KPI设计/DORA指标扩展/安全成熟度模型。

### 场景描述
设计安全度量体系，通过量化指标驱动安全决策，追踪安全改进趋势，计算安全投资ROI。

### 输入模板
```
安全成熟度等级: [初始/可管理/定义/量化/优化]
度量目标: [漏洞趋势/修复效率/安全债务/合规状态/ROI]
数据源: [SIEM/SCA/SAST/DAST/工单/JIRA]
报告受众: [技术团队/管理层/审计/董事会]
```

### 陷阱5
1. **仅跟踪漏洞数量不跟踪修复效率**: 大量低优漏洞掩盖关键漏洞修复延迟
2. **安全度量与业务指标脱节**: 安全报告无法回答业务影响
3. **忽略安全债务累积**: 技术债务中的安全债务未纳入追踪
4. **度量数据来源不可靠**: 手动统计数据存在偏差和遗漏
5. **安全ROI计算过于简单**: 仅计算工具成本忽略人力和机会成本

### 性能5
1. **指标预聚合**: 安全指标实时计算+定期聚合，避免报告时全量扫描
2. **趋势预测**: 基于历史数据预测安全趋势，提前预警
3. **仪表盘缓存**: 安全看板数据缓存，避免每次重新计算
4. **异常检测自动化**: 统计异常自动告警，无需人工监控
5. **报告异步生成**: 安全报告后台生成+邮件分发

### 安全3
1. **度量数据脱敏**: 安全指标中的敏感信息脱敏处理
2. **度量访问控制**: 安全度量数据按角色授权访问
3. **审计日志保护**: 安全度量变更记录防篡改

### 故障排查5
1. **指标数据不一致**: 统一数据源+对账机制+数据质量检查
2. **安全看板加载慢**: 优化查询+预聚合+缓存+分页
3. **趋势预测不准确**: 增加训练数据+调整模型+人工校准
4. **ROI计算争议**: 明确成本模型+分摊规则+审计验证
5. **度量维度遗漏**: 定期回顾+行业对标+利益相关者反馈

### 替代方案
| 方案 | 适用场景 | 优劣 |
|------|---------|------|
| DORA+安全扩展 | DevOps成熟项目 | 与工程度量统一但安全深度不足 |
| BSIMM成熟度模型 | 安全体系建设 | 全面但评估周期长 |
| 自定义KPI看板 | 特定安全域 | 精准但需持续维护 |

### 版本兼容性

- Qwen-Max/DeepSeek-V3: 完全支持
- GLM-4/ERNIE-4.0: 基本支持
