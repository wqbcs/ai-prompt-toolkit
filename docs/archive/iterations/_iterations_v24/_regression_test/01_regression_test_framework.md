## 一、效果回归测试框架

### 1.1 核心架构

```
版本变更触发 → 基线加载 → 回归测试执行 → 结果对比 → 退化判定 → 阻止/放行
     │              │            │            │          │          │
     └── Git Hook   └── JSON     └── 批量    └── Diff   └── 阈值  └── 门禁
```

### 1.2 基线管理

| 基线类型 | 内容 | 存储格式 | 更新时机 |
|---------|------|---------|---------|
| 版本基线 | 每个版本的提示词+评分+输出样本 | JSON | 版本发布时 |
| 场景基线 | 每个场景的测试用例+期望输出 | YAML | 场景变更时 |
| 模型基线 | 每个模型的基线性能 | JSON | 模型切换时 |
| 维度基线 | 每个维度的评分快照 | JSON | 维度变更时 |

**基线格式**:
```json
{
  "version": "v23.0.0",
  "timestamp": "2026-07-12T00:00:00Z",
  "scenario": "代码审查",
  "test_cases": [
    {
      "id": "TC-001",
      "input": "...",
      "expected_output": "...",
      "actual_output": "...",
      "scores": {
        "accuracy": 0.92,
        "completeness": 0.88,
        "relevance": 0.95,
        "safety": 1.0
      }
    }
  ],
  "aggregate_scores": {
    "accuracy": 0.91,
    "completeness": 0.87,
    "relevance": 0.94,
    "safety": 1.0
  }
}
```

### 1.3 回归测试执行

| 测试类型 | 触发条件 | 执行范围 | 超时 |
|---------|---------|---------|------|
| 完整回归 | 版本发布 | 全量场景 | 4小时 |
| 增量回归 | 场景变更 | 受影响场景 | 30分钟 |
| 快速回归 | 提交触发 | 核心场景 | 5分钟 |
| 热修复回归 | 紧急修复 | 修复场景+关联场景 | 15分钟 |

**测试用例结构**:
```yaml
test_case:
  id: TC-CODE-REVIEW-001
  name: 代码审查-安全漏洞检测
  category: 代码审查
  priority: P0
  input:
    prompt_template: code_review_security
    variables:
      language: Python
      code_snippet: "..."
  expected:
    must_contain: ["SQL注入", "XSS", "CSRF"]
    must_not_contain: ["忽略安全", "跳过检查"]
    score_threshold:
      accuracy: 0.85
      completeness: 0.80
      safety: 0.95
```

### 1.4 效果对比引擎

| 对比维度 | 指标 | 计算方式 |
|---------|------|---------|
| 准确率对比 | ΔAccuracy | (新-旧)/旧 × 100% |
| 完整性对比 | ΔCompleteness | (新-旧)/旧 × 100% |
| 相关性对比 | ΔRelevance | (新-旧)/旧 × 100% |
| 安全性对比 | ΔSafety | 新-旧（绝对值） |
| Token效率 | ΔTokenEfficiency | (旧Token-新Token)/旧Token × 100% |
| 延迟对比 | ΔLatency | 新延迟-旧延迟 |

**统计显著性检验**:
```
使用配对t检验:
- H0: 新版本效果不劣于旧版本
- 置信水平: 95%
- 效果量: Cohen's d
- 样本量: >= 30（中心极限定理）
```

## 二、退化阻止机制

### 2.1 退化判定规则

| 退化级别 | 条件 | 动作 |
|---------|------|------|
| 严重退化 | 任意维度下降>10%或安全评分下降 | 阻止发布+紧急修复 |
| 显著退化 | 任意维度下降5-10% | 阻止发布+定向改进 |
| 轻微退化 | 任意维度下降2-5% | 告警+人工审批 |
| 无退化 | 所有维度下降<2% | 自动放行 |
| 改进 | 任意维度提升 | 自动放行+记录 |

### 2.2 自动回退机制

| 触发条件 | 回退策略 | 验证步骤 |
|---------|---------|---------|
| 严重退化 | 自动回退到上一版本 | 回退后回归测试 |
| 显著退化 | 回退受影响场景 | 受影响场景回归测试 |
| 轻微退化 | 保留+告警+人工决策 | 人工验证后决定 |
| 生产环境退化 | 灰度回退+全量回退 | 全量回归测试 |

### 2.3 回退保护机制

```
版本发布
  ├── 灰度发布（5%流量）
  │   ├── 监控效果指标
  │   ├── 检测退化
  │   └── 退化 → 自动回退灰度
  ├── 扩大发布（50%流量）
  │   ├── 监控效果指标
  │   └── 退化 → 回退到灰度
  └── 全量发布（100%流量）
      ├── 监控效果指标
      └── 退化 → 回退到50%或全量回退
```

### 2.4 退化报告模板

```markdown

### 基本信息
- 版本: v24.0.0 → v23.0.0
- 触发时间: 2026-07-12T10:00:00Z

### 退化详情

|------|---------|---------|------|------|
| 代码审查-准确率 | 0.92 | 0.85 | -7.6% | 显著 |
| 代码审查-完整性 | 0.88 | 0.86 | -2.3% | 轻微 |

### 退化原因分析
[自动分析+人工补充]
```
