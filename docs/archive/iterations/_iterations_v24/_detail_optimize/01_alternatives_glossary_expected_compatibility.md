## 一、替代方案章节（所有场景模板统一添加）

### 1.1 替代方案规范

每个场景模板在"故障排查5"之后添加"替代方案"章节，格式统一为：

```markdown
### 替代方案

| 方案 | 适用场景 | 优劣 |
|------|---------|------|
| 方案A | [适用场景描述] | 优势: [核心优势] 劣势: [核心劣势] |
| 方案B | [适用场景描述] | 优势: [核心优势] 劣势: [核心劣势] |
| 方案C | [适用场景描述] | 优势: [核心优势] 劣势: [核心劣势] |
```

### 1.2 替代方案设计原则

1. **至少2种最多3种替代方案**: 不宜过多导致选择困难
2. **方案间需有明确区分**: 不是简单变体而是不同实现路径
3. **适用场景需具体**: 不能是"通用场景"而需有明确边界
4. **优劣势需客观量化**: 优于/劣于而非好/差
5. **推荐标记**: 最推荐方案用⭐标记

### 1.3 已完成替代方案覆盖统计

## 二、术语首现注释规范

### 2.1 注释规范

所有场景模板中，专业术语首次出现时需标注英文原文，格式：

```
中文术语（English Term）
```

**示例**:
- 提示词注入（Prompt Injection）
- 越狱攻击（Jailbreak Attack）
- 差分隐私（Differential Privacy）
- 服务等级协议（Service Level Agreement, SLA）
- 软件物料清单（Software Bill of Materials, SBOM）

### 2.2 术语分类与注释规则

| 术语类别 | 注释规则 | 示例 |
|---------|---------|------|
| 安全术语 | 首现标注英文 | 注入检测（Injection Detection） |
| 性能术语 | 首现标注英文+缩写 | 首Token延迟（Time To First Token, TTFT） |
| 合规术语 | 首现标注英文+缩写 | 个人身份信息（Personally Identifiable Information, PII） |
| 技术术语 | 首现标注英文 | 微分段（Micro-segmentation） |
| 方法论术语 | 首现标注英文 | 威胁建模（Threat Modeling） |

| 术语 | 英文 | 定义 |

## 三、期望vs实际对比格式

### 3.1 对比格式规范

所有场景模板的输出示例添加"期望vs实际"对比，格式：

```markdown
### 期望vs实际

**期望输出**:
[描述理想的输出结果，包含关键要素]

**实际输出**:
[用户执行后填写的实际输出，包含差异标注]
```

### 3.2 对比分析维度

| 维度 | 期望描述 | 实际描述 | 差异标注 |
|------|---------|---------|---------|
| 完整性 | 是否包含所有必要要素 | 实际输出要素覆盖 | ✅/⚠️/❌ |
| 准确性 | 信息是否准确无误 | 实际输出准确程度 | ✅/⚠️/❌ |
| 可操作性 | 建议是否可直接执行 | 实际建议可执行度 | ✅/⚠️/❌ |
| 格式规范 | 是否符合输出格式要求 | 实际输出格式合规度 | ✅/⚠️/❌ |

### 3.3 对比报告模板

```markdown
## 场景: [场景名称] - 期望vs实际对比

### 期望输出
1. 包含[要素A]+[要素B]+[要素C]
2. 格式符合[规范X]
3. 建议可直接执行

### 实际输出
1. ✅ 包含[要素A] ⚠️ [要素B]不完整 ❌ 缺少[要素C]
2. ✅ 格式符合[规范X]
3. ⚠️ [建议Y]不够具体

### 改进建议
1. 补充[要素C]的生成逻辑
2. 增强建议Y的具体性
```

## 四、版本兼容性标注

### 4.1 兼容性标注规范

所有场景模板添加"版本兼容性"章节，格式：

```markdown
### 版本兼容性

| 模型 | 兼容性 | 备注 |
|------|--------|------|
| GPT-4o/4o-mini | ✅ 完全支持 | 无限制 |
| Claude-3.5-Sonnet/Haiku | ✅ 完全支持 | 无限制 |
| Qwen-Max/DeepSeek-V3 | ✅ 完全支持 | 无限制 |
| GLM-4/ERNIE-4.0 | ⚠️ 基本支持 | 复杂推理可能降级 |
| Llama-3/Mistral | ⚠️ 部分支持 | 长上下文场景可能截断 |
| 本地7B-13B模型 | ❌ 不推荐 | 能力不足 |
```

### 4.2 兼容性评估维度

| 评估维度 | 说明 | 评分标准 |
|---------|------|---------|
| 完全支持 | 所有功能正常工作 | ✅ |
| 基本支持 | 核心功能正常，高级功能可能降级 | ⚠️+说明 |
| 部分支持 | 部分功能不可用 | ⚠️+不可用项 |
| 不推荐 | 效果严重降级 | ❌+原因 |
