## 二、逐项目深度分析

### 2.1 promptfoo (23.5k⭐) — 最直接竞品

**核心特性:**
- 声明式YAML配置驱动评估(`promptfooconfig.yaml`)
- 多Provider并行对比(GPT/Claude/Gemini/DeepSeek等)
- 内置Web Viewer可视化评估矩阵
- 红队漏洞扫描(Red Teaming) — 完整安全报告
- CI/CD集成(GitHub Actions code-scan-action)
- 本地缓存 + Live Reload开发体验
- 已被OpenAI收购，MIT许可
- 419个release，迭代极快(9252 commits)
- Docker/Helm部署支持

**最新特性(v0.121.x):**
- `code-scan-action` — GitHub PR自动扫描LLM安全合规
- Drizzle ORM数据库层
- Agent评估支持(.agents配置)
- MCP Server集成
- 多模态评估

**我们已有但promptfoo更强的:**
| 特性 | 我们(prompt-toolkit) | promptfoo | 差距 |
|------|---------------------|-----------|------|
| Lint规则 | 80条(Python) | 无 | **我们领先** |
| Fixer自动修复 | 25条 | 无 | **我们领先** |
| 红队Probes | 90个 | ~40+策略 | 接近 |
| 评估方式 | 自定义评估器 | 声明式assert + 模型graded | 各有优势 |
| CI/CD | 无 | GitHub Action | **他们领先** |
| 可视化 | CLI输出 | Web Viewer + 矩阵对比 | **他们领先** |
| Provider | 华为云专项 | 50+通用Provider | 互补 |

**可借鉴点(优先级排序):**

| # | 借鉴特性 | 优先级 | 说明 |
|---|---------|--------|------|
| 1 | **Web Viewer评估矩阵** | P0 | 对比矩阵是最直观的评估结果展示，promptfoo的核心UX。我们可用React+Tailwind实现 |
| 2 | **GitHub Action code-scan** | P0 | CI/CD集成是开发者刚需，promptfoo有现成action可直接参考 |
| 3 | **声明式评估配置** | P1 | YAML配置降低使用门槛，我们已有YAML评估配置，可增强 |
| 4 | **多Provider并行对比** | P1 | A/B对比模型输出，我们的AB-Test可扩展为矩阵模式 |
| 5 | **Live Reload开发模式** | P2 | 开发时自动重新运行评估，提升开发体验 |

### 2.2 DeepEval (17k⭐) — 评估指标体系最全

**核心特性:**
- **Pytest风格**单元测试 — `@observe()`装饰器 + `assert_test()`
- **30+内置评估指标**(分类最细):
  - 通用: G-Eval, DAG(图构建确定性评估)
  - RAG: Answer Relevancy, Faithfulness, Contextual Recall/Precision/Relevancy
  - Agent: Task Completion, Tool Correctness, Goal Accuracy, Step Efficiency, Plan Adherence/Quality
  - 多轮: Knowledge Retention, Conversation Completeness, Turn Relevancy/Faithfulness, Role Adherence
  - MCP: MCP Task Completion, MCP Use, Multi-Turn MCP Use
  - 多模态: Text-to-Image, Image Editing, Image Coherence/Helpfulness/Reference
  - 其他: Hallucination, Summarization, Bias, Toxicity, JSON Correctness, Prompt Alignment
- 合成数据集自动生成(单轮+多轮)
- Prompt自动优化(基于评估结果)
- 10行代码跑Benchmark(MMLU, HellaSwag, DROP, GSM8K等)
- Confident AI云平台(MCP Server集成)
- **Tracing系统**: `@observe()` + `trace()` + `update_current_span()`
- 框架集成: OpenAI/LangChain/LangGraph/Pydantic AI/CrewAI/Anthropic/LlamaIndex/Google ADK/AWS AgentCore/Strands
- Vibe-Coder模式: AI Agent自动生成eval + 修复

**可借鉴点(优先级排序):**

| # | 借鉴特性 | 优先级 | 说明 |
|---|---------|--------|------|
| 1 | **G-Eval指标** | P0 | 研究支撑的LLM-as-judge指标，人类水平准确度，我们评估器注册表可集成 |
| 2 | **Faithfulness/Hallucination指标** | P0 | RAG场景刚需，我们缺少专门的Faithfulness评估 |
| 3 | **Agent评估指标体系** | P0 | Task Completion/Tool Correctness/Step Efficiency等，Agent时代核心需求 |
| 4 | **DAG图构建评估** | P1 | 确定性+LLM混合评估，比纯LLM-as-judge更可控 |
| 5 | **Tracing系统** | P1 | `@observe()`装饰器模式，端到端+组件级评估 |
| 6 | **多轮对话评估指标** | P1 | Knowledge Retention/Role Adherence等，对话式AI刚需 |
| 7 | **MCP评估指标** | P1 | MCP Task Completion/Use，我们已有MCP Server可扩展 |
| 8 | **Benchmark集成** | P2 | MMLU等标准benchmark一行代码跑 |

### 2.3 textgrad (3.7k⭐) — Prompt自动优化引擎

**核心特性:**
- **PyTorch风格API**: `Variable`, `TextLoss`, `TGD(Textual Gradient Descent)`优化器
- **反向传播通过文本反馈**: LLM提供"文本梯度"，迭代优化变量
- 支持: Prompt优化、代码优化、Solution优化、多模态优化
- Nature论文发表(2025.03)
- litellm引擎: 支持Bedrock/Together/Gemini/任意模型
- 缓存支持

**核心模式:**
```python
import textgrad as tg
answer = tg.Variable(initial, requires_grad=True)
optimizer = tg.TGD(parameters=[answer])
loss_fn = tg.TextLoss(evaluation_instruction)
loss = loss_fn(answer)
loss.backward()
optimizer.step()
```

**可借鉴点(优先级排序):**

| # | 借鉴特性 | 优先级 | 说明 |
|---|---------|--------|------|
| 1 | **TextGrad优化器** | P0 | 我们的Fixer是规则修复，TextGrad是LLM反馈迭代优化，两者互补。可实现TGD优化器注册到评估器注册表 |
| 2 | **TextLoss函数** | P0 | 自然语言定义损失函数，与我们的YAML评估配置天然结合 |
| 3 | **多轮迭代优化策略** | P1 | 收敛判断、早停、学习率调整等策略 |
| 4 | **Variable抽象** | P1 | 统一优化目标(Prompt/代码/方案)，与我们的模板系统结合 |
| 5 | **华为云Pangu模型后向引擎** | P1 | litellm + 自定义引擎，可接入盘古模型做后向传播 |
| 6 | **缓存机制** | P2 | 优化过程中间结果缓存，避免重复调用 |

### 2.4 RAGAS (14.9k⭐) — RAG评估+测试数据生成

**核心特性:**
- **DiscreteMetric**: 离散值评估(accurate/inaccurate等)，支持reason
- **测试数据自动生成**: 合成测试数据集，单轮+多轮
- **RAG专项评估**: Answer Relevancy, Faithfulness, Contextual Precision/Recall/Relevancy
- **CLI**: `ragas quickstart rag_eval` 一键创建评估项目
- **Dataset版本化**: `Dataset(backend="local/csv")`
- **LLM适配器**: OpenAI/Anthropic/Gemini/Ollama/自定义
- **优化器**: 评估结果驱动的应用优化

**可借鉴点(优先级排序):**

| # | 借鉴特性 | 优先级 | 说明 |
|---|---------|--------|------|
| 1 | **测试数据自动生成** | P0 | 我们有数据集版本化但缺自动生成，RAGAS的合成数据生成是最强特性 |
| 2 | **DiscreteMetric离散评估** | P1 | 与我们的评估器互补，支持reason解释 |
| 3 | **quickstart CLI模板** | P1 | 一键创建评估项目，降低入门门槛 |
| 4 | **RAG专项指标** | P1 | Contextual Precision/Recall是RAG独有的，我们可扩展 |
| 5 | **优化器架构** | P2 | 评估→优化闭环，与textgrad互补 |

## 五、创新突破点(鬼才巧思)

### 5.1 终极脑洞: Prompt OS — 一站式Prompt工程操作系统

将Lint→Fix→Eval→Optimize→Deploy→Monitor形成完整闭环，这是所有竞品都没做到的:

```
Lint(发现问题) → Fixer(规则修复) → Eval(评估验证) 
  → TextGrad(LLM迭代优化) → Deploy(华为云部署) → Tracing(生产监控) → 回流Eval
```

### 5.2 差异化杀手特性

| # | 特性 | 灵感来源 | 鬼才巧思 |
|---|------|---------|---------|
| 1 | **Lint→Fix→TextGrad三级修复** | textgrad + 我们的Fixer | 规则能修的规则修，修不了的TextGrad迭代优化 |
| 2 | **华为云全链路可观测** | Langfuse Tracing | LTS+OBS+ModelArts一站式可观测，竞品无法复制 |
| 3 | **盘古模型原生评估** | DeepEval G-Eval | 盘古做评估Judge，中文场景准确度更高 |
| 4 | **鸿蒙AI Agent专项评估** | DeepEval Agent指标 | 全球首个鸿蒙Agent评估框架 |
| 5 | **对抗攻击+安全Lint双保险** | promptfoo红队 + 我们的安全Lint | Lint查静态问题，红队查动态漏洞 |
