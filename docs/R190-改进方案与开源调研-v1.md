# R190 改进方案与开源调研 (v1)

> 产出时间: 2026-09-27 | 依据: R189完成后现状 + 外部调研(promptfoo/garak/deepeval对比、prompt review实践)
> 指导原则: 第一性原理 / 奥卡姆剃刀 / 反低价值打磨陷阱 / 不重复造轮子

---

## 一、定位反思(每轮迭代必答)

| 问题 | 答案 |
|------|------|
| **项目定位是啥** | Prompt工程的CI门禁工具 — "prompts的ESLint + 安全扫描"。不是eval平台、不是LLM网关、不是观测平台 |
| **核心价值是啥** | ①零Token静态lint(255规则) ②安全/合规扫描(OWASP LLM映射/等保) ③CI硬门禁(SARIF/退出码) — 三者都指向同一句话: **把prompt当代码管, 在PR阶段拦住缺陷** |
| **当前方向有啥问题** | 见下方"低价值打磨陷阱自查" |
| **如何调整** | 聚焦"lint+门禁"主轴做深做透; eval/redteam/market等周边保持可用即可, 不再主动加码 |

## 二、低价值打磨陷阱自查(反问记录)

| 陷阱 | 判定 | 决策 |
|------|------|------|
| 继续堆Lint规则数(P256+) | ❌ 陷阱 — 规则数量不是价值, 覆盖真实事故模式才是 | 停止扩规则; 转向"规则从真实事故沉淀"机制(见F2) |
| 自研eval维度D131+ | ❌ 陷阱 — deepeval 50+指标/RAGAS已成熟, 自研无差异化 | eval保持现状, 不新增维度 |
| 自研红队探针生成 | ❌ 重复造轮子 — promptfoo的AI动态生成攻击是其核心壁垒, 追不上也不该追 | redteam保持静态探针, 定位"快速审计"而非"深度对抗" |
| 自研LLM Provider抽象 | ⚠️ 已有24个provider, 但外部已有litellm等成熟轮子 | 暂不动(替换风险>收益), 记入技术债, 不再新增provider |
| mypy/ruff/测试覆盖率等工程质量 | ✅ 高价值 — 这是工具链自身的"可信度资产", 门禁工具自己必须干净 | 继续(本轮R190即mypy治理) |
| Web UI/playground打磨 | ❌ 当前阶段陷阱 — CLI工具的抓手是CI集成和安装体验, 不是UI | 冻结playground投入 |
| **发布工程(PyPI/文档/安装体验)** | ✅ **最大缺口** — 包在PyPI上不存在, README的pip install是空头支票; 用户体验第一触点是坏的 | **R191主攻方向** |

## 三、外部调研结论(可复用资源)

| 来源 | 可借鉴 | 对本项目 |
|------|--------|----------|
| promptfoo (MIT) | YAML配置即测试、CI原生集成、AI生成攻击 | 配置schema设计可参考; 攻击生成不追 |
| garak (Apache-2.0, NVIDIA) | 探针分类学、buffs扰动 | 探针组织方式已对齐, 无需动 |
| deepeval (pytest-native) | pytest-native断言、指标即pytest用例 | F3 assertion pytest化可参考 |
| Medium: Prompt Review 2025 | **每事故沉淀一条lint规则的机制**; token diff上报PR; pre-commit五秒反馈 | F1/F2直接采纳 — 这是lint工具的长期护城河 |
| 调研总判断 | lint工具赛道比eval早期得多, 结构化prompt校验做硬门禁是正确卡位 | 定位确认, 不漂移 |

## 四、改进清单(分级)

### P0 — 发布与可信度(用户第一触点)
- **F1 PyPI发布工程**: twine发布脚本+CI自动发版(tag触发); README安装命令真实可用
- **F2 lint规则从测试逆向对齐**: 现有255条规则的测试覆盖审计, 无测试的规则标记并补齐(规则的正确性=工具的生命线)

### P1 — 质量与门禁深化(主轴)
- **F3 mypy棘轮继续压降**: 本轮no-any-return批(~30) + supply_chain 2处; 目标两轮内<150, 最终0错误硬门禁
- **F4 assertion引擎pytest化对齐**: 断言(contains/regex/no_pii等)支持pytest插件式消费(deepeval模式), 让prompt断言进入用户现有pytest流程 — 复用而非自建测试框架

### P2 — 体验细节(低成本高感知)
- **F5 doctor命令增强**: 检测mypy/ruff/pytest本地环境并给出pre-commit一键配置建议
- **F6 错误信息人话化审计**: cli_error_formatter覆盖所有异常路径(已有基础, 查漏)

### 暂缓/拒绝(记档防漂移)
- ❌ Web UI / playground打磨
- ❌ 新增lint规则数量竞赛
- ❌ 新增LLM provider(litellm替代方案记技术债)
- ❌ AI动态攻击生成(promptfoo壁垒, 不追)
- ❌ eval维度扩展
