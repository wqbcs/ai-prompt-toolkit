# R212 改进方案与开源调研

> ai-prompt-toolkit v67.27.0+ R212轮次 | 基于: R211现状盘点 + 互联网调研(promptlint/promptfoo/garak/promptci/PromptOps/中文社区) + 定位反问
> 前情: 误报率 8.38%→1.35% (R203→R211, 56干净样本), 高误报规则 41→7, mypy 0, 全量 5684 passed

## 0. 定位反问（鬼才产品经理视角）

**问1: 项目定位是什么?**
"ESLint for Prompts" — 零LLM调用的Prompt静态质量+安全工具链, 中文优先+华为云/鸿蒙生态。
竞品坐标: promptfoo(动态红队, 需LLM) / garak(模型端审计) / promptlint(2026新竞品, 纯静态lint,
最近身) / promptci+PromptOps(prompt资产化: 版本+门禁+渲染变量检测)。
**结论: 定位依然成立且稀缺** — 纯静态、零API、255规则密度无人超越; promptlint 20+规则
就能撑起一个产品, 反证"规则准"比"规则多"重要。

**问2: 核心价值是什么?**
不花token、不接API, 10秒内知道"这个Prompt能不能上生产"。
**推论: 可信度=双基线** — R203-R211 五轮只压了"误报率"(噪音面), 但从未度量"漏检率"
(该报没报面)。误报率1.35%只证明"不烦人", 不证明"有用"。**漏检基线是下一轮可信度
建设的对称缺口** — lint工具被用户淘汰的另一死因是真问题没报出来。

**问3: 当前推进方向有什么问题?**
对抗性审查发现4个方向性问题:
1. **单基线偏科**: 误报率连续5轮下降(8.38%→1.35%), 漏检率零度量。指标方向正在
   滑向"一个几乎从不告警的lint工具" — 那是最无聊的产品, 也是误报治理的过度目标。
2. **口径漂移复发**(同一故障源第三次出现): probes三个数(23/94/116), 版本号四处不一致
   (代码67.25.0 / CHANGELOG v67.27.0 / pip元数据67.7.0 / 徽章67.25.0), Tests徽章
   3665 vs 实际5684。R194/R207-6修过两次, 根因=同步脚本没进强制门禁, 靠人记必复发。
3. **CLI第一触点暗雷**: `python -m ai_prompt_toolkit.cli_core` 只显示 3/68 命令 —
   `if __name__ == "__main__"` 守卫位于文件中部(命令注册import之前), 用户照做
   得到残废CLI; `python -m ai_prompt_toolkit` 直接报无 `__main__` 模块。
4. **广度冲动**: 255规则已超竞品一个数量级; +1条新规则的边际价值 < 把存量做准
   +补漏检度量+修第一触点的边际价值。

**问4: 低价值打磨陷阱在哪?**
- ❌ P256+新规则(误报/漏检双基线不全前, 新规则=未度量的噪音+盲区)
- ❌ probes 23→200+扩样(三个口径都没统一, 数量无意义)
- ❌ 9语言i18n全量/华为云特性加码(核心用户无验证环境, 代码只会腐烂)
- ❌ 追promptfoo式动态红队(需LLM调用, 破坏"零调用"定位根基)
- ✅ 应该做: 漏检基线(对称可信度) / 模板变量静态检查(复用PromptOps思路) /
  四维健康分(复用promptlint思路) / 版本+徽章口径根治(消灭复发源) /
  CLI -m 真bug / 误报Top7收尾(1.35%→<1%)

## 1. 互联网调研信号 (R212轮)

| 信号源 | 关键发现 | 对本项目的含义 |
|--------|---------|---------------|
| promptlint (2026, PyPI/npm, Apache-2.0) | 最近身竞品: 20+纯静态规则; **A–F四维健康分**(Security/Cost/Quality/Completeness); `--baseline`增量门禁(仅新违规fail); SARIF; GitHub Action内联PR标注; **cost预估**(按调用量投影日成本, INFO级finding) | ①四维健康分>单维安全分 ②lint时cost预估是标配 ③baseline diff门禁我们已有(`--baseline compare`), 语义对齐即可 ④其"20条准规则"反向验证误报治理方向正确 |
| promptfoo vs garak (2025对比文) | 行业分裂确认: promptfoo=动态AI生成攻击+合规映射(OWASP/NIST/MITRE/EU AI Act)+CI原生; garak=静态研究攻击库+模型端单轮审计 | 本项目=静态侧, 对象是prompt文本(非模型端), 与两者互补不冲突; OWASP LLM 2025+Agentic 2026双映射是相对promptlint的护城河 |
| promptci/promptregistry (2026) | "prompt changes are the most common cause of silent LLM regressions"; 版本+diff+gate管线(LengthGate/**VariableGate**/InjectionRiskGate); PII scrub; audit log; cost ledger | 版本/diff/gate我们已有; **VariableGate(变量完整性)我们缺** → R212-4 |
| PromptOps (2026, local-first, TS) | 注册表+semver+diff+**render时unresolved/unused变量检测**+append-only审计+8步builder向导; 零LLM零依赖 | unresolved/unused变量检测=零成本高价值静态检查, 思路可直接移植 → R212-4; builder向导我们已有wizard, 不重复造 |
| 中文社区(CSDN/PromptShelf/MLflow Prompt管理) | 痛点: 版本混乱/复用困难/部署风险/效果评估; "Git只管文本diff, 管不了环境隔离/性能追踪/非确定性评估"; **黄金数据集(50-200条)+统计检验**判断版本优劣 | ab_test/eval_matrix部分覆盖; 黄金集显著性检验(版本A vs B)是缺口 → 记R213+候选, 本轮不动 |

**可复用资产结论**: 本轮**不引入任何新第三方依赖**。promptlint/promptci/PromptOps
均为**思路复用**非代码复用 — 其规则引擎/评分公式/变量检测语义作参照, 代码不搬
(与255规则体系架构冲突; 奥卡姆剃刀: 变量检测/健康分用现有 linter+token_analyzer
+pricing 一等公民组件即可实现)。

## 2. R212改进清单

### R212-1: CLI `python -m` 入口真bug修复 (P0, 0.2日)
**现状**: `cli_core.py` 的 `if __name__ == "__main__": main()` 在文件中部(L552),
而 11 个命令簇的注册 import 在文件末尾(L703) → `-m` 运行时 main() 先执行,
65条命令尚未注册, 帮助只显示 completion/doctor/probe 3条。
**改动**: ①`__main__`守卫移到文件末尾(import之后) ②新增 `ai_prompt_toolkit/__main__.py`
使 `python -m ai_prompt_toolkit` 可用 ③测试: 子进程跑 `python -m ai_prompt_toolkit --help`
断言命令数≥50。
**验证**: `-m` 帮助命令数与 `prompt-cli --help` 一致; 全量回归。

### R212-2: 版本号与徽章口径根治 (P0, 0.5日)
**现状**: 代码67.25.0 / CHANGELOG v67.27.0 / pip元数据67.7.0 / README徽章67.25.0
/ Tests徽章3665(实际5684)。同步脚本(sync_badges.py)存在但不在任何强制门禁里。
**改动**: ①pyproject+`__init__` 升至67.27.0 ②跑 sync_badges.py 刷新全部徽章
(版本号+真实测试数) ③**根治复发源**: pre-commit 加轻量校验(README Version徽章==
`__version__`, 不做pytest收集) + daily-scorecard workflow 跑 sync_badges.py 后
`git diff --exit-code` 漂移即fail。
**验证**: 四处版本号一致; 徽章测试数=真实收集数; pre-commit校验可拦截人为改坏徽章。

### R212-3: 漏检率基线建立 — 双基线对称可信度 (P0, 1日)
**现状**: 只有误报基线(干净样本不报), 无漏检基线(脏样本必报)。255条规则的
检测能力从未被系统性度量 — 误报治理5轮可能同时在无声削减真阳性。
**改动**(度量先行, 本轮不改任何规则):
1. 从既有测试脏样本(test_rules_*/attack fixtures)聚合**golden攻击集**
   (目标≥40条, 覆盖注入/越狱/敏感泄露/PII/结构缺陷五类, 每条标注期望命中规则)
2. 新建 `scripts/check_miss_rate.py`: 对golden集跑全量规则, 输出每条规则的
   命中率(期望命中/实际命中) + 全局漏检率 + 零命中规则清单
3. 新建 `docs/规则漏检率基线.md`: 基线值+口径说明(与误报基线同构)
4. CI 加漏检率棘轮(只降不升, 同 check_mypy_ratchet 模式)
**验证**: 脚本可复现; 基线文档落盘; 棘轮exit=0; 不改变任何现有规则行为。
**对抗性备注**: 不做规则调整 — 本轮只立标尺。若暴露大面积零命中规则, R213再处置
(避免"测量+修复"混杂导致归因不清)。

### R212-4: 模板变量静态检查 (P1, 0.8日, 复用PromptOps/promptci思路)
**现状**: `{{var}}`模板引用无完整性检查 — 引用了未声明的变量/声明了未使用的变量,
渲染时才炸(运行时才发现=最贵的发现时机)。竞品PromptOps/Promptci均有此门。
**改动**: 新增lint规则(编号顺延既有空位, 走rules.py注册):
1. **未声明引用**: prompt引用`{{x}}`但frontmatter/变量声明段无x → HIGH
2. **声明未使用**: 声明了变量但正文从未引用 → LOW(信息级)
3. 触发门(沿用R211纪律, 防新噪音): 仅当正文`{{`≥1时激活; 代码围栏内剥离;
   声明识别覆盖 frontmatter `variables:`/`输入:`/`变量:` 段落
4. **负样本纪律: 56干净样本0命中从第一天断言**(含clean43-46四个模板样本)
**验证**: 正样本(引用未声明/声明未用)命中, 负样本(完整模板/文档提及{{}})不报,
56干净样本0命中; 全量回归。

### R212-5: 四维健康分 (P1, 0.8日, 复用promptlint思路)
**现状**: `prompt-cli score` 仅单维安全评分。promptlint已把四维
(Security/Cost/Quality/Completeness, A–F)做成默认输出 — 单维分用户无法决策。
**改动**(全部派生自现有组件, 零新启发式):
1. Security分 = 现有score逻辑(不变)
2. Quality分 = lint findings按severity加权(规则已有分类)
3. Completeness分 = 关键维度覆盖(结构/输出格式/错误处理 — 复用现有规则命中面)
4. Cost分 = token_analyzer×pricing catalog(已有) → 按1k/1M调用投影
5. CLI: `prompt-cli score` 增加四维表+总字母级(A–F); `--format json` 向后兼容扩展
**验证**: 同一prompt四维分可复现; JSON新增字段不破坏旧消费者(只增不改); 单测边界。
**对抗性备注**: 指标膨胀风险 — 四维公式必须全部可从现有规则/分析器机械推导,
禁止为好看手调权重; 公式写入文档可审计。

### R212-6: 误报Top7收尾 (P1, 1日)
**现状**: 全局1.35%, 剩余>10%规则7条: P107/P119(14%), P039/P040/P110(12%),
P036/P109(11%)。
**改动**: 沿用R206-R211处置原则(修正则>降级>移出默认集, 每条负样本断言+保正样本),
目标全局<1.0%, 高误报7→0。棘轮阈值同步收紧(1.35%→处置后值, 只降不升)。
**验证**: 全量回归; 棘轮exit=0; 基线文档更新。

### R212-7: probes口径统一 (P2, 0.3日)
**现状**: 三个probes数 — 徽章23(`_PROBE_REGISTRY`) / `--version` 94
(`BaseProbe.__subclasses__()`) / 全局注册表116。命名冲突(encoding_bypass)存在。
**改动**: 确认R207-3统一注册表为唯一事实源, `--version`组件统计与徽章改读同一
`get_global_probe_registry()`, 冲突名在文档标注归属; 徽章数字随之校准。
**验证**: 三处probes数一致; 全量回归。

### R212-8: lint时cost预估 (P2, 0.3日, 复用promptlint思路)
**现状**: pricing+token_analyzer已有, 但lint输出无成本视角。promptlint把
"~$X/call, ~$Y/day at 1M calls"做成INFO级finding — 成本是用户第一直觉指标。
**改动**: lint报告尾部追加一行成本估算(INFO, 不产生finding不进门禁):
token数×定价catalog默认模型, 1k/1M调用两档投影。
**验证**: 输出稳定可复现; 定价数据缺失时优雅降级(显示token数即可)。

## 3. 非目标 (本轮明确不做)

1. **不加新规则编号到P256+** — 双基线(误报+漏检)达标前冻结规则数, 255为上限。
2. **不做动态红队** — 需LLM调用, 与零调用定位冲突; probe体系保持静态。
3. **不做9语言i18n** — 维持zh-CN/en-US, 错误信息双语已覆盖主要面。
4. **不做黄金集统计检验(A/B显著性)** — 记入R213候选, 本轮只建漏检标尺。
5. **不引入任何新第三方依赖** — 全部复用现有组件。
