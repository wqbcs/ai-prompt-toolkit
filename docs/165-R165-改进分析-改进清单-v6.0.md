## 五、架构可演进（分层解耦，5 年生命周期）

```
┌─ 端层 (adapter) ──────────────────────────────┐
│ CLI(click/Rich) │ MCP(JSON-RPC) │ VSCode ext │  ← 任一端可替换，不影响内核
├─ 服务层 (service) ────────────────────────────┤
│ LintService │ EvalService │ RedTeamService   │  ← 编排、门禁、报告
│ Observability(tracer) │ Pricing │ Audit      │
├─ 内核层 (core, 纯函数无 I/O) ─────────────────┤
│ RuleEngine(插件注册) │ Compiler │ Scorer     │  ← 稳定内核，任何语言端可重写
│ Judge(debias) │ Baseline/Diff │ Sanitizer    │
├─ 数据层 (data) ───────────────────────────────┤
│ rules.yaml │ pricing.json │ profiles.yaml    │  ← 配置即数据，零硬编码
│ probe corpus │ i18n/*.yml                     │
└───────────────────────────────────────────────┘
```

| # | 举措 | 说明 |
|---|------|------|
| A1 | **规则引擎插件化** | 规则经注册表自动发现（按文件名区间扫描），新增规则包不改引擎 | P2 |
| A2 | **可观测性抽象** | Tracer 接口（no-op/file/otel 三实现），CLI/MCP 不感知具体后端 | P1（随 F1） |
| A3 | **数据目录收敛** | `src/ai_prompt_toolkit/data/` 统管 JSON/YAML 数据资产 | P1（随 F3/D1） |
| A4 | **依赖克制** | 核心零新增硬依赖；OTel/OpenTelemetry SDK 均为可选 extra，保证 `pip install` 轻量 | P0（原则） |
