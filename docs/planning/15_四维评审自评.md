## 01 技术创新

**核心楔子：确定性的 LLM 提示词静态门禁**（prompt 的 ESLint）。
一句话：每次裁决逐字节一致 + 零 LLM 成本 + <100ms/文件 + 离线可跑——
这四条同时成立，是既有方案面没有占位的 lane。

### 01.1 相较同类的明确优势（对比面全部来自 03 号调研 + 实跑核实）

| 对比对象 | 其路线 | 未覆盖的问题=本项目覆盖 |
|---|---|---|
| LLM Guard 类 | 运行时防护（LLM 在线拦截） | CI 门禁场景：merge 前拦截，不依赖运行时；离线 air-gap 可跑 |
| promptfoo 类 | LLM-as-judge 评估 | 裁决确定性：LLM 输出不可复现，本工具逐字节可复现（不变量 5，测试锁死） |
| aiproof | 同 lane 静态扫描 | 误报面：其 96% FP 教训（03 调研留痕）；本项目 FP 实测 0.82% + FP 棘轮只收紧 |
| garak | LLM 红队（需在线模型） | 零 LLM 成本：667 探针全静态可跑，离线门禁可用 |
| 通用 linter（ruff/eslint 范式对标） | 代码静态分析 | prompt 专项语义：注入/越狱/PII/供应链/多模态/可移植性 25 大类，268 规则 |

定位澄清（README 原文）：运行时防护与 LLM 评估**互补不互替**——
本项目做 CI 门禁层（可复现裁决），不抢运行时/评估的活。

### 01.2 独有技术资产（非现成工具堆砌，全部仓库内可验证）

1. **双基线时间序列**：误报率 8.38%→0.82% 的 33 点收紧史（`docs/baseline_history.jsonl`，
   append-only）+ 确定性 sparkline（`scripts/gen_baseline_sparkline.py`，同数据→同 SVG 逐字节）；
   漏检率 0.00%（379/379 期望命中单元）。**样本随包分发，pip install 后一条命令自证**
   （`prompt-cli baseline`）——可信度不在嘴边上，在一行命令里。
2. **分语言检测基线表**：zh-Hans/en/ja/zh-Hant 四语言独立探针与基线口径
   （`scripts/check_language_baseline_readme.py` 机器核对进门禁）——竞品无公开基线纪律。
3. **OWASP LLM Top 10 2026 版 + ATLAS + 等保 2.0 三标准映射**（R228 全仓迁移，7db047f）；
   23 Probe + 11 检测器全局注册表 116。
4. **确定性工艺面**：mypy strict 286/286 模块级棘轮、29 步门禁链单入口、
   7+ 道只收紧不放松的棘轮（FP/漏检/覆盖率/gap/ReDoS/依赖/环境一致性）、
   反清单 + 陷阱清单 T1-T10（对抗审查产物）。
5. **性能不变量实测**：max 16.52ms/文件（6.1× 余量于 <100ms 预算，R305 机器复验留痕）。

**本维度自评：强。** 楔子=四个不变量同时成立（可复现/零 LLM/快/离线），
单一竞品无法用现成工具堆砌补齐（基线时序+分语言口径+探针集是数据资产，不是代码资产）。

### 02.2 需求真实（信号分级依据，08 号调研 ≥2 独立来源定 S 级）

- prompt 注入 = OWASP LLM Top 10 **第一位**（2025/2026 版连续在列）

  （03 调研留痕）——但**确定性 CI 门禁 lane 无人占位**

  Azure Code Analysis）——本工具输出直接落进既有 CI 纪律，零新心智

### 02.3 验证来自真实环境（非仿真）

- 667 条真实攻击探针（`src/ai_prompt_toolkit/data/golden_attacks.json`，含 OWASP 2026
  全部攻击面 + ATR 信源交叉核实）+ 60 干净样本 + 外部过防御基准（NotInject）
- 0.82% FP / 0.00% 漏检 = 实测值，且**任何机器一条命令复现**（样本随包）
- 本地=CI 验证步（`scripts/verify_local_ci_parity.py`，门禁第 29 步）：钉死包版本断言
  + CI workflow 命令面可达性——R223 四连红根因的机器护栏

**缺口（正面陈述）**：首次发布未执行 → PyPI/uvx/Docker 通道尚未被真实用户触达；
仓库私有 → 外部 adopter 当前不可达。闭合=用户 D1-D5 操作（~8-10 分钟）+ 打 tag。
发布后动作已预登记：uvx + docker pull 双通道实测 → Tier1 采用三件套。

**本维度自评：强（发布闭环待用户一步）。** 可部署/可运行/可测试/需求真实四项达标；
"真实环境验证"当前是真实样本+可复现命令，差"真实用户触达"最后一跳。

### 03.2 贡献机制 / 文档 / Issue-PR（规划面清单）

- **模板**：`ISSUE_TEMPLATE`×3（bug/feature/**vulnerability**）+ `PULL_REQUEST_TEMPLATE.md`

- **文档**：README（中文，P1-07 English-first 已预登记）/ CONTRIBUTING / CoC / SECURITY /
  14 份规划文档（00 交接-14 分层测绘）/ docs/rules 268 规则逐条页（机器生成，gen_rules_doc）
- **贡献纪律**（CONTRIBUTING + CLAUDE.md 双入口）：
  - 探针先行：新规则无 ≥2 独立真实 TP+TN 探针**禁止合入**（`data/golden_attacks.json` 机器核对）
  - 双基线不回归：`check_false_positives.py --fail-above 0.01` + `check_miss_rate.py --fail-above 0.05` 只收紧不放松
  - 收口单入口：`scripts/release_gate.py` 29 步全链，禁手工拆步/禁管道吞码
  - 板漂移机器核对：`check_board_status.py` 5 检查（sha 存在/CHANGELOG 声称/✅行引用/规则引用 vs 注册表/自相矛盾）

## 04 长期发展

### 04.1 持续维护能力（连续性本身就是机器证据）

- **R1→R306 共 306 轮连续自主迭代**，CHANGELOG 5185 行逐轮留痕（每轮=变更+测试+门禁+
  版本+commit hash）——任何评审可 `git log --oneline | wc -l` 现场验证
- 每轮固定收口协议（00 号 §9 任务循环协议 9 步）：git 状态→门禁链→push→板回写→
  交接更新→竞品扫描→四问自审→下一轮规划
- 不可观测面诚实标注纪律：CI 结果无法会话内观测时**明确写"CI 未观测"**而非声称绿
  （R286/P3-07 CodeQL 首跑、R304 fuzz CI 接线均按此留痕）

### 04.2 长期规划与治理结构（机械防退化，不靠自觉）

| 机制 | 形态 | 证据 |
|---|---|---|
| 5 年架构不变量 | 四层解耦/内核零第三方 runtime/任意端迭代不影响内核 | 04 号架构演进 + 机器护栏（第 17 步） |

| 反清单 | "不做什么"与任务清单同等权威（防往死里列任务的对抗产物） | 02 总板 §不做什么 |

### 04.3 社区/组织支撑（真实短板，正面陈述）

- **bus factor=1**（单人维护）——缓解设计：00 号交接文档=给下一棒 agent/人的 5 分钟
  上下文入口，规划集 00-14 全部可机器消费（AI agent 可接力，已实际接力 306 轮）
- 无 org/公司 backing、无社区频道、无赞助
- 答辩口径：单人项目的取舍=所有纪律机械化为门禁（人不在时门禁仍在），
  306 轮无人值守迭代是该设计的实证

**本维度自评：维护能力证据最强（306 轮+机械防退化）/ 组织支撑最弱（bus factor=1）。**
