## 2. 开源与痛点调研（2026-10-04 实搜留痕）

### 2.1 aiproof（NORTHTEKDevs，Rust）——最近竞品再核实
- **TS/Python 抽取路线 = tree-sitter**（`tree-sitter-typescript`/`tree-sitter-python`，C 扩展）：
  抽 `messages.create`/`PromptTemplate`/`ChatPromptTemplate.from_messages`/`Agent(system=...)` 调用点，
  模板字面量 → `{0}`/`{1}` 占位。
- 其 v0.1.0 教训（CORPUS_REPORT 自曝）：未加 `is_prompt_shaped()` 门控时 **37,118 诊断中 96% 是
  README 风格 markdown 的误报**；AIP011 在设计文档过火、AIP008 在测试夹具过火。
- **对本项目启示**：①纯 stdlib 路线必须复刻"强信号门控"（我方已有：SDK 调用实参/prompt 键/prompt
  命名变量三信号，比 aiproof 更严）；②TS 侧若做，门控必须同 Python 侧等强，否则重演 96% FP。

### 2.2 ContextHound（IulianVOStrut，npm/TS，2026-02 新）——赛道密度 +1
- 95 规则/14 类，**npm 单装**（无 Python 依赖）+ GitHub Action + SARIF + baseline diff + 插件系统 +
  增量缓存 + watch 模式。宣称多语言 LLM API 使用面扫描（Py/Go/Rust/Java/C#/PHP/Ruby/Swift/Kotlin/Vue/Bash）。
- **威胁评估**：它验证了"代码内嵌 prompt 扫描"是行业共识面（我方 P1-15/15b 方向正确）；其
  baseline diff 与我方 `--incremental` 同构。差异=我方确定性楔子（逐字节一致+双基线公开）+
  OWASP/ATLAS 标准映射 + 中文面。ContextHound 无标准映射、无可复现性叙事。
- **行动**：07 竞品监控 +1 行；**不跟**其插件系统/watch 模式（T7：无调用者信号）。

### 2.3 whitney（Python）——确定性叙事同行
- 默认路径 **zero-LLM + byte-identical output**（与我方楔子同构），opt-in LLM triage 分层（我方
  拒绝该层=T9 边界，质量 preflight 已独立成 preflight_hook，边界纪律一致）。
- 用 **Semgrep OSS** 做 taint（intra-file），不自造引擎；Python only，TS 在 roadmap。
- **启示**：Semgrep 路线=引入重型依赖（Python+规则 YAML 分发），违反核心零依赖；其
  "81.8% precision 盲测"数字值得我方对标——P5-11 误报曲线公开页正是回应面。

### 2.4 OWASP LLM Top 10 2026 子面核实（官方 PDF 目录+正文）

  subversion"）——不是独立项。
- **model artifact integrity → 归 LLM04:2026 Supply Chain**（"accounts for the trust failure when a
  promoted model artifact is not what it claims to be"；不安全序列化/pickle、篡改制品）。

  覆盖主面）。→ **P2-11 首批=探针扩充（TP 扩到 subversion/artifact 措辞变体）+ 映射面文档声明，

## 4. 对抗审查（关键决策的 5 问+陷阱自检）

### 4.1 P1-15b TS 抽取：做 or 不做？
- **做**：方向被市场验证（aiproof/ContextHound 都有）；我方 Python 侧已交付，TS 侧是同一模块
  的平行分支（高内聚）；09 触发器"M2 采用者 ≥20"是 npm **包装器**的触发器，不是**检测面**的触发器
  （检测面缺失=所有端共同的能力缺口，与分发通道无关）。
- **纯 stdlib or tree-sitter**：tree-sitter=C 扩展+每语言包=依赖面扩张（T8）+wheel 体积/平台矩阵
  爆炸（win/mac/linux×py310-312 的 manylinux wheel 里带 C 库=aiproof 用 Rust 是因为它本身就是 Rust
  写的；我们是 Python，代价不对称）。纯 stdlib 上限=regex/词法启发式对 TS 无 AST——**补偿设计**：
  强信号门控拉到与 Python 等强（已知 SDK 调用末段名 × prompt 键 × 长度门槛三条件 AND），误报面由
  TN 探针锁死。
- **判定：纯 stdlib 做**。陷阱 5 问：有探针支撑？是（先行 TP/TN）。用户 0 摩擦？是（`--inline` 已有）。
  确定性保持？是（纯文本函数）。5 年生命周期？是（规则引擎不动，只加抽取器）。反例=若 TN 探针摸底
  FP>1% 则回退登记观察区（07 §5 自检入口），不硬带。

### 4.2 P3-01 e2e：真进程 or mock？
- mock 子进程（pytest-subprocess/FakeProcess）测的是"代码调用子进程的参数"，测不到接线
  （PATH/编码/stdout 协议污染——R226 首跑横幅事故正是这类 bug）。**判定：真进程**，不引 mock 库。
- Windows CI：GH Actions ubuntu 为主，本地 Windows 抽样（09 既定风险缓解）。

### 4.3 P2-11 探针：新规则 or 探针扩充？
- 官方 2026 归属核实后，文本面可检测信号已被 P221/P222/P224 覆盖主面；新增 subversion/artifact
  **措辞变体**是探针集强度问题（P3-03 变异测试的前置弹药），不是规则缺失。**判定：只扩探针**。

### 4.4 方向级自检
- 本轮 6 项中 0 项触碰"prompt registry/运行时 SDK/A-B 游戏"反清单 ✅
- 0 项新增运行时依赖 ✅（pyproject 不动=check_dep_manifest 必绿）
- 与"顶配不图省事"的张力点=TS 纯 stdlib vs tree-sitter——已按 §4.1 对抗修正：**顶配=该端最优
  技术栈，Python 生态的 TS 静态分析"最优"在纯 stdlib 约束下是强门控词法启发式**（tree-sitter 的
  精度增益需 10× 依赖面代价，且 aiproof 96% FP 证明精度瓶颈在门控不在解析器）。此判断留痕于
  07 方向变更提案区供用户复核（不阻塞执行）。
