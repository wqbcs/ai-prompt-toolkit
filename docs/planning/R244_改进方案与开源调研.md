## §1 定位与反思（鬼才 PM 自检，开工前）

**项目定位**：确定性的 LLM 提示词静态门禁——prompt 的 ESLint。
**楔子**（产品核心价值）：每次裁决逐字节一致 + 零 LLM 成本 + **<100ms/文件** + 离线可跑。

**本轮自检四问**：

1. **定位是啥？** 可验证的楔子——四条承诺每条都要有机器护栏背书。
2. **逐条盘点护栏现状**：
   - 逐字节一致 → ✅ `--new-from-rev`/baseline diff/导出确定性 e2e（真子进程逐字节断言）
   - 零 LLM → ✅ 核心零依赖验证（check_layer_deps）+ 门禁链无 LLM 调用纪律
   - 离线可跑 → ✅ 依赖清单一致性 + core 零运行时依赖
   - **<100ms/文件 → ❌ 只存在于 README 楔子文案，零机器断言**
3. **问题在哪？** 规则集 0→267 的过程中性能预算无人看管——今天 16ms 达标，
   但第 300 条规则把 max 推到 150ms 时**没有东西会红**。楔子=对用户的承诺，
   承诺无护栏=可验证性叙事的自我削弱（我们批评检测器"FP 数字不可复核"，
   自己的性能承诺同样不可复核=同病）。
4. **需要怎样调整？** P2-16 落地，但**轻量形态先行**（板行既定"与 P2-15 OTEL
   解耦"）：直接计时断言，不依赖 OTEL trace 基建。

**低价值打磨陷阱清单（本轮主动避开）**：

| 陷阱 | 判定 | 依据 |
|---|---|---|
| 先做 P2-15 完整 OTEL 再做性能断言 | ❌ 不做（解耦） | OTEL=依赖+基建面，楔子断言只需一个计时值——奥卡姆：板行"与 P2-15 解耦先行"原话 |
| 相对回归检测（vs 历史基线 ±20%） | ❌ 不做（CI 面） | CI 全新 runner 无本地历史 SQLite；相对面=benchmark 命令本地辖区（既有 --threshold 20%）。CI 门禁用绝对预算=楔子原话，无历史依赖 |
| 复杂统计（95% CI/多 trial 分布） | ❌ 不做 | a2a-rust 的 95% CI 是其 267 基准×2 遍 PR 门场景；我 60 文件×3 遍 median 已把单点噪声压掉，CI 门禁只需 max<100ms 一刀切——过度统计=低价值打磨 |
| 新语料/新探针 | ❌ 不做 | 复用 CLEAN_DIR 60 文件单一真源（R243-2 刚固化），不建第二份 benchmark 语料=防双源 |

## §2 开源/外部调研（CI perf gate 模式）

**S 级参考（a2a-rust regression-gate，2026 调研）**：
- "3-trial median per run"——单次采样受 runner 抖动影响，中位数忽略单点噪声 → **采用**（warmup+3 遍中位数）
- 点估计不可作裁决：GitHub runner 噪声实证 20%+（"20%+ on small, fast benchmarks"）→ **采用**（median 而非 min/max 单点）
- 95% CI 下界超阈值才判回归 → **不采用**（场景差异：其 PR 门对比 base 分支历史，我无 CI 历史；绝对预算面 CI 统计面是过度设计）
- "[benchmark-skip] 可审计豁免" → **登记留痕**（若未来规则集合法膨胀需提预算，走独立 commit+理由，同基线重存纪律）

**A 级参考（ESLint --stats/TIMING + eslint#19680 Repeatable performance test）**：
- ESLint 官方承认 perf test "inconsistent results over time"（同机连跑 median 漂移 1s+）→ 佐证"perf 门禁必须降噪+宽预算"，点估计单跑不可信
- ESLint 的 per-rule 计时（stats.times.rules）= 我 lint_time_ms 的更细形态 → **不采用**（门禁只需 per-file 粒度，per-rule 归 P2-15 OTEL 辖区）

**内部复用面（不造轮子盘点）**：
- `lint_template().lint_time_ms`（linter.py:224）= 既有每文件计时真源，tracer/LSP 已消费 → **直接复用**
- `baselines.CLEAN_DIR` 60 文件 = R243-2 固化后单一真源固定语料 → **直接复用**（不建 benchmark 专用语料=防双源）
- `benchmark.py`/`prompt-cli benchmark`（SQLite 历史+20% 相对回归）= 本地回归分析面 → **保留原辖区**，本脚本不替代（互补：本地相对趋势 vs CI 绝对预算）
- `release_gate`/CI test 作业 3.12 单点步形态 → 同形接线

## §3 设计定稿

```
check_lint_performance.py:
  语料 = CLEAN_DIR 60 文件 (单一真源, R243-2 固化)
  warmup 1 遍 (热导入/规则模块缓存, 丢弃)
  采样 3 遍 × 60 文件, 每文件取 lint_time_ms
  降噪 = 每文件 3 遍中位数 (median-of-3)
  门控 = max(per-file 中位数) < 100ms (绝对预算, 楔子原话)
  退出码 0=达标 / 1=超预算(列文件) / 2=语料面异常
```

**预算值论证**：100ms=楔子原话（不取 50/80 等更严值——楔子是对外承诺，
门禁严于承诺=自设门槛无叙事价值；门禁宽于承诺=承诺失真）。R244 校准
max=15.74ms（6.3× 余量），覆盖 runner 噪声 20% 摆动后仍 <40ms，跨 runner 稳定。
**余量护栏**：测试断言 max≤60ms（校准值×4）——若规则集膨胀把 max 从 16ms
推到 60ms+ 会先于 100ms 预算红，逼出"性能退化评审"而非静默吃楔子。

**与 P2-15 边界**：本脚本=绝对预算门禁（CI 面，零依赖）；P2-15 OTEL=
per-rule 耗时 trace+趋势分析（本地/发布后面，依赖 OTEL SDK）——辖区不重叠。
