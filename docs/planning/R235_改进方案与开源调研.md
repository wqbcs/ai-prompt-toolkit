## 4. 对抗审查留痕（方案自审）

1. **P3-16 会不会污染 stdout 协议面？** 否——`--format summary` 是独立 fmt
   分支（json/sarif/cli/html 面不变）；GITHUB_STEP_SUMMARY 写**文件路径**
   （GH 原生 env），不经 stdout；装饰性输出仍过 `_is_decorative_output_allowed()`
   （R226 纪律）。协议纯净由既有 e2e（test_r231_e2e_cli 协议面断言）回归锁死。
2. **P2-05 "86%→<70%"是不是骗规则（T4）？** 边界判定：本仓 26 模板是
   **dogfooding 演示资产**（README quickstart 直接引用），它们本该有生产声明
   （密钥管理/注入防御/数据边界）——补声明=补齐模板应有内容（生产实践），
   参照 OWASP 2026 官方缓解措辞而非空声明；且 P1-10 棘轮只收紧不放松+
   独立 commit 降基线带理由=机器可审计。线在"声明有实际语义"vs"凑字过
   门禁"——验收含"声明文本过 265 规则不误报"反向约束（声明本身不能引入
   新 finding）。→ 无 T4 风险。
3. **P4-02 与 check_dep_manifest 是否重复造轮子？** 否——check_dep_manifest
   验证"src 运行时 import ⊆ pyproject 声明"（**包级**，防 jinja2 事故）；
   P4-02 验证"kernel/rules 层零第三方 import"（**层级**，更严：不仅声明了
   才允许，而是根本不允许）。两者输入不同（层归属来自 P4-01 测绘文档），
   正交不重叠。实现复用 dep_manifest 的 import 扫描函数，不新造扫描器。
4. **R235 四项会否超一轮容量？** #1 S（一个新 fmt 分支+env 感知+e2e）/
   #2 M（26 模板内容修改+gap 基线独立 commit）/#3 S–M（一个审计脚本+CI
   步）/#4 S（7 条探针+计数同步）。与 R234 实际负载同量级（已实证可行）。
   最坏砍 #4 → R236。→ 容量受控。
5. **DeepSeek Harness 爆发会不会让我方定位过时？** 否——它们供给
   **运行时**（LLM 调用流审计），我方供给**静态入库前**（prompt 文本
   确定性门禁）。一个 prompt 的生命周期=编写→入库（我方面）→部署→
   调用（它们的面）。辖区正交，互补叙事已写入 §2.2。若未来 agent 平台
   把"入库前静态检查"内化（如 Harness 加 pre-commit 插件），才是楔子
   被冲击的信号 → 07 §2 方向变更提案区登记触发条件（Harness 系出
   仓库级静态 lint 功能）。
6. **P5-11 上调到"公开后首轮"会不会被无限顺延？** P0-03 公开依赖用户
   授权（D1-D3 唯一等用户事项，已 10 轮打包待问）。若 D1-D4 长期无
   响应，P5-11 的**数据面**（曲线 JSON 生成+数字一致性 e2e）可先做
   （不依赖 Pages），页面发布后挂——登记为 R236 候选切分，防整体顺延。
