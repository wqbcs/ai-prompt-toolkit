## 1. 竞品与生态信号（按重要性）

### 1.1 promptfoo 被 OpenAI 收购（2026-03-09，重大）

- 信源: https://www.promptfoo.dev/blog/promptfoo-joining-openai/ +
  https://openai.com/index/openai-to-acquire-promptfoo/ + CNBC 报道
- 事实: OpenAI 收购 Promptfoo（Fortune 500 超 25% 使用，A 轮 1840 万美元），
  开源 CLI 承诺继续，企业能力并入 OpenAI Frontier 平台。
- **对我方的含义**: "LLM 驱动的 eval/安全平台"赛道被模型厂商直接内化——
  语义评估层的最大玩家现在与模型利益绑定。**"零 LLM、确定性、可离线"从
  功能短板升级为结构性优势**（中立性 + air-gap + 成本 0）。README 的对比叙事
  应补这条行业事实（P5-05 素材 ① 升级）。
- 风险: OpenAI 若把 promptfoo 开源 CLI 强化到"确定性静态层"，楔子被正面
  压缩。登记 07 §1 竞品监控，触发器=promptfoo 新增 lint/静态规则模式。

### 1.2 新竞品 aisona-lab/prompt-guard（2026-05，最近邻）

- 信源: https://github.com/aisona-lab/prompt-guard
- 事实: "ESLint for the new attack surface"——59 规则 6 类（injection/jailbreak/
  system-prompt-leak/obfuscation/goal-hijacking/pii-exfiltration），纯正则零网络，
  sub-ms；CLI/REST/TS 库/Web UI；benchmark 进 CI（curated 81 prompts 100%/
  external ~200 仅 recall ~20% —— 诚实披露 OOD 表现）；npx 零安装；
  可选 LLM 二审（provider 无关）。
- 差距对比（我方 vs 它）:
  | 维度 | 我方 | prompt-guard |
  |---|---|---|
  | 规则数 | 261（196 可自动修复） | 59 |
  | 基线纪律 | 双基线棘轮（FP 0.91%/miss 0.00% 时间序列） | benchmark 回归 guard（无时间序列） |
  | OOD 诚实 | 双基线样本随包分发可复现 | 披露 external recall 20%（诚实） |
  | brownfield | --incremental + 基线锁存量 | 无 |
  | 标准映射 | OWASP LLM Top10 + NIST RMF + 等保 | 无 |
  | 语言 | 中文优先（15 条中文注入规则） | 英文 |
  | 安装 | pip/pipx（Python 生态门槛） | npx（JS 生态零门槛）——**它的采用摩擦更低** |
  | 编辑端 | VS Code 扩展骨架 | Web UI |
- **含义**: 叙事窗口期在关闭。它 star 少但形态完整且发布早于我方 PyPI（我方
  至今未发布！）。**P0-03/P0-04（公开+发布）的紧迫性被此信号上调**——
  发布前每多一天，"第一个确定性 prompt 门禁"的定位就多一分被占位风险。

### 1.4 Prompt Preflight（新分发渠道信号）

- 信源: 搜索结果（VS Code Marketplace beta + 仓库）
- 事实: 2026 新形态——把 prompt 质量检查挂进 **AI 编码助手的
  UserPromptSubmit hook**（Codex/Claude Code/Kiro），在"人写给模型的 prompt"
  提交前拦截模糊/低质 prompt；VSIX 内嵌 Python analyzer；本地 JSONL telemetry。
- **含义**: "人→模型"的 prompt 入口正在成为新门禁面（我方目前只做"仓库→CI"
  面）。零代码适配 = 一个 10 行 hook 脚本调用 `prompt-cli lint -s`。
  边界纪律（T9）：这是**质量 preflight**（确定性，零 LLM），与 CI 安全门禁
  分文档分命令，不混入门禁语义。
- 新任务: **R225-N2（P1-14）**：AI 编码助手 hook 适配器（scripts/ 下 3 个
  脚本 + docs 一节），S 级，无内核改动。

### 1.6 行业基准方法论信号（Reddit r/LocalLLM，2026-07）

- 信源: https://www.reddit.com/r/LocalLLM/comments/1ukicum/
- 事实: 用户自建 prompt injection 检测器 benchmark，核心发现："大多数对比

### 1.7 检测器误报痛点实证（Claude Code issue #17804）

- 信源: https://github.com/anthropics/claude-code/issues/17804
- 事实: Claude Code 的 UserPromptSubmit 安全 hook 把**嵌套 JSON 数据结构**
  误判为 prompt injection，间歇性阻断正常操作。
- **含义**: "把合法数据当注入"是检测器通用痛点。我方双基线 FP 0.91%（60 样本）
  正是解药——但 60 样本的说服力有限。**P2-11（探针扩容 113→150）应优先扩
  TN 侧（干净但结构复杂的样本：嵌套 JSON/多轮对话/代码混排）**，
  让 FP 数字从"60 样本"升级到"150 样本"。

### 1.8 MCP 安全面（P2-18 预研的权威依据到位）

- 信源: https://developer.microsoft.com/blog/protecting-against-indirect-injection-attacks-mcp
  （Microsoft 官方）+ MCP tool poisoning/rug pull 研究综述（搜索结果）
- 事实: Microsoft 官方承认 MCP 间接注入（tool poisoning = 恶意工具描述；
  rug pull = 工具批准后延迟改描述；Unicode Tags/ANSI 隐藏指令嵌入描述）。
  官方建议 = prompt shield（语义层）+ 供应链安全。
- **静态可检测面（我方能做的，无 LLM）**:
  1. tool description 基线 + **变更告警**（rug pull 的静态检测 = 描述 hash
     与已批准基线对比）——mcp-lint 已有配置级 7 项检查，增量成本低
  2. description 隐藏字符检测（Unicode Tags/ANSI/零宽）——**已有 P258 零宽族
     规则可直接复用**，只是应用到 mcp-lint 的 description 字段
  3. 隐藏指令模式（"ignore previous"/角色切换）——注入检测器复用
- 新任务: **R225-N1（P2-20）**：mcp-lint 补 rug pull 检测（描述 hash 基线 +
  已有规则应用到 description），M 级，高差异化（竞品无人做）。

## 3. PM 自审四问（第一性原理/奥卡姆/对抗性/鬼才产品）

**Q1 定位是啥？** 确定性 Prompt 静态门禁——prompt 的 ESLint，CI 裁决层。
（不变。本轮调研强化了定位的市场位置：LLM 路线被厂商内化，静态门禁层是
唯一中立的开放空间。）

**Q2 核心价值（楔子）？** 每次裁决逐字节一致 + 零 LLM 成本 + <100ms + 离线。
（不变。新增佐证：promptfoo 进 OpenAI 后"中立性"成为显性卖点，楔子表述
可加第四句"模型厂商无关"。）

**Q3 方向有啥问题？**
- **问题（高）：发布缺位**。竞品已上架 Marketplace/npx，我方 PyPI 不存在。
  所有采用面（Action/pre-commit/npm/扩展/文档站）的入口都是 `pip install`——
  发布前这些全是空中楼阁。**P0-03/P0-04 是唯一真阻塞，等待授权期间应把
  "发布即采用"的物料（P1-06/11/12/07/02/03）全部备齐**，授权下来单轮落地。
- **问题（中）：叙事占位**。"ESLint for prompts"被 prompt-guard/promptlint
  两家占用。我方叙事应转向**可验证性**："唯一公开 precision 时间序列的
  prompt 门禁"——双基线历史+探针随包可复现是竞品做不出的差异化。
- **问题（低）：低价值打磨陷阱**。P2-13 在线 Playground（L，无采用信号）、
  P5-05 博客 3 篇（L，发布前无 PyPI 链接=无效）维持低优先；P4-06 多语言绑定
  只维护路线文档不写代码。**禁止**为对抗竞品加"LLM 可选二审"（T3/T9 红线）。
- **无问题**：架构分层（kernel/rules/io/adapters）、门禁纪律、双基线棘轮、
  确定性叙事——全部经本轮调研反向验证。

**Q4 需怎样调整？** 执行序调整为**"发布物料冲刺"**：
1. （本轮）P1-06 AI 助手指令文件 + P1-12 SECURITY.md + P1-11 三件套
   （纯内容，不依赖发布，仓库公开即生效）
2. （本轮）P2-09 audit-waivers + P2-08 doctor 增强（采用后第一周会用到的命令）
3. （授权后第一轮）P1-01 Action + P1-02 pre-commit + P1-08 quickstart 一次落地
4. （之后）P2-20 rug pull（差异化）/ P1-05a stdio（编辑器前置）/ P3-05 ReDoS
**不做**：本轮不启动 P1-04 npm 包装器（L 级，发布前无对象可包装）、
不启动 P5-12 文档站（P1-07 英文首屏前置未满足）。
