## §1 定位与反思（鬼才 PM 自检，开工前）

**项目定位**：确定性的 LLM 提示词静态门禁——prompt 的 ESLint。
**楔子**（产品核心价值）：每次裁决逐字节一致 + 零 LLM 成本 + <100ms/文件 + 离线可跑。

**本轮自检四问**：

1. **定位是啥？** 门禁工具的第一触点=CI 红/本地红的那一刻。那一刻用户只看到
   "`[P042] xxx 声明缺失`"——**然后呢？** 修复建议（remediation）是每条规则
   自带的数据（267/267 规则中/英双语全在位，单一真源 LintRule），但 CLI 默认
   输出面（开发者与 CI 日志最常被看的面）**零展示**——数据在、展示断链=
   "最后一公里"缺口。P5-01 板行原文："每条错误/finding 消息必须含下一步
   （修复建议 or `prompt-cli explain Pxxx` 指引）"。

2. **问题在哪（实查，非纸面）**：
   - `lint_commands.py:729`（lint 默认 CLI 面）：只输出
     `{marker} [{template}{loc}] {rule_id}: {description}`，无 remediation。
   - `lint_commands.py:1291`（scan 路径）：同形态；其 `--explain` 旗标才展示
     "修复: {remediation}"（:1295）——**同一 CLI 两个命令面，可行动化口径不一致**。
   - `--explain`（lint 路径 :270）是交互式规则解释入口，面向"这条规则是什么"，
     不是"这个 finding 怎么修"——语义不同位。
   - 数据面实证：267 规则 `remediation` 非空 267/267（>10 字实质内容 267/267，
     英文面 267/267）；lint finding 对象携带 remediation 字段（scan 路径
     `f.remediation` 直用即证）。
   - **结论：数据 100% 在位，纯展示面缺口。零新数据、零新检测面、零依赖。**

3. **需要怎样调整？** P5-01 落地取**最小闭环**：lint+scan 两路径加 `--fix-hint`
   旗标（默认 off，gate 输出稳定性不动），每 finding 下输出
   "修复: {remediation}"（缺省回退 `get_rule(rule_id).remediation` 双保险）；
   README quickstart 补一行示例让旗标可发现。P5-01 板行"or explain 指引"二选一中
   选直接展示——指引=用户多敲一条命令，直接展示=零摩擦（奥卡姆）。

4. **低价值打磨陷阱清单（本轮主动避开）**：

| 陷阱 | 判定 | 依据 |
|---|---|---|
| 默认输出直接加 remediation 行（改默认面） | ❌ 不做 | gate 输出=CI 日志/脚本消费面，改默认面=破坏既有输出契约（逐字节一致叙事+下游脚本解析）；opt-in 旗标零破坏 |
| rich 彩色表格渲染（P5-02 提前做） | ❌ 不做（重判 ⏸） | rich 已是 core 依赖（8 文件在用，非新依赖），但 ANSI 颜色进 CI 日志=噪音；分组/颜色收益低于 P5-01"数据可达"收益；恢复条件=ICP 信号+`--color auto` 设计先行 |
| 顺手给 117 条 critical/high 补行级定位（P2-06 全做） | ❌ 不做（重判 ⏸） | 实证：主导命中族是负向检查（P001 缺角色定义=88% 命中占比）——"缺失"无锚点行，强行定位=**假精度**（报 L1 是编的）；正向 regex 命中规则（如 P042，129 命中 0 行级）才是真可定位面，单独立项按规则逐个补 |
| remediation 双语自动切换 | ❌ 不做 | i18n 本地化大面=反清单显式禁止项；zh 默认（与 description 展示口径一致），en 面走既有 `--lang` 管线（若有）不新造 |

## §2 开源/外部调研

**S 级参考（semgrep CLI 展示形态，2026-10-08 检索）**：
- semgrep 默认输出=紧凑一行（severity+rule+message），remediation 走
  `semgrep explain <rule>` 独立入口+IDE 插件内联——**"默认紧凑+显式入口拿详情"
  是其双轨**；但 semgrep 用户多经 IDE/CI 消费，其 explain 入口曝光靠文档生态。
- 我方差异：无 IDE 插件面（P1-05 未落），CLI 是唯一交互入口——**旗标比独立
  命令更易发现**（`--help` 即见），且 remediation 是 finding 级（非规则级），
  内联在 finding 行下比 `explain Pxxx` 少一次 rule_id 映射。
- **采用**：`--fix-hint` 旗标内联（与 semgrep 默认紧凑不冲突，是其 explain 入口
  的 finding 级变体）。

**内部实证（本轮新数据，入 08 调研表）**：
- 267 规则 severity 分布：critical 12 / high 105 / medium 121 / low 29。
- 117 条 critical/high 在 golden(174)+clean(60) 真语料命中面：**集中 10 规则
  265 命中，行级 location 覆盖 0%**；P001（缺角色定义，负向检查）占 88% 命中
  =主导族无锚点（R247 勘误 02 板 P2-06 行"约 30 条"旧估算）。
- 8 条高频命中规则中 P042（129 命中）等为正向 regex 命中面=**真可定位子集**
  （loc_from_match 既有工具面，types.py:107）。

## §3 落地内容

### 3.1 P5-01 `--fix-hint` 旗标（lint + scan 两路径）

- `lint_commands.py` lint 路径：`@click.option("--fix-hint", ...)`；fmt=cli 时
  每 finding 行下加缩进行 `修复: {remediation}`（remediation 取
  `f.remediation or get_rule(f.rule_id).remediation`，空则跳过=不输出空行）。
  ci_mode/stdio/json 面一律不出现（机器面契约不动，与 deprecation 提示同纪律）。
- scan 路径：同旗标加入口（其 `--explain` 既有行为保留不动，避免破坏语义）。
- README quickstart 节补一行 `--fix-hint` 示例（发现性）。
- **确定性**：纯展示面（同一输入+同一旗标组合→逐字节一致输出），不碰裁决。

### 3.2 P2-06 重判（02 板行勘误+恢复条件登记）

- 板行勘误："约 30 条 critical/high 无行级" → 实锤 **117 条 critical/high**；
  但**命中面集中 10 规则**，其中负向检查族（缺声明/缺结构类，P001 占 88%
  命中）无锚点=行级定位对它们是假精度。
- 状态 ⬜ → ⏸：恢复条件=正向 regex 命中规则先行（P042 等，loc_from_match
  2 行/规则，双基线探针护栏），负向检查族不立项（无锚点=不报行号=现有契约
  已是正确形态：parse_location 空串=文件级，SARIF region 省略，规范行为）。

### 3.3 P5-02 重判（⏸ 观察区）

- rich 已是 core 依赖（8 文件在用，dataset/market 面）——**零新依赖可实施**，
  但收益面（彩色/表格分组）低于 P5-01（数据可达性）；ANSI 进 CI 日志与 gate
  面冲突需 `--color auto` 设计先行。状态 ⬜ → ⏸（恢复条件=ICP-① 发布后
  体验面信号+颜色开关设计）。
