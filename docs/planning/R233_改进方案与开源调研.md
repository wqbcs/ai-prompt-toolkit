## 2. 开源与痛点调研（2026-10-05 实搜留痕）

### 2.1 buried-injections（rudratoshs，2026-09）——本轮最重要信号
- **可复现基准**：10 个开源注入检测器 × 629 条 AgentDojo 真实攻击（埋入正常 tool output，
  即生产真实形态）+ 97 条良性 tool output。`make bench-agentdojo` 一键复现，MIT 系可引用。
- **结果**：最佳 = 51% 召回 @ 2% FP（jailbreak-detector-large）；Prompt Guard 2 默认 1%；
  纯 regex 基线 0%；"全报"型检测器 100% 召回 @ 98% FP（= 无用）。
- **方法论创新（LinkedIn 读者建议，已采纳进其仓库）**：**固定 2% FP 预算下比召回**——
  "rank detectors by what they cost when they are wrong"。每个检测器调阈值到误报预算内再排名。
- **对本项目启示**：
  1. **坐标系**：P5-11 公开页必须同时给"默认 operating point"和"2% FP 预算 operating point"
     两列，否则与行业基准不可比（我方静态规则无阈值可调=天然固定 operating point，
     这正是确定性楔子在评估面的红利——一句话叙事）。
  2. **语料可复用**：97 条良性 tool output = 高质量 TN 源（正常 JSON/文件读取/搜索结果混排，
     正是我方 TN 难点面）；629 条攻击里**静态可检测子集**（零宽/BiDi/编码变形/显式越权指令
     字面量）可作 TP 探针源。语义注入类（纯措辞社工）**不取**——诚实边界（T4）。
  3. **定位佐证**：统计检测器在真实埋入场景≈抛硬币 → 确定性静态层（可解释/可审计/零漂移）
     的生态位被反向夯实。竞品对比表（C 类内容件）可引用此基准。
- **行动**：登记 P2-23（语料扩容，探针先行）；P5-11 验收标准加 FP 预算双列口径；
  07 竞品监控 +1（基准类，非直接竞品）。

### 2.2 Prompt Guard 2 OOD 实证（r/PromptEngineering，2026-08-21）
- 社区实测：PG2（86M，Meta 官方）在 OOD 攻击集（新 HackAPrompt 注入 + dolly 良性）
  默认 operating point **仅 22.8%**，阈值扫到极限 26.6%。
- 同帖发现：冻结 embedding + 朴素 logistic regression → **AUC≈0.999**（编码器看得到，
  头没训好）。→ 官方检测器在 OOD 面脆弱是结构性问题，不是调参能救的。
- **对本项目启示**：再次验证"不引 ML 检测器"决策（楔子正交轴）；同时我方双基线
  （TN 集=OOD 面）正是暴露此类脆弱性的机器护栏——叙事素材 +1（P5-05 博客弹药）。

### 2.3 promptlint（AryaanSheth，2026-01）——同名叙事占位者 feature 面再核实
- **新增细节**（R225 登记后首查）：pip + npm 双端 + GitHub Action（inline 字符串免 checkout）+
  `.promptlintrc` 配置 + **CI 日志 A–F 健康分（--show-score）** + SARIF + PR diff annotations +
  **`--fix` autofix**（去礼貌填充/冗余短语/结构脚手架）+ `cost-limit` 规则（token 预算超即 CRITICAL）。
- **feature 差集核对（我方已有/缺）**：
  | 面 | promptlint | 我方 | 判定 |
  |---|---|---|---|
  | A–F 分 | CI 日志单字母 | prompt_doctor 健康分 + scan 四维健康分（R212-5）+ lint score 基线 | 已有，不重复造 |
  | autofix | --fix | `lint --fix`（196 规则可修，fixer.py）+ --dry-run/--interactive | 已有且更细 |
  | 配置 | .promptlintrc | **缺** → P2-03 promptlint.toml 正当性再确认 | 缺口成立 |
  | token 预算规则 | cost-limit | P265 cache-friendly + token 分析命令（无"预算超=CRITICAL"规则） | 观察项（无采用者信号，T7 不登记） |
  | 确定性承诺 | 无（无复现性声明/无双基线） | 逐字节一致 + 双基线时间序列 | **我方独占楔子** |
- **行动**：07 竞品监控 promptlint 行更新 feature 面；P2-03 设计对标其 rc 语义
  （fail-on 阈值/规则开关/severity 覆盖——配置 schema 取两者并集最小面）。

### 2.4 ClawGuard（prompttools.co，2026-03）——诚实基准叙事的同行验证
- regex 检测器自攻击：18 payload 33% 检出 → 加 6 规则后 83%，**FP 恒 0%**。
- 公开结论："A scanner that blocks legitimate requests will get disabled within a week.
  **Precision first, recall second.**" + "Honest benchmarking builds trust."
- **对本项目启示**：与 01 §2 moat 叙事同向的第二独立来源（08 §7 信号分级 ≥2 来源达 S 级：
  buried-injections 方法论 + ClawGuard 结论 = "precision-first 静态层"市场共识成立）。

### 2.5 Prompt 版本化 2026 指南（promptassay.ai，2026-04）——需求分层核实
- 四层常被混为一谈：**versioning（不可变版本史）/ eval / deployment / drift detection**。
- 高频失败模式 = "只 capture 文本不 capture model+params+rationale"；git+md 路线
  上限≈4 人协作；平台化（Langfuse/LangSmith）=非工程师编辑场景。
- **对本项目判定**：我方 P2-02（schema_version）+ baseline diff + git 留痕 = versioning 层
  的 git 侧地基，**已对齐该指南推荐的最小路线**；平台化（UI/审批流/canary）= 明确不跟
  （反清单 +1：无 ICP 信号，T7）。指南中"change rationale"面我方 waiver @owner 机制部分
  覆盖，不做扩展。

### 2.6 AgentDojo（ethz-spylab）——数据源可复用性核实
- 动态 agent 攻击基准（task/tool 环境），`agentdojo[transformers]` extra；
  攻击/防御/任务矩阵化。buried-injections 的 629/97 即取自此环境。
- **取用方式（P2-23）**：不引依赖，只**人工摘录**其 tool output 文本面（正常 JSON/文件读取
  混排 → TN）与静态可检测攻击形态（零宽/BiDi/编码/显式字面量 → TP）进
  `data/golden_attacks.json`，来源标注（MIT，可引用 URL+commit）。零代码依赖，
  与既有探针格式同构。

## 4. 对抗审查留痕（方案自审）

1. **P4-01 测绘会不会变成大工程？** 约束=只产文档。ast 扫描 import 边是机械活
   （`scripts/` 一次性脚本，不进门禁链）；G1-G7 是 7 个是/否判定，逐个给证据行号。
   产出物 1 个文档。→ 风险受控。
2. **P1-10 gap 棘轮会不会被 86% 高基线绑架？** 基线=当前值（86%），棘轮只拦"变差"。
   P2-05 补强后数字下降=棘轮自动收紧（独立 commit 降基线+理由，同双基线纪律）。
   → 无绑架风险，方向自洽。
3. **P2-02 引 jsonschema 依赖是否必要？** 否——读取端只有本工具自己（baseline 读取）+
   用户脚本（文档化兼容策略）。手写兼容层（未知字段忽略+warning）+ 测试锁死=奥卡姆解。
   → 零新依赖成立。
4. **P2-01 首个 deprecation 用例选谁？** 发布前无外部采用者=任意内部规则安全。
   选"从未被 golden 探针引用+无基线 findings"的规则（候选测绘后定），避免动双基线。
   → 选规则标准入验收。
5. **buried-injections 的 629 攻击会不会被误用为"我方应达到 51%"的对标？** 否——
   坐标系不同（它测的是**语义**注入的**运行时**检测；我方测的是 prompt 文本的**静态**门禁）。
   取用的只有：①评估方法论（FP 预算）②语料（TN+静态可检测面 TP）。文档 §2.1 已显式区分。
   → 无口径混淆。
6. **本轮 5 项会不会超一轮容量？** 1 项 M+1 项 S+2 项 M+1 项 S；P4-01 无代码变更；
   P2-02/P2-01 互不依赖可并行面小（都动 linter 元数据，串行更稳）。串行按序=
   测绘→gap 棘轮→schema→deprecation，最坏砍掉 #4 顺延（#1-#3 独立成立）。→ 容量受控。
