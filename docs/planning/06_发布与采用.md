## 1. PyPI 发布（P0-04，最高优先——产品存在的证明）

### 现状
- 版本 67.34.16 未发布；仓库私有（发布前必须 P0-03 转公开，PyPI 项目需公开可见性背书）
- 打包配置已有（pyproject build-system + package data 含 baselines/ 探针样本+数据）
- 本地/CI 环境漂移史 4 连红 → **发布前必须完成 P0-05 环境锁定**（wheel 构建环境也要锁）

### 方案：trusted publishing（OIDC，无长期 token）
1. **PyPI 侧**（需用户操作，一次性 ~5 分钟）：
   - 创建项目 `ai-prompt-toolkit`（名称需先查占用——若被占则 `ai-prompt-toolkit-cli`）
   - 项目 Settings→Publishing→Add integration：
     - Owner = GitHub 仓库（wqbcs/ai-prompt-toolkit）
     - Environment = `pypi`（先在 GH 建同名 environment + 保护规则）
   - **无需 API token**——GH Actions 以 OIDC 身份代签
2. **GH 侧**：`.github/workflows/publish.yml`
   ```yaml
   on:
     release: { types: [published] }   # 或 tag v* 触发（二选一，推荐 release）
     workflow_dispatch: {}
   permissions:
     id-token: write   # OIDC 必需
   jobs:
     publish:
       runs-on: ubuntu-latest
       environment: pypi
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-python@v5  (python 3.12 固定)
         - run: pip install build
         - run: python -m build            # sdist + wheel
         - uses: pypa/gh-action-pypi-publish@v1.x   # hash 锁定(05 §S7)
           with: { trusted-publishing: true }
   ```
   **注意**：`pypa/gh-action-pypi-publish` 必须 commit-hash 锁定（supply chain 标准）。
3. **构建质量**（wheel 用户视角，发布前冒烟）：
   - **干净 venv 冒烟**（关键——本地 venv 有未声明依赖 jinja2 史，wheel 用户是干净环境）：
     ```
     python -m venv /tmp/pypi-smoke && /tmp/pypi-smoke/bin/pip install dist/*.whl
     /tmp/pypi-smoke/bin/prompt-cli --version
     /tmp/pypi-smoke/bin/prompt-cli baseline      # 必须输出 0.00%/0.91%
     /tmp/pypi-smoke/bin/prompt-cli lint -s <样本> # 必须出 finding
     /tmp/pypi-smoke/bin/prompt-cli gap-report --help
     ```
   - wheel 内容审计：`unzip -l` 确认 baselines/ 探针样本+数据文件都在（package-data 配置正确）
   - PEP 517 构建无源码执行（05 §S5 check-wheel）
4. **元数据**：`pyproject` 的 classifiers（Programming Language / Topic / Operating System）、
   `project.urls`（Repository/Issues/Documentation）、long_description=README（英文版先行 P1-07）
   - **README 双语注意**：long_description 默认取 README.md——P1-07 英文首屏完成前，
     PyPI 页面显示中文（可接受但降级体验），或发布时临时 long_description 指向 EN 段
5. **发版后 30 分钟验证**：`pip index versions ai-prompt-toolkit` + 干净 venv 冒烟 + PyPI 页面截图存档

### 失败模式预案
| 失败 | 处置 |
|---|---|
| OIDC 签名 403 | 查 environment 名一致 + protection rules 允许 GH Actions |
| 包名被占 | 改名 `ai-prompt-toolkit-cli`（模块名 `ai_prompt_toolkit` 不变，仅 PyPI 项目名变） |
| sdist/wheel 内容缺文件 | package-data 检查；`python -m build` 后 `unzip -l` 对清单 |
| 干净 venv 缺依赖（jinja2 史） | `check_dep_manifest.py`（Q2-4）会先抓出；补声明或去依赖 |

**估时**：GH 侧 S（1 轮）；PyPI 侧依赖用户操作（一次性）；干净 venv 冒烟脚本 S（入库为 `scripts/pypi_smoke.sh`，此后每发版跑）

## 2. GitHub Action（P1-01，S2 采用主入口）

### 设计（复用 03 §A1 调研）
```yaml
# .github/action.yml（composite action）
name: prompt-lint
description: 确定性 LLM prompt 门禁（零 LLM，可复现）
inputs:
  paths:        { description: 扫描路径, default: . }
  incremental:  { description: "只看新增 findings（需 git 基线）", default: "false" }
  sarif:        { description: 输出 SARIF 到 Code Scanning", default: "true" }
  gate:         { description: 按 gate 阈值退出", default: "true" }
  fail-on:      { description: 拦截级别", default: "critical" }
runs:
  using: composite
  steps:
    - uses: actions/setup-python@v5 (3.12)
    - run: pip install ai-prompt-toolkit==${{ inputs.version || 'latest' }}
    - run: prompt-cli lint -s ${{ inputs.paths }} ... (参数透传)
    - if: inputs.sarif == 'true'
      run: prompt-cli lint ... --format sarif -o sarif.json
    - if: inputs.sarif == 'true'
      uses: github/codeql-action/upload-sarif@v4
      with: { sarif_file: sarif.json, category: prompt-lint }
```
**incremental 实现选择**（关键决策点）：
- 首选：`--incremental --baseline`（我们已有）——但 Action 场景基线从哪来？
  - 方案 A：`--new-from-rev`（P2-17 新增待办）——Action 内 `git diff --name-only ${{ github.event.pull_request.base_sha }}` 取变更文件，lint 只跑变更文件。**推荐**：CI 场景 git 天然可用，比基线文件更自动
  - 方案 B：基线文件入库（brownfield 用户已有此流程）——无 git 变更事件时回退
  - **结论**：Action 默认走方案 A（PR 场景），保留 `--baseline` 输入供 brownfield
- 退出码透传（gate 红→Action 红→PR 状态检查红）

### 发布
- Action 随主仓库发布（`actions/` 目录或仓库根 action.yml）——**不需要单独 npm 包**（composite 不打包 JS）
- marketplace 注册（免费，填 description+badge）——`prompt-lint` 名称先查占用
- 版本：`@v1` tag（composite action 版本=tag）
- 第三方调用文档（adoption.md）：
  ```yaml
  # R336 审计修正: 真实工件=根 action.yml（R287 修复）, 旧路径 actions/prompt-lint 已删除
  # 版本 tag=action/v1（不匹配 release 触发模式 v*, 随发布 tag 同推; 裸 v1 会误触发发布链）
  - uses: wqbcs/ai-prompt-toolkit@action/v1
    with: { target: prompts/, fail-on: "high" }
  ```

### 验收
- 本仓库 dogfood：我们的 prompt-ci.yml 改用自家 Action（吃自己的狗粮=最强演示）
- 造一个测试仓库（fork）跑 PR 验证：gate 红→PR 红；SARIF 进 Code Scanning

## 3. pre-commit 钩子（P1-02，提交前最后一道闸）

### 设计（复用 03 §A2 黄金先例 ruff-pre-commit）
```yaml
# .pre-commit-hooks.yaml
- id: prompt-lint
  name: prompt-lint
  description: 确定性 LLM prompt 门禁（零 LLM）
  entry: prompt-cli lint -s {0} --gate
  language: python
  additional_dependencies: [ai-prompt-toolkit]   # 用户无需装 Python
  files: \.(md|txt|prompt|json|yaml)$
  types: [text]
```
**注意**：
- `language: python` 要求包在 PyPI（P0-04 前置）
- pre-commit 环境是隔离 venv——**干净环境冒烟同样适用**（与 PyPI 冒烟同逻辑，加进 `scripts/pypi_smoke.sh` 的 pre-commit 段）
- 提交前场景：只跑 `--gate`（快），SARIF/基线留给 CI——**体验纪律：pre-commit 必须 <2s**（26 模板单文件毫秒级，满足）

### 验收
- `pre-commit run --all-files` 在干净环境（无 Python 用户机器）跑通
- 故意提交违规 prompt → 钩子红且提示可行动（映射 P5-01 错误消息可行动化）

## 5. JS/TS 端（P1-04，"每端最优技术栈"）

### 决策树（奥卡姆剃刀——能不加端就不加）
```
JS 用户需要 prompt 检查吗？
├─ 有 CI（Node 项目）→ uvx 方案（零 npm 层）
│    前提验证：uvx 在 GH Actions ubuntu runner 可用（setup-uv action 存在）
│    文档：npx 不行（uvx 非 npm），CI 加 setup-uv + uvx prompt-cli lint
│    本地：用户装 uv（一行命令）或 docker 镜像
├─ 无 CI 的 Node 脚本内嵌 → npm 薄包装（仅参数/退出码透传，spawn uvx/docker）
└─ 浏览器/零安装 → P2-13 playground（前端，远期）
```
**npm 包装器（若需要）的最小职责**：
- 包内**不嵌 Python**（体积灾难）——首次运行下载 uv standalone（python-build-standalone）或复用系统 uv/docker
- CLI 参数透传 + stdout 透传 + exit code 透传（全部职责，<100 行 TS/JS）
- **风险**：下载 python 运行时=用户机器上执行二进制（信任成本）——文档必须透明说明来源（uv 官方 release，hash 校验）
- **结论**：**先只做 uvx 文档路径（P1-04a，S），npm 层（P1-04b，L）延后到"真实 Node 用户反馈要求 npx 体验"再启动**——需求证明前不做（陷阱 T1 变体）

## 6. VS Code 扩展（P1-05，编辑器端）

### 前置：CLI 加 `--stdio` 协议（P1-05a，S）
```
prompt-cli lint --stdio
  输入：每行一个 JSON {"type":"lint","path":"...","text":"..."}
  输出：每行一个 JSON {"type":"result","path":"...","findings":[...]}
```
- **为什么 stdio 常驻 server 而非每文件起进程**（03 §A5 vscode-eslint 先例）：
  VS Code 保存事件频繁，进程启动开销（Python import 链）吃掉 <100ms 预算
- **协议纪律**：JSON 行协议是纯文本契约（04 §5）——JetBrains/Neovim 插件未来复用同一协议，零扩展端成本
- 超时/崩溃自恢复：server 崩溃 → 扩展重启（vscode-eslint 同机制）

### 扩展设计
- **技术栈**：TypeScript + VS Code Extension API（公认最优，无争议）
- **功能最小集**（奥卡姆剃刀——纯文本检测不需要 LSP）：
  - 保存/失焦触发 lint（`.md`/`.txt`/`.prompt`/`.json`/`.yaml`）
  - diagnostics 面板（severity 映射：critical→Error/high→Warning/medium→Info/low→Hint）
  - hover 显示规则 explain（`prompt-cli explain Pxxx` 输出缓存）
  - 状态栏 finding 计数
  - **不做**：补全/跳转/重格式化（prompt 不是代码，LSP 全套是过度设计）
- **行级定位依赖**：P2-06（critical/high 行级）——扩展 diagnostics 需要 line 号
- **发布**：VS Code Marketplace + Open VSX（Code-OSS 生态，两发——绑定风险零）
- **验收**：装扩展 → 新建 .md 写注入样本 → 保存 → 问题面板出 finding → 点击跳行

## 7. AI 编码助手指令（P1-06，零成本内容面）

### 设计（三文件一致，映射各 AI 工具的配置约定）
- `.cursorrules`（Cursor）
- `CLAUDE.md`（Claude Code）
- `.github/copilot-instructions.md`（GitHub Copilot）

### 内容模板（核心信息）
```
本项目 LLM prompt 受 prompt-cli 门禁保护（零 LLM 确定性静态检查）。
修改任何 .md/.txt prompt 文件时：
1. 遵循 .github/prompts/ 下模板的防御声明惯例（系统提示/工具边界/输出约束）
2. 本地验证：prompt-cli lint -s <file> --gate
3. 若需豁免：行内 waiver 注释 promptlint:ignore Pxxx @owner <到期日>（必须带 owner 和到期日）
4. 常见规则解释：prompt-cli explain Pxxx
5. CI 会跑同一门禁，本地绿=CI 绿
```
**价值**：AI 助手改 prompt 时自动对齐门禁规则=减少采用者的"AI 写的 prompt 过不了门禁"摩擦
**维护**：三文件内容相同（单一真源在 docs/adoption.md，三文件是其片段引用）——P1-11 维护

## 8. 采用漏斗（端到端路径图，adoption.md 的骨架升级）

```
发现层 → 评估层 → 接入层 → 习惯层

- 发现→评估：<2 分钟（pipx run 出第一个 finding）

- PyPI 下载数 vs GitHub 星数比（下载高星低=发现层弱；反之=评估层弱）
- Action 调用数（S2 北极星代理指标）

## 9. 发布节奏与通道矩阵

### 发版 SOP（固化进 release-please，P6-01 前手工）
```
1. python scripts/release_gate.py        # 全链门禁（Q3）
2. 升版（pyproject/__init__/README徽章/npm镜像版本 4 处 + CHANGELOG；R346 起 npm 入版本口径, check_version_consistency #5 强制锁步）
3. gen_rules_doc.py + sync_badges + sync_readme_metrics
4. check_version_consistency
5. commit（conventional: feat/fix/chore）→ push
6. CI 双绿（prompt-ci + owasp-scan）
7. 打 tag v<version> → 触发 release.yml（PyPI + npm + Docker 三通道；npm 需用户侧 provenance 已开启, 见 docs/pypi-trusted-publishing.md §H）
8. pypi_smoke.sh 干净 venv 冒烟
9. 更新 02 总板状态 + 00 交接文档

**升版门禁序是硬纪律**（已固化记忆：67.34.12/13 两次漏 gen_rules_doc）——
顺序不可调：版本→rules_doc→徽章/指标→一致性检查→commit

### 版本语义（P6-02 策略）
- **patch**（67.x.y+1）：bugfix/文案/文档
- **minor**（67.x+1.0）：新规则/新命令/新 flag
- **major**（68.0.0）：行为变更（规则语义改/退出码改/schema 破坏）——**5 年内尽量少 major**（采用者迁移成本=流失）
- deprecation 周期（P2-01）：规则下线跨 2 个 minor 版（warn→remove），CHANGELOG 预告
