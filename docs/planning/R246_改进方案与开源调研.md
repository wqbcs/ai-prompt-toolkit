## §1 定位与反思（鬼才 PM 自检，开工前）

**项目定位**：确定性的 LLM 提示词静态门禁——prompt 的 ESLint。
**楔子**（产品核心价值）：每次裁决逐字节一致 + 零 LLM 成本 + <100ms/文件 + 离线可跑。

**本轮自检四问**：

1. **定位是啥？** 可验证的确定性。双基线/性能/复现性（finding 序列）已有机器护栏
   （R232 property / R244 性能门禁 / P3-02 复现性 property），但**"逐字节一致"
   承诺的输出面里，SARIF 这条还埋着时钟**——这是楔子叙事的自伤点（我们批评
   检测器"输出不可复现"，自家 SARIF 带时间戳=同病）。

2. **问题在哪（实查）**：
   - `report/sarif_reporter.py:78/139`（CLI lint 真源）用 `datetime.now(timezone.utc)`
     填 `startTimeUtc`/`endTimeUtc`。
   - `sarif_report.py:135/183`（eval/scan 路径）用 `time.gmtime()` 填
     `invocation_time`/`endTimeUtc`。
   - 同一文件连跑两次，SARIF **字节级不同**（时间戳差）→ 直接违"逐字节一致"。
   - 07 R8 行连续多轮标 🟡"待护栏落地"，缓解列写"复现性 e2e（同输入 3 次逐字节
     相等）+OTEL 采样对比"——但**复现性 e2e 从未真正落到输出字节面**（P3-02 的
     `test_reproducible_verdict` 只锁 finding **关键序列**，不锁 SARIF 字节）。

3. **需要怎样调整？** 把"逐字节一致"从 finding 序列面**延伸到 SARIF 输出字节面**：
   - 时钟可注入（固定值可传入），默认保持真实时间（人读），门禁/测试用注入值断言。
   - 补 SARIF 字节级确定性 e2e（同输入 3 次逐字节相等）。
   - 收口 P2-07 板行验收"SARIF 过官方 validator"（离线结构校验，不引运行时依赖）。

4. **低价值打磨陷阱清单（本轮主动避开）**：

| 陷阱 | 判定 | 依据 |
|---|---|---|
| 引官方 SARIF 2.1.0 JSON schema（多 MB）+ jsonschema 运行时依赖做校验 | ❌ 不做 | schema 需联网拉取（air-gap 场景破坏楔子"离线可跑"）；jsonschema 进运行时=依赖面扩张。改用**离线结构校验脚本**（必填字段+类型断言，零网络零新依赖），与楔子"离线可跑"一致 |
| 把 267 条规则移植成纯前端跑 P2-13 playground | ❌ 不做（本轮） | 规则是 Python check 函数非纯 regex 数据（P2-14 export 无 patterns 字段）——纯前端=用 JS 重写 267 规则=重复实现；违反"不为全端而全端"反清单行。P2-13 前置=P4-06 规则数据 JSON 化（远期），本轮只登记重判不硬做 |
| 顺手把 dataset/compiler/compliance 所有时间戳全清 | ❌ 不做 | 那些是**数据产物面**（数据集生成时间/编译报告），不是"裁决输出"；楔子承诺的是**同一输入同一裁决逐字节一致**，数据产物的生成时间本就应反映真实时间。只清 SARIF 这条裁决输出面（奥卡姆：最小面闭环） |
| 为 SARIF 做 baseline 增量语义（P2-07 子项 automatedBaselineId） | ❌ 本轮不做 | P2-07 板行三子项（fixes/properties/baseline）中前两项已实现（实查），baseline 增量语义依赖 P2-02 schema 演进，单独立项评估；本轮只收"validator+确定性"两条，不贪大 |

## §2 开源/外部调研

**竞品信号（2026-10-08 检索，S 级：体验面成标配，差异化在双基线）**：
- aisona-lab/prompt-guard（TS，59 规则，CLI+REST+TS lib+**web UI**）："measured,
  not vibes"——带标注 benchmark 进 CI 跟踪检测质量；"Fast, deterministic core,
  sub-millisecond"。**可选 LLM second opinion**（provider-agnostic，可离线）。
- PromptLint（promptlint.dev，20+ 规则，"ESLint for LLM prompts"，PyPI+npm，
  **VS Code 插件**+SARIF，"12ms avg scan, 0 API calls"）。
- **信号解读**：竞品已把 web/playground/编辑器插件做成标配面；我方**差异化不在
  端数量**，在双基线时间序列+逐字节确定性+多语言分基线（cognis-promptlint 四端
  ports 是反面教材，反清单已登记）。体验面（P2-13/P1-04/P1-05）按 ICP 信号逐个
  上，不抢跑。本轮聚焦"确定性"这个差异化内核的护栏，不追端。

**SARIF 规范（OASIS 2.1.0 errata01，2026-10-08 核对）**：
- `invocations[].startTimeUtc`/`endTimeUtc` 为**可选字段**（spec 不要求）——锁定/
  注入不违反 SARIF 语义，符合"确定性输出"楔子。
- 官方 schema（`sarif-schema-2.1.0.json`）体积大、需联网；GitHub Code Scanning
  上传侧有独立校验，本地门禁用**离线结构断言**（必填字段+类型）即可覆盖
  "SARIF 过 validator"验收的**可验证性**诉求（不联网、不引依赖）。

**既有护栏盘点（防重复造轮子）**：
- P3-02 `test_r232_properties.py` 已含 `test_reproducible_verdict`（同输入两次
  finding 关键序列逐位一致，hypothesis derandomize）→ **finding 序列面已锁**。
- 本轮补的是**输出字节面**（SARIF），与既有 property 互补不重叠。
- R244 性能门禁（check_lint_performance.py）已锁 <100ms 楔子 → 不动。

## §3 落地内容

### 3.1 SARIF 时钟可注入（两个生成器）

- `report/sarif_reporter.py::findings_to_sarif`：已有 `run_id` 参数，新增
  `start_time`/`end_time`（`datetime`，默认 `None`→真实 `datetime.now(timezone.utc)`）；
  测试/门禁传入固定值即字节级确定。`write_sarif_report` 同参透传。
- `sarif_report.py`（eval/scan 路径 dataclass 生成器）：`SarifRun.invocation_time`
  与 `endTimeUtc` 改为可注入（构造参数），默认保持真实时间。
- **语义边界**：默认输出仍带真实时间（人读/审计友好）；确定性保证=**给定同一注入
  时间戳，同一输入输出逐字节一致**。这不是"假确定性"，是把时钟这个唯一外部变量
  变为可注入参数（与 `run_id` 同形态）。

### 3.2 SARIF 字节级确定性 e2e

- 新测试：同一 findings 输入 + 同一注入时间戳，跑 `findings_to_sarif` 3 次 →
  `json.dumps(sort_keys=True)` 逐字节相等；再断言 `startTimeUtc`/`endTimeUtc`
  等于注入值（防回归回真实时钟）。
- 覆盖两个生成器（reporter + report）各一条。
- 接 P3-02 property 族（同文件追加或独立 test 文件，按规模定）。

### 3.3 SARIF 离线结构 validator（收口 P2-07 验收）

- `scripts/check_sarif_schema.py`（离线，零网络零新依赖）：对 `--format sarif`
  产物断言必填结构（`$schema`/`version=2.1.0`/`runs[]`/`tool.driver.name+version`/
  `results[].ruleId+level+message.text`/`locations[].physicalLocation.artifactLocation`），
  红绿两态可测。
- release_gate 新步 + CI test 作业同命令（与 check_lint_performance 同接线形态）。
- **验收口径诚实声明**：这是**结构子集校验**（覆盖 Code Scanning 上传必需字段），
  非完整 OASIS schema 校验（完整 schema 需联网，与离线楔子冲突）——板行"过官方
  validator"按此离线口径收口并留痕（GitHub Code Scanning 上传侧的完整校验由
  CI 既有 `upload-sarif` 动作兜底）。

1. **让用户更信我们了吗？** 是——"逐字节一致"从文案变成 SARIF 字节级机器断言，

   结构校验（一个脚本）= 最小闭环；完整 schema/前端 playground/baseline 增量
   三个膨胀面全部主动避开（§1 陷阱表）。
3. **下轮该做啥？** 待定（R247 反思+调研）。候选：P2-07 baseline 增量语义
   （Code Scanning 增量体验）/ P3-08 mypy strict 棘轮 / 竞品 web 体验面重判。
