## §2 开源调研（R254 增量，只查 3 天增量+定向核验）

### §2.1 import-linter（P4-10 选型核验，S 级）

(import-linter，Python 事实标准的依赖方向契约工具) 契约类型=forbidden/layers/
independence/acyclic siblings。可借鉴语义：
1. **layers 方向语义**：上层可依赖下层，反方向（含间接）=违约——我方 04 §1 铁律
   同构。
2. **ignore_imports + unmatched_ignore_imports_alerting**：豁免边显式登记+
   **豁免不再命中时告警**（防永久豁免腐烂）——我方豁免表纪律增强：本轮豁免表
   每条带 14 §3 编号/处置归属轮次，修复落地同 commit 删行（check_layer_deps.py
   KNOWN_VIOLATION_EDGES 同纪律，已有先例）。
3. **exhaustive 契约**：声明必须覆盖全部模块——**不借鉴**：我方 linter/ 是
   kernel+rules 扩展混放（14 §2 G2 架构决策"允许暂混"），exhaustive 会把 79 文件
   全要求归类=为护栏造重构，违反 T6/Occam。

**选型定稿（不引依赖的理由，奥卡姆+楔子一致性）**：我方场景=3 条固定检查+
文件级豁免表，输入是 14 测绘+04 §1 的既有结论；check_layer_deps.py（P4-02）
已确立"纯 stdlib 检查脚本+豁免表留痕"形态且进门禁链 24 步稳定运行——P4-10 与其
同族（同输入源 kernel_files()、同豁免纪律、同 --json 面），引 import-linter
（dev 依赖+TOML 契约文件=第二套配置真源）=重复造轮子的反向：为一个检查器引入
外部真源。

### §3.2 实现要点

- `scripts/check_layering.py` 纯 stdlib（ast），~150 行；`--json` 面。
- 第一方 import 目标解析：覆盖 `import ai_prompt_toolkit.x` / `from ai_prompt_toolkit.x
  import y` / `from .x import y` / `from ..x import y` 四形态；`from pkg import name`
  的 name 候选做**文件存在性过滤**（name.py/name/ 存在且非 kernel 才判，纯符号名
  如 `__version__` 跳过）——防假阳性。
- 豁免表 `KNOWN_CROSS_LAYER_EDGES: dict[(src, target), reason]` 文件+目标粒度，
  每条带 14 文档编号+处置归属轮次；**豁免纪律**=修复落地同 commit 删行（同
  check_layer_deps KNOWN_VIOLATION_EDGES 先例）；豁免清单空且 0 命中=绿（不依赖
  豁免也绿时豁免行在告警面提示，import-linter unmatched-ignores 语义弱化版——
  本轮只做提示不阻断，防过度设计）。
- 诚实失败：kernel 清单文件缺失=红（复用 check_layer_deps 同纪律）。
- 与 check_layer_deps.py 的关系：L2 源清单 import 复用（`from check_layer_deps
  import kernel_files`），零复制。
