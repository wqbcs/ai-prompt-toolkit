## 1. 定位反问（每轮必答）

### 1.1 这个项目是干什么的
确定性 prompt 安全门禁（prompt 的 ESLint）：逐字节裁决一致 / 零 LLM / <100ms / 离线可跑。
价值 = "可验证的 prompt 安全基线"，不是"完美检测器"。

### 1.2 产品核心价值是什么
**可信度**。R249-R250 已证明曲线方向（33.92→20.94）。竞品（PIGuard/InjecGuard）给不了的
= 一条逐轮收紧、git 可 diff 的公开过防御曲线。本轮判据：**修真缺陷 + 如实记录正当
检测**，不为数字服务。

### 1.3 目前推进方向有什么问题（反问 + 纠偏）
**纠偏 1（优化单元错误）**：R249/R250 按"单规则命中数降序"排序，但同一 benign prompt
常同时被多规则共标（本轮数据：71 个 flagged 中 40 个被 2+ 规则共标；RAG 簇 5 规则同时
共标 6-11 个 prompt）。命中数排序系统性高估边际收益——真实优化单元是 **flagged prompt
集合的 set cover**。本轮起治理清单改按"可解标独有 flagged prompt 数"排序（G 项落盘
方法学）。

**纠偏 2（不为基准作弊）**：P163 的 21 个 benign 命中中 13 个**字面含
"jailbreak/jailbreaking"词**——它们是**正当的静态召回检测**（静态门禁见攻击词即保守
报警，是可辩护的设计选择）。把 "jailbreak" 从 pattern 里拿掉降数字 = 牺牲 3 条 golden
TP + 真实召回 = CLAUDE.md 禁止的"为指标卖核心价值"。本轮只修**可分面**（pretend/
roleplay 共现门、DAN 语境化、Data Access Object 排除），jailbreak 词提及面登记为残差
（I 项）并如实声明边界。

**纠偏 3（收益递减边界）**：本轮修后剩 ~46；再降到 <10% 需清 ~12 个 prompt，其中单例
（P042/P039/P071/P073 各 1）需逐个独立设计，且大头是正当词汇检测（I 项）——边际成本
陡升、边际可信度收益陡降。**<10% 不是本轮目标**，它属于"二阶信号（NPI/意图分类）设计
轮"，需独立可行性评估（且可能与确定性楔子冲突——NPI 是模型类信号，先验证再立项）。

### 1.4 为什么不"加规则/收紧"
相反方向：本轮是**放松型修复**（清误杀）。产品信任来自"独立硬负样本上的误杀率
在下降"，不是更狠。越狠 = 过防御越高 = 可信度越低（R249 首点 33.92% 的教训）。

## 5. 反思与调整（方向层面）

1. **曲线叙事**：33.92 → 20.94 → **14.45**。每点 git 可 diff + 探针可复现。到 14.45%
   后曲线进入"正当检测地板"区（I 项 13 个 jailbreak 词提及 ≈ 3.8% 是不可纯正则消除的
   下限）——**10% 以下 = 需要意图级二阶信号**，那是产品能力跃迁（新模块），不是治理
   收尾，必须独立立项评估（含与确定性楔子的兼容性论证）。
2. **指标诚实性**：过防御指标 = "任一安全规则命中 benign"，它混合了"缺陷误杀"与
   "正当保守检测"两类。README 公开声明应补充这一定义边界（本轮加），避免读者把
   14.45% 全读成"14.45% 是纯误报"——如实口径：缺陷面 ≈ (49 - 13 正当)/339 ≈ 10.6%。
3. **set-cover 方法学**（G 项）：R252+ 治理清单不再按命中数排序。这直接回答了
   "推进方向有啥问题"——前两轮排序启发式把 1/3 的治理预算花在了共标簇上（修单规则
   不解标 prompt），本轮纠正后同样的 6 项修复从"预期 14 解标"（命中数排序 top4）
   变为"31 解标"（set-cover 排序）。
