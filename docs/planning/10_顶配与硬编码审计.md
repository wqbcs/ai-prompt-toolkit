# 10 · 顶配与硬编码审计（"体验无天花板"的落地版）

> **来源**：用户硬约束——"最顶配的项目，体验无天花板：每一端都采用该平台公认的最优技术栈，
> 不被单一技术栈绑定，没有体验短板，避免硬编码；架构生命周期 5 年+"。
> **本文职责**：把这句口号拆成可验收的维度矩阵 + 硬编码审计清单。
> 任务编号对齐 02 总板；新登记任务见 §5。

## 1. "顶配"定义（先防误读）

| 是 | 不是 |
|---|---|
| 每端采用该平台**事实标准**技术栈（ruff 之于 Python 工具、MkDocs Material 之于 Python 文档站） | 追"最新"技术（陷阱 T8）——事实标准≠发布最久的，是"该平台用户默认选择" |
| 每个体验项有**验收依据**（机器断言或盲测标准） | 功能堆砌（陷阱 T1）——顶配是体验完整，不是功能最多 |
| 每端可**独立替换**（04 §1 adapter 层） | 单一技术栈绑定——核心 Python 是内核选择，端适配允许任何栈 |
| 数据与代码分离（配置/规则/基线外置） | 零常量——契约性常量（退出码/severity 枚举）是文档不是硬编码 |

## 4. 非代码顶配维度（详细设计）

### 4.1 文档站（P5-12，M）
- **现状**：docs/ 散 md（R 系列方案/backlog/gap_report/adoption 混排）+README；无导航/搜索/版本
- **选型**：**MkDocs Material**（Python 生态文档站事实标准——零构建成本/纯静态/GH Pages 托管/
  全文搜索内置/规则参考可直接挂 gen_rules_doc 产物）。**不选** Docusaurus（Node 构建链=为文档引入第二技术栈，
  违反奥卡姆）/Read the Docs SaaS（数据出域，与数据主权纪律冲突）
- **结构**（与 P4-08 目录治理合流）：
  ```
  docs/
  ├─ guide/        采用指南（adoption.md 拆页）
  ├─ reference/    规则参考（gen_rules_doc 产物 261 条）/CLI 参考/API
  ├─ decisions/    ADR（P4-09）
  ├─ planning/     本规划集（不公开到站点，仅仓库内）
  └─ samples/      缺口报告样例（P5-06）
  ```
- **版本化**：站点 tag 跟主版本（67.x）；unreleased 分支=main
- **验收**：规则 261 条全可搜索跳转；`prompt-cli explain Pxxx` 与站点规则页同源（gen_rules_doc 单一真源）；
  移动端可开；构建 <1min
- **与 README 关系**：README 只留 10 行入口，深度内容全在站点（04 §7 纪律）

### 4.2 品牌系统（P5-13，S）
- **命名映射表**（单一真源进文档站，防各端漂移）：
  | 面 | 名 | 用途 |
  |---|---|---|
  | PyPI | `ai-prompt-toolkit` | pip install |

- **GitHub 面**：topics（prompt-security/llm-security/lint/ci/prompt-injection/owasp-llm-top-10/
  deterministic/sarif）+org profile 简介+仓库 description（30 秒版楔子）
- **PyPI 面**：classifiers 完整（Python 版本矩阵/Topic/OS）+long_description=英文 README（P1-07 后）
- **验收**：四处 logo diff=0；PyPI 页面截图存档；搜索 `prompt lint security` 在 GH/PyPI 均可见

### 4.3 CI UX（P3-16，S）
- **Actions summary**（`$GITHUB_STEP_SUMMARY`）每轮产出 digest：
  ```
  ## prompt-lint digest
  FP 0.91% (baseline, ✓ ratcheted) | Miss 0.00% | 新增 findings: 3 | 耗时 42s
  Top rules: P180×2 P255×1 | gate: PASS
  ```
- **失败第一行纪律**：gate 红时 summary 首行=`FAIL: 2 critical in prompts/pay.md → prompt-cli explain P180`
  （原因+文件+解释入口，三要素齐全）
- **实现**：`prompt-cli lint --format summary` 新输出格式（纯文本，CI 专用）——P2-02 OutputAdapter 的首个新 adapter 实例（验证抽象合理性：此时 adapter 有 SARIF/JSON/MD/CLI/summary 五调用者，T7 通过）
- **验收**：红/绿两态 summary 截图存档；失败首行三要素断言（e2e）

## 5. 硬编码审计清单（P2-19，下一棒执行时照此扫）

### 5.1 硬编码分类（先分类再动，误杀契约=事故）
| 类别 | 定义 | 处置 |
|---|---|---|
| **契约性** | 对外承诺的稳定值（退出码 0/1/2、severity 枚举、SARIF 2.1.0、schema_version 语义） | **保留**，文档化为契约（P2-02），禁配置化 |
| **数据性** | 会随版本/年度变化的内容（OWASP 风险列表、规则集、基线数字、探针集、Provider/MCP 清单） | 外置为**数据文件**（包内 data，随 wheel 分发——P0-1 先例：baselines 已这么做） |
| **配置性** | 用户项目可调的参数（gate 阈值、fail-on、扫描路径、性能预算） | 进 `promptlint.toml`（P2-03） |
| **事故性** | 无意识写死的魔法数字/路径/URL | 抽模块级常量+注释，或进配置 |

### 5.2 已知硬编码点盘点（规划期静态判断，P2-19 执行时逐条验证）
| # | 位置 | 内容 | 类别 | 处置 |
|---|---|---|---|---|
| H1 | `pyproject.toml` + `__init__.py` | 版本号两处 | 事故性（可接受） | 保持双处+check_version_consistency 护栏（release-please 后单源，P6-01） |
| H2 | `linter/owasp_mapping.py` | OWASP LLM Top 10 风险定义+remediation 文本 | **数据性** | 外置 `data/owasp_llm_top10_2025.json`（年度更新=换文件，R5 触发器）+版本字段 |
| H3 | 规则文件 ×261 | 规则模式/严重度/waiver 提示 | 数据性 | P2-14 JSON 导出（不拆文件——规则即代码是确定性来源，JSON 是导出不替换） |
| H4 | 各规则模块 | 语言列表（zh-Hans/zh-Hant/en/ja/ko） | 数据性 | 集中到 `data/languages.json`（分语言基线 P2-12 依赖） |
| H5 | 包内 | baselines 样本路径 / templates 路径 / probes 路径 | 配置性 | P2-03 配置化（默认值=现路径） |
| H6 | 代码 | `wqbcs/ai-prompt-toolkit` 仓库 URL（文档/徽章引用） | 事故性 | 单一常量 `REPO_URL`（品牌表 4.2 单一真源） |
| H7 | CI workflow | Python 版本矩阵 3.10-3.12 / 作业名 `Prompt CI` | 配置性（CI 自描述） | 保留（CI 配置即声明）；作业名若文档引用需对齐 H6 同纪律 |
| H8 | 05 规划值 | 100ms 预算 / 50ms ReDoS 阈值 / 50 span 上限 / 90% 覆盖率门槛 | 配置性 | 执行时抽 `constants.py`（kernel 层）+ 进 promptlint.toml 可覆盖 |
| H9 | Provider(24)/MCP(73)/Probes 计数（**双口径**：徽章=redteam 全局探针注册表 116 / golden 攻击集=golden_attacks.json 113，11 报告 D6 定性） | 散落文档/徽章 | 数据性 | sync_badges.py 从源头计算（已有部分），全量对齐"计算不手写"纪律；文档引用探针数必须带口径（"golden 攻击集 113"或"全局探针注册表 116"） |
| H10 | 退出码 0/1/2 / severity 枚举 | 全代码 | **契约性** | 保留；P2-02 契约文档化；新级别只加（不变量⑤） |

### 5.3 扫描方法（P2-19 执行步骤，给下一棒的施工图）
```
1. 魔法数字：grep -rEn "\b[0-9]{2,}\b" src/ 过滤掉 import/版本号/测试期望 → 逐条判类
2. 路径字面量：grep -rn '"[^"]*\.\(md\|json\|txt\|yaml\)"' src/ → 应全部指向 data 或可配置
3. URL 字面量：grep -rn "github\.com\|pypi\.org\|ghcr\.io" src/ scripts/ .github/ → 收敛 REPO_URL
4. 年度数据：grep -rn "2025\|2026" src/ai_prompt_toolkit/ → 除注释外应为 0（数据进文件）
5. 语言字面量：grep -rn "zh-Hans\|zh-Hant\|ja\b\|ko\b" src/ → 收敛 languages 数据
6. 计数硬编码：grep -rn "261\|130\|73\|116\|113" src/ README.md → 应全为"计算产物"非手写
7. 产出：docs/reference/hardcode_audit.md 审计表（每行：位置/值/类别/处置/commit）
```
**验收**：数据性/事故性项 100% 处置（外置或抽常量）；契约性项 100% 有契约文档条目；
审计表入库；处置后门禁链全绿+双基线不回归+测试数不降（陷阱 T10 三断言）。

## 7. 顶配红线（自检三条）

1. 引入任何新工具/新栈前问：**该平台的用户默认选什么？** 答案是"最新"而非"默认"→ 停（T8）
2. 每个体验项验收后问：**用户能 30 秒内感知到它吗？** 不能感知的体验=伪顶配（进 P3 护栏而非 P5 体验）
3. 每次"加端"前问：**这个端有 ICP 真实信号吗？**（08 §5 ICP 验证）没有→登记 02 暂停项区，不启动
