# R280 改进方案与开源调研（2026-10-11）

> 定位一句话：确定性 LLM 提示词静态门禁（prompts 的 ESLint）——逐字节一致裁决
> + 零 LLM 成本 + <100ms/文件 + 离线可跑。五年不变量：不是运行时防火墙，
> 不是 LLM 评测平台，不追语义层召回。

## §0 定位再确认（四问）

1. **定位是啥**——设计时（pre-merge）静态门禁：规则确定性 + 裁决可复现 +
   数字可机器自证（`pip install → prompt-cli baseline` 一条命令）。
2. **核心价值是啥**——"可信的数字"而非"最强的检测"：漏检 0.00%（325/325
   期望命中单元）+ 误报 0.82%（60 干净样本）+ 过防御 11.50%（339 NotInject
   硬负样本）+ OOD 31.18%（263 deepset），全部棘轮化/公开化/可复现。语义层
   上限已在 README 诚实声明（机制上限段），这是叙事资产不是负债。
3. **方向有啥问题**——① 杠杆最大单点 P0-03（公开）/P0-04（PyPI）多轮等待
   用户授权，全部分发面（P1-01/02/03/04、P5-05）被它阻塞，本会话无法自主
   解锁；② P2-27 探针批次已近尾声（余 MEDIUM 17+LOW 27），边际价值递减但
   终点里程碑（267/267 探针覆盖 100%）是可营销收口数字，5 轮内可清完；
   ③ 分语言面 ja 仅 6 探针=差异化轴最薄数据面，需补。
4. **低价值打磨陷阱自查**——陷阱判据=「为指标改规则（J 簇纪律）/新内部
   度量/无信号文案重写」。本轮判定：探针补欠=还债（探针是漏检数字的锚，
   44 条零探针规则=漏检数字未覆盖它们，护栏强度的真实缺口）；autofix=
   fixable 0/267 无机械可修面→不做；threat-intel/输出扫描/ML 分类器=
   楔子（确定性/离线/零 LLM）冲突→不做。

## §5 对抗性审查（攻击本方案自身）

- **A1「为何磨 MEDIUM 批次而不做 ja 面？」**→ 100% 覆盖收口数字是一次性
  可营销里程碑（同赛道对照：aiproof ~100 规则/prompt-guard 59 规则，我方
  267 规则+100% 探针覆盖=无同赛道竞品的组合）；ja 面无 TP 支撑仅 TN 侧
  扩容（不加固漏检锚），分语言表边际价值低于收口数字。板纪律（前缀序）
  同向。
- **A2「探针批次本身是不是打磨陷阱？」**→ 陷阱判据=「为指标改规则/新内部
  度量/无信号文案重写」；探针=漏检 0.00% 数字的锚，44 条零探针规则=漏检
  数字未覆盖=护栏强度真实缺口。陷阱从 100% 里程碑之后开始（继续堆 TN=
  堆分母）→ P2 队列 ja 面改「由新攻击面驱动」口径，不主动堆量。
- **A3「最大杠杆点等用户，自主工作会不会白做？」**→ 不会：P0-03/04 授权
  后 README 首屏数字是「267/267 探针覆盖+漏检 0.00%@585+ 探针」vs
  「83.5% 覆盖（223/267）+@325 单元」——分发面就绪度差由本轮工作填。
- **A4「业界共识是 hybrid regex+ML（prompt-shield/prompt-guard），纯静态
  是不是落后？」**→ 赛道不同：它们是运行时请求期防火墙，我们是设计时
  pre-merge 门禁；互补（P1-13 双轨叙事已写明）。PINT/GenTel 数字是运行时
  赛道语义层上限面，静态赛道上限已在 README 诚实声明。不混坐标系则
  「不落后」成立。
- **A5「调研信息量够吗？」**→ 14 项目+1 论文，同赛道最接近竞品（aiproof/
  aisona）已覆盖；局限诚实标注：1 次搜索撞 Exa 限流、aiproof 规则总数
  未核实（不影响结论）。
