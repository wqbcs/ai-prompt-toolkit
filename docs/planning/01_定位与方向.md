## 1. 一句话定位

**LLM 应用提示词的 ESLint —— 且每次裁决逐字节一致。**

- 不是 promptfoo（LLM 输出评估器），不是 garak（探针式漏洞扫描器），
  不是 prompt-defense-audit（防御意图静态扫描器，最像我们的竞品）。
- 是**确定性静态门禁**：零 LLM、可复现、<100ms/文件、SARIF/CI 原生、离线可跑。
- 类比定标：ESLint 之于 JavaScript == 我们之于 Prompt。ESLint 没有去做代码质量 LLM 评审，
  也不该被批评"检测不了并发 bug"——检测面是声明出来的，不是无限扩张的。

## 2. 核心价值主张（moat 分析）

| 价值 | 为什么竞品补不上（结构性原因） | 强度 |
|---|---|---|
| **确定性/可复现** | LLM 路线的采样方差是物理性的，`repeat:3`/Fisher 检验是对冲不是消除（garak 作者实测 no-op PR 误红率 54%） | ★★★★★ 核心楔子 |
| **零 LLM 成本** | 按 token 计费是商业结构决定的，改不了；我们的 CI 成本与使用量无关 | ★★★★★ |
| **<100ms 毫秒级** | 可进 pre-commit 钩子；LLM 调用数百 ms~秒级，进不了提交前 | ★★★★ |
| **零 key / 离线 / air-gap** | 无供应商依赖；对金融/政企 air-gap 场景是硬门槛 | ★★★★ |
| **可审计裁决** | 规则=代码，finding 可 diff、可 blame、可复审；LLM verdict 不可审计 | ★★★★ |
| 规则数量 261 | **不是 moat**——会被追平，且堆规则稀释叙事 | ★（防守项） |
| 维度 130 / MCP 73 / Provider 24 | 同上，是能力面不是壁垒 | ★（防守项） |

**推论**：一切规划资源向"加深确定性楔子"（基线可信度、采用摩擦、裁决可审计性）倾斜；
"加数量"（规则/维度/Provider）只做防守性维护，不做进攻性扩张。

## 3. 五年北极星与阶段目标

**北极星指标**：*每周在多少条 CI 流水线里产生"阻止了一次不安全 prompt 合入"的可复现裁决。*
（不是下载量、不是 star 数——门禁工具的价值=被信任的执行次数）

| 阶段 | 时间窗 | 目标 | 验收 |
|---|---|---|---|
| **S1 可信** | 0-3 月（R225→M1=R227 完成；R228-R230 为 S1→S2 过渡） | 可信度自证闭环 + 采用入口打通 | PyPI 真实可装；README 3 秒传达楔子；`prompt-cli baseline` 任何机器可自证；CI 连续 14 天双绿（M1 验收口径，02 P0 完成定义；11 报告 D5/D12：原 30 天与 09 M1 的 14 天冲突已统一，30 天绿史为 P3-10 徽章长期目标） |
| **S2 被采用** | 3-9 月 | 前 50 个真实外部仓库接入（含 10 个 brownfield 老仓库） | GitHub Action 存在且被第三方调用；增量门禁解决老仓库死结；缺口报告成为评审素材 |
| **S3 被依赖** | 9-24 月 | 成为 2-3 个 LLM 应用框架/平台发布流程的默认检查步骤 | 框架上游集成 PR 合入；版本兼容性承诺（规则变更走 deprecation 周期） |
| **S4 标准** | 24-60 月 | 确定性 prompt 门禁的事实标准（规则格式/退出码契约/SARIF 方言被引用） | 他人工具兼容我们的基线文件格式；OWASP/行业引用 |

**5 年不变量**（任何技术栈迭代不得违反）：
1. 核心检测路径零 LLM 依赖（永远）
2. 裁决可复现（同输入同规则版本→同输出，逐字节）
3. 单文件检测 <100ms（P99）
4. 规则数据与检测逻辑分离（规则可热更新不改内核）
5. 退出码契约稳定（0/1/2 语义永不变，新级别只加不改）

## 4. 方向反思（本轮鬼才 PM 四问，含历史脉络）

**问：项目定位是啥？** 答：见 §1。历史一致性良好——从 v67 早期（255 规则/5557 测试）
到现在，定位没漂移过；漂移风险出在"能力面扩张"（MCP/Provider/模板市场）看似热闹但不服务楔子。

**问：核心价值是啥？** 答：见 §2。注意历史事实：误报率棘轮从 R206 的 **6.03%** 一路压到
现在 **0.91%**（6.8 倍改进），漏检 0.00%——**"基线数字持续收紧"本身就是可信度叙事的核心素材**，
下阶段要把它变成可被外部引用的时间序列图（见 02 总板 P1）。

**问：目前推进方向有啥问题？** 五个真问题：
1. **仓库私有 + 未发 PyPI = 楔子无法被验证**：`pip install` 都不存在，README 再锋利也是
   自说自话。→ 最高优先级是发布闭环（02 P0 / 06 发布文档）。
2. **CI 硬门禁作业仅 PR 触发，直推 main 无门禁**：我们自己"卖门禁"却在最常用路径上没开门禁。
   → 加 push 硬门禁作业（05 质量文档 Q1）。
3. **本地/CI 环境漂移已造成 4 连红**（ruff 未钉版、click 8.5.0 类型漂移、mypy 版本差、
   管道吞退出码假绿）：门禁工具的"自家 CI 绿"是可信度楔子，红一次叙事裂一次。
   → 锁环境（`pip freeze` 快照进 CI、CI 安装清单可复现校验）（05 Q2）。
4. **行:列定位缺失（237 条文件级）**：SARIF 进 Code Scanning 后文件级定位体验打折，
   但 R219 判定全量重构高风险。→ 折中：只对 critical/high 规则做行级（05 Q3）。
5. **缺口报告显示自家模板 LLM07（系统提示泄露）100% 缺声明**：我们给模板库开的缺口报告
   第一份就是自己的体检报告——86% 平均缺口率既是社会证明，也是待办矿脉（02 P2 模板补声明）。

**问：低价值打磨陷阱在哪？** 见 §6（硬清单，违反即停）。

## 5. ICP（理想客户画像）与反 ICP

**ICP**：
- ① 有 LLM 应用上线流程的中小团队（5-50 人）：有 prompt 文件、有 CI、缺安全门禁、买不起安全团队
- ② air-gap/合规敏感行业（金融、政企、医疗）：零 key 离线是硬需求，LLM 系工具直接出局
- ③ brownfield 老仓库：存量 prompt 多，最怕"一开门禁全红"——增量门禁是我们的杀手锏
- ④ 多语言团队：zh-Hans/zh-Hant/en/ja/ko 独立规则与分语言基线（竞品 prompt-defense-audit 只 en+zh-T）

**反 ICP**（明确不做，省资源）：
- 要 LLM 语义评估的（找 promptfoo）
- 要红队/越狱探测的（找 garak）
- 单文件个人用户无 CI 场景（价值不成立）
- 要"一个工具解决所有 LLM 安全"的（我们的声明边界：静态可检测面）

## 9. 顶配原则与端全景（用户硬约束的落地映射）

> 用户硬约束："最顶配，体验无天花板——每一端采用该平台公认最优技术栈，不被单一技术栈绑定，
> 没有体验短板，避免硬编码；架构 5 年生命周期。" 本节是其定位层表述，验收细则在 10 文档。

**顶配=每端事实标准，不是追新**（防误读，详见 10 §1）：
1. **端全景**（当前承诺 6 端，远期 2 端，触发器见 09 §5）：
   | 端 | 事实标准选型 | 状态 |
   |---|---|---|
   | CLI | Python+click，rich 渲染 | 已有，体验项 P5-01/02/03 |
   | CI | GitHub composite action+SARIF | R228 落地（P1-01） |
   | 容器 | ghcr+slim 多阶段 | R229 落地（P1-03） |
   | 提交前 | pre-commit 生态 | R229 落地（P1-02） |
   | 编辑器 | VS Code 扩展走 `--stdio` 桥（vscode-eslint 架构） | 触发器：M2 后（P1-05） |
   | JS/TS | 先 uvx 零层，npm 薄壳待需求证明 | 触发器：M2 后（P1-04） |
   | 浏览器（远期） | 静态站+规则 JSON+JS 子集引擎 | 触发器：P2-14 后（P2-13） |
   | 多语言绑定（远期） | 规则数据 JSON 化→WASM 仅当性能证明 | 路线文档占位（P4-06） |
2. **不绑定的结构保证**：核心（kernel+rules）零第三方依赖 + 输出走适配器接口（SARIF 是 OASIS
   标准→可移植 GitLab/Azure DevOps）+ `--stdio` 是纯文本协议（编辑器跨 JetBrains/Neovim 复用）——
   详见 04 §5 各端选型逃生门
3. **无体验短板=矩阵核对制**：10 §3 四端体验矩阵逐项有验收，收口时核"无空项"才宣告无短板
4. **避免硬编码=分类处置制**：契约性保留并文档化 / 数据性外置（随 wheel 的 data 文件，
   baselines 先例）/ 配置性进 promptlint.toml / 事故性抽常量——审计清单 10 §5（P2-19 执行）
5. **5 年不变量**（§3）与顶配的关系：顶配是"手段层"自由（端技术栈随便迭代），不变量是"结果层"
   锁定（确定性/可复现/性能/契约）——**端迭代不得触碰不变量**，这是架构 5 年生命周期的真正含义
