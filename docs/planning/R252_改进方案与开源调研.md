## §0 本轮定位反问（鬼才 PM 四问，R252 时点）

**问 1：项目定位是啥？** 答：LLM 应用提示词的 ESLint——每次裁决逐字节一致、零 LLM、<100ms/文件、离线可跑（01 §1，宪法级）。推进 251 轮，定位从未漂移；漂移风险始终在"能力面扩张"（MCP/Provider/多端），不在核心楔子。

**问 2：产品核心价值是啥？** 答：确定性/可复现（★★★★★）+ 零 LLM 成本（★★★★★）+ 毫秒级（★★★★）+ 零 key 离线（★★★★）+ 可审计裁决（★★★★）。规则数量 267 **不是 moat**（会被追平、堆规则稀释叙事）。一切资源向"加深确定性楔子 + 降低采用摩擦"倾斜。

**问 3：目前推进方向有啥问题？需要怎样调整？** R252 时点的真问题（对抗性审查，不粉饰）：
- 北极星 = "每周在多少条 CI 流水线里阻止一次不安全 prompt 合入"，**当前值 ≈ 0**。根因不是规则不够（267 条、FP 0.84%、漏检 0%、过防御 13.27%、6565 测试、22/22 门禁——内部可信度已极扎实），而是**楔子无法被外部验证**：仓库私有（P0-03）+ 未发 PyPI（P0-04）+ README 全中文（海外 ICP 看不懂，P1-07）+ GitHub Action（P1-01）/官方 pre-commit（P1-02）不可消费。
- **方向调整结论**：项目已越过"内部可信度建设期"，进入"楔子可验证/可采用期"。此阶段继续加规则=低价值（T1 陷阱）；**降低采用摩擦的边际价值最高**。R252 不碰"多端"（见 §1）。

### §3.3 可复用组件结论（不重复造轮子）

**结论：无可直接复用的开源包**——竞品都是"引擎+规则集"整体（Semgrep/CodeQL/自研），我方纯 Python 单文件规则 + 267 规则 + 24 维度 + 零依赖的形态无对应物可搬。**借鉴的是"形态/纪律"不是"代码"**：

## §4 本轮实施计划（R252 落地项，逐项：改什么 / 文件 / 验证）

### I-1 修复 `.pre-commit-hooks.yaml`（P1-02 真交付物）
- **改**：`entry` 由 `promptkit lint` → `prompt-cli lint`（真实 entry，pyproject `[project.scripts]` 单一真源）；description 对齐真实规则面（267 规则 / 24 维度，非"100 规则+84 family"）；删除 `promptkit-sanitize/probe/eval` 幽灵命令（真实 CLI 无 `promptkit` 命令族）；`language: python` + `additional_dependencies: [ai-prompt-toolkit]` 声明包（用户仓无需预装）；`files` 收窄为 `\.prompt(\.md)?$`（我方 lint 的合法目标=prompt 文件，扫全部 md 会把 README/文档误当 prompt→FP，违背"prompt 是纯文本声明面"定位）。
- **验证**：`yaml.safe_load` 结构合法；`files` 正则只匹配 prompt 文件；entry 命令在本地 venv 可跑（`prompt-cli lint --help`）；**探针**：构造一个含已知 finding 的 `.prompt.md` 临时仓，确认钩子 entry 语义正确。
