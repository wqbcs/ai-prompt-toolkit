## 1. 路线总纲（数据面解耦先行，端按 ICP 信号逐个上）

5 年不变量"任意端技术栈迭代不影响业务内核"的落地次序——**先数据可移植，
再端可执行**（02 反清单 R242 行"不为全端而全端"的正面表述）：

```
Phase 0 (已落)   规则数据 JSON 化 (P2-14 export-rules, R242 ✅)
                 267 规则元数据单点导出 (ESLint meta 形态, 同一树逐字节一致)
      ↓
Phase 1 (已落)   语言无关协议契约 (P1-05a --stdio, R226 ✅)
                 每行 JSON 文本契约: 未来任意端 (编辑器/IDE/脚本) 零成本复用
      ↓
Phase 2 (远期, 激活触发器见 §4)  端执行器 (按 ICP 信号逐个上)
                 2a. Node 包装器 (P1-04: spawn python wheel, 先调研再定)
                 2b. VS Code 扩展 (P1-05: TS + --stdio 桥, vscode-eslint 形态)
                 2c. 前端 playground (P2-13: 规则数据 JSON + JS regex 子集引擎)
                 2d. WASM 核心 (仅当性能需求证明, 奥卡姆: 当前 <100ms 楔子 6× 余量)
```

**核心决策（对抗性审查留痕）**：
1. **不复制 267 规则到第二语言**——规则逻辑留 Python（单一真源），数据面（meta）
   JSON 化让端"知道规则"，执行面按需选（spawn/协议桥/子集引擎）。JS 重写 267
   规则=双源漂移（R246 P2-13 重判 ⏸ 的同根因：规则是 Python check 函数非纯
   regex 数据，P2-14 export 无 patterns 字段，前端无法直接跑规则）。
2. **不追端数量**——cognis-promptlint ports 四端=摊薄信号（反清单 R242 行）；
   我方端数由 ICP 信号驱动（npm 优先=P1-04 既有登记，因 JS/TS 生态是 LLM 应用
   主战场；编辑器端 P1-05 待 --stdio 稳定后）。
3. **WASM 是逃生门不是目标**——内核零依赖（P4-02 机器护栏）是 WASM 化的
   **前提**（可被编译），不是**理由**（无性能需求证明不启动，04 §5 绑定检查
   纪律：本端选型若 5 年后被废弃，迁移成本≤"换 adapter 层一个文件/目录"）。

## 5. 与 5 年不变量的映射

| 不变量（01 §3） | 本文对应机制 |
|---|---|
| ④ 规则与逻辑分离 | Phase 0 数据面（P2-14）=端可移植的前提；Phase 2 端不复制规则逻辑 |
| ① 核心零 LLM/零外部依赖 | 内核零依赖（P4-02）=任意语言端可编译/可桥的前提 |
| ② 裁决可复现 | 端执行面透传（spawn/协议桥）时裁决真源恒=Python 内核=逐字节一致楔子跨端成立；WASM 端需同输入逐字节 e2e 同内核（激活时验收项） |
| ⑤ 退出码契约稳定 | spawn 包装器=退出码透传（0/1/2 契约不变）；协议桥面=响应 JSON 带 verdict 同 CLI 语义（P1-05a 已锁） |
