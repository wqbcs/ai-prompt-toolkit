## 2. 互联网调查发现（5 路, 2026-10-16 检索）

### 2.1 生态事件路（最高信号）

**LLM Guard（Protect AI）2026-07-08 归档**（3.2K stars, 月下载 10 万）:
- 仓库转只读, HuggingFace 模型（含旗舰 deberta-v3-base-prompt-injection-v2）
  明示"不再维护" — 分类器冻结在 2025-05, 新攻击类永不增补, **静默腐化**
  （无分数下跌/无警告地失保）— 行业最大信任痛点
- 社区 fork **Gorget**（MIT, 无 PyTorch ONNX 路线）接棒; 暴露**许可证地雷**:
  LLM Guard 默认匿名化模型是 CC-BY-NC-4.0（非商用）未披露 — 集成方商用不知情
- **对本项目**: 零 LLM/零第三方模型/零许可证面 = 结构性免疫; "抗腐化"叙事
  （棘轮+golden+双基线=机器可查的保真度, 不靠模型保鲜）= 差异化卖点,
  README 显式化 = 登记项（P5 面, 非本轮）

## 3. 第一性自问（反思记录）

### 3.1 这个项目的定位是啥
确定性 LLM 提示词**内容**静态门禁（prompt 的 ESLint）。2026 全景再验证:
代码级扫描拥挤（Whitney/nox/llmpromptdefender/ContextHound/promptaudit）,
agent 文件面起步（ipi-check）, **prompt 内容面仅 prompt-armor 一家**（ML 混合,
recall 76.3% 不可验证）。定位未被蚕食, 且"可验证保真度"楔子被生态事件
（LLM Guard 归档=静默腐化样本）反向强化。

### 3.2 产品核心价值是啥
**门禁本身可信且不会静默腐化**: 逐字节确定性+双基线棘轮+golden 667 探针+
板状态机查 — 全部机器可查, 不依赖任何模型保鲜。行业最大失败模式（LLM Guard:
分类器冻结后无信号失保）正是我们架构结构性免疫的。

### 3.3 目前推进的方向有啥问题吗
① 发布仍未执行（D1-D5 用户操作阻塞, 所有采用面/通道实测都在其后）— 方向无
误, 执行依赖用户; ② 2026 热点在 agentic 面, 我们是单文档静态 — 多轮面
（crescendo）需状态+ML 与楔子互斥=显式非目标; MCP 清单/技能文件面=相邻新面,
登记为发布后路线项（板 P4 行）, 不预支; ③ 其余无方向性问题。

### 3.4 低价值打磨陷阱审计（本轮 6 个"不做", 全部留痕）

| 候选 | 不做的理由 |
|---|---|
| 浏览器扩展（ContextHound 有） | 端扩张需 ICP 信号（既有纪律"不为全端而全端"）; 现无采用信号 |
| 签名插件市场（nox 有） | 无插件架构, 先有生态需求再谈 |
| 多轮意图漂移检测（PromptGuard 有） | 需会话状态+ML, 与单文档静态楔子互斥 |
| AI 依赖 SBOM/AIBOM（Whitney/nox 有） | 代码级面, 与 prompt 内容面不相交 |
| Council LLM judge（prompt-armor 有） | 与零 LLM 楔子直接互斥 |
| ML 检测层（prompt-armor L2/L3 有） | ML recall 不可验证, 与双基线可验证楔子互斥 |

### 3.5 结论
高杠杆项裁定 = **P269 tag 块 ASCII smuggling 规则**（探针先行, §4）— 同时满足:
零宽族下一层（既有辖区自然延伸）/ 2026 生产利用实证（非臆想威胁）/ 独立真实
源 ≥4（T1 证据充分）/ 阈值有合法用途边界实证（旗帜 6 < 8 < payload 10）/
零新增依赖零架构变更（奥卡姆）。agentic 面（MCP 清单/技能文件扫描）登记
板行, 发布后执行。

## 4. P269 决策记录（Unicode tag 块 ASCII smuggling 注入面）

### 4.1 新规则 vs 扩展 P261: 裁定=新规则
码点域互斥（P261=零宽 U+200B/200C/2060+BiDi 控制; P269=Plane 14 tag 块
U+E0000–E007F）, 独立信源, 独立阈值, 独立探针 — 同 R293 P268 先例
（独立证据源→独立规则, 非塞进既有规则膨胀其辖区）。

### 4.2 检测设计（确定性+低误报优先）
- 子1: tag 块字符总数 **8+**（线性扫描, O(n); 阈值=合法旗帜上限 6 与
  最小 payload ~10 之间, Cisco YARA 阈值 >10 同向）
- 子2: 转义形态 **2+**（\\U000E00xx 8 位形态 / \\uDB40\\uDC[0-7]xx 正确代理
  对域 — 低代理 DC00–DC7F 才对应 tag 块; AWS 样例 DD20–DD7F 实属他区,
  不采用其宽口径; 1+ 提及=Unicode 科普合法形态）
- Severity HIGH, family encoding_evasion, OWASP LLM01, ATLAS AML.T0015
  （同族映射行）
- details 含 count + decoded_preview（解码回 ASCII 前 40 字符 — Cisco
  skill-scanner 参考实现同型, 审查者直接看到隐藏内容）
- 不入 AUTO_FIXABLE_RULES（P260/P261 族不入, 一致性; 移除不可见字符的
  自动修复价值待真实需求驱动）

### 4.3 探针与验证
- golden 667→672（+5, 全 en）: TP×4（Trend Micro 形态 / AWS 邮件场景 /
  arXiv MCP 描述 / 转义形态）+ TN×1（旗帜 emoji, 6 tag < 8）
- 期望单元 379→383; 13 测试 test_r312_p269_tag_block.py（TP/TN/边界 7-8 tag/
  location 契约/确定性/linter 集成/规则元数据）
- 双基线: 漏检 0.00%（383/383）, 误报 0.82%@60 零新增; P260/P261 族回归绿

### 4.4 诚实残留（机制上限声明）
① <8 tag 短 payload（如 "go"=2 tag）漏检 — 同 P261 3+ 阈值同型, 真实 TP
驱动重评; ② 代理对拆散跨边界（\\uDB40 与 \\uDCxx 间插文字）漏检; ③ 变体
选择符 U+FE00–FE0F 不覆盖（emoji 呈现选择符在 emoji 文本大规模合法, FP
验证未覆盖 — 同 P261 ZWJ/BOM 排除同型纪律）; ④ tag 块在模型侧的解码行为
因模型而异（部分模型不重建 payload）— 规则报的是"隐蔽载体存在", 不是
"攻击必然成功", 与 P260/P261 的"信号面"定位一致。
