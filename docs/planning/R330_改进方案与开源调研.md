## 1. 定位反思（第一性原理三连问）

### Q1 这个项目的定位是啥？

**确定性的 LLM 提示词静态门禁（prompt 的 ESLint）**。楔子四要素：
逐字节一致裁决（同输入永远同输出）+ 零 LLM 成本（裁决路径不碰任何模型）+
<100ms/文件（编辑器保存即 lint 可用）+ 离线可跑（无网络依赖，air-gapped 可用）。

定位边界（不是什么）：不是 runtime rail（请求路径拦截，NeMo/Lakera/Arcjet 的辖区）；
不是 LLM-as-Judge 评估器（ab_test/gepa 是评估面，出检测路径，有 LLM_EXEMPTIONS 留痕）；
不是红队服务（probe 红队是 dev-time 测试套件，CI 里跑，不是线上守门）。

### Q2 产品核心价值是啥？

**可审计的裁决信任**——不是"规则最多"，而是"每个裁决可复现、可溯源、可对抗验证"：
- 双基线时序（误报 0.81%@60 clean / 漏检 0.00%@703 probes / 过防御 6.78%@339，
  逐轮追加 history，棘轮只收紧）
- 探针先行纪律（无探针支撑的规则禁止合入，TP+TN 各 ≥2）
- 裁决面 LLM 零接触机器护栏（check_layering L3，R321 防漂移红线）
- 确定性三面证明（CLI 字节级 e2e + stdio 协议字节一致 + MCP 工具确定性 sweep）
- 本地=CI 命令集机器核对（P3-11，29 步门禁链逐条对齐）

规则数 271 是防御性资产（table stakes），不是进攻锚点——竞品 20~59 条规则就能
自洽，规则多 10 条不构成购买理由；裁决可信 + agentic 原生（73 工具 MCP）才是差异。

### Q3 目前推进方向有啥问题？需要怎样调整？

| 判断 | 证据 | 调整 |
|---|---|---|
| "规则数"叙事边际递减 | R324 调研结论 + 本轮竞品面（prompt-guard 59 条自洽、promptlint 20 条卖 npm+VSCode marketplace） | 叙事重心转向可信度叙事（双基线时序公开页）+ agentic 面（MCP/LSP）；规则数降为防御面 |
| 发布窗口是最大阻塞 | P0-03（公开）+ P0-04（PyPI）未解锁，一切"可被用户安装"的改进都悬空 | 发布前只做：①四大既有端（CLI/CI/MCP/LSP）顶配化 ②可信度叙事资产 ③架构护栏深化；不铺新端 |
| MCP 是 linter 新入口（2026 共识） | ESLint 官方 MCP（@eslint/mcp, 27.3k★ 项目内置）、SonarQube MCP（Cloud 原生 endpoint）、prodlint 单行 `npx prodlint-mcp`、Skylos MCP（`python -m skylos_mcp.server` 进 Claude Desktop） | 我方 73 工具零依赖手写 MCP server 是差异化既有资产；缺的是**接入面**（一行配置进各客户端）与**可安装性**（发布解锁后） |
| 自托管开源面出现窗口 | LLM Guard（Protect AI/Palo Alto）2026-07-09 归档停维；Rebuff 2025-05 归档；媒体文章明示"未维护的检测器比没有更危险" | "活跃维护 + 可自托管 + 可审计"是窗口期卖点；我方 CI 双绿 + 棘轮纪律 = 直接可用证据 |
| 基线/棘轮是全赛道标配但各家指纹机制朴素 | alint/wardline/gimme-the-lint/slopscore/ratchet-gate：fingerprint=rule+file+content（不用行号）；wardline 额外有 `--new-since <git-ref>`（CI 防 PR 自抑制伪造：ref 由 operator 提供）+ waiver/judged 分层 | 我方双基线比它们强（时序+分语言+过防御二阶信号），但 `--new-since` 防伪造 CI 棘轮是可直接吸收的机制（A3） |

**低价值打磨陷阱（明确不做，及理由）**：
1. i18n 本地化大面（02 反清单显式禁止）；
2. 发布前铺新端（npm wrapper/playground/更多语言端——"不为全端而全端"，端按 ICP
   信号逐个上；且无用户可装，打磨无反馈闭环）；
3. 规则数扩张冲数字（边际收益递减，且每条新规则都要探针+双基线成本）；
4. 新增 ratchet 门禁（8 道已密，加一道=每轮收口成本+1，收益递减）;
5. 装饰性输出/动画（确定性楔子的 TTY 面纪律：机器通道神圣，装饰只进交互 TTY）；
6. 追求"每端最优技术栈"字面铺端——本仓四大端的既有栈（Python CLI + GH Actions +
   MCP stdio 零依赖手写 + LSP）即各平台公认栈，顶配化=把既有端到无短板，不是换栈。

## 4. 对抗性审查（5 问留痕）

### Q1 这个项目的定位是啥？有没有漂移？

**确定性的 LLM 提示词静态门禁（prompt 的 ESLint）**。楔子四要素=逐字节一致裁决 + 零 LLM 成本 +
<100ms/文件 + 离线可跑。本轮二查竞品面（malskanner 仓库级不可见 payload / agent-audit
OWASP Agentic 2026 映射 / whitney Semgrep 策展层）**全部在"静态入库前面" lane 内且无一越界
runtime rail**——定位无漂移；本轮清单无越界项（watch=CLI 端能力, baseline-from=门禁完整性,
UX pass/LSP 指南=接入面），不碰反清单 runtime/ML/SaaS 任何一行。

### Q2 目前推进方向是陷阱吗？

**不是**。规则数/端数/ratchet 数三个边际递减方向已被反清单（24 项）持续拒绝；唯一真阻塞=
发布窗口（P0-03/P0-04 待用户解锁, 19 轮等待）。自主面本轮清单全部落在已批准三焦点区
（既有端顶配化/可信度资产/架构护栏），无新端、无新 ratchet、无规则数冲数字。
**残留风险**=发布持续不解锁→一切采用面悬空；缓解已就位（README Roadmap 节=clone 者可见
授权清单, 00 §5 每轮明示）。方向调整建议=不变，继续推用户解锁（每轮 00 交接重申）。

### Q3 低价值打磨陷阱自查（逐项 + 拒绝项）

- A1 watch：编辑器保存即反馈=<100ms 楔子的**天然使用场景**，ruff/biome/promptlint 标配面
  （非玩具能力）；实现=薄壳（事件过滤+debounce+既有 lint 内核复用），不造新检测逻辑。
- A3 baseline-from：CI 门禁完整性**真缺口**（`--incremental --baseline` 读 PR head 工作树，
  基线文件可被 PR 作者篡改=门禁自废）；不是"看起来更严谨"的叙事打磨。
- C1 UX pass：**判定驱动**（产出判定表，缺口逐项登记，不自动实施）——防"对标=打磨"滑坡。
- D2 LSP 指南：零代码内容（能力已有 R197 起, 缺的只是接入面文档）。
- **拒绝项（留痕）**：发布前 playground/npm/新语言端（反清单）；发布前叙事再磨（B 轴判定：
  无受众）；新增 ratchet（8 道已密）；in-place auto-fix 大面（反清单, SARIF fixes 标准通道）；
  watchfiles Rust 后端（编译 wheel 矩阵 T8）。

### Q4 "每端最优技术栈/体验无天花板"与反清单如何调和？

本仓四大端的既有栈**即各平台公认栈**（Python CLI + GH Actions + MCP stdio 零依赖手写 +
LSP pygls）；"顶配"=把既有端到无短板（A1/A3/C/D 全部在此语义内），**不是加端不是换栈**
（反清单"不为全端而全端"+T8"5 年不变量"）。"不被单一技术栈绑定"的既有机器答案=
P2-14 规则数据 JSON 化（数据面解耦, ✅）+ P4-06 路线（WASM 逃生门, ✅ 文档）+ P4-02/10
架构护栏（kernel 零依赖/分层方向, ✅ 机器化）——不新增投入, 维持机器护栏即可。

A3 --baseline-from=linter/baseline + cli_helpers 同层薄封装（git plumbing）。二者均过

无 public API 破坏, 既有命令零行为变更）。
