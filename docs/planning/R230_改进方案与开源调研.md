### 1.2 需求/痛点信号（本轮新增，补 08 §7）

1. **prompt caching 成本**（强信号）：Anthropic 官方 skill 文档 + 多源工程博客共识——
   cache key=前缀精确字节哈希，"any change anywhere in the prefix invalidates everything
   after it"；失效源=时间戳/UUID 前置、JSON key 顺序不稳定、工具列表中途变更、
   系统提示插值动态上下文。"Treat the stable prefix as part of your agent's interface."
   → 静态可检测面明确：**动态 token 位置 vs 前缀稳定性**（P1-17 立论）。
2. **误报基准成社区自建面**（延续 R225 信号）：prompt-guard 把"labeled benchmark in CI"
   当卖点并自曝 in-repo vs external 口径差；HN 帖（47689822）实证"False positives are
   harder than detection… took more work than improving detection rates"。
   → P5-11 上调 P2 维持正确；我方 precision 时间序列（6.03%→0.91%）是现成获客素材。
3. **非英文注入是公认盲区**（HN 帖："An English-trained classifier misses every
   non-English attack that dodges regex patterns"）→ 我方 zh-Hans 84/ja 6/zh-Hant 2 探针
   是差异化，但 **TN 侧仅 7 条**（本轮盘点）——探针集偏科攻击面，TN 扩容（12 §1.7
   既定方向）价值再确认：误报数字的可信度取决于 TN 语料质量，不是 TP 数量。

## 2. 对抗性审查（鬼才 PM 四问 + 陷阱自检，2026-10-04）

**Q1 定位是啥？** LLM 应用提示词的确定性静态门禁（prompt 的 ESLint）。
现状核对：264 规则/25 类/113 探针/6158 测试，楔子四不变量（逐字节一致/零 LLM/
<100ms/离线）全部保持。**无漂移**。

**Q2 核心价值是啥？** 可信度叙事=①裁决可复现 ②基线数字持续收紧 ③采用摩擦低。
本轮盘点的**最弱环节**：②的数据基础设施缺位——误报 6.03%→0.91% 的收紧史
只存在于文档叙述，没有机器可查的时间序列（P2-04 未开工）；③的漏斗断点=
发布未闭环（待用户 D1-D4）+ JS/编辑器端入口缺位（P1-04/05 排 M2 后）。

**Q3 方向有啥问题？** 三个真问题（本轮新识别，非复述 01 §4）：
1. **探针集结构偏科**：113 探针中 TN 仅 7 条，且 ja/zh-Hant 各 6/2 条几乎全是 TP。
   误报率 0.91% 的分母质量依赖 TN 语料——**尺子的刻度盘太窄**。不补 TN 就扩 TP，
   precision 数字的可信度叙事会先于能力面增长而漏气。（登记：P2-11 后续，本轮启动）
2. **规则计数硬编码债**：`== 264` 散落 ≥5 个测试文件（test_r112/r115/r122/r124/
   test_r217_p261）——每加一条规则要改 5+ 处，这是 R229 已发生过的机械债
   （26 处 `==261`→264）。动态化=一行 `len(get_all_rules())`，但 5 处断言的
   **语义**要分别核对（有的锁"总数"，有的锁"某类别数"）——不是无脑替换。
   （本轮顺手收口，登记为 R230-X1）
3. **发布闭环仍是最大阻塞**（复述 01 §4 问题 1，状态未变）：D1-D4 等用户。
   本轮继续推进不依赖发布的全部项。

**Q4 低价值打磨陷阱自检（07 §5 五问）**：
- P1-17 cache 规则：有对标实证（aiproof AIP009 真实采用叙事"双倍账单"）+官方文档
  支撑检测面 → **不是** T1 凑数。判定：做。
- 新规则 P266（见 §4.3）：探针先行，TP+TN 各 ≥2，双基线不回归 → 不是 T1。
- 误报曲线页（P5-11↑）：依赖 P2-04 数据源，本轮先落 P2-04 数据基础设施（S 级）
  → 不直接做页面（页面等发布后 GitHub Pages，避免 T6 采用窗口期大动）。
- 规则计数动态化：纯机械债清理，无行为变更 → 不是 T2/T10（不带重构，只去硬编码）。
- **不做清单**（本轮明确拒绝）：autofix 扩展（aiproof 有，我方 cache 规则只给
  建议——动态段移动不可机器判定安全，T9 边界）；LLM 可选分类器（ipi-check Stage2
  形态——T3/T9 明确不做）；TS 内嵌 prompt（P1-15b 观察项，tree-sitter 依赖=

## 4. 设计要点（实施用）

### 4.1 P265 cache-unfriendly 精度设计

检测面（静态可判定，零 LLM）：
1. **动态 token 词表**（数据驱动，`_CACHE_DYNAMIC_TOKENS`）：
   时间戳形态（`%Y-%m-%d`/`{datetime}`/`{timestamp}`/`当前时间`/`now()`）、
   UUID/随机 ID（`{uuid}`/`random`/`随机ID`/`nonce`）、运行时变量引用
   （`{{user_*}}`/`${env}`/`<runtime>` 类前缀标记）。
2. **前缀区定义**：模板正文（strip_frontmatter 后）前 N=512 **有效字符**
   （CJK=1 有效/ASCII=1 有效，与 P1-15 CJK 感知门槛同口径）。N 数据驱动可配
   （对标 aiproof ~1024 token；我方用有效字符近似，<100ms 不变量优先于 token
   精确换算——口径写进 description）。
3. **强信号共现**（防 T4 式误报）：动态 token 出现在前缀区 **且** prompt 含
   缓存意图信号（`cache`/`缓存`/`prefix` 词）或 prompt 长度 > 前缀区×2
   （长 prompt=缓存受益场景）才报——两者都不满足时动态内容属正常短 prompt
   用法，不报（TN 锚点）。
4. **frontmatter 豁免**（R229 教训）：与 P262 同惯例，只扫正文，
   location 行号原文精确。
5. severity=MEDIUM（成本类，对标 aiproof warning 档）。

TP 探针：①时间戳插值在 system 头部+长正文 ②UUID 前置+缓存声明。
TN 探针：①动态内容全部在尾部（多轮追加形态）②短 prompt 含"当前时间"但
<2×前缀区（正常用法）。

### 4.2 R230-B 对抗审查预判（P266 JSON key 顺序）

判定倾向：**放弃或降级**。理由：JSON key 顺序是**运行时序列化行为**
（`json.dumps(sort_keys=?)`），静态文本面只能看到字面 JSON——字面 JSON 的
key 顺序固定不变（文件就是那个顺序），真正的失效发生在渲染后。检测字面
JSON key 顺序≈检测文件自身属性，无行为信号。**奥卡姆剃刀：不造检测"不存在
于文本面"的缺陷的规则**。→ 本轮只登记观察项，P265 的 remediation 文案里
带一句"序列化用 sort_keys 固定顺序"即可覆盖该知识传递。
