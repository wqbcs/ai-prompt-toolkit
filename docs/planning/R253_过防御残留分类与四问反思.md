# R253 过防御残留 45/339 分类调研 + 四问反思

> 承接 R252（过防御 13.27% = 45/339 被 flag）。本轮不刷数字、不加规则——
> 把 45 条 flagged 逐条定性成 H/I/J 三类，按"有无 golden TP 支撑"决定动/不动，
> 只修无 TP 支撑的纯 FP 根因，其余登记不动手（低价值打磨陷阱）。

## 0. 四问反思（定位校准）

- **项目定位**：确定性 prompt 静态门禁（prompt 的 ESLint）。楔子=逐字节一致 /
  零 LLM / <100ms / 离线。
- **核心价值**：每条裁决可机器验证、可复现——**报得准**，不是"多报"。过防御率是
  健康度指标之一，不是目标本身。
- **当前方向有无问题**：45 条 flagged 里，H 簇（9 条）是**纯 FP 根因**——P071
  华为云 API 触发 pattern 含裸子串 `ris`，撞 risks / risky / risk / observed（6 条
  P071 全部由 `ris` 子串误触发）。这是真实质量缺陷（一个通用英文词"risk"就能让
  华为云 endpoint 校验误报），该修。I 簇（P163 越狱 10 条）是 TP/FP 难区分区
  （虚构/哲学叙事撞 roleplay∧约束解除共现），golden 有 4 TP，**动它=漏检风险**。
  J 簇单例多为"防御缺失型"规则撞通用域词，属棘轮锁定区。
- **低价值打磨陷阱**：I 簇越狱下限 + J 簇单例。为刷过防御率去收窄 P163/P009 这类
  有 TP 支撑的安全规则，等于为指标牺牲真实检测（P009 DELETE 审计、P163 越狱都有
  golden TP）——典型"为指标修规则"反模式。**结论：只修 H 簇（无 TP 支撑的纯 FP
  根因），I/J 登记不动手。**

## 1. 残留 45/339 分类（per-rule 分布 → 定性）

### H 类 — 华为云/鸿蒙生态规则口径误触发（9 条，纯 FP，本轮修）

P071（华为云 API endpoint）触发 pattern `_HW_CLOUD_API_PATTERN` 含裸子串
`ecs|obs|ris`。6 条 P071 flagged 全部由 `ris` 撞通用英文误触发（实证）：

| IDX | 撞词上下文 | 实义 |
| --- | --- | --- |
| 32 | `d potential risks...` | risk |
| 169 | `ensored and risky content` | risky |
| 200 | `ures are at risk of bypass` | risk |
| 232 | `any risk in executing` | risk |
| 266 | `without risking data loss` | risking |
| 282 | `Is it risky to proceed` | risky |

**根因**：`ris` 是 risk/risks/risky/risking 的子串，且这些词在安全语料里高频（恰恰是
prompt 门禁的主战场语料）。`obs` 同理会撞 observed/observe。这是 R47 早期华为云专项
规则写 pattern 时贪宽（想覆盖 Huawei Cloud ECS/OBS/RIS 三个服务缩写），未加词边界。

**golden 支撑**：226 探针里华为/鸿蒙关键词探针 = **0**（P071-P080 整族无 golden TP）。
→ 收窄 P071/P073 的触发 pattern **不漏任何探针**，安全。

**修法（探针先行，CLAUDE.md 纪律）**：
1. 新增 2 条华为云 TP 探针（真实 endpoint/认证缺失场景）补 P071/P073 golden 缺口。
2. 新增 2 条 TN（含 "risk/risks" 但非华为云语境的干净 prompt）。
3. 收窄 `_HW_CLOUD_API_PATTERN`：`ecs|obs|ris` → 加词边界 `\b(?:ecs|obs|ris)\b` 不够
   （ecs 会撞 "recs/pecks"，仍宽），改为只保留强信号 `华为云|huawei.?cloud|
   api\.huaweicloud|maas\.cn|modelarts`，裸 ECS/OBS/RIS 服务缩写要求与华为云语境
   共现才触发（`\b(?:ecs|obs|ris)\b.{0,40}(华为云|huawei|myhuaweicloud)` 反向亦然）。

### I 类 — 越狱检测下限（P163，10 条，TP/FP 难区分区，不动手）

P163 三分判定已较严（直接越狱词 / DAN 人格排除 DAO / roleplay∧约束解除共现）。
10 条 flagged 全是**虚构叙事/哲学探讨/游戏场景**撞 `roleplay + 约束解除` 共现：
- "jailbreak a video game character"（游戏破解，非模型越狱）
- "unrestricted exploration in scientific research"
- "character who creates a dotted map to escape"
- "bypassing societal norms while..."（哲学）
- "pretend to be a detective bypassing conventional methods"

**golden 有 4 条 P163 TP**（真实越狱探针）→ 收窄 roleplay∧约束解除 会同时削弱对真实
越狱的召回。这是**检测下限**，不是 bug。本轮**登记不动手**，列入 T6（越狱检测
召回/精度联合调优，需独立一轮 + 探针扩充 + 漏检基线背书）。

### J 类 — 单例防御缺失型规则撞通用域词（登记不动手，棘轮锁定区）

多为"prompt 未声明 X 防护"型规则，撞通用语料域词：
- **P009 DELETE 审计（8 条，最大 J 簇）**：`safely DELETE files / delete lines of
  code / DELETE 数据` 撞 `_DELETE_DATA_TARGET` 宽目标词（file/code/program/document）。
  golden 有 2 TP。三分判定（否定窗口 + 数据目标语境）已较严，"delete a file" 本身
  就该触发审计提醒——**属真实提醒，非 FP**。
- **P132/P138/P139/P140/P216 多模态簇（5 条）**：含 🔓 emoji / "image" 撞多模态防护
  缺失。P132/P216 golden 有 2 TP。
- **P169 毒性过滤（3 条）**："enviromentally-friendly / immoral actions" 撞毒性域词。
  **P170 引用验证（2 条）**："academically" 撞引用域词。
- **P239 速率限制（2 条）**："Discord server" 撞 inference 域词。
- **P206/P207/P208/P209/P257 RAG 簇（5 条）**："manages and organizes digital files"
  撞 RAG 检索域词。P206/P257 golden 有 TP。
- **P114 GDPR / P168 偏见 / P193 CoT / P195 记忆 / P133 音频（各 1）**：单例，均"未声明
  防护"型，撞通用域词。

**结论**：J 簇是过防御的"长尾"，单条 1 例，规则本身有 TP 支撑（防御缺失型规则的价值
就是提醒"你声明防护了吗"），收窄=牺牲安全面。**全部登记，不动手**——它们是棘轮棘齿，
不是待修缺陷。
