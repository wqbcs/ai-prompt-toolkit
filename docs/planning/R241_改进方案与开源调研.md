## 5. 对抗审查（鬼才 PM 视角，含方案收窄的决策辩护）

**审查问题 1：P267 立项判定是否成立？**
→ 成立。2 独立 TP（不同前缀族 AKIA/ASIA，不同语言 zh/en）+**全量
规则重验**（不只 PII 集——AKIA 文本 P006/P051/P252-255/P266 零覆盖，
仅结构类 P001-003/P005/P177 非凭据规则命中）=真缺口实证+原型 11/11+
**立项前**三源零误报+CRITICAL 与凭据族同级+OWASP 2026 LLM02（A15
对照真源）。对抗点"与 P051 重叠"：P051 管命名赋值面（`aws_access_
key_id=xxx` 即使值不合规也报），P267 管字面形态（**无命名上下文**的
裸 key ID 也报，精确度高）——两辖区正交，P051 抓"赋值意图"，P267
抓"凭据标识符出现"，互补非重复。

**审查问题 2：该不该 SSN+AKSK 双形态一起上？**
→ **不该，收窄为 AKSK-only**。这是本轮最重要的方案修正。SSN 裸形态
`\d{3}-\d{2}-\d{4}` 的 TN 面封不死：3-2-4 分段是国际电话/工单号/
序列号的常见分段，纯形态锚点（`(?<![\d-])`）只能挡紧邻数字/连字符，
挡不住独立 3-2-4 业务编号。要封住需"SSN/社保 关键词邻近"上下文设计
——但那是上下文规则（非纯正则单点），需要真实语料 FP 量化证明
关键词邻近面也干净。决策=**不对称 downside**：上线一个高误报规则
伤"FP 率是赛道生死指标"的核心口碑（aiproof 96% FP 修复史是前车
之鉴）vs 留观察区零损失。奥卡姆：只上证据闭合的 AKSK 面，SSN 等
三条晋升条件（07 T-7）齐备再说。

**审查问题 3：前缀集该用 gitleaks 的 5 前缀还是 AWS 官方的 4 前缀？**
→ **AWS 官方 4 前缀（AKIA/ASIA/ABIA/ACCA）**。gitleaks 的 A3T 自标
"might not be a valid AWS token"=其遗留形态非现行凭据前缀。A15 纪律
=对照单一真源收窄，不自带存疑项。trufflehog 交叉印证 4 前缀集。
反清单：AGPA/AIDA/AROA/ANPA 是 IAM 资源标识 ARN 前缀非凭据，不纳入
（FP 面扩张无信号收益）。

**审查问题 4：`\b` 零长度容差的 19/21 位漏报是否问题？**
→ 不是。20 位定长+`\b` 双向锚定=**只报精确 20 位形态**，19/21 位
（截断/粘贴残缺）不报是设计限定面——残缺 key ID 通常无泄露风险
（不可用）。零宽插入 20 位形态（21 字符含零宽）由 P260/P261 混淆族
交叉覆盖（R217 既有设计），非漏检。

**审查问题 5：README Roadmap 节是否范围蔓延？**
→ 不是。纯文档不依赖授权，消解的是**用户侧**授权摩擦（clone 者
看不到"还有一批事等拍板"=D1-D4 卡了 15 轮的根因之一）。唯一真源
口径（与 02 总板 P0/P1 区同步）防双写漂移。R240 §3.3 已建议，本轮
落地=闭环。
