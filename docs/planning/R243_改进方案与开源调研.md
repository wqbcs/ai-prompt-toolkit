## §1 定位与反思（鬼才 PM 自检，开工前）

**项目定位**：确定性的 LLM 提示词静态门禁——prompt 的 ESLint。
**产品核心价值（楔子）**：每次裁决逐字节一致 + 零 LLM 成本 + <100ms/文件 + 离线可跑。

**本轮自检四问**：

1. **定位是啥？** 可验证的尺子（不是检测器数量，是"尺子本身可信"叙事：双基线时间序列、
   逐字节复现、OWASP 映射、探针可审计）。
2. **核心价值是啥？** 信任资产——clone 者能机器复核每一个数字。
3. **当前推进方向有啥问题？** 267 规则内部质量已过边际递减拐点（R242 判定），真瓶颈=
   D1-D5 发布授权（用户侧，已等 18 轮）。但**可信度叙事的根基有内部漏洞**：
   ① 板漂移 3 轮内 3 处（R239 P1-18 / R241 P3-02+P3-09）=收口回写靠人肉记忆；
   ② P3-12 符号链接方案=双源语料副本的定时炸弹（Windows 物化成普通文件后静默漂移，
   R243 实证：fixture 快照 157⊂174 已被 5 个测试消费，test_r214_name_boundary 硬编码
   计数锁死在陈旧面）。
4. **需要怎样调整？** 本轮**不加任何检测能力**——把上述两类隐患机器强制化
   （P3-17 脚本化 + P3-12 改直读固化）。这是保护差异化资产的投入，不是打磨。

**低价值打磨陷阱清单（本轮主动避开）**：

### 2.2 P3-12 测试夹具治理固化（符号链接核实→改直读单一真源）

**核实结论（符号链接地雷排查闭合）**：全仓 0 symlink——git index mode 120000=0、
工作树 find -type l=0、core.symlinks=false、文件均 100644 普通文件 → **无 clone 地雷**，
"符号链接 CI 失效"前提不成立，不建 symlink。

**真问题（比登记时预想大）**：Windows 物化后的"符号链接"其实是**陈旧实体副本**：
- `tests/fixtures/golden_attacks.json`：157 探针 ⊂ 真源 174（R240+12/R241+5 后未同步），
  被 5 个测试经 `_FIXDIR` 消费 → test_r214_name_boundary 硬编码 157/zh-Hans 103/en 46
  **静默锁死在陈旧面**（改直读后断言失配=漂移实锤）
- `tests/fixtures/clean_prompts/`：60 文件副本（与包内 data 逐字节相同），14 测试消费

**固化处置（验收"改直读"分支）**：
- 两份副本全删（git rm）
- 14 测试统一 import `baselines.CLEAN_DIR`/`GOLDEN_FILE`（与双基线同一解析真源，
  editable/非 editable 安装行为一致，无硬编码相对路径）
- test_r214_name_boundary 计数更新为真源口径：174 / zh-Hans 110 / en 56 / ja 6 / zh-Hant 2
- CODEOWNERS 收口为包内 data 单路径（原 golden_×2 行删一）
- docs 引用改指 data/（规则漏检率基线/语言面覆盖矩阵/L2_data/规则误报率基线）
- baselines.py docstring 失实修正

**教训（固化 07 A14 家族）**：符号链接在 Windows 物化成普通文件后，"双源"会静默漂移且
测试会跟着陈旧面走——单一真源必须机器强制（直读 import），不能靠约定或文档声明。
