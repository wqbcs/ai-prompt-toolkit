## §0 定位再确认（四问 + 对用户指令的正面回应）

1. **定位是啥**——设计时（pre-merge）静态门禁：规则确定性 + 裁决可复现 +
   数字可机器自证（`pip install → prompt-cli baseline` 一条命令）。R285 后
   楔子完整度再升一级：267/267 探针覆盖 100%，"漏检 0.00%"锚点覆盖全规则面。
2. **核心价值是啥**——"可信的数字"而非"最强的检测"：漏检 0.00%（369/369
   期望命中单元）+ 误报 0.82%（60 干净样本）+ 过防御 11.50%（339 NotInject
   硬负样本）+ OOD 31.18%（263 deepset），全部棘轮化/公开化/可复现。语义层
   上限已在 README 诚实声明——这是叙事资产不是负债。
3. **方向有啥问题（对抗性自查 + 对用户"多端顶配/5 年架构"指令的回应）**——
   - 指令"每一端都采用该平台公认的最优技术栈，不被单一技术栈绑定"与本项目
     反清单"不为全端而全端"正面相撞。**裁决：指令的意图（顶配/无短板/5 年
     架构）接受，执行方式纠偏**——
     a) 架构可演进**已经达成**：内核零第三方依赖（纯 stdlib）+ 数据面 JSON
     化（P2-14 export-rules 已落地）+ adapter 层隔离（cli/mcp/evaluator 各自
     薄壳）+ 分层验证（P4-10 check_layering 进门禁）。任意端技术栈迭代
     不触内核，5 年生命周期由"内核零依赖+契约面稳定"而非"多端实现"保证。
     多端实现**不增加**架构寿命，只增加双真源维护面（playground 判定 ⏸ 的
     同一论证）。
     b) "每一端最优技术栈"在端按 ICP 信号逐个上时**天然成立**：npm 端用
     npm 生态公认形态（wrapper+spawn）、VS Code 端用 LSP 官方扩展模型、
     Action 端用官方 composite action——每一端落地时选该端最优，不做
     "统一技术栈"绑架。P4-06 路线文档已载明，不重复造。
     c) 当前最大方向问题**不在架构**，在**采用漏斗**：仓库仍私有、无 PyPI，
     全部分发面（P1-01/02/03/04、P5-05）被 D1-D5 阻塞。本轮自主线继续
     压缩"发布后可立即分发"的就绪度（ja 面=差异化轴最薄数据面、CI 可信度
     =安全工具审计自身、发布摩擦=CI 时长/成本）。
4. **低价值打磨陷阱自查**——陷阱判据（07 §5 A1-A8）：为指标改规则（J 簇
   纪律）/新内部度量/无信号文案重写/为全端而全端。本轮判定：
   - ja 探针扩容=差异化轴数据面还债（分语言表 ja=6 是全表最薄，且 R286
     调研给出 ja 市场需求硬证据：promptgate 已上 PyPI + Promtect 商用 SaaS
     + JSAI2026 学术数据集），非堆量；
   - CodeQL 进 CI=安全工具被安全审计（"尺子可信"叙事补强），非新度量；
   - CI 矩阵减重=降低发布后每次 PR 的采用摩擦，直接服务采用漏斗；
   - **拒绝执行**：多端并行实现（无 ICP 信号）、富美化（P5-02 ⏸）、
     autofix（fixable 0/267 无机械可修面）、MCP 配置 lint 新规则族
     （无 ≥2 独立真实 TP 支撑，先观察区）。
