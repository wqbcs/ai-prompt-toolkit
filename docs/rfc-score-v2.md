# RFC: lint score v2 — 评分语义演进设计

**状态**: 待评审（设计项，未实施）
**日期**: 2026-09-26（R183 起草）
**背景**: 现行 `score = (passed / rule_count) × 100` 是"规则通过率"模型。审计发现其对极短 prompt 系统性虚高：4 字 prompt（"处理数据"）得分 92.9，而结构完备的 1KB 模板仅 89.8 —— **分数倒挂**（R181 demo 冒烟实测）。根因：未激活的规则被计入分母并视为"通过"，而未激活 ≠ 通过。

---

## 问题定义

| 场景 | 现行分数 | 用户预期 | 差距 |
|---|---|---|---|
| 结构完备模板（1KB，26 个 MEDIUM/INFO） | 89.8 | 90± | ✓ 基本一致 |
| 极简 prompt（4 字，无角色/格式/约束） | 92.9 | <60 | ✗ 严重虚高 |
| 零 finding 的空模板头 | 100 | ? | ✗ 无意义 |

根因：分母 = 255（全量规则），但大多数规则仅在特定语境激活（长文本/多模态/部署语境）。未激活规则对"质量评估"无信息量，却推高分母稀释惩罚。

## 方案对比

### 方案 A: 覆盖因子（分母改为"适用规则数"）
`score = passed / (核心必检 + 已激活规则)`
- ✅ 语义最正确："未激活不等于通过"
- ❌ "激活"定义模糊（每条规则一个适用性判定 = 255 个判定函数），维护成本高
- ❌ 对既有测试断言影响面最大

### 方案 B: 加权扣分制（推荐）
`score = max(0, 100 − Σ(critical×12 + high×6 + medium×2 + low×0.5))`
- ✅ 可解释性最强（"扣了 X 分，来自哪几条"），与 CVE/CVSS 扣分直觉一致
- ✅ 短文本虚高自然修复：缺角色(1 high) + 缺格式(1 medium) → 100−6−2 = 92？❌ 仍不够狠
- ✅ 修正版：**核心要素缺失叠加罚**——角色/任务/格式/约束四要素每缺一项额外 −10（要素缺失由现有 P001/P002 等触发即判定），4 字 prompt ≈ 92−40 = 52 ✗ 仍倒挂修复不足
- ❌ 权重与要素罚的取值需要数据校准，拍脑袋会引入新的倒挂

### 方案 C: 双层分数并存（最小迁移成本）
- `score`（通过率）保留不动 — 兼容 gate/badge/等级全部既有消费方
- 新增 `quality_score`（方案 B 扣分制）为独立字段，CLI 优先展示，`--legacy-score` 回退
- ✅ 零破坏、可并行对比一个版本周期
- ❌ 双分数存在用户困惑成本

## 推荐

**方案 C 起步 → 一个版本周期后切 B（含核心要素罚）**。理由：
1. 语义变更需要真实用户反馈校准权重，双轨是最低风险的采样方式；
2. gate/badge/等级的消费方迁移可逐步进行，避免一次性 big-bang；
3. 核心要素罚的"要素清单"应与 clean-prompt 基线（tests/test_r173.py）同源维护，避免两套定义漂移。

## 影响面清单（实施前必读）

| 消费方 | 位置 | 迁移动作 |
|---|---|---|
| Quality Gate | linter/quality_gate.py `min_score=60` | 语义重校（通过率 60 ≈ 扣分制 ?） |
| 等级映射 | cli_helpers.lint_grade（A≥90/B≥75/C≥60） | 与扣分分布重新对齐 |
| Badge/Scorecard | security/badge.py、prompt_scorecard.py | 独立评分体系，需决策是否合并 |
| 演示资产 | demo.sh、docs/OSC2026-参赛示例.md | 输出文案与数字 |
| 测试断言 | lint score 精确断言 ~10 处 + 快照（test_r178 score 字段） | 数值更新 |

## 低价值陷阱警示

- 不引入 LLM 评分混入 lint score（破坏"零 Token Lint"核心卖点）；
- 不做"多个分数并列展示"（>2 个分数 = 用户困惑）；
- 权重校准前不做任何公钥变更承诺。
