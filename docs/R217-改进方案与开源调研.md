## 一、定位反问（第一性原理 — 每次推进前必答）

### 1.1 这个项目的定位是啥

**零 LLM 调用、确定性、CI 原生的 Prompt 质量与安全门禁 — "Prompt 的 ESLint"**。
输入 prompt 文件/模板, 输出可度量 finding + 门禁裁决（PASS/WARN/FAIL）,
全程不烧 token、同输入同输出、秒级、可嵌入任意 CI。
（R213 定位, R217 核验**仍然成立**: 竞品动态反而强化了该定位 — 见 1.3）

### 1.2 产品核心价值是啥（R217 更新: 护城河排序变化）

| 价值 | R217 现状 | 变化 |
|---|---|---|
| **可度量** | 双基线公开: FP 0.91%（58 clean, 棘轮 0.01）/ 漏检 0.00%（75/75, 棘轮 0.05）; 80 探针带 BCP-47 lang 分语言统计 | **护城河地位上升** — 2026 新竞对（llmguard-cli 公开 hybrid F1 0.94）开始公开度量, "无一公开"窗口收窄, 但我们的双基线+棘轮+CI 强制是更深的水位 |
| **确定性/零成本** | 纯静态, <100ms, 0 API 调用 | **护城河地位上升** — 2026 竞对集体向"regex+LLM 二审"混合架构漂移（PromptGuard v3.7 LLM-as-judge / llmguard-cli meta-reasoning / promptdiff A/B via LLM）, 混合架构=非确定性+成本+供应商依赖, 与 CI 门禁的可复现要求冲突; 纯静态确定性路线的稀缺性反而提高 |
| **全生命周期** | lint→scan→redteam→evaluate→compliance→version→compile→MCP | 不变 |
| **中文深度 + 华为生态** | 中文注入面（含 R217 零宽/BiDi 三语探针）/ 等保 2.0 / 鸿蒙模板 | 不变 |

### 1.3 目前推进方向有啥问题（对抗性自审 — R217 新证据）

**问题 1: "静态检测"赛道正在被"混合架构"竞对以营销叙事侵蚀**

2026 新信源全部指向同一趋势 — regex 快筛 + LLM 二审:
- **PromptGuard v3.7（2026-03）**: "Regex runs first (fast, deterministic);
  LLM-as-judge classifies; score merger combines" — 可选开启, 默认关闭
- **llmguard-cli（2026-02）**: 公开 500+500 评测: regex only F1 0.79 <
  hybrid F1 0.94, 叙事"regex too brittle, LLM too slow, hybrid both"
- **promptdiff**: A/B 测试走 Claude/GPT-4o/Ollama

→ **对策（不改变定位, 强化叙事）**: 不跟进 LLM 二审（破坏确定性 = 核心价值
自毁, 见 1.5 陷阱表）。但**必须把"确定性=CI 门禁唯一可信基础"的论证写进
README/文档**: hybrid 架构的 LLM 二审层不可复现（同输入不同输出）→ 不能当
门禁（门禁 fail 了重跑又 pass = CI 不可信）; 我们的漏检 0.00% 是"静态可检测面
内的确定性保证", 混合架构的 recall 数字来自一次性评测且含 LLM 方差。
**这是文档层动作, 零代码** — 最高 ROI。

**问题 2: 2026 攻击面迁移 — 编码/隐写输出攻击成为新主战场**

PromptGuard v3.6 一次性加了 5 组 44 pattern（COVERT_EXFILTRATION_CHANNELS /
LANGUAGE_SWITCH_EVASION / FEW_SHOT_HIJACK / INSTRUCTION_PIGGYBACKING /
RECURSIVE_DELEGATION_PAYLOAD）; garak 2026 encoding 探针族（quoted-printable/
MIME/zero-width）; 我们 R215/R217 已落地 P260+P261（零宽/BiDi/base64/同形
异码/hex-URL）— **方向正确且已占位**, 但对照 2026 新攻击面仍有**确定缺口**:

**定位反问修正（2026-10-01 实施中抓出）**: 2026 新攻击面必须按"**prompt 文件
属性 vs 模型输出属性**"切层 — 本项目定位=输入(prompt 文件/模板) lint, **输出侧
攻击面（输出 DLP）不在范围**, 应交由运行时/输出侧工具（LLM Guard 类）。下表按
此重切:

| 2026 新攻击面（信源实证） | 层 | 本项目现状（内部核验） | 裁决 |
|---|---|---|---|
| 莫尔斯/二进制节奏**输出**（"•-• …"式） | **输出侧** | — | **出局（定位外）**: 输出 DLP 属性, 非 prompt 文件属性 → 登记"定位外", 不做 |
| 倒序**输出**（"tnecres"） | **输出侧** | — | **出局（定位外）**: 同上 |
| Emoji 编码通道 | 输入/输出均可能 | 无规则 | **观察登记**: 输入侧需真实 prompt 文件案例（R214 emoji 实测无真实绕过）, 不预支 |
| 首字母/尾字母拼接（acrostic） | 输入侧 | 无规则 | **观察登记**: 构造成本高, 真实案例驱动 |
| **语言切换规避**（prompt 中途切语言躲关键词门） | 输入侧 ✅ | 分语言统计已有（R214 lang 标签）, 无跨块切换检测 | **P1 首选（F5-2）**: 机械 pattern（单 prompt 内 2+ 语言块+指令动词跨块）, 先扩样 |
| **尾部注入**（大量合法填充+尾部 HIGH 载荷） | 输入侧 ✅ | P011 填充率是**质量**门（短行占比>40%）, 非攻击门 | **P1 首选（F5-1）**: 尾部 N 字符指令密度检测, 先扩样; **FP 风险实测高**（合法 prompt 常以约束/格式结尾 — 语境门必须含"填充占比"前置） |
| Few-shot 投毒（示例对藏指令） | 输入侧 ✅ | 无规则 | **P2（F5 后续）**: 示例段内指令动词密度, 扩样先行 |
| 递归委托载荷（多步任务第 N 步藏恶意指令） | 输入侧 ✅ | 无规则 | **观察登记**: 依赖多步结构解析, 机制上限高 |

**问题 3: "lint 作为 eval 与生产之间的层"是 2026 社区共识 — 结构正确性
（变量解析）是该层的第一需求, 我们覆盖度有真实缺口**

tianpan.co（2026-04）列举 lint 层 5 类结构检查: required-section presence /
**variable resolution** / deprecated identifiers / length budget / PII absence。
内部核验:
- section presence: 大量既有规则覆盖（P010-P026 族）✅
- **variable resolution: 实施中实测 — 高价值半边已被 P256 check2 覆盖**
  （2026-10-01 数据驱动修正）: 边界用例实测（`# 变量` 声明段 + 正文引用
  `{{customer_name}}` 未列名 → P256 check2 正确报 HIGH "引用了变量声明段之外
  的变量"）— 即 tianpan 描述的"renders literal {user_locale} to the model"
  **最高价值故障形态已被覆盖**, 非缺口。**剩余半边=dead var（声明了但正文
  未引用, 卫生级 LOW）**: 58 clean 无一含声明段（扫描实测）→ 零样本支撑 →
  按 R213 问题 2 纪律（新规则必须先扩样, 无样本=噪音风险无度量背书）**不落地**,
  降级 P2 观察（F6 同批: 需先构造"含声明段且 261 规则全 0 命中"的 clean 样本,
  该样本本身会触发结构规则, 扩样可行性存疑 — 与 P256 声明段 header 复用同批评估）
- deprecated identifiers: 无（deny-list 基建）— **P2 候选**
- length budget: 无 token 预算规则（P011 是填充率非预算）— **P2 候选**
- PII: P241/P243 等已覆盖 ✅

**问题 4: 探针规模 80 达标, 但显著性检验仍被"家族覆盖"卡住（L3-6 维持）**

80 探针达成 R214 设定的 80+ 门槛, 但 L3-6 的完整裁决是"扩样到 80+ **且覆盖
更多真实攻击家族**" — 当前 80 条中 21 条是 R215/R216/R217 的**观察型+已知
缺口型**（expected 空）, 有效期望单元 75。A/B 显著性检验的统计功效取决于
**独立攻击家族数**而非总条数 — 当前家族: 注入/越狱/编码/密钥/PII/结构/
供应链/合规/多模态/RAG/Agent/治理 12 类（R212 口径）。**裁决: 不降门槛凑数,
但把"家族覆盖矩阵"显式化**（语言面覆盖矩阵的攻击类型轴已有, 缺"家族×规则"
交叉表 — 文档层动作）, 显著性检验排在"编码/隐写新家族扩样"之后。

### 1.4 需要怎样调整

1. **叙事升维（文档层, 零代码, 最高 ROI）**: README 加"为什么确定性检测是
   CI 门禁唯一可信基础"节 — 回应 1.3 问题 1 的混合架构叙事; 把双基线+棘轮
   从"我们公开了"升级为"混合架构做不到门禁级可复现"
2. **结构层补强（问题 3）**: 变量交叉解析规则（声明↔引用双向, 复用 P256
   已解析的声明段 + 占位符 span 机制 — 不造新解析器）
3. **攻击面跟进（问题 2）**: 按"先扩样→数据裁决→落地"的 B5 模板, 优先
   语言切换+尾部注入两个机械面（pattern 可写, 信源 PromptGuard v3.6 有
   44 pattern 实证但需逐词核对避免带入其误报面）
4. **明确不做（不改变）**: Web UI / LLM 二审 / codebase 污点 / 新依赖 /
   MCP 客户端

### 1.5 低价值打磨陷阱清单（R217 更新）

| 陷阱 | 为什么是陷阱 |
|---|---|
| **跟进 LLM 二审/语义检测层** | 2026 竞对主推叙事（PromptGuard/llmguard/promptdiff 全在做）— 但混合架构=非确定性+成本+供应商依赖, 与 CI 门禁可复现核心要求直接冲突; 做=自毁核心价值换营销叙事。零调用是特性不是缺陷, 文档讲清即可 |
| **为跟 2026 攻击面清单而把 8 项全落地** | PromptGuard 44 pattern 是其 FP 验证后的值, 我们的 58 clean 样本对 emoji/acrostic 等面**无样本** — 无样本支撑=噪音风险无度量背书（R213 问题 2 纪律: 先扩样）; 8 项中只有 2 项（语言切换/尾部注入）机械 pattern 可立即写+可扩样, 其余 6 项观察登记, 真实案例驱动 |
| **为 promptdiff 的"217 tests / 94% coverage"叙事凑覆盖率** | 当前 coverage 68.49% vs 70% 目标（L3-3）— 为覆盖率写"为测试而测试"的断言=低价值打磨; 随 P1 批次自然抬升 |
| **MLflow/prompt 仓库/git-like 版本控制**（promptdiff 在做） | 偏离"门禁"定位 — prompt 版本管理是 git/CI 的活; 我们的 version 命令已覆盖变更 diff 需求 |
| **自定义规则 DSL**（promptdiff .promptdiffrc / promptlint 自定义规则） | 看似高价值, 实为"让用户写规则"=把误报风险转嫁给用户; 与"确定性+可度量"冲突（用户规则无基线背书）; 261 条+family 分组+waiver 已覆盖团队定制需求 |
| **probe tier/tag 元数据（garak 式）** | 维持 R213 裁决: 展示层优化, 优先级 P2 |
| **性能微优化** | 维持 R213 裁决: <100ms, 感知阈值远未到 |
| **A/B 显著性检验现在做** | 家族覆盖不足时统计功效有限（L3-6）— 顺序不能反: 先扩编码/隐写家族探针, 再检验 |

## 二、开源调研结论（R217 新信源, 借鉴思路不抄代码, 零新依赖）

### 2.1 PromptGuard v3.6/v3.7（2026-03, TS, prompt-guard 生态活跃版本）

**可借鉴（思路层, 逐项内部核验过）**:
- **COVERT_EXFILTRATION_CHANNELS（莫尔斯/二进制/首字母/倒序/emoji 编码输出）**:
  2026 新攻击面实证 — 本项目 0 覆盖（grep 核验）→ F4 候选（先扩样, 见 1.3 问题 2）
- **LANGUAGE_SWITCH_EVASION**: 语言切换躲关键词门 — 我们分语言统计已有
  （R214 lang 标签机械派生）, 缺**跨块切换检测** → F5 候选
- **INSTRUCTION_PIGGYBACKING / _check_tail_payload（尾部注入）**: 大段合法
  填充+尾部 HIGH 载荷 — P011 填充率是质量门非攻击门 → F5 候选
- **Pre-filter gating 思路（~80% 跳过 LLM 调用）**: 混合架构的成本控制 —
  我们零 LLM 无需, 但**"语境门"哲学同构**: 先便宜门过滤再深检。我们的
  `_RAG_CTX_GATE`/`_AUDIT_SENSITIVE_CTX` 等已是该模式（R206-R208 收窄史）,
  验证路线正确, 文档可引用该类比
- **可插拔 detector 架构（BaseDetector+Registry）**: 与我们的
  rules.py 注册表同构, 不借鉴

**不借鉴**: LLM-as-judge（定位冲突, 见 1.5）; 付费 premium 层（API 独占
DNS 隧道/隐写/多态）— 商业模式不是我们的车道; pattern 库本身（其 FP
验证语料与我们不同, 逐词带入=误报面转移）

### 2.2 llmguard-cli（2026-02, rawqubit, 新竞对）

**可借鉴**:
- **hybrid 评测表公开（regex F1 0.79 vs hybrid F1 0.94, 500+500）**:
  这是 1.3 问题 1 的"对手叙事" — 回应不是做 hybrid, 是**指出其数字的局限**:
  F1 来自一次性离线评测, LLM 二审层有方差（同输入重跑不同输出）, 且 400ms
  均延迟不可嵌入 pre-commit 热路径; 我们的漏检 0.00% 是棘轮强制的
  **持续保证**（CI 每跑一次验证一次）, 不是一次性快照 → README 叙事节素材
- **威胁分类 6 类 + ATLAS 对齐**: 与我们的 family 分组+ATLAS 映射表同构,
  无新信息

**不借鉴**: HTTP API server（我们的 MCP server 73 工具已覆盖程序化消费,
且 MCP 是 2026 生态标准而非私有 HTTP）; 子进程调用模式（其 main.py 被
subprocess 包装 — 反面教材, 我们 import 级 API 更优）

### 2.3 promptdiff（TS, 2026, promptdiff 生态）

**可借鉴**:
- **`.prompt` 结构化格式（PERSONA/CONSTRAINTS/EXAMPLES/OUTPUT FORMAT/
  GUARDRAILS/CONTEXT section）**: 我们的 frontmatter+章节检测已覆盖 section
  presence; 其 `extends`/`includes` 组合语义是**模板组合面** — 观察登记
  （L3 候选, 需求未验证: 我们的用户以单文件 prompt 为主）
- **migrate 命令（plain text → 结构化）**: 我们的 upgrade-fm 已覆盖 frontmatter
  升级; 正文结构化迁移观察登记
- **watch 实时 lint**: VS Code 扩展面（1.6 短板项）, 维持 P1 不本轮

**不借鉴**: A/B via LLM（定位冲突）; MLflow 集成（偏离门禁定位, 1.5）;
自定义规则 DSL（1.5 陷阱）; git-like prompt 版本控制（1.5 陷阱）

### 2.4 tianpan.co "Prompt Linting Is the Missing Layer"（2026-04, 社区共识文）

**可借鉴（定位层最高价值信源）**:
- **"lint 是 eval 与生产之间的层"框架**: 行为 eval 测的是模型输出, 不测
  prompt 结构; 结构缺陷（变量未解析/section 缺失/预算超支）"eval-green 但
  生产炸" → 这正是我们 README 缺失的**需求侧论证**, 直接作为 README
  "为什么需要 prompt lint" 节素材（F1 文档项）
- **variable resolution 是 5 类结构检查中唯一有真实生产故障描述的**:
  "renders literal {user_locale} to the model, model gracefully ignores it"
  → F2 变量交叉规则的需求实证
- **deprecated identifiers deny-list**: 需求真实（"search_v1 弃用 6 周后
  prompt 还在引用"）→ F6 候选（P2, 基建: 需 .promptlint deny 配置面）
- **length budget**: 需求真实（"4200 token 的未清理 context block"）→
  F6 候选（P2, 字符/token 预算 frontmatter 声明+门禁）

**不借鉴**: 无（纯文章, 无代码）

### 2.5 garak 2026（NVIDIA, encoding 探针族更新）

**可借鉴**: quoted-printable/MIME 编码探针 → P260 子3 的 b64 有限集之外,
quoted-printable（`=` 前缀转义）与 MIME 头注入是 P260 机制上限声明的

## 四、对抗性审查（对本方案）

1. **F1 是"自卖自夸"风险?** — 是。缓解: 叙事节必须含**对手最强论据的正面
   回应**（llmguard-cli 的 F1 0.94 数字）+ 我们数字的**适用边界声明**
   （"静态可检测面内的确定性保证, 语义层攻击需混合架构" — 不贬低对手,
   划清各自适用域）。诚实声明是本项目度量可信度的组成部分
2. **F2 会不会误报合法"自由模板"?** — 高误报风险点。缓解: ① 仅当 prompt
   **含声明段**（`# 变量` header, P256 既有 header 定义）时才启用交叉校验 —
   无声明段=不启用（与 P256 文件级门同款作用域限定）; ② 声明段解析直接
   复用 P256 机制（不另写 header 识别）; ③ 扩样时必须含"含声明段的干净
   模板"（含合法 dead var 边界: 条件分支变量/文档示例变量 — 死变量报 LOW
   非 HIGH 是误报成本缓冲）
3. **F4/F5 的"先扩样"会不会拖死?** — 会, 如果扩样变成无限收集。缓解:
   每面扩样上限 = 2 clean + 2 golden（与 R213-B5/R215-B1 同量级）, 扩样后
   **一个门禁周期内必须出数据裁决**（过线落地/不过线登记观察）, 不悬置
4. **规则数 261→263 膨胀张力?** — R213 问题 2 纪律: 新规则必须先扩样+
   双基线全跑, F2/F4/F5 全部在门禁义务列有双基线流程 — 合规。且 F1/F3
   是纯文档项, 不增规则, 本批次叙事重心是"度量+结构层"而非"规则数"
5. **为什么不先做 F7（扩展短板端）?** — 奥卡姆: 内核能力（F2 变量解析/
   F4/F5 新攻击面）是扩展展示的价值来源; 先给扩展加 2 个"展示内核既有
   能力"的功能 = 空壳打磨。顺序: 内核 → 展示
6. **tianpan 的"lint refuses changes" 暗示 PR 级阻塞, 我们的 waiver 是文件级
   — 会成体验短板?** — 是潜在短板, 但 L3-13 裁决维持（行级 waiver 需 finding
   行号地基, 当前 location 是 "1:1" 级）; 文件级 waiver + `prompt-cli lint
   --ignore Pxxx` 已覆盖"本次放行"需求。登记 F6 重评条件含此
