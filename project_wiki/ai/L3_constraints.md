# L3 约束（团队层硬性约定 — 从代码与 CHANGELOG 实际惯例提取）

> 这些约定违反即 CI 红或基线回退, 新改动必须遵守

## 规则工程纪律

1. **56 干净样本 0 命中**: 任何新规则/规则修改, 从第一天断言 56 干净样本 0 命中（tests/test_r2XX_false_positive_fix.py 模式）
2. **正样本保留**: 收窄触发门时必须断言真场景仍命中（检测能力未削弱）+ 逐样本根因复核
3. **规则编号顺延**: P001-P256 只增不跳; 双基线达标前冻结规则数（R212 非目标, R213 解除视基线而定）
4. **触发门收窄优先序**: 修规则 > 降级 > 移出默认集（R206-R212 处置原则）
5. **否定前缀剥离**: DECL/放行类 pattern 必须防否定形式（"无转义"≠"有转义"）— R206 `_strip_negated_data` 现成组件, R213 修 4 盲区用

## 依赖与复用纪律

6. **零新第三方依赖**: 复用现有组件优先（R212 非目标; 新增需论证）
7. **不重复造轮子**: 实现功能前先查现有模块/开源参考（_strip_negated_data、RAG 语境门同构等先例）
8. **JSON 只增不改**: 新字段追加, 旧消费者不破（R212-5 health 先例）
9. **口径唯一事实源**: 展示数字（probes/规则数/版本号/测试数）必须读同一注册表, 禁止多处硬编码（R212-2/R212-7 根治的漂移源）

## 产品定位约束

10. **零 LLM 调用是核心定位**: lint/scan/probe 保持纯静态; 需 LLM 的能力（optimize/ab-test）隔离在可选依赖
11. **中文优先**: 错误信息双语, 中文 Lint 规则（全角标点为正常写作, ruff RUF001-003 ignore）
12. **i18n 仅 zh-CN/en-US**: 不做 9 语言（R212 非目标）
13. **静态探针**: 不做动态红队（需 LLM, 与定位冲突）

## 工程约定

14. ruff: line-length 120, double quote, ignore 清单有逐条理由（pyproject 注释）
15. 提交: 每批次全量回归 + ruff + mypy 棘轮 + 误报棘轮后才 commit; 消息格式 `R{轮次}-{批次}/v{版本}: 摘要`
16. 基线文档: 口径变更必须标注（如 32/56 样本不可直接对比）
17. 探针扩样: 标注 expected（可空=仅观察）; "已知否定盲区" note 前缀单列不藏
