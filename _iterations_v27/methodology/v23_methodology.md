## 一、核心原则 (P1-P54)

### 1.1 基础原则 (P1-P10)

| 编号 | 原则名称 | 核心要义 |
|------|----------|----------|
| P1 | 单一职责原则 | 每个Prompt仅承载一个明确目标，避免职责混杂导致模型注意力分散 |
| P2 | 上下文完备原则 | Prompt必须提供充分的上下文信息，消除模型的猜测空间 |
| P3 | 约束显式原则 | 所有约束条件必须显式声明，禁止依赖模型隐式推断 |
| P4 | 输出确定性原则 | Prompt应通过格式规范和示例引导，使输出结构可预测 |
| P5 | 防御性设计原则 | Prompt应预设异常路径和回退策略，防止模型进入不确定状态 |
| P6 | 最小权限原则 | Prompt仅赋予模型完成任务所需的最小操作权限 |
| P7 | 可审计原则 | Prompt的关键决策节点必须可追溯、可解释 |
| P8 | 版本锁定原则 | Prompt必须声明兼容的模型版本和依赖版本 |
| P9 | 渐进式复杂度原则 | Prompt应从简单任务逐步递进到复杂任务，避免一次性加载过多指令 |
| P10 | 正向引导原则 | 优先使用"应该做什么"而非"不应该做什么"的表述方式 |

### 1.2 安全原则 (P11-P20)

| 编号 | 原则名称 | 核心要义 |
|------|----------|----------|
| P11 | 注入隔离原则 | 用户输入必须与系统指令严格隔离，防止指令注入 |
| P12 | 敏感信息保护原则 | Prompt中禁止硬编码敏感信息，必须使用环境变量或安全存储 |
| P13 | 输入验证原则 | 所有外部输入必须经过校验和清洗后方可使用 |
| P14 | 输出过滤原则 | 模型输出必须经过过滤，防止泄露敏感信息或产生有害内容 |
| P15 | 角色边界原则 | Prompt定义的角色必须具有明确的权限边界，防止角色逃逸 |
| P16 | 降级安全原则 | 当模型无法完成任务时，必须降级到安全的默认行为 |
| P17 | 继承安全原则 | 模板继承链必须经过安全审计，防止风险沿继承链传播 |
| P18 | 最小暴露原则 | Prompt仅暴露完成任务所需的最少信息 |
| P19 | 时效性原则 | Prompt必须设置合理的超时和过期机制 |
| P20 | 沙箱原则 | 模型操作应在受限环境中执行，防止越权访问 |

### 1.3 性能原则 (P21-P30)

| 编号 | 原则名称 | 核心要义 |
|------|----------|----------|
| P21 | Token效率原则 | Prompt应在保证效果的前提下最小化Token消耗 |
| P22 | 缓存友好原则 | Prompt设计应考虑缓存复用，减少重复计算 |
| P23 | 延迟优化原则 | Prompt应优化模型推理路径，降低响应延迟 |
| P24 | 批处理原则 | Prompt应支持批处理调用，提高吞吐量 |
| P25 | 并行安全原则 | Prompt在并行调用下必须保持幂等性和安全性 |
| P26 | 流式适配原则 | Prompt应适配流式输出模式，提升用户体验 |
| P27 | 成本控制原则 | Prompt应平衡效果与成本，避免过度消费API资源 |
| P28 | 模型兼容原则 | Prompt应兼容多种主流模型，降低供应商锁定风险 |
| P29 | 降级适配原则 | Prompt应能在低配模型上降级运行而非完全失败 |
| P30 | 重试幂等原则 | Prompt的重复调用必须产生一致的结果 |

### 1.4 质量原则 (P31-P40)

| 编号 | 原则名称 | 核心要义 |
|------|----------|----------|
| P31 | Few-shot质量原则 | Prompt中的示例必须高质量、有代表性、覆盖典型场景 |
| P32 | 推理链原则 | 复杂推理任务必须包含Chain-of-Thought引导 |
| P33 | 错误处理原则 | Prompt必须覆盖常见错误路径并提供明确处理策略 |
| P34 | 边界覆盖原则 | Prompt必须考虑边界条件和极端输入 |
| P35 | 多语言原则 | 面向国际化的Prompt必须支持多语言输出 |
| P36 | 文化适配原则 | Prompt应适配不同文化背景的用户 |
| P37 | 可解释性原则 | Prompt的决策过程应可解释和可追溯 |
| P38 | 鲁棒性原则 | Prompt应在异常输入下保持稳定输出 |
| P39 | 一致性原则 | Prompt多次调用应产生语义一致的输出 |
| P40 | 意图匹配原则 | Prompt输出必须精准匹配用户意图 |

### 1.5 工具链原则 (P41-P54)

| 编号 | 原则名称 | 核心要义 |
|------|----------|----------|
| P41 | 编译验证原则 | Prompt的条件编译必须经过词法、语法、求值三阶段验证 |
| P42 | 缓存一致性原则 | 编译缓存必须基于内容哈希，保证缓存键的唯一性和一致性 |
| P43 | 依赖声明原则 | Prompt的所有外部依赖必须显式声明 |
| P44 | 环境隔离原则 | Prompt运行环境必须与开发环境隔离，凭证通过环境变量注入 |
| P45 | 版本兼容原则 | Prompt的依赖必须有版本锁定，防止不兼容变更 |
| P46 | 安全扫描原则 | 所有Prompt在上线前必须通过安全扫描 |
| P47 | 继承审计原则 | 模板继承链必须经过深度、循环、断裂和风险传播审计 |
| P48 | 注入检测原则 | Prompt必须经过5规则注入检测（指令覆盖、角色劫持、数据外泄、越权操作、模板逃逸） |
| P49 | 评估维度原则 | Prompt必须通过52维度评估框架的质量门禁 |
| P50 | Lint门禁原则 | Prompt必须通过P001-P020共20条Lint规则检查 |
| P51 | A/B验证原则 | Prompt的关键变更必须经过A/B测试统计验证后方可上线 |
| P52 | 渐进发布原则 | Prompt变更应采用灰度发布策略，逐步扩大影响范围 |
| **P53** | **工具链可运行验证原则** | Prompt引用的所有工具链（编译器、Linter、扫描器、评估器）必须在CI流水线中实际运行验证，禁止仅声明不执行；工具链运行失败必须阻断发布 |
| **P54** | **Prompt Linter驱动质量原则** | Prompt质量门禁必须由Prompt Linter自动驱动执行，而非人工检查；Lint规则(P001-P020)的覆盖率必须≥90%，未覆盖规则必须有显式豁免说明 |

## 三、新增原则详解

### P53：工具链可运行验证原则

**背景**: v22及之前版本中，工具链（编译器、Linter、安全扫描器、评估器）的存在仅体现为代码文件和设计文档，但缺少在CI流水线中强制运行的验证机制。实际项目中多次出现工具链代码存在但未执行的情况。

**要求**:
1. CI流水线必须包含以下工具链的实际运行步骤：
   - 条件编译器（Lexer → Parser → Evaluator → Renderer）
   - Prompt Linter（P001-P020规则检查）
   - 安全扫描器（注入检测 + 继承审计）
   - 52维度评估器
2. 工具链运行失败必须阻断发布，零容忍
3. 每次CI运行必须产出工具链执行报告，包含：执行状态、发现数、通过率
4. 工具链的测试覆盖率必须≥80%

**检查点**:
- [ ] CI配置文件中是否包含所有4类工具链的执行步骤
- [ ] 工具链失败是否配置为阻断发布
- [ ] CI报告是否包含工具链执行摘要
- [ ] 工具链测试覆盖率是否达标

### P54：Prompt Linter驱动质量原则

**背景**: v22及之前版本中，Prompt质量检查主要依赖人工Review，效率低且标准不一致。Prompt Linter已实现P001-P020共20条规则，但未强制在CI中执行。

**要求**:
1. Prompt质量门禁必须由Prompt Linter自动驱动，替代人工Review作为首要质量关卡
2. Lint规则(P001-P020)的覆盖率必须≥90%（即至少18条规则在每次检查中被执行）
3. 未覆盖的Lint规则必须有显式豁免说明，包括：
   - 豁免规则ID
   - 豁免原因
   - 豁免有效期
   - 审批人
4. Lint结果必须生成标准化报告，包含：通过/失败规则数、评分、自动修复记录
5. 评分低于60分的Prompt禁止上线

**检查点**:
- [ ] CI是否自动执行Prompt Linter
- [ ] Lint规则覆盖率是否≥90%
- [ ] 未覆盖规则是否有豁免说明
- [ ] Lint评分<60是否阻断发布
- [ ] Lint报告是否标准化输出

### AP53：不可运行设计反模式

**识别特征**:
1. 工具链代码存在于代码库中，但CI配置未引用
2. CI流水线中工具链步骤被注释或条件跳过
3. 工具链执行失败但CI结果为绿色（`|| true` 或 `continue-on-error: true`）
4. 工具链无任何测试覆盖

**危害**:
- 工具链形同虚设，质量问题无法被自动发现
- 开发者信任CI绿色状态，实际存在未检测的质量隐患
- 工具链代码退化，长期不运行导致兼容性问题

**修复方案**:
1. 在CI配置中添加工具链执行步骤，设置`fail-fast: true`
2. 为工具链编写集成测试
3. 定期（每周）运行工具链全量回归测试

### AP54：无Lint质量门禁反模式

**识别特征**:
1. 项目依赖人工Review检查Prompt质量
2. Prompt Linter未集成到CI流水线
3. Lint规则执行覆盖率<90%且无豁免说明
4. Lint结果不阻断发布流程

**危害**:
- 人工Review效率低，检查标准不一致
- 质量问题漏检率高
- 无法实现质量门禁的自动化和标准化

**修复方案**:
1. 将Prompt Linter集成到CI流水线的必经路径
2. 配置Lint规则白名单/黑名单，确保覆盖率≥90%
3. 设置Lint评分阈值（≥60分）作为发布门禁
4. 启用自动修复（`fix: true`）处理可自动修复的问题
