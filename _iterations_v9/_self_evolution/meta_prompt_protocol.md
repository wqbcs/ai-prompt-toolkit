# Meta-Prompt自改进协议 v1.0

> **版本**：v1.0
> **日期**：2026-05-29
> **来源**：第七轮G1批次

---

## 1. 五步闭环协议

```
┌─────────────────────────────────────────────────────────┐
│  Prompt → Execute → Evaluate → Improve → Re-execute    │
│     ↑                                       │           │
│     └───────────── 收敛判定 ←───────────────┘           │
└─────────────────────────────────────────────────────────┘
```

### Step 1: Prompt（当前提示词版本）
- 输入：当前版本的提示词P_n + 上下文C
- 输出：执行请求(P_n, C)

### Step 2: Execute（执行提示词）
- 输入：执行请求(P_n, C)
- 输出：执行结果R_n + 执行追踪T_n
- 追踪包含：trace_id, input_hash, output_hash, duration, token_count, model_version

### Step 3: Evaluate（评估执行效果）
- 输入：执行结果R_n + 期望标准S
- 输出：评估报告E_n = {score, subdim_scores, issues, suggestions}
- 评估维度权重：功能正确性(40%) + 输出质量(30%) + 安全合规(20%) + 效率(10%)

### Step 4: Improve（生成改进版本）
- 输入：评估报告E_n + 当前提示词P_n
- 输出：改进候选列表[Candidates] = Proposer(E_n, P_n)
- 候选筛选：安全边界检查 → 人工审批门禁 → 质量门禁
- 最终选择：P_{n+1} = Selector(Candidates, E_n)

### Step 5: Re-execute（重新执行验证）
- 输入：改进版本P_{n+1} + 相同上下文C
- 输出：执行结果R_{n+1} + 评估E_{n+1}
- 收敛判定：|E_{n+1}.score - E_n.score| < ε 连续3次 → 收敛

## 2. 安全边界

### 2.1 改进范围白名单（允许自动修改）
- 示例优化（替换/增加/删除示例）
- 约束强度调整（放松/加强非安全约束）
- 输出格式细节（字段顺序/描述措辞）
- 推理链步骤调整（增加/合并/重排步骤）
- 角色经验描述细化

### 2.2 改进范围黑名单（禁止自动修改，需人工审批）
- 安全属性与安全检查项
- 角色核心职责定义
- 输出Schema结构
- 审计与合规要求
- 形式化验证属性规约

### 2.3 改进幅度限制
- 单次参数变更≤±10%
- 约束项增删≤2项/次
- 示例替换≤1个/次
- 推理链步骤变更≤1步/次

## 3. 改进提议策略

| 策略 | 触发条件 | 改进动作 |
|------|----------|----------|
| 约束强化 | 约束完备性子维度<9.5 | 增加缺失约束/加强弱约束 |
| 示例优化 | 输出质量子维度<9.5 | 替换低效示例/增加边界示例 |
| 角色细化 | 角色深度子维度<9.5 | 细化经验描述/增加领域知识 |
| 格式调整 | 格式精确性子维度<9.5 | 优化输出Schema/增加格式约束 |
| 推理链调整 | 推理适配性子维度<9.5 | 调整CoT步骤/增加推理锚点 |

## 4. 收敛监控

- 收敛阈值ε = 0.01
- 收敛判定：连续3次|Δscore| < ε
- 震荡检测：连续5次Δscore正负交替
- 退化检测：Δscore < -0.05
- 最大迭代轮数：20（超限自动终止并告警）
